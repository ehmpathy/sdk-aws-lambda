# 🌙 dream: the blackbox suite imports `src`, so `dist` is built by every run and loaded by none

- kind = fix
- owner = `ehmpathy/sdk-aws-lambda`
- caught 2026-09-18

## .the cue that fired

self review `r3.has-all-tests-passed` at stone `5.3.verification` asked what a green acceptance
gate actually proves. the suite runs `npm run build` as its first step
(`package.json:50`) — so `dist/` is rebuilt on every acceptance run, and i went to check that the
built entrypoint carried this branch's new exports.

it does. `dist/index.d.ts` carries `getValidatedInput`, `getValidatedOutput`, `TranslateLog`, and
every peer.

⇒ **then the question inverted: which test imports it?**

## .the gap, precisely

**none.** every blackbox file imports the source:

```
grepsafe --pattern "from '\.\./src|from '\.\./dist" --path blackbox   →  14 hits, all ../src
grepsafe --pattern "from 'sdk-aws-lambda"          --path . --glob '*.ts'
    →  4 hits, and NOT ONE is an import — two are declapract fixtures, and two are
       GENERATED SOURCE TEXT that codegen emits into the sdk it writes
```

so the state is:

| step | happens? |
|---|---|
| `dist/` is compiled by `tsc -p tsconfig.build.json` | ✅ on every acceptance run |
| its path aliases are rewritten by `tsc-alias` | ✅ |
| its `.d.ts` carries the public surface | ✅ verified |
| 🔴 **any test loads `dist/index.js` and calls it** | **no** |

### the failure mode this leaves open, and why it is publish-shaped

`build:compile` is `tsc -p ./tsconfig.build.json && tsc-alias -p ./tsconfig.build.json`. the
second command rewrites `@/…` aliases in the **emitted js** into relative paths. if it ever
mis-rewrote — a config drift, a moved root, a version bump — then:

- `tsc` still succeeds, so `test:types` is green
- `dist/index.d.ts` is still correct, so a types-only check is green
- every test still imports `../src`, so **all 274 acceptance tests are green**
- and `require('sdk-aws-lambda')` throws `MODULE_NOT_FOUND` for the first consumer who installs it

⇒ **a published-package defect with no gate in front of it.** and it is not hypothetical for this
repo specifically: `asMechanismsFileSource.ts:40` emits `import { askLambdaEndpoint, type
ContextAwsLambdaCaller } from 'sdk-aws-lambda'` into every generated sdk, so **every consumer of
codegen loads `dist` on their first build**.

## .the shape of the fix

`rule.require.blackbox-via-selflink` (ehmpathy/mechanic) names the pattern: a blackbox test imports
the package **by its own name**, through a self-link, so the test exercises the artifact a consumer
receives rather than the source a maintainer edits.

1. **one smoke test, self-linked** — the cheapest rung by a wide margin. a single
   `blackbox/local.selflink.acceptance.test.ts` that imports the package by name and calls one
   exported operation. it closes the `MODULE_NOT_FOUND` class entirely, and it leaves the other 14
   files alone
2. **migrate the suite** — every blackbox file imports by name. this is what the rule asks for and
   it is a 14-file change plus the self-link wiring
3. **a publish-time smoke gate** — install the packed tarball into a temp dir and require it. the
   strongest, and it needs a new CI job

⇒ **rung 1 is the recommended first move.** the harm is one class — the built entrypoint does not
load — and one import proves it does.

## .why it is not done in this round

| question | answer |
|---|---|
| **SAFE?** | ✅ yes — a new test file touches no prod behavior |
| **CLEAN?** | 🔴 **no.** a self-link needs `package.json` + `tsconfig` wiring, and the acceptance config's `testMatch` and `transformIgnorePatterns` would both have to admit it. that is repo scaffolding this bound did not open |

⚠️ **and it is PRE-EXISTENT, not introduced here.** all 14 blackbox files imported `../src` before
this branch, and this branch added no new one that behaves differently. it is recorded because
`rule.require.sweep-the-defect-class` says a peer found outside the bound is still worth the
measurement — *"measure it, record it, and flag it — never leave it unlooked-at."*

### 🟡 why this carries NO fulcrum, stated rather than assumed

`rule.always.fix-forward-under-scouts-honor` says a deferral for **dirt** owes a fulcrum beside its

- the fulcrum board is what a wisher reads to see which of *my* choices to overturn. a

⇒ so the judgment is visible here rather than hidden, which is the property the rule protects.
