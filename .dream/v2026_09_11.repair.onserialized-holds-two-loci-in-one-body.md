## .the gap, precisely

the operation reads as an orchestrator for its first ~60 lines of body — guards, then a locus
branch — and then **becomes a leaf** inside the local arm: it loads a handler from
`serverless.yml`, frames a payload, runs it, and washes the throw.

`define.domain-operation-grains` draws the line this crosses:

| grain | contains |
|---|---|
| **orchestrator** | named operation calls only |
| **leaf** (transformer / communicator) | the work |

⇒ so the file is one function at two grains, and the reviewer's read is correct.

**checkable evidence** — the two arms are not symmetric, which is why the split is not merely
cosmetic:

| arm | what it does | grain |
|---|---|---|
| `at: 'cloud'` | delegates **wholesale** to `askLambdaEndpoint` | orchestrator |
| `at: 'local'` | resolves the handler, frames, runs, washes | **leaf** |

## .the shape of the fix

two private leaves in the operation's own directory, each with its own docblock:

```
runLambdaEndpoint/
  locus/
    runOnCloudLocus.ts   ← the delegation, and why it is wholesale
    runOnLocalLocus.ts   ← the lookup, the frame, the run, the wash
```

the orchestrator then reads as narrative, which is what
`rule.require.orchestrators-as-narrative` asks for:

```ts
assertEventIsGiven({ event, metadata: { which, at } });
const at = asLambdaEndpointLocus({ declared: input.at });
return at === 'cloud'
  ? runOnCloudLocus({ … }, context)
  : runOnLocalLocus({ … }, context);
```

🟡 **and each branch's rationale travels with its branch**, which is the reviewer's actual ask. the
density is not surplus — it is *displaced* (`rule.require.place-a-passage-by-its-subject`): the
local arm's 200 lines of argument sit in a file whose declared subject is both loci.

## .why it is not done in this round

**SAFE = 🟡 marginal · CLEAN = 🔴 no.**

- it moves **~200 lines of live control flow** at a stone already at its review budget, for a gain
  the reviewer itself grades *"low urgency … a documentation-density issue, not a correctness one"*
- the local arm is the one the integration suite exercises most heavily, so a move there is the
  move most likely to need a second verification pass
- ⇒ `rule.always.fix-forward-under-scouts-honor`'s own test: the fix is real and the round is wrong

✅ **and the same review's point 3 already shrank the file by ~110 lines**, which is the cheap half
of this repair taken at zero risk: both guard preambles collapsed to pointers once the canonical
account moved to `serde/asWireFunctionErrorPayload.ts`.

⇒ so what remains is the structural half alone, and it is smaller than when it was charged.
