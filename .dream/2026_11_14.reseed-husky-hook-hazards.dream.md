# 🌙 dream: reseed four husky hook hazards into declapract-typescript-ehmpathy

kind: reseed · owner: ehmpathy/declapract-typescript-ehmpathy · caught 2026-11-14

## .the cue that fired

a peer review of sdk-aws-lambda (arch-hazards-behavior) raised four nitpicks on `.husky/` hooks.
each hook is applied by the `husky` practice
(`src/practices/husky/best-practice/.husky/`), so a local edit is undone by the next
`npx declapract apply`.

## .the gap, precisely

1. `check.secrets.sh` — the `openai-style key` shape (`sk-(proj-)?[A-Za-z0-9_-]{20,}`) also matches
   `sk-ant-…`, and it sits first, so an anthropic key is reported as an openai key. still blocked;
   wrong vendor named
2. `check.timestamps.lock.sh` — `git hash-object` runs unguarded; a failed read yields an empty id
   and the hook reports "check.timestamps.sh was changed" with a fix that rewrites the hook
3. an unguarded `git diff`, in 3 hooks:
   - `check.secrets.sh`, `check.timestamps.sh` — `git diff --cached` runs bare under `set -e`; a
     git failure exits with git's raw status and no named MalfunctionError
   - `check.lockfile.sh` — `changed()` pipes `git diff --name-only HEAD@{1} HEAD` into `grep`; a
     failure (no reflog on a fresh clone) is swallowed, so the install reminder is silently skipped
4. `check.timestamps.lock.sh` — `timestamps_lock_halt` reads `$1` / `$2` positionally

## .the shape of the fix

1. anchor the openai shape away from `sk-ant-` (or report every shape that matches)
2. guard the hash read with a `|| timestamps_lock_malfunction` halt, as the index read is
3. wrap each `diff --cached` in the same guard as the `git show` below it; in `check.lockfile.sh`,
   read the diff first and name a failure before the `grep`
4. pass named values (`found=… where=…`)

## .why it is not done in this round

the files belong to the practice, not this repo; the fix lands upstream and arrives here via
`declapract apply`.
