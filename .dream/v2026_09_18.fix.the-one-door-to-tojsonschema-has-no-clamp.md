# 🌙 dream: the one door to `z.toJSONSchema` is an invariant with no clamp

- kind = fix
- owner = `ehmpathy/sdk-aws-lambda`
- caught 2026-09-18
- ✅ **CLOSED 2026-09-20 — rung 3 landed, in the same bound that caught it**

## ✅ .how it closed

`genIntrospectionMiddleware.getJsonSchemaFromZod.integration.test.ts` — 5 rows, and **both arms of
the table below are now clamped**: `[t1]` counts the prod call sites, `[t2]` grades the face on the
one that remains. each row was driven RED before the clamp was trusted, then reverted to green
(`rule.require.clamp-edge-cases`).

⚠️ **the `CLEAN? 🔴 no` verdict below was wrong, and the reason is worth more than the fix.** it
read *"rung 3 mints a test genre with no precedent"*. the genre is **declared** —
`rule.forbid.unit.remote-boundaries` states outright that a filesystem read belongs in an
`.integration.test.ts`, and `src/` already carries 9 of them. the probe that produced *"no
precedent"* grepped `*.test.ts` for `readFile|readdir|…`, which matches an integration test's
**suffix** but was read as the whole test corpus — so the search was sound and the **conclusion
drawn from it** was not.

⇒ **the general lesson: a `CLEAN? no` graded on an absence owes a positive control**
(`rule.require.positive-control-before-absence-claims`). a zero that blocks a fix is the most
expensive zero there is, and this one held a real repair for two stones.

**rung 1 (the lint rule) stays unbuilt, and the recommendation below stands as written** — it is
still the better rung, it still needs a wisher call on config scope, and rung 3 now makes the
invariant non-silent meanwhile.

## .the gap, precisely

`getJsonSchemaFromZod` exists to hold ONE decision — `{ io: 'input' }` — in one place. its own doc
says so:

```ts
// .why = this is the one door to `z.toJSONSchema` in src, so the wire face is a property of …
return z.toJSONSchema(schema, { io: 'input' }) as JSONSchema;
```

a second door — any future bare `z.toJSONSchema(schema)` — reopens the defect this whole change
exists to retire. **and it fails in two arms, only one of which is loud:**

| the second door meets… | the failure | caught by? |
|---|---|---|
| a schema with an `X.contract()` position | 🔊 `Transforms cannot be represented in JSON Schema` | **yes** — it throws at the first dobj it meets, so the author's own test goes red |
| a schema with a `.default()` field and no dobj | 🔇 it publishes that field inside `required` when it is **not** required | **no** — no throw, no red test, and the published contract lies |

the silent arm is the whole point. `local.introspection` `[case6]`/`[case13]` prove the ONE door
publishes `.default()` as optional; no clamp at all proves a **second** door does not exist to
publish it as required. a cross-service caller generated against that document is then told it MUST
send a field that has a default — the exact lie the vision names as its one observable behavior
change, restored.

## .the shape of the fix

three rungs, best first (`rule.prefer.prevent-over-correct` — make it impossible before you make it
detectable):

1. **make the second door impossible** — a lint rule that forbids `z.toJSONSchema` outside
   `genIntrospectionMiddleware.getJsonSchemaFromZod.ts`. biome has no import-path allowlist rule
   shipped for this, so it is either an `eslint` `no-restricted-syntax` addition or a biome plugin —
   a config change, with its own ripple
2. **make it hard** — hide `z` behind a module boundary so the raw symbol is unreachable from most of
   `src`. larger, and it fights the fact that `z` is used legitimately everywhere for schema
   declaration
3. **make it detectable** — a test that reads `src` and asserts exactly one call site

⇒ ~~rung 3 is the cheap one and it is the one this repo has **no pavement for**~~ — 🔴 **struck. the
claim was false, and the probe behind it was scoped narrower than the conclusion drawn from it.**

`grepsafe 'readFile|readdir|globSync|__dirname' --path src --glob '*.test.ts'` returned 6 lines in
one file — a **sound query**, whose hits were real. but `*.test.ts` matches an integration test's
**suffix**, so the corpus it was read as was not the corpus it reached. the genre is **declared** by
`rule.forbid.unit.remote-boundaries`, and `src/` already carried **9** `.integration.test.ts` files.

⇒ the control that settles it is one command, and it was never run:
`globsafe 'src/**/*.integration.test.ts'`. rung 3 mints no genre at all — it cost **one file and
zero config**, and it is what SHIPPED (see the header).

**the recommended first move is rung 1**, since the invariant is genuinely a lint concern rather than
a behavior, and a lint rule states it at the grain a future contributor actually meets — at the
keystroke, rather than after a run.

## .why it is not done in this round

the SAFE/CLEAN test:

| question | answer |
|---|---|
| **SAFE?** | ✅ yes — a lint rule or a test touches no prod behavior |
| **CLEAN?** | ~~🔴 no~~ → **split by rung.** rung 1 is still a lint-config change that re-grades the whole repo and can surface unrelated violations. ✅ **rung 3 is CLEAN** — one file, zero config. ⚠️ its original reason, *"mints a test genre with no precedent"*, was **false**; see the strike above |

⇒ so the deferral held for rung 1 on **ripple**, which is a real dirt call — and held for rung 3 on
an **absence that was never checked**, which is not. the second is the defect
(`rule.require.positive-control-before-absence-claims`), and it is why rung 3 shipped the round a
reviewer re-raised it rather than the round it was first weighed.

⚠️ **and the bullet it protects is NOT open.** this is insurance against a future regression, never a
gap in what the wish or the vision asked for. a reader who meets this dream should not read it as an
unmet acceptance line.
