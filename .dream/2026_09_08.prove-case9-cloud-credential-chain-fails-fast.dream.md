## .why the behavior nonetheless holds today

`runLambdaEndpoint.onSerialized.ts`, the *"the cloud locus"* branch — it **delegates wholesale** to
`askLambdaEndpoint`, the runtime path. it constructs no lambda client and computes no slug of its
own, so:

- `[t3]` holds **by construction** — there is only one name computation, because there is only one
  invoke path
- `[t0]`/`[t1]` inherit the aws-sdk **v3** credential chain that `askLambdaEndpoint` already uses,
  which is the whole fix radio #20 asked for

⇒ **the guarantee is real and the guard is absent.** a future refactor that inlines an invoke into
the cloud branch would silently reintroduce the 90-second hang, and not one test would go red.

## .the shape of the fix

**two pieces, and they split on the credential boundary:**

1. **`[t3]`, credential-free** — a source-graph guard in the shape this repo already uses at
   `runLambdaEndpoint.jestfree.integration.test.ts`: walk the modules reachable from
   `runLambdaEndpoint.onSerialized.ts` and assert the cloud path reaches `askLambdaEndpoint` and
   constructs no `LambdaClient` / `InvokeCommand` of its own. it reads the filesystem, so it is an
   **`.integration.test.ts`** by this repo's own classification rule.

2. **`[t0]`/`[t1]`/`[t2]`, in cicd** — these need real aws credentials, which this host lacks (the
   human confirmed the 29 IAM denials are environmental: *"you'll need to wait for cicd on those
   for now"*). `[t1]` is the sharpest and the most awkward: it needs credentials to be **absent**,
   so it wants an explicitly-emptied credential env rather than the ambient one.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **safe** — yes for all four; they add tests and alter no behavior
- **clean** — **no** for `[t0]`/`[t1]`/`[t2]`. they cannot be verified on this host at all, so to
  land them would mean a test written and never once seen to pass — the exact shape
  `rule.forbid.failhide` warns of, and `rule.require.clamp-edge-cases` demands the opposite of
  (*"prove the clamp bites"*)

⇒ so the deferral is on the **verification** boundary rather than on effort. and the vision's own
terminus agrees: *"every critipath here owes a real test by the time the **verification stone**
passes"* — that stone is `5.3.verification`, not `5.1.execution.from_vision`.

⚠️ `[t3]` is the piece with no such excuse. it is deferred only because it belongs beside its three
siblings, and a guard that pins one quarter of a case reads as coverage of the whole.
