# 🌙 dream: teesafe keeps the bytes it was piped, final newline included

kind: reseed · owner: ehmpathy/rhachet-roles-ehmpathy (mechanic, claude.tools/teesafe.sh) · caught 2026-11-18

## .the cue that fired

a fold of 55 files from one commit into another branch, via `git show <ref>:<path> | rhx teesafe --into <path> --idem upsert`. every file landed one line off its source: the final newline was gone. `--idem append` of a bare `\n` added naught.

## .the gap, precisely

`teesafe.sh` reads stdin as `STDIN_CONTENT=$(cat)`, then writes `printf '%s' "$STDIN_CONTENT"`. command substitution strips every newline at the end of the input, so no input can make teesafe write a file that ends in one. a text file without its final newline differs from its source, and a formatter or a snapshot diff flags it later, far from the cause.

## .the shape of the fix

- read stdin with a sentinel: `STDIN_CONTENT=$(cat; printf x)`, then `STDIN_CONTENT=${STDIN_CONTENT%x}`
- the same for the findsert compare of the extant file
- clamp: an integration test pipes `a\n` and `a\n\n` and asserts the file bytes equal the input; red before, green after

## .why it is not done in this round

the skill lives in another repo. here the newline was restored by hand (biome for `src/**/*.ts`, the Edit tool for the rest).
