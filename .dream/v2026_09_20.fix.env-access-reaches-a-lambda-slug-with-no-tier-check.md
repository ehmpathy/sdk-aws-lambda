`asLambdaEndpoint` builds a slug from an `access` value it never checks. an absent or malformed
`access` therefore produces a **well-formed-looking slug with a garbage segment**
(`svc-invoice-undefined-getInvoice`), which AWS answers with an opaque `ResourceNotFoundException`.

**.proof it is live** — read `src/domain.operations/asLambdaEndpoint/asLambdaEndpoint.ts:23-30`.

`LambdaEndpoint` types the field `access: string` (`src/domain.objects/LambdaEndpoint.ts:23`),
never the `EnvironmentAccessTier` union.

## .the gap, precisely — the family is THREE, plus their common ancestor

the membership rule: **a path where an `access` value reaches a `LambdaEndpoint` slug with no
runtime tier check.**

| # | site | what happens to a bad `access` today |
|---|---|---|
| 1 | `askLambdaEndpoint.ts:68` | **no guard catches it.** the slug is built, AWS is called, an opaque `ResourceNotFoundException` comes back |
| 2 | `getOneLambdaContract.ts:59` | an **incidental** catch — the `endpoint.access !== 'prep'` gate at line 68 throws, but its message reads *"introspection is only available in prep environment, got: undefined"*, which blames the tier where the true fault is an absent value |
| 3 | `getAllLambdaContracts.ts:99` | uses the `{ slug }` form; `access` is **parsed out of a real AWS function name**, so it is data rather than config |
| — | `asLambdaEndpoint.ts:17-54` | the common ancestor. **neither form checks `access`** |

row 1 is the one with no backstop at all. row 3 is the one that makes a naive repair hazardous.

## .why this violates a rule this repo already holds

`rule.require.env-access-in-context` states it outright:

> absent `env.access` handled by a silent fallback instead of a thrown `ConstraintError` = **blocker**

and gives the reason: *"access selects which deployed lambda you actually invoke … a silent default
could route a prod caller to a prep function."* a malformed slug is the same hazard, one step
further along — it routes nowhere and says why in AWS's words rather than in ours
(`rule.require.failloud`).

## .the shape of the fix

`isEnvironmentAccessTier` already ships from `sdk-environment` and is already used in this repo, at
`src/contract/cli/asGenArgs.ts:43` — so the check needs no new dependency.

**the fix is one assure at the common ancestor, plus a decision about form 2:**

```ts
// src/domain.operations/asLambdaEndpoint/asLambdaEndpoint.ts, form 1
if ('service' in input) {
  if (!isEnvironmentAccessTier(input.access))
    throw new UnexpectedCodePathError('env.access is absent or not a valid tier', {
      access: input.access,
    });
  // …
}
```

⚠️ **form 2 must NOT take the same guard without a decision.** `getAllLambdaContracts` parses every
function name a real AWS account returns. a live account that still carries a legacy tier segment
(`svc-x-demo-y`) would then throw and break **enumeration of the whole account** — a wider outage
than the defect being repaired. the two forms have different inputs (config vs observed data), so
they may legitimately want different strictness.

⇒ that choice is the fulcrum, recorded at `F37`.

**what the fix owes beyond the guard:**

- a unit case per row — the `[case2]` shape the deleted test held (`env` null, `env.access` null)
- row 2's message repaired, so an absent access stops reading as a wrong tier
- `LambdaEndpoint.access` narrowed from `string` to `EnvironmentAccessTier`, if form 2 is guarded too

## .why it is not done in this round — the SAFE/CLEAN answer

| question | answer |
|---|---|
| **SAFE?** | ✅ yes. every valid caller is unaffected; only a caller already headed for a malformed slug changes behavior |
| **CLEAN?** | 🔴 **no.** measured: `asLambdaEndpoint(` has **34 call sites across 9 files**, and `git diff --stat origin/main` is **empty** for all three cited paths. the repair opens the caller-side subsystem this branch never touched, and its riskiest path (`getAllLambdaContracts` against a real account) is **credential-gated**, so the fix cannot be proven on the path that matters most |

⇒ `rule.always.fix-forward-under-scouts-honor` grades `safe ✅ / clean 🔴` as **defer, and raise a
fulcrum** — which is `F37`.

⚠️ **the grade is sourced to a COUNT, never to an absence** — 34 sites, 9 files, one named
untestable path. `rule.require.positive-control-before-absence-claims` grades a `dirty` sourced to
a zero a blocker; this one carries its measurement and the command that produced it.
