# 🌙 dream: the error payload carries its metadata twice

- **kind** = fix
- **owner** = unclaimed
- **caught** = 2026-09-18, at stone `5.3.verification`, self-review `r7.has-ergonomics-validated`

## .the cue that fired

a probe captured the real error payload **from `dist`**, the built artifact, and printed it whole
for the first time on this branch. read side by side rather than field by field, the duplication is
immediate — and it is invisible in every extant snapshot, because each snapshot renders the two
copies far enough apart that no reader holds both at once.

## .the gap, precisely

one error response carries the same facts at two fidelities:

```json
{
  "errorMessage": "✋ ConstraintError: validation failed: surfer.name: Invalid input: expected string, received undefined\n\n{\n  \"issues\": [\n    {\n      \"path\": \"surfer.name\",\n      \"message\": \"Invalid input: expected string, received undefined\",\n      \"code\": \"invalid_type\"\n    }\n  ],\n  \"hint\": \"send a value that satisfies the endpoint declared input schema — correct each path named in `issues`\"\n}",
  "errorType": "BadRequestError",
  "details": {
    "issues": [
      {
        "path": "surfer.name",
        "message": "Invalid input: expected string, received undefined",
        "code": "invalid_type"
      }
    ],
    "hint": "send a value that satisfies the endpoint declared input schema — correct each path named in `issues`"
  }
}
```

**the mechanism:** `helpful-errors` appends the whole metadata block to `.message`. the sdk sets
`errorMessage: err.message`, so `errorMessage` inherits a serialized copy of exactly what `details`
already holds, structured.

**the cost:** a caller who logs `errorMessage` — the AWS-contract field, so the one most callers
reach for — gets a multi-line string with a whole JSON document escaped inside it. that is
`rule.require.treestruct-output` at the wire grain: the payload is not scannable at the field a
caller is most likely to read.

## .the shape of the fix

the honest form keeps `errorMessage` as a **title** and lets `details` carry the structure:

```ts
// today — err.message carries the serialized metadata block
errorMessage: err.message,

// the shape — the TITLE line only; `details` already holds the rest
errorMessage: err.message.split('\n')[0] ?? err.message,
```

⚠️ **`asErrorTitle` already exists as this exact transform**, in
`src/domain.operations/genLambdaEndpoint/middleware/getValidatedOutput.test.ts`, written for the
identical reason — *"`error.message` is NOT the title; `helpful-errors` appends the whole metadata
block to it"*. so the fix is to promote a test-local helper to a shared transformer and call it at
the two error-body builders.

### ⚠️ a SECOND escape, measured 2026-09-20 — and it is upstream, cleaner, and unnamed above

the fix above trims the **consumer** side. a read of `helpful-errors@1.7.5`'s own dist shows the
mechanism has an exempt-key list already, and it is two keys wide:

```js
// node_modules/.pnpm/helpful-errors@1.7.5/node_modules/helpful-errors/dist/HelpfulError.js:26
const metadataForMessage = metadata ? omit(metadata, ['cause', 'code']) : metadata;
```

⇒ **ONE `metadata` argument produces BOTH copies** — the serialized one at `:40-49`, the structured
one at the `.metadata` getter `:94-101`. so a consumer **cannot** keep a key structurally and drop
it from the message. that is why `r5.blocker.1`'s stated fix-forward — *"stop [the] hint in the
serialized `errorMessage` copy"* — is not expressible here, and the blocker was refuted on it.

⇒ but `cause` and `code` prove the **capability exists upstream**. the upstream shape is to widen
that list, or to accept a marker (`{ hint: { $structuredOnly: true } }`), so every consumer of
`helpful-errors` gets a scannable `.message` with no wire break on the structured half.

**seed it as a `reseed` dream to `ehmpathy/helpful-errors`** rather than solve it here — a
`.message` trim in this repo is the `SAFE? no` row below, and the upstream change is neither.

**the sweep this owes** (`rule.require.sweep-the-defect-class`): grep the **subject** —
`errorMessage` — never the form. the cause is *"a field set from `err.message`, which carries
metadata"*, so every site that assigns `err.message` to a wire field is in the family, whatever
syntax sits around it.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- 🔴 **SAFE? no.** `errorMessage` is the field an **ancient caller** reads
  (`invariant.ancient-vs-contemp-callers`). to trim it changes a shipped wire contract for callers
  this repo does not control, and an ancient caller that parses the embedded JSON out of
  `errorMessage` would break
- 🔴 **CLEAN? no.** it ripples into every error snapshot across both handler families, and the
  acceptance snapshots cannot be re-measured while `rhx keyrack unlock --owner ehmpath --env test`
  is locked
- and the stone is **verification**, not execution — a contract change here would verify a tree
  nobody executed

⇒ no fulcrum is owed: the deferral is not a judgment call I made about a design, it is an older
condition surfaced by a scored capture.
