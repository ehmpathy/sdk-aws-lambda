# 🌙 dream: header key case may differ between v1 and v2

**kind** `fix` · **owner** `ehmpathy/sdk-aws-lambda` · **caught** 2026-09-20 ·
🔴 **status: done** — shipped on the branch that caught it (fulcrum **F08**)

## .the gap

v1 (rest api) delivers header keys as the sender spelled them; v2 (http api) lowercases them. a
verbatim passthrough means `headers['X-Signature']` reads on v1 and is `undefined` on v2 — a silent
auth bypass in a webhook verifier.

the fixture `asApiGatewayRequestPayload` handed one header object to both arms, so no extant test
could tell the two apart (`rule.require.a-harness-types-as-wide-as-its-contract`).

## .the fix, as shipped

`asApiGatewayRequestEventUnified` lowercases header keys on both arms via `asHeaderKeysLowercased`
(rfc 9110 §5.1: field names are case-insensitive). the fixture can now vary case, so the clamp bites.

## .the evidence that settled it

the deferral this file first recorded said a lowercase fold would change reads for *"every extant
consumer."* measured across `ahbode/*` `src/**`:

| read | files |
|---|---|
| an inbound capitalized header key | **0** (the two `Authorization` hits are outbound) |
| any index of the inbound bag | **0** — the 129 sites forward `rawEvent.headers` whole |
| ✅ control: `{ authorization: … }` constructed | **68** in `svc-gateway` |

and the hazard was live: 4 app repos send `Authorization:` capitalized, while
`@middy/http-response-serializer/index.js:25` reads `headers?.Accept ?? headers?.accept`.

⇒ one grep would have avoided the deferral; the live deploy the deferral asked for was never needed.

## .the residual

the downstream package that reads `authorization` is unmeasured. if it reads lowercase, the fold
fixes v1 and no-ops v2; if capitalized, it is already broken on v2, so the fold cannot worsen it.
