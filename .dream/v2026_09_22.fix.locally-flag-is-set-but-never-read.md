# 🌙 dream: `LOCALLY` is set and never read, so `--against local` and `--against cloud` are one run

**kind** `fix` · **owner** `ehmpathy/sdk-aws-lambda` · **caught** 2026-09-22

## .the gap

```json
"test:acceptance:locally": "npm run build && LOCALLY=true jest -c ./jest.acceptance.config.ts …"
```

`rhx grepsafe --pattern 'LOCALLY' --path .` → 1 hit, the line above (control: `THOROUGH` → 2). no
test, config, or harness reads it. the mechanic harness maps `--against local` to
`test:acceptance:locally` and `--against cloud` to `test:acceptance`, so both arms run the same
config over the same files: 12 suites, 251 passed, identical.

this is not a coverage gap — all 12 suites run either way, `deployed.*` included. what is false is
the independence the two arm names assert.

also: `.github/workflows/.test.yml:211-212` names a step `test:acceptance:locally` and runs
`test:acceptance`.

## .the shape of the fix

keep the npm target name (the harness binds to it). then either:

- **make it real** — `jest.acceptance.config.ts` branches on `process.env.LOCALLY`: the local arm
  runs `blackbox/local.*`, the cloud arm `blackbox/deployed.*`. two disjoint, faster runs
- **make it honest** — retire the target, map both arms to one, correct the flag's docs

either way, fix `.test.yml:212` to match, or ci silently stops to run the local arm.

## .why it is not done here

not safe — option 1 changes which suites gate a release; a mis-split drops `deployed.*` with no red.
not clean — `jest.acceptance.config.ts`, `package.json`, `.test.yml`, and the harness docs, two of
them declapract-templated. the verification yield records the two arms as one run.
