# 🌙 dream: `getValidationError`'s hint names api gateway, in every family that calls it

**kind** `fix` · **owner** `ehmpathy/sdk-aws-lambda` · **caught** 2026-09-25

## .the gap — LIVE, NOT FIXED

on an `unrecognized_keys` failure on `headers`, `getValidationError` says *"api gateway injects keys
you did not declare — `host`, `x-forwarded-for`, `x-amzn-trace-id` — so a `.strict()` header schema
refuses every request."*

`setSqsRecordValidated` reuses it, and at sqs the clause is false:

| | api gateway | sqs |
|---|---|---|
| who else writes the header bag | the platform, every request | no one — `messageAttributes` is exactly what the sender set |
| `.strict()` on `headers` | ⛔ total outage | ✅ safe and correct |

an sqs author who correctly writes `.strict()` is told to loosen it.

clamp: `forSqs.perRecord`'s `[case14]` asserts the message contains *"api gateway injects keys"* —
green means the defect is present. `setSqsRecordValidated.ts` carries the in-code `.defect` block.

## .the shape of the fix

1. give `getValidationError` an input named for bag ownership, e.g. `{ headersBagIsShared: boolean }`
   — never a `trigger: 'apigateway' | 'sqs'` flag (`rule.forbid.names-that-mash-dimensions`)
2. emit the api-gateway clause only on the shared arm
3. clamp both arms; each case asserts the other's clause is absent. invert `[case14]`, do not delete it

sweep: `getValidationError` is the only shared error reader that composes its own prose;
`genInternalServiceErrorMiddleware`, `genConstraintErrorMiddleware`, and `getErrorResponseBody*`
forward `error.message` and author none. family = 1.

## .why it is not done here

safe (message prose), not clean: 3 production sites across two families and 6 test cases, several
snapshotted.
