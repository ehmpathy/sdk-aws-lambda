# 🌙 dream: `zod` and `domain-objects` want a peer range, not only a pinned hard dep

- **kind** = fix
- **owner** = `ehmpathy/sdk-aws-lambda`
- **caught** = 2026-09-18, during peer review `r011 enroll-impl-arch-defects` of
  `v2026_08_03.feat-input-only-validation-and-hydration`

## .the cue that fired

a reviewer read `package.json` — which **no round of this branch's review chain had opened** — and
found `"domain-objects": "0.34.0"` and `"zod": "4.4.3"` declared as plain `dependencies`, with **no
`peerDependencies` block in the file at all**.

its argument: before this PR, a consumer's own domain-object classes touched this sdk only at
codegen time. now `X.contract()` schemas built from a **consumer's** install are parsed on every
request, so a version split risks two live copies of `DomainEntity` in one `node_modules`.

## .the gap, precisely

the reviewer's **conclusion** holds. its **mechanism** does not, and the difference decides the
repair — so both are recorded.

### what was measured, not read

```
grepsafe --pattern "instanceof (DomainEntity|DomainLiteral|DomainObject)|from 'domain-objects'" --path src
```

⇒ **zero runtime `instanceof` against a domain-objects class anywhere in `src` prodcode.** every
prodcode import is a `import type` (`DomainObjectKind`, `DomainObjectPragma`,
`DomainObjectPragmaRef`, `DomainObjectRefBy`), which erases at compile time. three files import the
base class as a **value**, and each one only `extends` it to declare one of this sdk's OWN domain
objects — `LambdaEndpoint`, `GeneratedFile`, `DomainObjectCaptured`.

so on the parse path the sdk's copy of `domain-objects` is never reached: the consumer builds the
schema with their install, and `.safeParse()` runs **their** code. the split the reviewer described
cannot bite there.

### the cross-copy call that IS live, and it is `zod`

`genIntrospectionMiddleware.getJsonSchemaFromZod.ts:1` is a **value** import:

```ts
import { z } from 'zod';
…
return z.toJSONSchema(schema, { io: 'input' }) as JSONSchema;
```

⇒ **this sdk's `z` is handed a schema object the consumer's `zod` constructed.** zod's internals
read `_zod.def` off the schema, so a minor-version split in that internal shape publishes a wrong
contract, or throws, with no version check anywhere to name the cause.

⚠️ so the exposure ranks **`zod` first, `domain-objects` second** — the inverse of the review's
framing. `domain-objects` still earns a range, for two reasons the parse path does not supply: this
sdk's three own dobjs extend its bundled base, and `ContractOf` is a type this sdk names in a
public signature.

## .the shape of the fix

```jsonc
"peerDependencies": {
  "zod": "^4.4.3",
  "domain-objects": "^0.34.0"
},
"peerDependenciesMeta": { /* neither optional — both are load-bearing at runtime */ },
"dependencies": { /* keep both, so a direct consumer still installs */ }
```

and the half that makes it more than a manifest edit: **a clamp**. an acceptance case that asserts
the two copies are ONE module — compare the file path this sdk's `z` was loaded from against the
path a consumer's own `import { z }` yields, and fail loud when they differ. today a split
publishes a wrong contract with no tell (`rule.forbid.failhide`).

## .why it is not done in this round

**SAFE** — ⛔ unmeasured. a peer range changes how every consumer's install picks a version. npm 7+
auto-installs a peer and can **hard-error** where no version satisfies the range; pnpm's
`strict-peer-dependencies` errors by default. neither behavior was measured here, so the change
could break an install this round cannot observe.

**CLEAN** — ⛔ no. it ripples past this diff into every consumer's lockfile, and the range's WIDTH
is its own call: `^4.4.3` bets that zod holds its internal `_zod.def` shape across minors, and the
very defect this dream names is that internal shape adrift.

⇒ both answers are ⛔, so it defers — and per `rule.always.fix-forward-under-scouts-honor` a
deferral for **dirt** is a ripple-cost judgment, so it owes a fulcrum as well as this dream:
**F03** in `.behavior/v2026_08_03.feat-input-only-validation-and-hydration/.fulcrums/`.

## .what this round DID repair

the review's item 2, which rode in the same lane and passed both tests: the dangling `F33`
citation in `genZodOutputValidationMiddleware.ts` now names the sibling behavior folder that holds
that fulcrum.
