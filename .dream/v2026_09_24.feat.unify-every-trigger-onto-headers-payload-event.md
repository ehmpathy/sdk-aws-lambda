# 🌙 dream: unify every message trigger onto `{ payload, headers, event }`

- **kind** = feat
- **owner** = `ehmpathy/sdk-aws-lambda`
- **caught** = 2026-09-24

## .the cue that fired

> *"should we make a message|record|invocation always in shape `{ headers, payload, event }`?"* ·
> *"`forSqs.perRecord()` -> one by one -> headers, payload, event … `forSqs.perBatch()` -> batches ->
> event, records"* · *"and then it becomes universal"* — the wisher

## .the target

```ts
invoke: ({ payload, headers, event }, { log }) => log.trail.exid
```

| slot | sense | reach |
|---|---|---|
| `payload` | the body, parsed and validated | every family that carries a message |
| `headers` | the transport's metadata bag, raw | every transport that carries such a bag |
| `event` | the whole object that arrived | every family |

the lineage rides `context.log.trail`; an `input.trail` slot is forbidden (`domain.terms/trail.md`).
the rule is *every family that carries a message* — s3, dynamodb streams, and cron carry no body, so
`payload` does not apply there.

## .the shape of the rest

**`forAsk`** gains a `headers` slot only if `askLambdaEndpoint` grows a metadata bag on the wire.

**`forSns`** — unwrap `Records[0].Sns`: `Message` → `payload`, `MessageAttributes` → `headers`, the
notification → `event`. reuses the extant chain.
