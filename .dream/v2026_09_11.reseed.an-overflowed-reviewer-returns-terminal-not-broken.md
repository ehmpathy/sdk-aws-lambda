# 🌙 dream: an overflowed reviewer returns TERMINAL, so a drive reads it as a clean pass

- **kind** = reseed — the fix belongs to `bhrain`'s route-skill, not to this repo
- **owner** = `bhrain/role=driver` + the `rhx review` harness
- **caught** 2026-09-11, on `v2026_09_03.feat-absorb-handler-invoke-test-util`

## .the cue that fired

i032 r011 (`enroll-impl-arch-defects`) charged:

> *"Every rubric-based review round from **i023 through i031** … failed outright:
> `✋ prompt exceeds 75% of context window — 94.8%–95.2% of 1,000,000 tokens`.
> Only the two agent-driven `enroll-impl-*` lanes have produced real signal since i023 — every
> other lane has been silently non-functional for **8+ iterations**."*

⚠️ **the word "silently" is the part to correct, and the correction is what makes this a dream
rather than a nitpick.** each overflowed lane DID emit its diagnosis to stderr, with the file count
and the token total. what is absent is a consumer that reads it.

## .the gap, precisely

`rule.always.diagnose-reviewer-malfunctions` already names this exact case, and names it as the
hardest of the four:

> *"🔴 **its temptation is unique.** every other malfunction announces itself as broken; an
> overflowed reviewer returns **terminal** and unlocks the next level, so it reads much like a
> reviewer that ran."*

⇒ so the rule knows the hazard and puts the whole burden on the driver's attention. **the harness
offers no signal a guard can read.**

**checkable evidence** — the two states are indistinguishable downstream:

| the lane | stdout the guard parses | what the guard concludes |
|---|---|---|
| ran clean | `0 blockers` / `0 nitpicks` | approved |
| **overflowed** | (no numeric count; the `✋` goes to stderr) | 💥 malfunction — **which is terminal, and unlocks the next level** |

and `contract.reviewer-output` states the consequence outright:

> *"a silent `0/0` would read as a clean approval where in truth **no verdict was seen**"*

🔴 **this drive proves the cost empirically.** nine rubric lanes were non-functional for **eight
iterations**, and the tree still carried real defects the whole time — i032 r011, the first arch
pass that actually ran, found **two on its first read** (a verbatim guard duplication and a fact
narrated three times). so the `0/0` was not merely unverified; it was **wrong**.

⇒ **an unreviewed reviewer is indistinguishable from a clean one**, which is `rule.forbid.failhide`
at the harness grain.

## .the shape of the fix

the harness already knows it overflowed — it prints the percentage. so the fix is a **third
verdict**, not a new measurement:

1. **emit a distinguishable state.** an overflow is neither `approved` nor `malfunction`; it is
   `unmeasured`. give it its own stdout token so the guard can branch on it.
2. **make `unmeasured` non-terminal for unlock.** an overflowed l1 must not unlock l3 — that is the
   precise inversion the current design carries.
3. **print the scoped re-run in the failure text.** `rule.always.diagnose-reviewer-malfunctions`
   already documents the remedy (`rhx review --rules … --paths-with … --goal exhaustive`); the
   harness should hand the driver that command rather than expect them to recall the brief.
4. 🟡 **or, upstream of all three: auto-scope.** the guard hardcodes `--diffs since-main`. a lane
   that overflows could retry once, narrowed by subsystem, before it reports a verdict at all.

## .why it is not done in this round

**SAFE = 🔴 no · CLEAN = 🔴 no.**

- the fix lives in `bhrain`'s route-guard and the `rhx review` harness — **another repo**. a tree
  adopts only what is scoped to itself (`rule.always.catch-dreams-for-followups`)
- it changes a **verdict taxonomy** that every route in every repo reads, so the ripple is
  org-wide rather than diff-local
- ⇒ it is a `reseed`, and the seed is this file

.note = the driver-side half was already performed in this tree, and is not what this dream asks
  for. the execution yield's *"the first arch sweep in 21 rounds"* section re-grades every
  overflowed round as **unmeasured** rather than clean, by hand. that is the workaround; this is
  the repair.
