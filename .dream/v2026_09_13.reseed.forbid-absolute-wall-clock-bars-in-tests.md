# 🌙 dream: forbid an ABSOLUTE wall-clock bar inside a test

- **kind** = `reseed` — the fix belongs to `ehmpathy/role=mechanic`, not to this repo
- **owner** = `ehmpathy/role=mechanic`, practices `code.test/`
- **caught** = 2026-09-13, at i038 r011 of
  `v2026_09_03.feat-absorb-handler-invoke-test-util`

---

## .the cue that fired

a clamp I wrote — `getOneHandlerFromServerlessYml.integration.test.ts` `[case7][t1]` —
asserted that a memo hit costs under 2 ms:

```ts
expect(elapsedMs).toBeLessThan(2);
```

with a comment that claimed, in my own hand:

> *"a LOOSE bound on purpose … it cannot flake on a slow machine."*

**it flaked at 4.80 ms**, on the first run that put 16 suites against
`maxWorkers: '50%'`.

🔴 **and it had gone green minutes earlier, scoped to the one file** — so the
defect is invisible to the very command an author reaches for to verify a single
test:

```sh
rhx git.repo.test --what integration --mode apply --scope path://<file>
```

one suite, no contention, 3s. the same file under `--thorough` took 19.4s.

## .the gap, precisely

`rule.forbid.time-assumptions` names this defect and then **excludes the files it
lives in**:

```md
## .scope
applies to **production code**. …

**out of scope:**
- *.test.ts, *.integration.test.ts, *.acceptance.test.ts
```

⇒ so a wall-clock bar in a test is not merely unrated — it is **deliberately**
unrated, and a reviewer who reads that scope line will decline to grade it.

the exclusion is defensible for what it was written for (a test may `sleep`, may
set a jest timeout, may await a real network call). it is too wide by one case:
**an ASSERTION whose subject is elapsed time.**

⚠️ **and the harm lands on the shared suite, never on the author.** the clamp is
correct when they run it, so it ships; it reddens later, for someone else, on a
busy ci box — which is the shape that teaches a team to re-run rather than to
read.

## .the shape of the fix

a nitpick-or-blocker rule under `code.test/`, roughly
`rule.forbid.absolute-wall-clock-assertions`:

> **an assertion on elapsed time must be RELATIVE to a baseline measured in the
> same test, under the same load — never an absolute constant. and it must take
> the MINIMUM of several trials, because one sample can catch a scheduler pause.**

the two repairs, and what each answers:

| the flaw | the repair |
|---|---|
| an absolute bar drifts with machine load | measure the slow path in the same test, then compare the two |
| one sample can catch a scheduler pause | take the min of N — a pause inflates some samples, never all |

the worked form is already on disk, in this repo, at
`getOneHandlerFromServerlessYml.integration.test.ts` `[case7][t1]` — five hit
trials against five forced-miss trials, `min(hit) * 4 < min(miss)`. it survives
`--thorough` and still goes red the moment the memo is removed (bite-probed both
ways).

🟡 **the rule should also name WHERE to verify.** the practice half carries as
much weight as the assertion half:

> a clamp whose subject is elapsed time is verified under `--thorough`, never
> scoped. a scoped run is the one condition under which it cannot fail.

⇒ that sentence has no home today. `rule.require.clamp-edge-cases` demands the
bite probe and says naught about the load the probe runs under, and a bite probe
is cheapest scoped — so the extant rule actively steers an author to the run that
hides this class.

## .why it is not done in this round

the fix is a rule file in `ehmpathy/role=mechanic`, a different repo. the
instance in THIS repo is already repaired forward, in the diff that was open
(`rule.always.fix-forward-under-scouts-honor`), and the reason is recorded at the
site.

⇒ so what is owed upstream is the generalization, and it is not clean to pull
into a `sdk-aws-lambda` behavior tree.
