# 🌙 dream: `genServiceSdk` takes a `log` and emits no status

- **kind** = fix
- **owner** = unclaimed
- **caught** = 2026-09-18, at stone `5.3.verification`, self-review `r7.has-ergonomics-validated`

## .the cue that fired

a probe ran `genServiceSdk` from `dist` and printed the generated files. **between the section
header and the first file, the terminal emitted not one line** — no count of endpoints found, no
name of a file it wrote, no report of where the output landed.

that silence is what prompted the grep. it would never have prompted a code read: the operation
works, its tests pass, and the absence is only visible when a human watches it run.

## .the gap, precisely

`genServiceSdk` does two things `rule.require.status-feedback` names outright:

| what it does | the rule |
|---|---|
| walks a service over the network — one `ListFunctions`, then one `Invoke` per endpoint for its schema | *"a wait longer than a moment with no progress indication = blocker"* |
| **writes files to disk** | *"a mutation that does not report what changed = blocker"* |

and it reports neither.

🟡 **the sharper half: it demands a `log` it does not use.** the context signature is
`{ log, env, aws }`, so every consumer must supply an instrument — and the operation threads it
downward to the caller op without ever emitting a line of its own.

## .the shape of the fix

three lines at the boundaries the operation already has, in `genServiceSdk.ts`:

```ts
// before the network walk
context.log.info('genServiceSdk.began', { service: input.which.service, into: input.into });

// after the contracts are gathered — the count is the progress signal
context.log.info('genServiceSdk.contracts', { count: contracts.length });

// after the files land — the mutation report `rule.require.status-feedback` demands
context.log.info('genServiceSdk.wrote', { into: input.into, files: names });
```

**the sweep this owes** (`rule.require.sweep-the-defect-class`): the cause is *"an operation that
accepts a `log` in context and never emits one"*, so grep the **subject** — every operation whose
context type carries `log` — never the form of this one call. `genLambdaEndpoint` and
`askLambdaEndpoint` are the obvious peers and each should be checked, not assumed.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- ✅ **SAFE? yes.** log lines add no behavior a caller can observe, and no snapshot captures stdout
- 🔴 **CLEAN? no.** `genServiceSdk.ts` is not in this branch's diff, and its subject — codegen
  status — is not this branch's subject, which is input validation, hydration, and the
  introspection publish
- 🔴 **and the stone is `5.3.verification`.** to add a feature at a verification stone is to verify
  a tree nobody executed. the find is the deliverable here; the fix is not

⇒ no fulcrum is owed: this is an older condition surfaced by a scored capture, not a design call I
made and deferred.
