# 🌙 dream: the `logTranslate` redaction case asserts only the handler's return

**kind** `fix` · **owner** `ehmpathy/sdk-aws-lambda` · **caught** 2026-09-25

## .the gap

`genLambdaEndpoint.forAsk.test.ts` `[case5]` is named `logTranslate for redaction`. it sets a
`logTranslate.input` that replaces `password`, then asserts only `result` and a snapshot of
`result`. the redaction happens on the way to the log, which is never read — so the case stays green
if the hook never runs, and reads as coverage.

the hook's liveness per family:

| family | chain order | `logTranslate.input` |
|---|---|---|
| `forSqs.perRecord` · `.perBatch` | trail before io logger | ✅ live, measured (`perRecord` `[case11]`) |
| `forAsk` | trail before io logger | ⚠️ live by order, unmeasured |
| `forApiGateway` | io logger before trail | 🔴 dead — see `v2026_09_22.fix.logtranslate-input-is-dead-for-the-apigateway-family.md` |

one shipped family already has this hook silently dead, so *"the order looks right"* is not
evidence. `logTranslate.output` is measured only by `forSqs.perBatch` `[case12]`.

## .the shape of the fix

copy the sqs pattern (`perRecord` `[case11]`, `perBatch` `[case12]`), which bites:

1. a spy `logTranslate.input` that increments a counter; assert 1
2. a positive control — a `dispatch` string the handler sets — so 0 reads as *the branch never ran*
3. the `output` half for `forAsk` and `forApiGateway`

## .why it is not done here

safe (test-only), not clean: the round was bounded to the sqs family, and the api-gateway half waits
on a deferred chain reorder.
