# 🌙 dream: a pr opened by git.commit.push can carry a body the route wrote

kind: reseed (ehmpathy mechanic role, `git.commit.push`) · owner: mechanic · caught 2026-10-23

## .the cue that fired

pr #75 (sdk-aws-lambda) opened with a body built from the branch's FIRST commit, which describes the `.name` guard the human later dropped. the true body sits in `.behavior/v2026_10_22.fix-local-locus-reads-error-name/appendix/pr.body.md`, with two questions for the commander. `gh pr edit --body-file` is not paved, and `git.commit.push --help` lists no body option.

## .the gap, precisely

- `git.commit.push` options: `--mode`, `--auth`, `--output`, `--pr-title-fallback`, `--debug`. none sets the body
- `gh pr edit` is blocked by the permission hook; `rhx permissions.get --for 'gh pr edit 75 --body-file x.md'` names no paved alternative

## .the shape of the fix

`git.commit.push --pr-body-file <path>` (and `git.commit.set --push --pr-body-file`): findsert the pr, then set its body from the file. a pr that already exists gets its body upserted, so a stale body from an early commit is overwritten.

## .why it is not done in this round

the skill lives in another repo; a tree adopts only what is scoped to itself.
