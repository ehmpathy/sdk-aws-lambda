# 🌙 dream: jest scans the gitignored `.log/` for snapshots, so one scratch `.snap` reddens every run

**kind** `fix` · **owner** `ehmpathy/sdk-aws-lambda` · **caught** 2026-09-23 · fulcrum **F19**

## .the gap

```
rhx git.repo.test --what unit --mode apply --scope 'path://asHeaderKeysLowercased'
   ├─ status: ✋ failed (2s)
   └─ tests: 5 passed, 0 failed, 0 skipped
```

the cause, only in stderr: `1 snapshot file obsolete … • .log/verify/old.wireResponse.snap`.

jest discovers snapshots outside `testMatch`, and none of the four jest configs excludes `.log/`. an
obsolete snapshot is a non-zero exit. `.log/` is gitignored (so the break is local-only and CI never
sees it) and is where the test skill writes its own logs (so it is the first scratch path a human
reaches for).

## .what already shipped

`'!**/.log/**'` in `testMatch` — jest also loaded `.log/**/*.test.ts` as suites:

```
before:  Test Suites: 3 failed, 53 passed, 56 total · Snapshots: 1 file obsolete · exit 2
after:   Test Suites:           53 passed, 53 total · Snapshots: 1 file obsolete · exit 2
```

the snapshot half stays open. sweep note: biome had the same defect on `.agent/.cache`.

## .the shape of the fix

```ts
modulePathIgnorePatterns: ['<rootDir>/.log/'],
```

in the base `jest.config.ts` if the four configs compose, else in each. prove it bites: drop a
`.snap` under `.log/verify/` → green; revert the config → red.

## .why it is not done here

not safe — `modulePathIgnorePatterns` governs module resolution too, and an overreach shows up only
as a smaller green run. not clean — up to four configs every suite loads. the trigger is dormant (the
scratch file was renamed `.snap.txt`).

the runner-side half — `✋ failed` beside `0 failed` with no reason — is upstream as
`ehmpathy/rhachet-roles-ehmpathy#805`.
