## ✅ .closed — and what fell was the deferral's own premise

the defer rested on one claim: *"three of the 14 are integration snapshots I cannot run here, so
their state is genuinely **unmeasured**."*

⚠️ **"unmeasured" was a choice.** the snapshots could be run; only the aws call beneath one of them
could not. measured, with the quotes in place:

```
Snapshots:   1 failed, 3 passed, 4 total
```

the single failure is the **known** IAM denial — `"messageContains": "not found"` → `"other"`,
downstream of the 29 the human already ruled environmental. every cli contract snapshot passes.

⇒ local integration baseline **29 → 30 failures**, and the 30th shares the other 29's root cause.

🟡 **`-z` collapsed identically and was accidentally right.** `[ -z $THOROUGH ]` unset is also a
one-argument test of a literal, so it was also always true — and *"always narrow the scope"* was the
intended default anyway. one bug, two variables, one bite. **a defect that yields the right answer
is still a defect**, and the quoted form is what makes either behavior legible.

## .the cue that fired

i reached for a snapshot as a drift clamp on the package barrel, then dogfooded it per
`rule.require.clamp-edge-cases` — land the clamp, break what it guards, watch it go red.

it did not go red.

```
1. resnap               → .snap written with 35 exports
2. add an export to src/index.ts
3. run WITHOUT --resnap  → 🎉 passed ... and the .snap file now holds 36
4. withdraw that export
5. run WITHOUT --resnap  → 🎉 passed ... and the .snap file is back to 35
```

⇒ **the snapshot re-writes itself on every run.** a run with no `--resnap` must never write a
*changed* snapshot, so this is not jest's documented behavior — `--updateSnapshot` is always on.

## .the gap, precisely

`package.json:48-52` — the test scripts, all four of them:

```jsonc
"test:unit":        "jest ... $([ -n $RESNAP ] && echo '--updateSnapshot')",
"test:integration": "jest ... $([ -n $RESNAP ] && echo '--updateSnapshot')",
"test:acceptance":  "jest ... $([ -n $RESNAP ] && echo '--updateSnapshot')",
"test:acceptance:locally": "jest ... $([ -n $RESNAP ] && echo '--updateSnapshot')",
```

**`$RESNAP` is unquoted.** when it is unset the expansion vanishes and the test degrades to:

```sh
[ -n ]
```

POSIX `test` with a **single** argument tests that argument for non-emptiness as a *string*. the
argument here is the literal `"-n"`, which is non-empty. so `[ -n ]` is **always true**, and
`--updateSnapshot` is passed on **every run of every suite**.

| `RESNAP` | the test | jest gets `--updateSnapshot`? | intended? |
|---|---|---|---|
| unset | `[ -n ]` → **true** | ✅ yes | 🔴 **no** |
| `true` | `[ -n true ]` → true | ✅ yes | ✅ yes |

🟡 **its neighbour on the same line is the same shape and is accidentally correct**, which is why
the defect survived: `[ -z $THOROUGH ]` unset → `[ -z ]` → true → adds `--changedSince=main`
(right), and set → `[ -z true ]` → false → omits it (right). so `-z` works by luck and `-n` fails
by the same luck, one clause apart.

⇒ this is `rule.forbid.failhide` at the harness grain — 14 tests that report success on every

impact … sometimes diff shows blockers or nitpicks"* — since the diff is auto-accepted rather than
raised.

## .the shape of the fix

quote the variable, on all four lines:

```diff
- $([ -n $RESNAP ] && echo '--updateSnapshot')
+ $([ -n "$RESNAP" ] && echo '--updateSnapshot')
```

🟡 **quote `$THOROUGH` in the same pass**, even though it is accidentally correct today — an
unquoted `[ -z $THOROUGH ]` breaks the moment `THOROUGH` holds a value with a space, and a reader
who sees one quoted and one bare cannot tell which was deliberate.

## .why it is not done in this round

**it passes SAFE and fails CLEAN** (`rule.always.fix-forward-under-scouts-honor`):

- **SAFE ✅, and measured rather than assumed** — after many full-suite runs on this drive,
  `git status` shows **zero** modified `.snap` files. so the 11 unit-reachable snapshots all
  currently match, and to enable them turns on 11 assertions that already pass.
- **CLEAN ❌** — the diff is 4 characters on 4 lines, and **diff size is not ripple size**. it
  flips the pass/fail semantics of every snapshot test in the repo, in every suite, in cicd. three
  of the 14 belong to integration suites that cannot run on this host (no IAM), so their state is
  **unmeasured** — to enable them could turn cicd red for a reason wholly unrelated to this wish,
  on a branch already heavy with diff.

⇒ that is the "smuggled refactor" the rule names as scouts-honor's mirror failure: a change that
ripples, ridden along on an unrelated wish.

## .what was done instead

1. the snapshot clamp was **abandoned for an explicit `toEqual`** in `src/index.test.ts` `[t4]`,

   author does not reach for a snapshot here and rediscover it the hard way
3. raised as **fulcrum F14**, so the deferral is reviewable rather than only recorded
