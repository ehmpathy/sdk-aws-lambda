# 🌙 dream: anchor biome's `includes` glob so it stops to lint the rmsafe trash

- **kind** = repair
- **owner** = `ehmpathy/sdk-aws-lambda` (and likely `declapract-typescript-ehmpathy`, which stamps this config)
- **caught** = 2026-09-08, at self-review r6 of `5.1.execution.from_vision`

## .the cue that fired

`rhx git.repo.test --what lint` failed with **one** error, and the error was not in `src/`:

```
.agent/.cache/repo=ehmpathy/role=mechanic/skill=rmsafe/trash/src/probeVisionContract.ts
  × Formatter would have printed the following content:
```

a file I had **deleted** — via `rmsafe`, which moves rather than unlinks — failed the lint gate from
inside the trash can.

🔴 **it fired twice on this one drive** (self-review r5, then r6), which is what moved it from an
annoyance to a caught dream. both times the fix was to `rmsafe` the trash copy of what I had just
`rmsafe`'d, which reads as a joke and cost a gate cycle each time.

## .the gap, precisely

`biome.jsonc:10`:

```jsonc
"includes": [
  "**/src/**/*.ts",     // 🔴 unanchored — matches ANY directory named src, at ANY depth
  "**/provision/**/*.ts",
  "!**/dist",
  "!**/coverage",
  "!**/node_modules",
  "!**/.artifact",
  "!**/.generated",
  "!**/.test*"
]
```

the `**/` prefix means the glob is **not rooted at the repo**. so it matches:

| path | intended? |
|---|---|
| `src/domain.operations/…` | ✅ yes |
| `.agent/.cache/repo=…/skill=rmsafe/trash/src/…` | 🔴 **no** |
| any future tool cache that happens to hold a `src/` | 🔴 no |

### and `vcs.useIgnoreFile` does NOT save it — checked

the config sets `vcs: { enabled: true, clientKind: "git", useIgnoreFile: true }` (`:3-7`), and git
**does** ignore the path:

```
$ git check-ignore -v .agent/.cache/repo=ehmpathy/role=mechanic/skill=rmsafe/trash/probe.ts
.agent/.cache/.gitignore:6:*    .agent/.cache/…/trash/probe.ts
```

⇒ so the file is gitignored **and** linted. either `includes` takes precedence over the ignore file
in biome 2.3.8, or nested `.gitignore` files are not traversed. **the exact mechanism is unverified
and is the first item to check.**

## 🟡 .what this is NOT — a false lead I chased and cleared

this branch stages a deletion of `.agent/.cache/repo=ehmpathy/role=mechanic/skill=rmsafe/trash/.gitignore`
(added by `877f8dd`, contents `*` + `!.gitignore`).

that looked like the cause. **it is not, and it is also harmless** — the parent
`.agent/.cache/.gitignore:6` carries the same `*`, and `git check-ignore` above confirms coverage.
so version control is unaffected either way, and the lint behavior traces to the unanchored glob.

⇒ recorded so the next traveler does not re-chase it.

## .the shape of the fix

**one line, and the safest form is the exclusion rather than the anchor:**

```jsonc
"includes": [
  "**/src/**/*.ts",
  "**/provision/**/*.ts",
  "!**/dist",
  "!**/coverage",
  "!**/node_modules",
  "!**/.agent",        // ← add: tool caches are not this repo's source
  "!**/.artifact",
  "!**/.generated",
  "!**/.test*"
]
```

⚠️ **prefer this over an anchor change (`"src/**/*.ts"`).** the anchored form is more correct in
principle and riskier in practice — it would also drop any *intended* nested `src/` (a future
`packages/*/src/`, an example app), and it changes which files the gate covers rather than merely
which it skips. the exclusion is additive and cannot silently un-cover real source.

**verify with**: `rhx rmsafe --path 'src/probe.ts'`, then `rhx git.repo.test --what lint`. green
without a second `rmsafe` means it is fixed.

**and check upstream**: `biome.jsonc` is stamped by `declapract-typescript-ehmpathy`
(`dist/practices/lint/best-practice/biome.jsonc`), so a local fix is overwritten on the next
`declapract upgrade`. the durable fix is upstream; the local one buys time.

## .why it is not done in this round

**SAFE** — 🔴 no. it changes which files the lint gate covers, repo-wide. a mistake here silently
stops the lint of real source, and the gate is what would have caught it.

**CLEAN** — 🔴 no. `biome.jsonc` sits outside this wish's diff entirely (which touches
`src/domain.operations/`, `src/index.ts`, `readme.md`, and `.behavior/`), and the real fix lives in
another repo.

⇒ both questions answer no, so the deferral is correct rather than convenient
(`rule.always.fix-forward-under-scouts-honor`). the workaround costs one extra `rmsafe` and is
recorded here so the next person spends seconds rather than a gate cycle.
