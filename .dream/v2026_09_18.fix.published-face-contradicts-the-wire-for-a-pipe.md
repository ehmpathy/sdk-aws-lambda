# 🌙 dream: the published output face contradicts the wire for a `.pipe()`

- kind = fix
- owner = `ehmpathy/sdk-aws-lambda`
- caught 2026-09-18

## .the cue that fired

peer review `repo-rules` raised a blocker against
`genIntrospectionMiddleware.getJsonSchemaFromZod.ts`: the unconditional `{ io: 'input' }` was
justified at the OUTPUT border by an argument about what the code emits, with no run behind it.

the run was owed, so it was taken. it confirmed the reviewer AND found a wider class than the
find named.

## .the gap, precisely

the subject publishes ONE face for both borders. at the output border, measured across six
shapes — `[case5]` of `genIntrospectionMiddleware.getJsonSchemaFromZod.test.ts`:

| the shape at the output border | the wire | the published face | grade |
|---|---|---|---|
| a coerced dobj — `X.contract()` | `{ uuid, name }` | the same, pragma intact | agrees |
| a plain schema, no transform | agrees | agrees | agrees |
| `.default()` | `limit: 10` present | `limit` OPTIONAL | under-declares |
| `.catch()` | `limit: 7` present | `limit` OPTIONAL | under-declares |
| a type-shift `.transform()` | `handle: 5` | `handle: string` | **CONTRADICTS** |
| `.pipe()` — `string` → `number` | `n: 42` | `n: string` | **CONTRADICTS** |

the last row is the one that matters most: `io: 'output'` publishes `n: number` there and does
NOT throw, so the face this change discarded was **correct for that shape**. a `.pipe()` at the
output border is therefore a regression this change introduces.

the two `under-declares` rows are tolerable — a caller typed against `limit?: number` handles a
`limit: number` document correctly. the two `CONTRADICTS` rows are not: a generated client is
typed `string` and a `number` arrives.

### ⚠️ AMENDED 2026-09-18 — there is a SECOND facet, and it is worse

the table above measures what the endpoint **publishes**. a clamp written at the **handler**
grain — `genLambdaEndpoint.forAskEndpoint.test.ts` `[case14]` — measured a second facet the unit
grain cannot reach: **`invoke`'s own return type is unsatisfiable.**

`output: z.object({ waveHeight: z.string().pipe(z.coerce.number()) })` binds `TOutput` to the
pipe's OUTPUT side, so the **compiler** demands a `number`. `getValidatedOutput` then runs
`.parse` on that return, which enters at the pipe's INPUT side and demands a `string`. measured,
both arms:

| the `invoke` return | the compiler | the runtime |
|---|---|---|
| `{ waveHeight: '6' }` — obeys the runtime | 💥 `TS2322: Type 'Promise<{ waveHeight: string; }>' is not assignable to type 'Promise<{ waveHeight: number; }>'` | ✅ settles, wire carries `6` |
| `{ waveHeight: 6 }` — obeys the compiler | ✅ compiles | 💥 `MalfunctionError: output validation failed: waveHeight: Invalid input: expected string, received number` |

⇒ **no `invoke` body satisfies both.** the first arm is only reachable through a documented
`as unknown as` cast, which is the exact anti-pattern this repo's wish set out to retire.

so the published-face divergence is the facet a consumer notices LAST — a generated client with
a wrong type, and no error anywhere. the `invoke` contract is the one they hit FIRST, at their
own keyboard, with no way through.

## .the shape of the fix

the divergence exists because one face serves two borders. the honest repairs, in order of
cost:

1. **publish the output border under whichever face renders.** this is the small fix and it is
   forbidden as written — a `try io:'output', catch → io:'input'` is two code paths for one
   guarantee (`rule.forbid.parallel-codepaths`) plus a silent fallback
   (`rule.forbid.failhide`). it becomes legal the moment the choice is made from an **observed
   property of the schema** rather than from a caught throw: zod exposes enough to ask "does
   this schema hold a transform that cannot render?" before it is asked to render one. that
   check is the whole fix, and it is where the work sits.
2. **publish BOTH faces at the output border** — the introspection payload gains
   `output.wire` beside `output.instance`, and the codegen picks. this is a contract change to
   `{ introspect: 'schema' }`, so it reaches every consumer of `getAllLambdaContracts`.
3. **refuse the shape.** an output schema whose two faces disagree is arguably a defect in the
   endpoint rather than in this sdk — a response that re-encodes on the way out is a codec, and
   a codec belongs in the handler. a loud refusal at endpoint construction would close the class
   and break any extant `.pipe()` output schema.

⇒ 1 is the likely answer and 3 is the sharpest. both want a wisher call, which is why this is a
dream over a fix.

⚠️ **the second facet re-ranks them.** repairs 1 and 2 each address the PUBLISHED face alone, so
either would ship while `invoke` stays unsatisfiable — a consumer still meets the compiler/runtime
contradiction with no diagnostic that names it. **repair 3 is the only one that closes both
facets**, since a refusal at endpoint construction means neither face can diverge. that raises 3
from "sharpest" to "the one that actually closes the class", and it is a break, which is squarely
a wisher call.

## .why it is not done in this round

- **safe?** no. every repair above changes what a published contract says, so it reaches every
  generated cross-service client. that is beyond the reach of the change it would ride in.
- **clean?** no. repair 1 wants a new predicate over zod internals; repair 2 changes the
  introspection payload's own shape; repair 3 is a break.

the divergence is declared at the subject and clamped at two grains, so the next traveler meets
it as a measured table rather than as a surprise in a generated client:

- `genIntrospectionMiddleware.getJsonSchemaFromZod.test.ts` `[case5]` — the **published face**,
  six shapes, at the unit grain
- `genLambdaEndpoint.forAskEndpoint.test.ts` `[case14]` — the **`invoke` contract**, both arms,
  at the **ask** family's wired handler
- `genLambdaEndpoint.forApiGateway.test.ts` `[case21]` — the same, at the **api-gateway** family

⚠️ **the two wired clamps are NOT redundant, and the measurement says so.** the api-gateway body
crosses `httpResponseSerializer` on its way out, which the ask family never reaches — so the two
run different code past output validation, and the compiler-obedient arm lands differently:

| family | `invoke` returns the compiler's `number` |
|---|---|
| `forAskEndpoint` | the invocation **REJECTS** — it hands `asOutputAfter: false` |
| `forApiGateway` | it **settles with a 500** the handler never chose |

⇒ a result carried from one family to the other would have measured the wrong harm
(`rule.require.retest-the-model-on-every-family`).

⚠️ **a consumer meets NO signal for this.** the three clamps above record the defect for a
traveler who reads the suite; they reach no one who writes a `.pipe()` into an output schema. the
readme carried that caution for a while and it was cut — a readme states how to use the sdk, and a
defect stated there is a defect documented rather than repaired. **so the signal a consumer meets
is part of the fix, never a substitute for it**: repair 3's loud refusal at endpoint construction
IS that signal, which is one more reason it ranks first.
