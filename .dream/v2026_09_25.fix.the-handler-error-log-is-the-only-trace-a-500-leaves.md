# 🌙 dream: the `handler.error` log is the only trace a 500 leaves, and no test reads it

**kind** `fix` · **owner** `ehmpathy/sdk-aws-lambda` · **caught** 2026-09-25

## .the gap

```ts
// genInternalServiceErrorMiddleware.ts
const logError = log?.error ?? console.error;
logError('handler.error', { errorMessage: error.message, stackTrace: error.stack });
if (opts.asOutputAfter === false) throw error;
request.response = opts.asOutputAfter({ error, exid });
```

| family | `asOutputAfter` | the stack survives outside the log? |
|---|---|---|
| `forSqs.*`, `forAsk` | `false` — rethrown | ✅ the thrown error carries it; aws records the failure |
| `forApiGateway` | absorbed into a generic 500 | 🔴 no — the log is its only home |

no test reads the emission: `rhx grepsafe --pattern 'handler.error' --path src --glob '*.test.ts'` → 1
line, a case name (control, no glob → 9). delete `logError` and `forApiGateway` `[case4]` stays green
while an operator holds a 500 with no stack in cloudwatch.

## .the shape of the fix

in `forApiGateway` `[case4]`: spy on the console method (`sdk-logs` routes `log.error` there), find
the entry by the name `handler.error`, assert it carries the handler's message and a stack; keep the
response body as a positive control. `forSqs.perBatch` `[case13]` already does this, and bites.

## .why it is not done here

safe (test-only), not clean: the round was bounded to sqs, whose variants all rethrow and so do not
depend on this log.
