## .the gap, precisely

one concept, two call sites, opposite stances on an unknown value:

| call site | the code | an unknown value |
|---|---|---|
| `runLambdaEndpoint` (both subdomains) | `asLambdaEndpointDialect({ declared })` | **throws** a `ConstraintError` that names the valid set |
| `askLambdaEndpoint.ts:74-76` | `input.struct?.payload ?? 'contemp'`, then `=== 'ancient' ? … : …` | **silently becomes `'contemp'`** |

```ts
// askLambdaEndpoint.ts:74-76 — every non-'ancient' value falls to the wrapped payload
const structOfPayload = input.struct?.payload ?? 'contemp';
const payload =
  structOfPayload === 'ancient' ? input.event : getLambdaPayload({ … });
```

⇒ **checkable consequence.** a caller who writes `struct: { payload: 'anceint' }` — or reads the
value from config — sends a **wrapped** `{ event, trail }` payload to a handler that cannot unwrap
it. the field is typed `LambdaEndpointDialect`, so a typed caller is safe; a js consumer, an
`as any` call site, or a data-driven value is not. that is the identical argument the locus guard
carries in `runLambdaEndpoint.onSerialized.ts` (the *"an UNKNOWN locus is refused"* block), and the
identical one `asLambdaEndpointDialect` was extracted to settle.

🟡 **and the failure direction is the quiet one**, exactly as with the locus: the fall-through picks
`'contemp'`, which is the *newer* format — so an ancient handler receives a shape it will reject on
its own terms, and the caller reads the rejection as a fault in their event.

## .the shape of the fix

one line, plus its clamp:

```ts
// askLambdaEndpoint.ts:74
const structOfPayload = asLambdaEndpointDialect({ declared: input.struct?.payload });
```

`asLambdaEndpointDialect` already defaults an absent value to `'contemp'`
(`asLambdaEndpointDialect.test.ts:40-50`), so the **absent** case is byte-identical and only the
**unknown** case changes. add a `given` to `askLambdaEndpoint`'s suite that asserts the throw, and
the two call sites then share one philosophy and one implementation.

## .why it is not done in this round

the SAFE/CLEAN test, per `rule.always.fix-forward-under-scouts-honor`:

| question | verdict |
|---|---|
| **SAFE?** | 🔴 **no.** `askLambdaEndpoint` is a shipped production caller this wish does not touch. a live service that passes a bad value today gets `'contemp'` and works; after the fix it gets a thrown `ConstraintError`. that is a runtime break in someone else's deploy, introduced by a test-util wish |
| **CLEAN?** | ✅ one line, one import, one test |

⇒ `safe 🔴` is the harder stop, and the rule's own table puts it at *defer*. the scope boundary is
declared already — `rule.forbid.scope-leaks`, and the docblock at
`runLambdaEndpoint.onSerialized.ts:214-224` names `askLambdaEndpoint` as the production caller this
wish deliberately does not reach into.

⚠️ **the deferral of the REPAIR is not a fresh judgment** — it is a scope bound ruled before this
drive began, and this file tracks the work.

🔴 **but the decision to leave the asymmetry is itself a call, and it now carries a fulcrum row —
`F23`.** this file's own prior claim (*"carries no new fulcrum row"*) conflated two decisions: the
decision NOT to repair (scope-bound, tracked here) and the decision NOT to record the divergence for
a council (which was owed). i029 r011, i039, and i041 r010 §1a converged on the record gap; F23 closes
it. the repair stays deferred exactly as this file argues.
