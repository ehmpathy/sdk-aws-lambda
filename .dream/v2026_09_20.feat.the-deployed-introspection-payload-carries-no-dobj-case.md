## .the cue that fired

two independent reviewers converged on one claim in a single round:

> *"the new markers are never asserted against the real deployed lambda"*

**that claim is FALSE**, and it was refuted by a file read — `deployed.codegen.refs` deploys four
real lambdas and asserts the codegen reconstructed `RefByPrimary<typeof SvcTrophySeaturtle>` and
`export class SvcTrophySeaturtle`, neither of which is expressible unless `x-domain-object` and
`x-domain-object-ref` survived the real wire.

⇒ 🟡 **but convergence is a prompt to sweep, never reassurance** (`rule.require.sweep-the-defect-class`).
two lanes reached the same wrong premise because both were scope-bound to the **introspection**
suites, and the proof lives in the **codegen** suites. so the premise was wrong and the *instinct*
found a real gap one level down.

## .the gap, precisely

> 🟡 **every sentence below is AS-OF 2026-09-20 and the last row is now CLOSED.** kept verbatim
> because the gap's shape is what makes the close checkable; read it as the statement of a
> problem that has since been solved, never as a live one.

the deployed proof asserts the markers' **downstream effect** — the generated TypeScript — never
the **payload bytes** a caller of `getOneLambdaContract` receives.

| what is proven on the real service | by |
|---|---|
| a dobj pragma survives the wire well enough for codegen to rebuild the class | `deployed.codegen.refs`, `deployed.codegen` |
| a dobj pragma's **exact published shape** | ✅ `deployed.codegen.refs` `[case2]` — was **absent** until 2026-09-21 |

so the uncovered case is precise: **a caller who reads `{ introspect: 'schema' }` directly** — no
codegen in between — meets bytes that no deployed snapshot pins. a pragma change that codegen
tolerates would ship silently to that caller.

⚠️ **the severity is lower than the reviewers graded it**, and the reason is checkable: a shape
change that alters the generated output goes RED in three deployed suites, each of which snapshots
its whole generated file (`rule.require.snapshots-deny-volatile-not-allow-expected`). the residue is
the direct-payload consumer alone.

## .the shape of the fix

add one `given` to `deployed.introspection.acceptance.test.ts` that deploys a dobj-schema handler
and snapshots its raw introspection payload — the **bytes**, not their effect.

⚠️ **prefer a fixture that is ALREADY deployed.** `surfboardContractHandler` carries an
`X.contract()` position and is already live under three deployed suites, so a case aimed at it
costs zero extra `setLambdaLive` budget. a fresh fixture costs one more deploy, and the budget is
the open `F34` problem — see below.

## .why it was not done in that round

> reason 2 never applied to where the fix actually landed — the refs suite's hook already
> deploys the dobj lambdas, so `[case2]` added **zero** `setLambdaLive` calls. kept so the
> deferral stays auditable against what was true at the time.

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- ✅ **SAFE? yes.** a new `given` in a deployed suite touches no production path
- 🔴 **CLEAN? no**, on two counts, and the first is decisive:
  1. **the proof is unavailable.** the deployed gate needs an AWS SSO browser click no robot holds.
     `rhx keyrack unlock --owner ehmpath --env test` was re-run in the same turn as this dream and
     returned `✋ aws sso login timed out`. ⇒ the case would ship **never once executed** — an
     unproven claim, which is exactly what `philosophy.verification-strictness` refuses
  2. a case that needs its OWN fixture adds a `setLambdaLive` to a suite whose budget already
     **loses on a cold run** (`F34`, graded `dirty` @ 28%,
     `.dream/v2026_09_18.fix.the-deploy-hook-budget-loses-on-a-cold-run.md`)

⇒ **the honest sequence is: fix `F34`'s budget first, then add this case, then run both.** to add
an unrunnable case to an already-over-budget suite makes two problems out of one.

**no fulcrum is owed** — the deferral is a credential gate plus a known open fulcrum, never a design
call I made.
