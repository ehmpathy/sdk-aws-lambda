# 🌙 dream: the 500 a bad schema position raises names neither endpoint nor field

- **kind** = fix
- **owner** = `ehmpathy/sdk-aws-lambda`
- **caught** = 2026-09-18

## .the cue that fired

a peer reviewer asked what an engineer mid-deploy actually **reads** when an unrenderable schema
position crashes introspection. the case that covers it — `genLambdaEndpoint.forApiGateway.test.ts
[case17][t1]` — asserted `statusCode === 500` and not one character of text.

that is the branch's own rubric turned on itself: every other error surface here is clamped for
*"does the message name the fix"*, and the one place a schema slip takes down a whole service's
introspection was graded by a bare status.

## .the gap, precisely

measured, and now snapped at `[case17][t1]`. the body a caller meets:

```json
{
  "errorMessage": "internal server error",
  "errorType": "InternalServiceError",
  "correlationId": "exid:…"
}
```

⇒ it names **neither the endpoint nor the schema position at fault**. the zod text that says what
went wrong —

```
Void cannot be represented in JSON Schema
```

— reaches the cloudwatch line and never the response. so the engineer's path is: meet a 500, find
the correlation id, find the log group, find the line, and only then learn it was a `z.void()` in
one schema of one endpoint.

⚠️ **and it is worse at this border than at most**, because introspection is service-wide: one
endpoint's bad position 500s `getAllLambdaContracts` for every endpoint beside it. the reader has
the least context exactly where they need the most.

## .the shape of the fix

the envelope is built by `genInternalServiceErrorMiddleware`, and it is **every** 500's shape
rather than this one's. so the fix is not local:

1. decide whether a 500 body may ever name a schema position. it is our own contract text, never a
   caller value, so it leaks no user data — but it does name internals, and that is a call the
   wisher owns rather than the driver
2. if yes, the seam is the middleware's metadata pass-through: the `MalfunctionError` already
   carries the zod message, so what is absent is a rule for which metadata reaches the wire
3. if no, the repair moves to the **log** line instead — make the cloudwatch entry name the
   endpoint slug and the schema path, so the correlation-id hop lands on a legible line

⇒ in both branches the clamp is the snapshot that now exists: it goes red the moment the envelope
changes, which is what makes this dream checkable rather than a memory.

## .why it is not done in this round

**SAFE** — no. `genInternalServiceErrorMiddleware` shapes every 500 this sdk emits, across both
families and every consumer. a change there ripples into behavior this bound never opened.

**CLEAN** — no. it would touch the middleware, its own snapshot set, and both families'
acceptance suites, none of which this branch's diff opens.

⇒ so it is deferred, and the deferral is itself a **judgment about ripple cost** — which is why a
fulcrum rides beside this dream rather than the dream alone
(`rule.always.fix-forward-under-scouts-honor`).

what DID land in this round is the measurement: the gap is snapped, in place, with a note that
states it is a gap rather than a pass. the next traveler reads the envelope without a re-run.
