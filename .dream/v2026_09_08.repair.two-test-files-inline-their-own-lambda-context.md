# 🌙 dream: two test files inline their own lambda context

- **kind** = repair
- **owner** = `ehmpathy/sdk-aws-lambda`
- **caught** 2026-09-08

## .the cue that fired

self-review r2 (`has-consistent-mechanisms`) on the `5.1.execution.from_vision` stone. a grep for
`test-function` — one of the context's default labels — returned hits in **four** files where I
expected two.

## .the gap, precisely

the aws lambda `Context` defaults are declared in four places:

| file | shape |
|---|---|
| `src/domain.operations/runLambdaEndpoint/context/asLambdaContext.ts:20-35` | the shipped source of truth |
| `src/__test_assets__/createTestContext.ts:14-21` | ✅ **now delegates** to it |
| `src/domain.operations/genLambdaEndpoint/genLambdaEndpoint.forApiGateway/genLambdaEndpoint.forApiGateway.test.ts:10-20` | 🔴 inlined |
| `src/domain.operations/genLambdaEndpoint/genLambdaEndpoint.forAskEndpoint/genLambdaEndpoint.forAskEndpoint.test.ts:11-21` | 🔴 inlined |

checkable: `rhx grepsafe --pattern "test-function|test-request-id" --path src` returns hits in the two
`genLambdaEndpoint` test files that do **not** import `createTestContext`.

⚠️ the two inline copies use the **same literal values** as `createTestContext`, so they are copies
rather than variants — which is what makes this a repair and not a design question.

## .the shape of the fix

per file, delete the inline object literal and import the extant helper:

```ts
import { createTestContext } from '../../../__test_assets__/createTestContext';

const context = createTestContext();
```

⚠️ **check the `functionName` first.** `forApiGateway.test.ts` may assert on it via a snapshot; if so,
pass it explicitly — `createTestContext({ functionName: 'test-function' })` — which is the default
anyway, so the assertion holds either way.

⇒ verify with `rhx git.repo.test --what unit --mode apply --thorough`. the suite is 512 green today,
so any change to a default the tests depend on will surface at once.

## .why it is not done in this round

**SAFE, but not CLEAN.** the fix touches no behavior and cannot break a consumer — but both files sit
outside the diff this wish opened. this stone shipped `runLambdaEndpoint` and `asLambdaEvent`; it did
not touch `genLambdaEndpoint`'s suites, and to edit them is to open two test files an unrelated wish
owns (`rule.always.fix-forward-under-scouts-honor`'s CLEAN test, and
`rule.require.review-test-changes`).

⇒ the in-scope half **was** done in this round: `createTestContext` now delegates, so the source of
truth exists and has one consumer. this dream is the other two.
