# 🌙 dream: the error wire names its own class two ways

**kind** `fix` · **owner** `ehmpathy/sdk-aws-lambda` · **caught** 2026-09-22 · **grade** better ·
fulcrum **F17**

## .the gap

```json
{
  "errorMessage": "✋ ConstraintError: validation failed: payload.email — invalid email",
  "errorType":    "BadRequestError"
}
```

| field | source |
|---|---|
| `errorType` | chosen by `getErrorResponseBody` — `invariant.ancient-vs-contemp-callers` mandates `BadRequestError` for an ancient caller, and api gateway is always ancient (its envelope never matches `getIsWrappedPayload`) |
| `errorMessage` | `helpful-errors`' own `.message`, which the library prefixes with its class at construction |

each half is correct alone; together they name two classes for one failure. the contemp arm agrees
(`class: "ConstraintError"` beside the same message), so the defect is the ancient shape's alone.

⛔ **do not move `errorType`** — ancient callers branch on `BadRequestError`, and the invariant
exists to keep upgrades incremental. only `errorMessage` may move.

## .the shape of the fix

`getErrorResponseBodyAncient` already sets `errorMessage: input.error.message`, so there is no
concatenation to delete. the fix strips a prefix the sdk did not write:

```ts
const asMessageWithoutClassPrefix = (input: { error: Error }): string =>
  input.error.message.replace(new RegExp(`^\\W*${input.error.name}:\\s*`), '');
```

probe a real `helpful-errors` instance first — the glyph, separator, and name match are the
library's (`rule.require.measure-the-value-you-emit`).

clamp: `blackbox/local.httpResponse.acceptance.test.ts` `[case11]` asserts the mismatch today. apply
the fix, watch it go red, then invert its two `errorMessage` assertions. 11 snapshot entries across
4 acceptance suites (`local.sdkContract` 6, `local.introspection` 2, `local.payloadCompat` 2,
`local.httpResponse` 1) must move; fewer means the transformer did not match.

## .why it is not done here

not safe — `errorMessage` reaches 78 consumer handlers, and a log-grep on `ConstraintError` would go
quiet. not clean — it lands in the shared `getErrorResponseBody`, so it reaches `forAsk`
(scoped out by F06), and moves 11 snapshots.

graded better: a caller that reads the documented `errorType` behaves correctly; the confusion lands
on a human at triage.
