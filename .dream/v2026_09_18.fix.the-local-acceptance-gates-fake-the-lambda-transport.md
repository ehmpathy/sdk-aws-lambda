# 🌙 dream: the local acceptance gates fake the lambda transport

- **kind** = fix
- **owner** = unclaimed
- **caught** = 2026-09-18, at stone `5.3.verification`, peer review `r8.mech-test-scope-purity`

## .the cue that fired

a peer reviewer read `blackbox/**` and found `jest.fn().mockImplementation(...)` fakes of the aws
lambda sdk inside four `.acceptance.test.ts` suites. `rule.forbid.acceptance.mocks` forbids a mock
in an acceptance test outright, and permits a documented exception only where the circumstance is
**clearly unavoidable** — a severe rate limit, a prohibitive cost, no sandbox.

> 🔴 **the reviewer's sharpest point, and it is correct:** this repo maintains REAL deployed twins
> for the same behaviors (`deployed.codegen.*`, `deployed.introspection.*`). that is strong evidence
> the fake is a **convenience** rather than a necessity — which is exactly the test the exception
> clause applies.

## .the gap, precisely

nine transport fakes, across four suites:

```
blackbox/local.introspection.acceptance.test.ts:678, 782
blackbox/local.codegen.acceptance.test.ts:123, 148, 190, 207
blackbox/local.codegen.journey.acceptance.test.ts:117, 160
blackbox/local.codegen.refs.acceptance.test.ts:189
```

each carries an inline rationale of the shape:

```ts
// .rule = rule.forbid.acceptance.mocks — transport-only fake: an empty
//         function set. real fidelity is proven in the deployed test.
send: jest.fn().mockImplementation(async (command) => { … }),
```

⇒ the rationale is **honest about what it does** and does **not** meet the clause it cites: run
speed and determinism are not an unavoidable external constraint.

## .the shape of the fix

two candidate repairs, and the choice is the open question:

| the move | what it costs |
|---|---|
| **rename** the four to `.integration.test.ts` | the acceptance label becomes honest, and the repo loses four fast local gates from the `acceptance` run. the `deployed.*` twins remain the real gate |
| **keep**, and rewrite the rationale to cite the real reason | honest prose over an honest label — but the rule's exception clause still is not met, so this is a declared deviation rather than a fix |

⚠️ **a third option is likely the right one and needs a call from the repo owner:** the `local.*` /
`deployed.*` split may be a deliberate house convention that predates the generic rule, in which
case the repair is to **declare that convention in a repo brief** so the generic rule has a
specialization to defer to.

### the fifth member, and why the family is 5 rather than 4

the same reviewer raised a **nitpick** against `blackbox/local.dobjWire.acceptance.test.ts` on the
same grain — its action is `invokeHandlerForTest` against an internal fixture rather than a public
contract. that is the identical question at a different site, so it belongs to this dream rather
than to a separate one.

```
$ rhx grepsafe --pattern 'invokeHandlerForTest|genApiGatewayProxyHarness' --path blackbox
  blackbox/local.dobjWire.acceptance.test.ts       <- NEW on this branch (untracked)
  blackbox/local.wireResponse.acceptance.test.ts   <- tracked, predates
  blackbox/local.introspection.acceptance.test.ts  <- tracked, predates
  blackbox/local.payloadCompat.acceptance.test.ts  <- tracked, predates
  blackbox/local.sdkContract.acceptance.test.ts    <- tracked, predates
```

⇒ **five suites, one convention, and four of the five predate the branch.** so the pattern is the
repo's norm rather than four exceptions, and a repair that renames only the four cited would leave
the fifth as a lone inconsistency. whichever way the call goes, it must reach all five.

🟡 **the two sets overlap and are not identical.** the `jest.fn` transport fakes are 9 sites across
4 files; the in-process handler drive is 5 files. `local.dobjWire`, `local.wireResponse`,
`local.payloadCompat`, and `local.sdkContract` drive handlers with no transport fake at all — so a
verdict on the transport fake does not settle the in-process drive, and the brief owes both.

**the sweep this owes** (`rule.require.sweep-the-defect-class`): grep the **subject** — a test file
whose name carries `.acceptance.` and whose body constructs a fake of an external boundary — never
the form `jest.fn`. a hand-rolled object literal with an `async send` is the same defect with no
`jest` token in it, and this branch's own deleted probe used exactly that form.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- 🔴 **SAFE? no.** a rename moves four suites out of the `acceptance` run, which changes what CI
  gates on. that is a change to the release gate, made from a verification stone
- 🔴 **CLEAN? no.** it re-points four files, their jest config classification, and any CI job that
  names the acceptance suite — and it re-opens a house-convention question that reaches five suites
  rather than the four cited
- **older than the branch**, on measured blame, so it is out of this bound's subject entirely

⇒ **a fulcrum is not owed**: this is not a design judgment I made and deferred, it is an older
condition a peer reviewer surfaced against a generic rule. the call it needs belongs to whoever owns
the `local.*` / `deployed.*` convention.
