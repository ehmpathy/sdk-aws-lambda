# 🌙 dream: a refusal's `message` holds its headline only; the metadata lives in `details`

kind: feat · owner: ehmpathy/sdk-aws-lambda · caught 2026-11-14

## .the cue that fired

a 5.3 peer review (ergo-snapshot-visual-blemishes) of the event-source schemas flagged the refusal
body: `error.message` carries the `{ issues, hint }` metadata as a pretty json blob, and
`error.details` carries the same metadata beside it. fulcrum F18 held it out of that wish.

## .the gap, precisely

- one body shows the issues and hint three times (`details.hint`, `details.issues`, the blob)
- the blob's key order (`path, message, code`) differs from the sorted `details` in a snapshot
- every family emits it; six acceptance snaps on `main` pin it

## .the shape of the fix

- frame the refusal message as the headline alone (`✋ ConstraintError: validation failed: <path>:
  <cause>`), with the metadata only in `details`, for the ancient and contemp bodies alike
- resnap every acceptance snap that pins the blob; call it out in the release note, since a caller
  that matches on message text sees a shorter string

## .why it is not done in this round

a change to the refusal frame of every family is a contract change outside the event-source wish
(F18).
