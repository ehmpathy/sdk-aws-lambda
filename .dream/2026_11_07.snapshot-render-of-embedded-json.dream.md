# 🌙 dream: snapshots render embedded json and error labels so a reader can scan them

- kind: repair
- owner: sdk-aws-lambda
- caught 2026-11-07

## .the cue that fired

peer review i001 r006 on `v2026_11_06.fix-peer-failure-surfaces` (stone 5.3) flagged three snapshot traits as blemishes. each is repo-wide and extant on origin/main, so the fix is out of that pr's scope (fulcrum F12).

## .the gap, precisely

- jest prints a string with `escapeString: false`, so a json body renders `"body": "{"id":"user-123"}"`. a reader cannot see where the string ends. no `jest*.config.*` sets `snapshotFormat`
- an error whose `.name` is its class renders `[LambdaEndpointError: LambdaEndpointError: …]`: the label and the message prefix both name the class
- a helpful-errors class keeps `.name` as `Error`, so it renders `[Error: ✋ ConstraintError: …]` beside `[LambdaEndpointError: …]`

## .the shape of the fix

1. pick one: `snapshotFormat: { escapeString: true }` in each jest config, or a serializer that parses a json-string `body` / `text` into a nested object for the snapshot
2. for errors: a snapshot serializer that prints `{ class: constructor.name, message, metadata }`, so every error reads one way, whatever its `.name`
3. `--resnap` every suite, and review the diff is render-only (no value changes)

`.name` on `LambdaEndpointError` / `LambdaEndpointRefusedError` must stay: the api gateway chain and aws label an escaped throw by it (#75).

## .why it is not done in this round

a config change rewrites every snap file in the repo. in a pr about peer failures, that buries the contract diff a reviewer must read.
