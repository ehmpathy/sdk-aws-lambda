🟡 **and the outcome converges anyway, because the harness parse is not its last word.** it looks the

🔴 **and the harness's tolerance is arguably CORRECT, not a defect.** it impersonates the aws sdk,
and aws answers an unknown function name with `ResourceNotFoundException` — never with a parse
error. a harness that adopted the strict parser would be **less** faithful to what it simulates.

⇒ so this half of the dream is **not** *"two readers, one should win."* it is *"two readers, each
right for its own boundary"* — which leaves the **duplication** as the whole debt, and narrows the
fix below to the write side plus a shared reader that takes a strictness flag.

## .the shape of the fix

two halves, and they are independent.

### 1. the write side — a prefix transformer, on the owner

```ts
// asLambdaEndpoint.ts
export const asLambdaEndpointPrefix = (input: {
  service: string;
  access: string;
}): string => `${input.service}-${input.access}-`;
```

`getAllLambdaContracts.ts:51` then reads
`asLambdaEndpointPrefix({ service: input.which.service, access: context.env.access })`.

⚠️ **the cost is the barrel, never the line.** a new export ripples into `index.ts`,
`publicSurfaceShapes.test.ts`, and `index.test.ts` — which is what makes it a change to review on
its own merits rather than one to ride along.

⇒ the cheaper variant, if a public export is unwanted: keep it internal to
`domain.operations/asLambdaEndpoint/` and import it directly. that costs no barrel change and still
gives the convention one writer.

### 2. the read side — reach the extant parser

`asLambdaEndpoint({ slug })` already parses. the harness should call it.

🟡 **probe the dash case FIRST.** if the strict parser rejects a function name with a dash, the
harness is not merely a duplicate of the parser — it compensates for a gap in it, and the fix is to
close that gap rather than to delete the compensation.

## .why it WAS deferred, and why the deferral no longer holds

the original CLEAN objection rested on a forecast that a write-side fix needed a **new public
prefix transformer** — which would ripple into the barrel and its two surface tests. that forecast
was wrong: the extant `asLambdaEndpoint` builder, called with `function: ''`, yields the exact
`'{service}-{access}-'` prefix with no new export at all. ⇒ the write-side fix was CLEAN after all,
so it was taken.

the read-side fork (the harness) was already closed earlier this round, and the strict-vs-tolerant
disagreement was probed and found benign (both boundaries refuse the same input; only the error
class differs — see PROBED section above).

⇒ **both halves are now done**, and `[case9][t4]` pins the single-owner set. the guard keeps its
exact-list assertion, so a SECOND writer goes red and names its file.
