# 🌙 dream: `rhx grepsafe` must not report `0 matches` for a glob that matched zero FILES

- **kind** = reseed — the skill is `ehmpathy/role=mechanic/skills/claude.tools/grepsafe.sh`, not this repo's code
- **owner** = `ehmpathy`
- **caught** 2026-09-12, at execution i033 of `v2026_09_03.feat-absorb-handler-invoke-test-util`

## .the cue that fired

i was about to ship a `[REFUTE]` against a peer reviewer's blocker, on the strength of this:

```sh
rhx grepsafe --pattern 'introspect' --glob '.behavior/**/*.md' --count
→ 🐢 crickets...
→ └─ matches: 0
```

i read that as *"the term is absent from the vision artifacts"* — which would have made my refutation
**false**, and i would have filed it as measured.

⇒ the term is in **four** of those files, one of them 555 lines long.

## 🔴 .the gap, precisely

`--glob` does not match a **dot-directory**, and the skill reports that as `0 matches` rather than as
`0 files`. measured, same host, same moment:

| invocation | result | truth |
|---|---|---|
| `--glob '.behavior/**/*.md'` | `matches: 0` | 🔴 **false** — 4 files match |
| `--glob '.behavior/…/1.vision.experience.dimensions.md'` (a literal path) | `matches: 0` | 🔴 **false** — 129 lines match |
| `--path '.behavior/v2026_09_03.…'` | `lines: 129` | ✅ correct |
| `--glob 'src/**/*.ts'` | correct | ✅ — a non-dot dir works |

🔴 **and `0 matches` is indistinguishable from `no matches exist`.** that is
`rule.forbid.failhide` in a search tool: the caller cannot tell a searched-and-empty result from a
never-searched one, and the quiet answer is the one that reads like a fact.

⚠️ **the sibling skill already gets this right.** `rhx globsafe` prints `files: 0` — a count of what
the glob *matched*, which is the number that exposes the miss:

```
🐚 globsafe
   ├─ pattern: .review/*i033*
   └─ files: 0          ← the glob matched none, and says so
```

`grepsafe` prints only the line count, so the two failures collapse into one number.

## .the shape of the fix

two options; the first is enough on its own.

1. **report the file count, always** — `grepsafe` already knows how many files it is about to scan.
   emit it beside the line count, the way `globsafe` does:

   ```
   🐚 grepsafe
      ├─ glob: .behavior/**/*.md
      ├─ files: 0          ← NEW. the discriminator
      └─ matches: 0
   ```

   ⇒ this alone removes the failhide: `files: 0 / matches: 0` reads as *"i searched no files"*, and
   `files: 4 / matches: 0` reads as *"i searched and found none."*

2. **match dot-directories**, so the glob does what a caller expects. in bash, `shopt -s dotglob`;
   in `find`, drop the implicit hidden-dir prune. 🟡 **this is the riskier half** — it would newly
   surface `.git/`, `node_modules` under a dot path, and every cache dir, so it wants an explicit
   exclude list rather than a flag flip.

🟡 **and if neither is taken, the third option is to FAIL** rather than answer: a glob that matches
zero files could exit non-zero with *"the glob matched no files — check for a dot-directory, or use
`--path`"*. that is `rule.require.errors-name-the-fix`, and it is what i needed at the moment i was
misled.

## .why it is not done in this round

the two questions of `rule.always.fix-forward-under-scouts-honor`:

| question | answer |
|---|---|
| **SAFE?** | ✅ for option 1 — an extra output line changes no result |
| **CLEAN?** | 🔴 **no.** the file lives in `ehmpathy`'s role skills, not in this repo. a tree adopts only what is scoped to itself |

⇒ a cross-repo fix is the defining case for a **reseed** dream, per
`rule.always.catch-dreams-for-followups`.

## 🟡 .the cost this already imposed, measured

on this drive alone, `grepsafe --glob` returned a false `0` **twice**, and both were caught only
because a second read happened to contradict it:

1. the execution yield — an untracked file. i concluded a section was absent; it was
2. the vision inventory — a dot-directory. i had written a `[REFUTE]` citing verdicts i had not read,
   and the correct verdicts turned out to be **better** for my argument than the ones i invented

⇒ **the second is the dangerous shape**: a false `0` does not merely hide information, it invites a
confident claim built on its absence. a reviewer reading that `.taken` would have had no way to tell
the citation was fabricated from a silent tool failure.
