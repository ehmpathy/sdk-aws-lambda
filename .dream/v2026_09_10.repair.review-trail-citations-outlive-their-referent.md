# 🌙 dream: source citations to the review trail must outlive the trail

- **kind** = repair
- **owner** = `ehmpathy/sdk-aws-lambda`
- **caught** 2026-09-10, on the `feat-absorb-handler-invoke-test-util` drive

## .the cue that fired

peer review i011 r010 (`enroll-impl-behavior-intent`), item #5:

> *"38 source files (confirmed via grep) still carry citations like 'found at i010 r011', 'raised at
> i005 r010', 'self-review r6/r8'. This is a maintenance hazard: once `.behavior/` is archived, these
> become unresolvable references for a future reader who has no access to the review trail. Flagged
> at i009, never addressed, and it's grown rather than shrunk since."*

⚠️ **flagged twice — i009 and i011 — and the count grew between them.** that is the cue's sharper
half: the practice that produces these citations is still live, so the set widens each round.

## .the gap, precisely

a citation of the form `i010 r011` points into
`.behavior/v2026_09_03.feat-absorb-handler-invoke-test-util/.reviews/peer/…`. ~~once that directory
is archived or pruned, the pointer lands nowhere.~~

### 🔴 MEASURED 2026-09-11 — the referent is not ARCHIVED, it is GITIGNORED

**the premise this dream was built on is wrong, and the truth is sharper.** walked against
`origin/main`:

| what | state on main |
|---|---|
| `.behavior/` itself | ✅ **committed** — five prior drives live there (`v2026_05_08.rename`, `…blend-priors`, `…feat-introspection`, `…feat-sdk-codegen`, `…feat-apigateway-wire-response`) |
| a drive's `0.wish.md`, `1.vision.yield.md`, `5.*.yield.md`, guards, stones | ✅ **committed** |
| a drive's `.reviews/peer/` directory | ✅ committed — **and it holds one file** |
| that file | 🔴 `.gitignore`, verbatim: `# ignore all peer-review files` / `*` / `!.gitignore` |

⇒ **so `.behavior/` is never archived.** the review trail is simply **never committed** — it is born
ignored and dies with the worktree.

🔴 **and that makes the defect WORSE than this dream stated, on two counts:**

1. **the moment it bites.** *"once archived"* implies some future prune. in fact the referent is
   unreachable **the moment this worktree is deleted**, which is the normal end of a drive — so
   every citation dangles on day one of the merge, never eventually.
2. **a citation that names a YIELD is durable, and one that names a ROUND is not.** the two forms
   read identically in a docblock and have opposite lifespans. `1.vision.yield.md` resolves forever;
   `i010 r011` never resolves at all.

### ⇒ which collapses option 1 from "one move" to ONE CHARACTER

the table below prices option 1 as *"one move, one convention"*. the measurement says the trail is
already in the right **place** — it is merely ignored there. so the fix is an edit to one line of
one `.gitignore`:

```gitignore
# ignore all peer-review files
*                      ← this
!.gitignore
```

⚠️ **and that is precisely why it is not mine to make.** that `.gitignore` is written by `bhrain`'s
route skills, so to change it here forks a convention for one drive — which is the reseed this dream
already recommends, now with a one-line diff attached.

**and a dead pointer is worse than an absent one**, because it carries a pointer's authority: a
reader takes it as a promise that evidence exists somewhere, and spends time on a hunt for it.

### 🔴 what the defect is NOT — and this bounds the fix

it is **not** a `rule.require.timeless-comments` violation. that rule's own test is *"strip every
temporal word — does the comment still stand as a statement of what IS and why?"* run on a sample:

> *"the absent-event guard was duplicated ahead of the delegation precisely to dodge the wash. that
> duplication is what hid the class — it fixed the one caller that had been probed."*

strip `i010 r011` and the claim is unchanged and complete. **every one of these sites states its
mechanism first and cites second**, which is the shape the rule permits.

⇒ so the citations carry real provenance and must NOT be stripped. the defect is narrower: the
**referent** is impermanent, and the fix belongs there.

## .the shape of the fix

three options, cheapest first. all preserve the argument at the site.

| option | what it costs | what it leaves |
|---|---|---|
| **1. archive the trail, addressably** — move `.reviews/peer/` under a stable `docs/` or a released tag rather than prune it | one move, one convention | every citation lands forever; zero source edits |
| **2. cite the ARTIFACT, not the round** — swap `found at i010 r011` for the `.taken` file's path | a 38-file sweep | lands while the file lives; same fragility, one level down |
| **3. cite the RULE, not the round** — swap `raised at i005 r010` for `rule.forbid.failhide` | a 38-file sweep, plus judgment per site | fully durable; loses *who* found it and *when* |

🔴 **option 1 is the recommendation, and it is the only one that costs no source churn.** the
citations are correct as written; what is impermanent is the directory they point into. fix the
referent and 38 files need no edit at all.

⇒ if the trail genuinely must be pruned, option 3 beats option 2 — a rule reference is durable where
a file path is merely durable-for-now.

## .why it is not done in this round

**SAFE:** ✅ — a comment-only change touches no behavior.

**CLEAN:** ❌ — and this is the half that fails.

- it is a **38-file sweep** on the round immediately before `5.3.verification`
- it touches every file the eleven review lanes have just read, so it invalidates every cached clean
  hash and forces a full re-review that grades no behavior change
- ⇒ `rule.require.review-test-changes` blocks a large unrelated change smuggled into a stone, and
  `rule.prefer.wickup-touched-prose` bounds a prose fix to *"prose your change already touches"*

🟡 **and option 1 — the recommended fix — is not this repo's call to make alone.** where a behavior
trail lives after a drive closes is a `bhuild`/`bhrain` convention, so the repair likely wants a
**reseed** rather than a local sweep.
