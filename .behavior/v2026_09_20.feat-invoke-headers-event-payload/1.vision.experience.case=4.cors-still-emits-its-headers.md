# case=4 — cors still emits its headers

**cells** `E2·D1·A*·B*` (happy) **and** `E2·D2·A*·B*` (sharp) · **care** 🔴 critipath · **density** 1

⚠️ **two catalog rows, one case file — 4a and 4b.** the `A` and `B` axes are wildcards here: an
`E2` consumer observes only the response, so the cell is invariant under both (region 1 of the
partition). and the `D` axis takes **both** values off **one** assertion — this file's clamp
asserts the cors headers are present, so its **green is 4a** and its **red is 4b**.

⇒ they are two experiences with one measurement, which is why the catalog carries two rows and
this file carries one narrative. the feel axis stays binary per row, and neither outcome is
silent.

**this is the clamp the wish demands by name**, and the one cell where the experience belongs to a
browser rather than to a handler author.

## the narrative

dory's spa calls a cors-configured endpoint from a different origin. the browser sends the request,
reads `Access-Control-Allow-Origin` off the response, and lets dory's javascript see the body.

dory notices nothing. **that is the experience** — a cors header that arrives is invisible, and a
cors header that vanishes looks exactly like a network error to every user of every browser.

the hazard is precise and the repo already wrote it down:

> `genZodBodyValidationMiddleware.ts:17-25`
> cors picks its method extractor by `request.event.version ?? '1.0'`, and `UnifiedApiGatewayEvent`
> declares no `version` — so cors always falls to its **v1** extractor, `(event) => event.httpMethod`.
> it also reads `request.event.headers` in its `after` hook.
> ⇒ *"whatever occupies `request.event` when cors's `after` runs must keep `httpMethod` and
> `headers` readable at the top level, with v1 names."*

⚠️ **this change does not move `request.event`** — it only renames a key in the object `logic`
hands to `invoke` (`forApiGateway.ts:222-225`). so cors is untouched by construction.

**but "by construction" is a read, not a run.** and the failure this guards against is silent:
cors that emits no headers looks identical to cors never configured. no throw, no log, no type
error (`rule.require.read-the-slot-a-dependency-reads`).

## the bdd sketch

```
given [case4] a cors-configured handler

  when  [t0] a normal request arrives and the handler succeeds
  then  `Access-Control-Allow-Origin` is PRESENT on the response
  ⇒ the positive control. without it, an absent header and a broken
    harness are the same observation

  when  [t1] `request.event` is replaced with a non-http shape (the defect simulated)
  then  the cors header is ABSENT
  ⇒ the CLAMP BITES. this arm must go RED under the repair and GREEN
    under the defect — prove it by hand, both directions
    (`rule.require.clamp-edge-cases`)

  when  [t2] the handler WRITES to `event` (its `invoke` input alias for
             middy's `request.event` slot)
  then  🔴 the write THROWS, and the cors header is still present on the
        error response
  ⇒ RE-AIMED by F04. it once recorded the mutation hazard as a
    baseline for a future freeze; the wisher ruled the freeze on
    2026-09-21, so this arm now clamps that the freeze HOLDS. a green
    here under a removed `Object.freeze` means the clamp is toothless

  when  [t3] the handler's `schema.input` declares NO `headers` key
  then  `event.headers` is still populated, and the cors header is present
  ⇒ the ZOD-STRIP clamp. zod strips unknown keys, so an sdk that parses
    `{ headers, payload }` against a payload-only schema and writes the
    result back would put a HEADERS-LESS object into the envelope —
    and `@middy/http-cors` reads exactly that slot (`index.js:83`).
    this is the one arm that catches F12's implementation trap
```

⚠️ **`event` now means two values in this file, one line apart** — the handler's field (public,
the whole object) and middy's `request.event` (internal, its own bag slot). they are the **same
reference** here, which is exactly why the hazard existed. an sdk contributor who edits middleware
holds both senses; no consumer does. recorded in `domain.terms/event.md`, where the code cannot
say it.

🔴 **and the one-reference property is why the freeze is the right repair, not a copy.** a
defensive copy would end `[t2]`'s hazard and break `[t0]`'s premise — two objects means the bag
and the slot can diverge, so a handler's read of `headers` would stop to be a read of what cors
sees. **the freeze removes the hazard and keeps the identity** (F04).

## 🔴 how this sharp critipath fails safe — and why it is PREVENTION, not detection

a sharp critipath owes proof that nobody gets cut: **fast, loud, teaches the fix**
(`define.experience`). read literally, this case appears to owe that and not deliver it — so the
argument is made here rather than left for a reviewer to reconstruct.

| the demand | at runtime | verdict |
|---|---|---|
| **fast** | the loss happens in cors's `after` hook, at the end of the chain | ⛔ no |
| **loud** | 🔴 **silent.** an absent header raises no throw, no log, no type error. it is indistinguishable from cors never configured | ⛔ no |
| **teaches the fix** | dory's browser reports a cors error that names her origin, never our chain | ⛔ no |

⇒ **there is no runtime fail-safe available here, and there cannot be one.** the failure is a
vendor's silent degradation inside a third-party hook we do not own
(`rule.require.read-the-slot-a-dependency-reads` — *"the framework does not object… it degrades"*).

so the safety is taken one rung **higher** instead:

> `rule.prefer.prevent-over-correct` — *"prefer to design the error out over a message that reports
> it after the fact. the best error is the one the human can never trigger."*

| the ladder | what stands here |
|---|---|
| 1. make it impossible | ⚠️ partly — the change does not touch `request.event`, so the defect is unreachable **by construction**. but "by construction" is a read |
| 2. make it hard | the constraint is written at the seam, `genZodBodyValidationMiddleware.ts:17-25` |
| 3. **catch it early** ✅ | **the clamp.** `[t1]` goes red in CI before a human ever meets it |
| 4. report it well | ⛔ unavailable — see the table above |

⇒ **the clamp IS the fail-safe**, and it is a stronger answer than a loud error would be: a loud
error cuts someone and then explains itself; a clamp means no one is cut at all. what the clamp owes
in exchange is **teeth** — and that is the next section, which is why it is not optional here.

⚠️ **the honest bound**: prevention protects every consumer of a *shipped* release. it does not
protect a consumer of a release where the clamp was green for the wrong reason. that is the whole
weight `rule.require.clamp-edge-cases` carries, and why step 2 below is mandatory rather than
advisory.

## ⚠️ prove the clamp, both directions

the wish demands *"a test that goes red if `request.event` stops to be http-shaped"*. a clamp
nobody has seen fail is a guess.

1. land the change · run `[t0]` and `[t1]` · both green
2. **break it on purpose** — hand `invoke`'s bag into `request.event`'s slot · `[t1]` MUST go red
3. restore · `[t1]` MUST go green

if step 2 stays green, the clamp does not exercise the defect and must be rewritten.

## what makes it a critipath

- the wish names it as an acceptance line, so it is not optional
- it is the only cell whose failure is **silent and total** — every cross-origin call in every
  browser breaks at once, with no error anywhere in the logs
- the repo has met this exact class before: a cors mapper that emitted `origins: undefined`
  clobbered the vendor default and turned every success into a 500, green suite and all
  (`forApiGateway.ts:160-167`). the class stays open until a clamp with teeth closes it
