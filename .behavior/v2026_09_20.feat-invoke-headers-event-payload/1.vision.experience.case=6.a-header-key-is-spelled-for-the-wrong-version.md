# case=6 — a header key is spelled with a capital, and the miss is now DETERMINISTIC

**cell** `A2·B1·D2·E1` · **feel** sharp · **care** alterpath · **density** 1

🔴 **this case was REWRITTEN on 2026-09-21, and the rewrite is the point.** it was drawn as a
*version-dependent* hazard this route did not measure — a key that reads on v1 and misses on v2,
with a `[tn]` blocked behind a fixture that could not vary the case. the wisher ruled a **case-fold**
(**F08**), which does not soften the hazard: it makes it **deterministic**, and therefore catchable
by crush's own first test run.

⇒ so the case survives, its `[tn]` unblocks, and its grade holds for a **different and better
reason**. the earlier draft is recorded below rather than deleted.

## the narrative

crush writes a brand-new webhook verifier. no migration, no stale name, no term to unlearn — the
`B1` posture. he reads the new shape, finds `headers` one hop from his hand, and writes the obvious
line:

```ts
export const handler = forApiGateway({
  invoke: async ({ headers, payload }) => {
    const sig = headers['X-Signature'];        // ← the key as the vendor's docs print it
    if (!sig) throw new UnauthorizedError('unsigned');
    return { body: await verify({ sig, body: payload }) };
  },
});
```

🔴 **it does not work, and it does not work the first time he runs it.** the sdk lowercases every
key on both arms, so `headers['X-Signature']` is `undefined` for every request that will ever
arrive — v1, v2, local harness, deployed stage, all of them. crush's own first test throws
`unsigned`, he reads the type (`Record<string, string | undefined>`), lowercases the key, and ships.

### 🔴 what the fold actually changed — the failure moved, and it moved the right way

| | the earlier draft | after the fold |
|---|---|---|
| when it fails | **only on one version.** v1 reads, v2 misses | **always**, or never |
| who meets it first | 🔴 **a vendor's callback in prod**, on a day crush is not in the room, after someone else moved the route to a v2 stage | ✅ **crush, at his keyboard**, on his first run |
| what changes to trigger it | a config edit **in another repo** | ⛔ naught — it is not triggerable, it is constant |
| how it reads in a stack trace | *"the verifier is broken"* — the wire is nowhere in it | the same trace, but on a red local test with the fix one line away |
| the inverse shape — a verifier that treats an absent signature as *"unsigned but allowed"* | 🔴 **a silent auth bypass, latent until a stage moves** | the same bypass, and it is **red before it ships** |

⇒ **a deterministic wrong answer is strictly better than an intermittent right one.** the sharp
feel is unchanged — crush still meets a miss he did not expect — but its **blast radius collapses
from a production auth surface to one local test run.**

## the mechanism, and where it is written

```ts
// asUnifiedApiGatewayEvent.ts:68 — after the fold
headers: asLowercasedKeys(input.payload.headers),
```

> **rfc 9110 §5.1: http field names are case-insensitive.** the fold is not a convenience — it
> ends a contradiction between this sdk and its own protocol.

⚠️ **the vendor split the earlier draft called *"unmeasured"* is real**, and the measurement found
it rather than settled it:

| evidence | what it shows |
|---|---|
| 4 app repos send **`Authorization:`** — capital — on the wire (`fetchAgainstSvcGateway.ts`) | the sender's case is capitalized |
| `svc-gateway`'s 68 fixtures construct **`authorization:`** — lowercase | every extant test asserts the lowercased form |
| `@middy/http-response-serializer/index.js:25` reads `headers?.Accept ?? headers?.accept` | 🔴 **a vendor that has met both cases in production** |

⇒ the last row is the strongest: a library does not write a two-case fallback for a case it has
never seen. **the fold makes that fallback unnecessary**, and the vendor's `?? accept` arm catches
our keys either way.

  when  [t0] a v1 payload delivers the key as `X-Signature`
  then  the read returns `undefined`

    by hand, both directions (`rule.require.clamp-edge-cases`)

  when  [t1] a v2 payload delivers the same header already lowercased
  then  the read returns `undefined` — IDENTICALLY to [t0]
  ⇒ the determinism proof. the two arms must AGREE, and their agreement
    is the whole gain the fold buys

  then  the read returns the signature on BOTH versions

⚠️ **`[t2]` is not decoration.** an absence (`undefined` at `[t0]`/`[t1]`) is the least trustworthy
observation a suite can make, because a misconfigured fixture produces the identical result
(`rule.require.positive-control-before-absence-claims`). **this case has already been wrong once for
exactly that reason** — its earlier draft priced the fold as a behavior change to 129 production
lines, and those 129 lines forward the bag whole rather than index it. the real count was **zero**.
