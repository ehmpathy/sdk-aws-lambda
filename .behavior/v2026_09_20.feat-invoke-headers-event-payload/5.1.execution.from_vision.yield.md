## 🔴 the find, before any edit — F08's "first deliverable" is NOT owed

the vision, `case=6`, `case=1`, `case=5`, and F08 all carry the same instruction:

> *"the fixture must be able to deliver a DIFFERENT header object per version arm. today it cannot
> (`asApiGatewayRequestPayload.ts:31,66` pass one object to both), so every arm would pass
> vacuously. ⇒ widen the fixture FIRST, else this case is theater."*

**read the fixture and the claim splits in two.** the vision conflated two different clamps:

| the claim to clamp | does it need per-arm variance? |
|---|---|
| *"v1 and v2 deliver different key cases"* — the ORIGINAL question | ✅ **yes.** the fixture cannot vary case per arm, so this is unprovable in-repo |
| 🔴 *"the sdk lowercases, on both arms"* — the FOLD, which is what ships | ⛔ **no.** it needs one **capitalized input**, and the fixture already takes `headers: Record<string, string>` and passes it **verbatim** to both arms (`:31`, `:66`) |

⇒ so the fold's clamp is available with the fixture as it stands:

```
feed { 'X-Signature': 'abc' } at version 'v1'  ->  event.headers['x-signature'] === 'abc'
                                               ->  event.headers['X-Signature'] === undefined
feed the same at version 'v2'                  ->  identical
remove the fold                                ->  BOTH invert. the clamp has teeth
```

**and the verbatim passthrough is what makes it work** — the property F08 called the defect is the
same property that lets the test state a capitalized input. the fixture asserts naught about aws,
so no vendor claim is smuggled in (`rule.require.measure-the-value-you-emit`).

⇒ **the widen is not done**, and the reason is recorded rather than the work skipped quietly. what
stays unprovable in-repo is aws's own behavior — and the fold makes the sdk's emitted case
independent of it, which is the whole point of Q5's *"the question dissolves"*.

⚠️ **the class this belongs to is the drive's own**: a claim stated in the register of a
measurement, with no observation behind it. the instruction was repeated across five artifacts and
**not one of them had read the fixture's own type**. that is instance 7.

## 🔴 the second find — the zod-strip trap is a cors MIS-DECISION, not a starvation

the vision recorded the trap as an **absence**: zod strips unknown keys, so a naive write-back puts a
headers-less object into the envelope and `@middy/http-cors` finds no bag to read. ⇒ the remedy it
named was to fill an absent `headers` key before the parse.

⛔ ~~**that remedy covers only half the trap.** it answers the author who declares NO header
schema.~~

🔴 **STRUCK in self-review r6 — the remedy covers NEITHER half, and this line understated it in the
same direction the vision did.** zod strips by the object **SHAPE**, never by the input: a key
absent from the shape is dropped whatever value you feed in, so a permissive default fed in
beforehand is dropped with it.

⚠️ **measured, and the measurement was already on the page.** the shipped code feeds the *entire
wire bag* into `safeParse` — a strictly more permissive default than the vision asked for. when the
header MERGE was swapped for a replace, `[case17]` went **RED** — and `[case17]`'s schema is
`payload`-only, the very arm the struck line claimed was answered. ⇒ the remedy runs today and is
inert; only the merge closes either arm.

the author who declares ONE header is the sharper case, and the vendor's own dist says why:

```js
// @middy/http-cors/index.js:83-85 — inside `modifyHeaders`, reached from the AFTER hook
const eventHeaders = request.event.headers ?? {};
const incomingOrigin = eventHeaders.Origin ?? eventHeaders.origin;
headers['Access-Control-Allow-Origin'] = options.getOrigin(incomingOrigin, options);
```

```js
// @middy/http-cors/index.js:2-14 — what an ABSENT origin produces
if (options.origins.length > 0) {
  if (incomingOrigin && options.origins.includes(incomingOrigin)) return incomingOrigin;
  else return options.origins[0];          // 🔴 the FIRST allowlisted origin, unconditionally
}
```

⇒ so a header schema that strips `origin` does not leave cors silent. **cors runs, and emits a wrong
answer**:

| the config | an absent origin produces |
|---|---|
| `origins: ['https://a.com', 'https://b.com']` | `Access-Control-Allow-Origin: https://a.com` — for a caller from **b.com**. the browser refuses a response the sdk allowlisted |
| `origins: []`, `credentials: true`, `origin: '*'` | `Access-Control-Allow-Origin: *` — which every browser refuses **with credentials**, per the fetch spec |

🔴 **and the trigger is the PAVED example.** the vision's own sample header schema is
`headers: z.object({ authorization: z.string() })` — the one shape a reader would copy, and the one
that strips `origin`.

⚠️ a wrong header is **worse than an absent one**. absent reads in a browser console as *"no CORS
header"* and points at the sdk; wrong-origin reads as a deliberate denial and points at the caller.

### ⇒ the remedy: headers WRITE BACK AS A MERGE; payload replaces

```ts
event.headers = { ...event.headers, ...result.data.headers };   // merge
event.payload = result.data.payload;                            // replace
```

**the axis that makes this a second case rather than a defended exception** is
`rule.require.read-the-slot-a-dependency-reads` — *who else reads the slot*:

| slot | other readers | so the write-back |
|---|---|---|
| `payload` | ⛔ none. the body is wholly the handler's | **replaces** |
| `headers` | ✅ `@middy/http-cors` reads `origin` (`index.js:84`); `@middy/http-response-serializer` reads `accept` (`index.js:25`) | **merges** — the author's schema constrains a SUBSET, and the rest is not theirs to delete |

the projection survives: one object is assigned to `event.headers`, and `headers` is lifted from
`event.headers` after the chain — so `headers === event.headers` holds, and a `.transform()` on a
declared key reaches the handler AND the wire keys stay readable by the vendors.

### ✅ and the fold is a no-op for cors — the positive control

line 84 tries `Origin` first, then `origin`. under the fold `Origin` is never present, so the `??`
arm serves. today, v1 delivers a browser's capitalized `Origin` and the first arm serves; v2 delivers
aws's lowercased `origin` and the second arm serves. **all three paths land on the same value**, so
the fold cannot regress cors — which is the same `?? accept` argument `headers.md` already makes for
the response serializer.

## 🔴 the sixth find — the rename CREATED a near-homograph: `ResponseWire` vs `WireResponse`

every find above asks *"does the old word survive?"*. this one asks the inverse, and the inverse is
where the route's own defect was: **`ApiGatewayResponseWire` is a name this route introduced**, and
the repo already held `getOneWireResponse` / `asWireSnapshot` / `setWireResponseForError` for a
different value.

| compound | names | grain | sites |
|---|---|---|---|
| **`ResponseWire`** | the value a handler RETURNS, which aws receives | lambda | 10+ |
| **`WireResponse`** | the bytes `fetch` read off the SOCKET | http | 3 |

🔴 the same two words, opposite order, two values — and they **meet inside one file**:
`genApiGatewayProxyHarness.ts` imports `ApiGatewayResponseWire` at `:7` and declares
`setWireResponseForError` at `:72`. the acceptance suite `local.wireResponse.acceptance.test.ts` was
the sharpest case: it tests the socket bytes and **explicitly not** the `ResponseWire`, so its name
read exactly backwards.

⚠️ **a near-homograph is worse than a synonym** — a synonym makes a reader pause, a homograph lets
them read past with the wrong value in mind and no signal that they did.

the `ResponseWire` side is ruled vocabulary and public (`src/index.ts`); the `WireResponse` side is
3 test-asset names with **zero** consumer reach. ⇒ the test assets yield:

| was | now |
|---|---|
| `getOneWireResponse` | `getOneHttpResponse` |
| `asWireSnapshot` | `asHttpResponseSnapshot` |
| `setWireResponseForError` | `setHttpResponseForError` |
| `blackbox/local.wireResponse.acceptance.test.ts` + its snapshot file | `local.httpResponse.acceptance.test.ts` |

✅ the **bare word** `wire` survives as the parameter, on purpose: the collision was the compound,
and at the http grain the value genuinely IS the wire.

✅ **the rename orphaned no snapshot key**, proven rather than assumed — a byte-diff of the moved
file against `HEAD` shows exactly **one** changed line, and it is F12's zod path (`""` → `"payload"`)
from earlier in the route. ⚠️ the green suite alone would NOT have proven this: jest writes a new
snapshot rather than fails, so an orphaned key passes.

⇒ **the lesson that pairs with the fifth find**: a rename is not done when the old word is gone. it
is done when the **new** word is unambiguous — so for each word a rename introduces, grep the repo
for its reversal and its near-neighbours. a sense-sweep is blind by construction to a collision its
own fix creates.

⚠️ what is deliberately KEPT: aws's *"payload format version"* (`PayloadFormatVersion`, `1.0`|`2.0`)
— the vendor's own config key, which an author finds under that word and no other. it now carries a
`⚠️` block that names the collision, since aws's sense there is the whole event: the retired one.

### 🔴 the sixth row is the WISH's own clamp line, and it was unproven until review r5

> the cors behavior owes a clamp that goes red if `request.event` stops to be http-shaped
