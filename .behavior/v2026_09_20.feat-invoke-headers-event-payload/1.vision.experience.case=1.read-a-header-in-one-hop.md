# case=1 — read a header in one hop

**cell** `A2·B1·D1·E1` · **feel** happy · **care** 🔴 critipath · **density** 1

## the narrative

kai writes a webhook handler for an sms provider. the provider signs each request, and the
signature rides in a header.

kai types `invoke: async ({ ` and the editor offers three keys: `headers`, `payload`, `event`. the
first one is the one kai wants, and its name says so. kai writes:

```ts
invoke: async ({ headers, payload }) => {
  const signature = headers['x-twilio-signature'];
  if (!isValidSignature(signature, payload)) return { status: 403 };
  return { status: 204 };
}
```

no envelope. no hop. no moment where kai must ask *"which field holds the headers — and why is it
called `raw` when the docs say it is normalized?"*

**the contrast**: today kai writes `rawEvent.headers['x-twilio-signature']`, and — if kai is the
sort who reads doc-comments — pauses at a `⚠️ .misnomer` block that explains the field name is
wrong and a rename is pending. that pause is the cost this case removes.

## the sharp edge nearby

`headers` and `event.headers` both work. a reader may wonder which is canonical.

⇒ they are **the same object**, and the doc must say so plainly. the peer is a convenience read,
never a second source of truth.

⚠️ **and the peer slot's safety rests on that word: `headers` is a PROJECTION.** 🔴 **so is
`payload`** — `payload === event.payload`, one object, since the validator writes the parsed value
back into the envelope.

⛔ ~~its sibling `payload` is a **transform** of `event.rawPayload` — two values, one of them
unjudged — which is why the envelope deliberately exposes **no `event.payload`** for it to shadow.
⇒ the same-name-at-two-levels pattern is safe here and **only** here.~~ 🔴 **struck by F13.** the
two-values trap comes from an *unvalidated* slot, never from the slot — and the exception this
paragraph defended was the defect it described (`rule.forbid.defended-exceptions`).

⇒ **one rule, no exception**: every lifted field is a projection of the envelope. and the envelope
is **deep-frozen** when `invoke` receives it, so the identity cannot be broken from the handler
either (**F04**).
