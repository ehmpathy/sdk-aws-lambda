# 1.vision — `invoke` takes `{ headers, payload, event }`

```ts
invoke: ({ headers, payload, event }) => …
//         projection   the body    the whole object
```

| term | sense | source |
|---|---|---|
| `event` | **the whole object that arrived**, v1/v2 reconciled | aws's word for every lambda trigger |
| `payload` | **the body**, parsed and validated | http's word — rfc 9110, *"payload body"* |
| `headers` | a projection of `event.headers`, lifted one hop | measured: **129** production reads |

> *"http = api gateway, we treat the body as the payload, event is the whole object"*
> — the wisher, 2026-09-20

## 🔴 the one rule

> **`event` = what arrived. `payload` = its body.**

neither word asserts a transport, so neither can be falsified by a family we have not built:

| family | `event` | `payload` |
|---|---|---|
| `forApiGateway` | the reconciled http event | the parsed, validated body |
| `forAskEndpoint` | the whole invoked event | — no envelope, so no body to lift |
| a future `forSqs` | the sqs event | a record's message body |
| a future `forSns` | the sns notification | the `Message` |

⚠️ the cardinality caveat is about **shape**, never the word: an sqs invoke carries N messages, so a
`forSqs` cannot keep a singular `payload`. no word choice settles that.

⇒ the etymology, the rejected synonyms, and the two vocabulary reversals this drive made are
recorded under their own mandate in `.agent/repo=.this/role=any/briefs/domain.terms/`
(`rule.require.persist-domain-term-evidence`). the forks are in `.fulcrums/`. neither is restated
here.

## the outcome world

### day in the life

```ts
export const handler = forApiGateway({
  schema: {
    input: z.object({
      headers: z.object({ authorization: z.string() }),   // ← constrained, not merely read
      payload: z.object({ to: z.string() }),
    }),
    output: asApiGatewayResponseSchema({ body: z.object({ sent: z.boolean() }) }),
  },
  invoke: async ({ headers, payload }) => {
    return { body: { sent: await send(payload.to, headers.authorization) } };
    //                                            ^ one hop, and typed — no `| undefined`
  },
});
```

⇒ the schema and the destructure are **the same two words**, so a reader checks one against the other
with no level-gap to hold in their head.

a handler that genuinely needs the envelope has it, under aws's own word:

```ts
invoke: async ({ payload, event }) => ({
  body: { method: event.httpMethod, path: event.path, id: event.requestContext.requestId },
})
```

and the version-locked escape hatch is exactly one `_` away, still marked:

```ts
invoke: async ({ event }) => ({ body: { raw: event._.raw } })   // you have left the paved path
```

### before / after

| | before | after |
|---|---|---|
| read a header | `rawEvent.headers['authorization']` | `headers['authorization']` |
| read the body | `event.to` — where `event` denotes *the body* | `payload.to` |
| read the method | `rawEvent.httpMethod` | `event.httpMethod` |
| what the field name claims | *"this is the untouched wire value"* — **false** | *"this is the event"* — aws's own word, **true** |
| the doc-comment | a `⚠️ .misnomer` note that confesses the lie | deleted; no confession is owed |
| the twin's asymmetry | undocumented, so it reads as an oversight | documented, so it reads as a boundary difference |

### the aha

> **the field name no longer excuses itself.**

`forApiGateway.ts:115-117` carries a comment whose whole job is to tell you the field name is wrong.
that comment is the defect, written down. a name that needs a disclaimer is a name nobody has chosen
yet.

## the shape

```ts
schema: {
  /**
   * .what = describes `inputAfter` — THE PAIR a caller may constrain
   * .why = headers and body are the only two a handler reaches for: measured 65 and 78,
   *        against 0 for method, path, query, path params, and request context (F12)
   * .note = `payload` is REQUIRED and `headers` is OPTIONAL, and the axis is not taste:
   *         `payload` names an EXTANT guarantee — 78 sites already get body validation, so
   *         an absent key would silently drop it. `headers` names a NEW capability — headers
   *         have never been validated, so an absent key is the status quo (F12)
   * ⇒ header enforcement is OPT-IN. declare no `headers` key and no header can refuse a
   *         request, which is why this widens the contract for zero extant callers
   */
  input: ZodSchema<{ headers?: THeaders; payload: TPayload }>;

  /**
   * .what = describes `outputBefore` — the whole response `invoke` returns
   * .note = the ENVELOPE, never the body inside it. `asApiGatewayResponseSchema({ body })`
   *         lifts a body schema into one
   */
  output: ZodSchema<ApiGatewayResponse<TBody>>;
},

invoke: (
  input: {
    /**
     * .what = the request headers, keys LOWERCASED. validated if you declared them
     * .why = rfc 9110 §5.1 makes field names case-insensitive, and every http runtime in
     *        this path lowercases — node, express, api gateway v2. verbatim passthrough
     *        was the sdk's own third behavior (F08)
     * .note = the same object as `event.headers`. a projection, never a second source
     */
    headers: THeaders;

    /**
     * .what = the BODY — parsed and validated. `inputAfter`
     * .why = http's own word for a message body (rfc 9110, "payload body")
     * .note = the same object as `event.payload`. a projection, exactly as `headers` is
     */
    payload: TPayload;

    /**
     * .what = the whole object that arrived, v1/v2 reconciled, DEEP-FROZEN
     * .why = it is middy's own `request.event`, which `@middy/http-cors` and
     *        `@middy/http-response-serializer` read in their `after` hooks. a frozen
     *        object keeps the projection (one object, two paths) while it removes the
     *        mutation hazard — a defensive copy would remove the hazard and destroy the
     *        projection (F04)
     * .note = the wire union is at `event._.raw`
     */
    event: Readonly<UnifiedApiGatewayEvent<{ headers: THeaders; payload: TPayload }>>;
  },
  context: ContextLogTrail,
) => Promise<ApiGatewayResponse<TBody>>
```

### 🔴 the one rule the shape yields

> **the schema describes what you constrain. `event` is what you reach for when you did not.**

⇒ so `invoke`'s bag is **the validated pair, plus the escape hatch**, and both constrained slots are
projections of the envelope:

| the bag | the envelope | relation |
|---|---|---|
| `headers` | `event.headers` | one object |
| `payload` | `event.payload` | one object |

**one rule, no exception.** an earlier shape here carried a `payload` with no envelope peer and a
paragraph to explain why — which is a shape defect with good prose on top (F13).

⚠️ **the invariant this owes is load-bearing: the validator writes BACK into the envelope.** the
chain already does it — `genZodBodyValidationMiddleware` replaces `event.body` with the parsed value,
which is why `event.body as TInput` (`:223`) is true at `logic` time rather than merely hoped for.
⛔ validate into a side bag instead and the two slots diverge: a zod `.default()` on a header produces
a **different object**, so `event.headers` would silently go stale.

### 🔴 the shape carries ZERO ⚠️ caveats, and that is the measurable difference

an earlier draft of this block carried two, and the wisher struck both on 2026-09-21 by repair of the
**form** rather than by better prose:

| the struck caveat | what replaced it |
|---|---|
| ⛔ ~~*"keys arrive AS THE WIRE DELIVERED THEM … do not assume a lowercase key"*~~ | 🔴 a **case-fold**. the keys are lowercase, so there is naught to assume (**F08**) |
| ⛔ ~~*"it is the live middy `request.event`; a handler that writes mutates what cors reads"*~~ | 🔴 a **deep freeze**. the write throws (**F04**) |

⇒ each caveat existed because the form did not carry the guarantee. that is
`rule.forbid.defended-exceptions` exactly — **the rule this drive enbriefed, fired on its own author
one message later** (F14).

### ⚠️ the one implementation trap the optional `headers` key creates

**zod strips unknown keys by default.** so an author who writes `z.object({ payload: … })` and an sdk
that parses `{ headers, payload }` against it gets `{ payload }` back — and the write-back then puts a
**headers-less** object into the envelope. `event.headers` goes `undefined`, and `@middy/http-cors`
reads exactly that slot (`index.js:83`).

⇒ so the optional key is **not free**: ⛔ ~~the sdk must fill an absent `headers` with a permissive
default **before** it parses~~ — 🔴 **that remedy is INERT and was struck at execution.** zod strips
by the object SHAPE, so a default fed in beforehand is stripped too. the hazard named above is real;
the fix is a **write-back MERGE** (`event.headers = { ...event.headers, ...result.data.headers }`),
which closes both the absent-key and the declared-partial arms with no branch.

⚠️ the clamp named here was also wrong: `case=4`'s cors test (`[case3]`) allowlists ONE origin, so it
cannot tell an echo from `origins[0]` and stays green under the defect. the real clamps are
`[case17]` and `[case18]`. ⇒ see `5.1.execution.from_vision.yield.md` and self-review r6.

#### 🔴 the migration note a reader MUST act on

> **`event` keeps its word and changes its type.** it denoted the body; it now denotes the envelope.

so a migration is **not** a hunt for `rawEvent`. every `invoke` site moves, not only the 65 that read
the envelope. the compiler catches it — measured **0 silent collisions** against a control of **129**:

| the stale read | production hits |
|---|---|
| `event.path` · `event.httpMethod` · `event.queryStringParameters` · `event.pathParameters` · `event.isBase64Encoded` | **0** each |
| ✅ *control, identical form* — `rawEvent.headers` | **129** |

⇒ a stale `event.<bodyField>` fails to compile (the envelope has no `.to`, `.jobUuid`, …), and a
stale `event.<envelopeField>` was never written. `case=3` demonstrates both arms.

#### 🔴 the cast this DELETES, and why the type may now state it

```ts
// forApiGateway.ts:217-223 — today
// `genZodBodyValidationMiddleware` has already parsed it against `schema.input`
//  and replaced it with the parsed value
{ event: event.body as TInput, rawEvent: event }
//              ^^^^^^^^^^^  .removal = drops when the input translate owns this seam
```

**at `logic` time `event.body` already IS the validated value** — the middleware replaced it. the cast
exists only because the *type* says `unknown` while the *runtime* says `TInput`.

⇒ `payload: TPayload` on the envelope closes that gap, and the cast goes with it
(`rule.forbid.as-cast` — *an `as`-cast at a seam is the model's absent edge, asserted by hand*).

⚠️ **an earlier draft DELETED the envelope's body slot instead**, to dodge a validated-beside-parsed
collision. the collision is real and the remedy was wrong: it comes from an **unvalidated** slot, not
from the slot. ⇒ the write-back the chain already performs is the fix, and it leaves one rule with no
exception (**F13**).

⚠️ **`rawPayload` is open.** it measured **0** consumer reads, and `event._.raw` already carries the
wire union — so it may drop rather than sit beside `payload`. owed: a check of the sdk's **own**
internal reads (F13).

### 🔴 why NOT the spread — option C, rejected on a measured collision

the wish demands this be recorded rather than dropped. option C spreads the envelope's fields into
`invoke`'s bag:

```ts
// option C — REJECTED
invoke: async ({ headers, body, httpMethod, path, payload }) => …
//                        ^^^^                     ^^^^^^^
//                        `unknown`                `TInput`
```

| the field | its type | its position | verified |
|---|---|---|---|
| `body` — from the spread envelope | `unknown` | **pre-validation** — parsed, unjudged | `UnifiedApiGatewayEvent.ts:19` |
| `payload` | `TInput` | **post-validation** — `inputAfter` | `forApiGateway.ts:110` |

⇒ **two names for ONE slot, at two pipeline positions, in one destructure.** worse, the wrong choice
is the one that *appears* safe: `body` reads as the plainer name, hands back `unknown`, and a handler
that takes it has silently opted out of every guarantee the schema makes. that is the exact
conflation the position vocabulary exists to prevent
(`rule.prefer.names-by-position-over-claim`, `rule.require.retest-the-model-on-every-family`).

⚠️ and a spread **flattens the escape hatch's mark**: `_` becomes a bare field beside `headers` and
`body`, which violates the wish's *"do NOT lift `_` to a top-level field"* by side effect.

🔴 **the ruled shape does not merely avoid the collision — it DELETES the field that causes it**, so
the hazard cannot recur under a later spread either.

## 🔴 the version bump — the next MINOR, not `1.0.0`

under semver a `0.x` package makes no stability promise, so a break is carried by a **minor** bump —
and release-please, which this repo uses, maps a break on a `0.x` line to the next minor by default.

⚠️ not cosmetic: a consumer pinned `^0.N.x` takes only `0.N.x` and **refuses** the next minor, so the
bump already protects them. `1.0.0` would additionally assert a stable public api — a claim this
package has not made and, on the evidence of this route, should not yet make.

⛔ ~~`package.json:5` reads `0.4.2` … maps to `0.5.0` by default~~ 🔴 **STRUCK 2026-09-22 — the
arithmetic went stale while the argument held.** `origin/main` shipped **`0.5.0`** in `#43` after
this vision was written, so the break now lands at **`0.6.0`**.

⚠️ and the repair is the **form**, not the digit. an **absolute** target in a vision goes stale the
moment the trunk moves, and a stale number is the kind a later stage copies rather than argues with —
the same failure this vision's own F09/find-21 pair names for *"the next minor"* in a readme,
inverted. ⇒ **the vision states the RULE; the execution stage reads the trunk for the number.**

⇒ **the execution stage owes a `feat!` commit with the conventional-commits break footer, and naught
more.** it must not hand-set a version at all — major or minor.

### 🔴 the provenance of `rawEvent`

## what is awkward?

### 1. ✅ `event` was a live alias into the middy chain — **resolved, not documented**

`forApiGateway.ts:223` passes the value straight from **middy's own `request.event` slot**, by
reference. a handler that wrote `event.headers['x'] = 'y'` mutated the object `@middy/http-cors`
reads in its `after` hook.

the hazard existed **today** under `rawEvent`, undocumented. this change did not create it — but it
put the value under a friendlier name, which made a mutation **more likely**.

⛔ ~~the shape adds a `.note` that names it. a deep freeze is out of scope and would need its own
measurement.~~ 🔴 **struck 2026-09-21.** the measurement took one grep of the vendor dist and
returned **0 writes across all 5 middy packages**, so the freeze is in and the `.note` is out
(**F04**). ⇒ **the awkwardness that remains is only that this was ever deferred**: the entry priced a
run it never attempted, which is this drive's defect class once more.

⚠️ **one real residual**: `@middy/http-json-body-parser` **does** write `request.event.body`
(`index.js:25`). it is not in this chain — positive control: 16 files import `@middy/`, none import
it — but a later author who adds it meets a frozen object. that belongs in the shape's `.note`.

### 2. every constrained slot has two routes to one value

deliberate redundancy, twice over — `headers`/`event.headers` and `payload`/`event.payload`. the
alternative is one hop for the two most common reads, which is the ergonomics defect the wish exists
to fix.

⚠️ the trade is **safe only because each pair is a projection rather than a copy**, and that safety is
a property of the **write-back**, never of the names: `genZodBodyValidationMiddleware` replaces the
value in the envelope, so there is one object with two access paths. ⛔ a validator that wrote into a
side bag would turn both pairs into two-values-one-name at a stroke.

🔴 **and that is exactly why F04 ruled a FREEZE rather than a defensive copy.** a copy removes the
mutation hazard and **destroys the projection** — two objects, drift re-opened, this section's whole
argument void. a freeze removes the hazard and leaves one object. ⇒ the two options look
interchangeable and are not, and the tell is that only one of them survives this paragraph.

### 3. the noun flipped mid-pipeline — repaired at the ENDS, not the middle

```
before:  ApiGatewayRequestPayload ──▶ UnifiedApiGatewayEvent ──▶ event: TInput
              "Request"                    "Event"                  (the BODY ⛔)

ruled:   ApiGatewayEventWire      ──▶ UnifiedApiGatewayEvent ──▶ payload: TInput
              "Event" ✅                  "Event" ✅               (the body, named correctly)
```

the middle keeps its name; the ends move. measured, each with a positive control in the identical
form:

| symbol | `svc-gateway` | `svc-home-services` |
|---|---|---|
| `UnifiedApiGatewayEvent` · `asUnifiedApiGatewayEvent` · `genApiGatewayEventNormalizationMiddleware` | **0 files** each | **0** |
| ✅ *control* — files that import the sdk | **101** | **5** |

⇒ the type is exported and **no consumer names it**, so the rename question was always free. F05
keeps it anyway, because `Event` is the correct noun for a family aws calls events.
`genZodEventValidationMiddleware` does **not** follow — it belongs to the twin.

### 4. it is no longer "a rename" — it retires a repo-wide CONVENTION

| | reach |
|---|---|
| the `invoke` field names | 3 fields, 1 file |
| 🔴 the `Payload`-means-wire-form convention | **~250 lines, 7 sites, 2 doc-comments** — one outside `src/` |
| the exported wire types | `*Payload` → `*Wire` |

⚠️ **a reviewer may fairly call this scope creep.** the counter: the two were never separable.
`rawEvent` exists *because* `Payload` held aws's sense here, so a fix to the field names alone would
leave the cause in place and the same defect would regrow under a new word.

⇒ 🔴 **and the re-scope of 2026-09-21 broke the bound that used to keep it honest.** every prior draft
closed here with *"no behavior changes — field names, type names, doc-comments."* **F12 cannot say
that**: a schema that describes headers can refuse a request on one, so a new 400 path exists that
did not before.

| what still holds | what does not |
|---|---|
| the `invoke` bag, the envelope slot, the wire types — all names | 🔴 `schema.input` changes what `TInput` **denotes**, and opens a refusal path |

⇒ the honest bound is now narrower: **the shape is ruled, and so is the enforcement** — but the
refusal path is **opt-in**, so it reaches no caller who does not ask for it.

⛔ ~~the shape is ruled; the enforcement is **unruled**, and the conservative default lets every
extant caller through until an author narrows a header schema~~ 🔴 **STRUCK 2026-09-21.** the wisher
ruled the enforcement half the same day, and by a move that dissolved the question rather than
answered it: `headers` is an **optional key**, so the 65 unguarded production sites declare no header
schema and **cannot** be refused. there is no "conservative default" to argue about, because there is
no default at all (`rule.require.explicit-optout` — the opt-out is the absent key, on the page).

⚠️ **the same sentence shipped twice**, here and in the edgecase table above, and the strike reached
only one copy. ⇒ a struck claim owes a sweep of its own **subject**, never a repair of the line that
raised it (`rule.require.sweep-the-defect-class`). i007/r1 found one; the sweep found the pair.

### 5. the payoff is honesty, and the price rose

no capability is added; `headers` is the only ergonomic gain, and it is one hop. a reviewer may
reasonably ask whether a version break is worth it — and the base is **78 production files**, so the
*"correct it before consumers multiply"* case does not apply. they already multiplied.

⇒ what survives is measured rather than asserted:

- **the one hop is paid 65 times**, in production, today. the gain is a line that gets shorter in
  every one of them
- **78 authors have met the `.misnomer` comment**, or worse, have not. it sits on the field the sdk's
  largest consumer touches most
- **the cutover is mechanical**, compiler-guided, and shrinks each call site — the cheapest form a
  break of this size can take

⚠️ and the honest statement of the cost: it rises with each consumer, so it is higher today than a
deferral would admit. the wisher ruled the cutover anyway, on purpose.
