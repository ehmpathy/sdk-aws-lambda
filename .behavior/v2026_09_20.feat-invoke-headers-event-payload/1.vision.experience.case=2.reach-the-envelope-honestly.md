# case=2 — reach the envelope, under a name that is true

**cell** `A3·B2·D1·E1` · **feel** happy · **care** 🔴 critipath · **density** 1

## the narrative

crush writes a handler that must echo which route it answered — a debug endpoint. the body alone
cannot tell it; the method and path live on the envelope.

crush reaches for `event`:

```ts
invoke: async ({ event }) => ({
  body: { method: event.httpMethod, path: event.path },
})
```

and reads it as prose: *the event's http method, the event's path.* no decode step, no
disclaimer to reconcile.

**the contrast** is not about hops — it is one hop either way. it is about **what crush has to
believe**. today the same line reads `rawEvent.httpMethod`, and a careful reader stops:

> *"raw? then is this `httpMethod` the v1 field? does it exist on a v2 event? do I owe a
> fallback to `requestContext.http.method`?"*

those questions are the cost of a name that claims *untouched*. the answer is that the value is
already reconciled and `httpMethod` works on both versions — but the name says the opposite, so
the reader must go verify it. `event` makes no such claim, so the question never forms.

## the bdd sketch

```
given [case2] a handler that reads the event envelope
  and   the handler destructures `{ event }` from invoke's input

  when  [t0] a v1 api-gateway event arrives, POST /users
  then  `event.httpMethod` is 'POST'
  and   `event.path` is '/users'
  and   the response body carries both

  when  [t1] the same request arrives as a v2 (http-api) wire form
  then  `event.httpMethod` is still 'POST'
  and   the handler holds no version-specific code
        ⇒ this is the proof that `event` is the RECONCILED shape

  when  [t2] the handler needs the true wire union
  then  `event._.raw` yields it
  and   the `_` still marks the step off the paved path

  when  [t3] the handler reaches for the unvalidated body
  then  ⛔ there is NO such field — `event.rawPayload` is the string, and
        `event.payload` holds the VALIDATED body
  and   `event.payload === payload` — one object, two access paths
  ⇒ 🔴 RE-AIMED by F13. it once clamped that the envelope has NO body
    slot at all; the wisher ruled the slot IN on 2026-09-21. what it
    clamps now is that the slot holds the validated value, never an
    unjudged one — the property the deletion was meant to secure

  when  [t4] the handler WRITES to `event`
  then  🔴 the write THROWS — the envelope is deep-frozen (F04)
  ⇒ the clamp on the freeze at this boundary. `case=4` clamps the
    consequence for cors; this arm clamps the throw for the handler
```

⚠️ `[t1]` is this case's whole point. `[case5]` today runs **v1 only**
(`forApiGateway.test.ts:271` → `createV1Event`), so the reconcile claim at this seam has never been
run at the `invoke` boundary. the replacement owes both arms
(`rule.require.a-harness-types-as-wide-as-its-contract`).

⚠️ **and the whole unit file is v1-only** — `createV1Event` is local to it (`:28`) and used at 20
call sites; **no `createV2Event` exists anywhere in the repo** (swept `--path .`, not just `src`).

⇒ so the v2 arm costs a fixture, not a flag. reuse `asApiGatewayRequestPayload({ version })` from
`src/__test_assets__/asApiGatewayRequestPayload.ts:86`, which takes `'v1' | 'v2'` and carries its
own clamp (`asApiGatewayRequestPayload.test.ts:34,62`).

⚠️ that fixture is itself renamed by this route's cascade — `ApiGatewayRequestPayload` →
`ApiGatewayEventWire`, so the transformer becomes `asApiGatewayEventWire`. the file and its clamp
move with it; **0 consumer files name either**.

### where v2 IS already exercised, and why that does not close this

`blackbox/local.wireResponse.acceptance.test.ts` runs v2 at **five** sites —
`genApiGatewayProxyHarness({ handler, version: 'v2' })` at `:758, :811, :849, :906, :909`.

⇒ so the **wire** path is covered on both versions. what is **not** covered is the `invoke`
boundary itself: no test asserts what a handler *reads* out of the envelope under v2. that is the
exact seam this route renames, and `[t1]` is the one arm that would notice if the rename ever
carried the reconcile away with it.

## what makes it a critipath

- it is the **only** extant reader of the field (`forApiGateway.test.ts:251-285`), so it is the one
  test the rename must carry forward rather than delete
- 🔴 it is where the **whole vocabulary correction** shows itself to a consumer. the drive reached
  three different answers for this one line, and only the third survives contact with a reader:

  | draft | the line crush writes | why it failed |
  |---|---|---|
  | today | `rawEvent.httpMethod` | the name claims *untouched* and the value is reconciled |
  | the `payload` read of the wish | `payload.httpMethod` | ⛔ `payload` is the **body**; an envelope field is not on it |
  | the `request` proposal | `request.httpMethod` | ⛔ true here, **false at sqs** — a claim a later family falsifies |
  | ✅ **ruled** | `event.httpMethod` | aws's own word for what arrived, at every trigger |

- `_.raw` reachability is part of the wish's bound (**do NOT lift `_`**), and `[t2]` is where a
  regression would surface
- 🔴 `[t3]` clamps the **rename** at the heart of the cascade: `body: unknown` becomes
  `payload: TPayload`, so the one-name-two-types trap cannot form — and the `as`-cast at
  `forApiGateway.ts:223` dies with it (see `payload.md`, **F13**)
