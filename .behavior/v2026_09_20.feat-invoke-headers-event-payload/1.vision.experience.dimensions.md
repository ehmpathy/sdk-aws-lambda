# 1.vision.experience.dimensions

## .what

the orthogonal axes of the experience space this wish touches, and the walked product.

the subject is **one surface**: what `forApiGateway`'s `invoke` hands a handler. so the space is
small and the walk is exhaustive rather than sampled.

## the axes

### axis A — what the handler reaches for

the only axis the wish actually changes. values taken from the measured reads, never free-listed
(97 `invoke:` sites surveyed; see `1.vision.yield.md` → groundwork).

| value | today | proposed | measured demand |
|---|---|---|---|
| `A1` the body, or no input at all | `event` / no destructure | 🔴 `payload` / no destructure | **96 of 97 sites reach no envelope** |
| `A2` a header | `rawEvent.headers[k]` | `headers[k]` | 0 in-repo · **documented** in declapract's migration guide |
| `A3` method / path | `rawEvent.httpMethod` | `event.httpMethod` | 1 site (`forApiGateway.test.ts:263`) |
| `A4` deep envelope — query, pathParams, requestId | `rawEvent.queryStringParameters` | `event.queryStringParameters` | **0** |
| `A5` the true v1\|v2 wire union | `rawEvent._.raw` | `event._.raw` | **0** |

🔴 ⚠️ **`A1`'s "proposed" cell read `unchanged` until F01, and that is now FALSE.** `event` keeps
its word and changes its type — from the body to the whole object — so a body-only handler renames
its field to `payload`. ⇒ this is the largest single correction in the catalog:

| | before | after |
|---|---|---|
| sites `A1` touches | 96 of 97 | 96 of 97 — the same |
| sites `A1` **changes** | 🔴 **0** | 🔴 **all that destructure a field** |
| `A1`'s reachable feel | `D1` only (happy) | `D1` **and** `D2` (a stale `event.<bodyfield>` fails at compile) |

⇒ **the change now reaches every `invoke` site that names its input**, and the only reason that is
affordable is the measurement in `case=3`: **0 silent collisions**, control 129. `A1`'s sharp arm
is loud.

⚠️ **what the count actually says.** the measurement is `grepsafe --pattern 'invoke: async'` →
**97 lines**, of which exactly **1** destructures the envelope and **0** read headers. `A1` merges
two populations — sites that destructure `{ event }` and sites that destructure no input at all
(`invoke: async () => …`) — and **that split is unmeasured**.

🔴 **that split now matters, where it did not before.** a site that names no input is genuinely
untouched; a site that destructures `{ event }` must rename. so the honest statement is that
`A1`'s change-set is **somewhere between 0 and 96 in-repo sites**, and the execution stage owes
the count this vision did not need
(`rule.require.positive-control-before-absence-claims` — an unmeasured split is not a zero).

## the walked product

## 🔴 the B × D matrix — ONE shape, instantiated by all five `E1` regions

⚠️ **this section took three review rounds to reach, and the third one is the lesson.** the class
was raised, repaired, and re-raised each time — because each repair covered the **regions named**
rather than the **cause stated**:

| round | the find | what i repaired | what i left open |
|---|---|---|---|
| peer 1 | `A3·B3·D2` unwalked | that one cell | every other `B3` cell |
| peer 2 | `B3·D1` unwalked in regions 3 **and** 4 | those two regions | regions 2, 5, 6 |
| peer 3 | region 5 collapsed with no `B × D` walk — *"the driver even named region 4 as `A4`'s twin and walked one, not the other"* | — | — |

🔴 **the cause i wrote down in round 2 was already general**: *"`B3` composes with `D1` as well as
`D2`."* that sentence names **no region**. i applied it to the two regions the reviewer had
pointed at, which is the pattern trap verbatim — a sweep bounded by the instance rather than by
its stated cause (`rule.require.sweep-the-defect-class`). ⇒ **a per-region walk is the wrong
artifact**, because it can always be short one region. so the matrix is stated **once**, generally,
and each region instantiates it.

### the general matrix

post-merge `B ∈ {B1/2, B3}` × `D ∈ {D1, D2}`, for any `A`:

| | `D1` happy | `D2` sharp |
|---|---|---|
| **`B1`** new | reads the new field, first time. **demoed by `case=1`** (`headers`) / **`case=2`** (envelope) | live **only where a version-visible hazard exists** — see the `D2` rule below |
| **`B2`** in-repo | ⇒ **≡ `B1·D1`.** the `B1`=`B2` merge, which this wish claims and the catalog shows on both sides | ⇒ **≡ `B3·D2`.** after a clean break the compile error is identical wherever the stale name came from |
| **`B3`** migrator | ⇒ **the fixed read** — literally `case=3` `[t1]`. this is where all **78** measured production sites land | holds a stale `rawEvent.X`. **demoed by `case=3`** |

### the two rules that make every region derivable

🔴 **the `D2` rule.** after a clean break, **every** stale `rawEvent.X` is the *same* experience:
one compile error, one fix, `rawEvent.X` → `event.X` — with `rawEvent.headers` → `headers` the
single exception, because that field is lifted to a peer slot. ⇒ so a region's `D2` column is
never a new experience; it is `case=3` **at a different field**, and what a region owes is the
**field and its fix**, never a fresh demo.

🔴 **the `B1·D2` rule.** a new author holds no stale name, so their sharp path exists **only where
the sdk leaves a version difference visible**:

| region | is `B1·D2` live? | why |
|---|---|---|
| `A1` body | ⛔ **empty by nature** | a body-only handler names no envelope field at all |
| `A2` headers | ✅ **live** → cell 11 | ⛔ ~~headers pass through **verbatim** — no reconcile, so key-case can differ~~ 🔴 **the reason changed, not the verdict (F08).** the keys are now **lowercased**, so the versions cannot differ — and a capital-key read misses on **both**, which is a sharp path a new author can still walk. deterministic rather than version-dependent |
| `A3` method / path | ⛔ **empty by nature** | `asUnifiedApiGatewayEvent` **reconciles** `httpMethod` across versions |
| `A4` deep envelope | ⛔ **empty by nature** | same reconcile, same argument as `A3` |
| `A5` `_.raw` | ✅ **live, and type-guarded** → cell 8 | `_.raw` is the v1\|v2 **union** by design, so the compiler forces the discrimination. sharp, never silent |

⇒ these two rules are what a later reader should carry, because they settle a **new** region
without another review round. the per-region instantiations follow.
