# case=8 — the boundary flips the stance

> cell **S1** · sharp · **critipath** · actor: migrant + native · density 4
> D5 = `serialized` · D2 = `constraint-error`

## the narrative

**nia** has two suites for the same endpoint.

`getServiceBySlug.integration.test.ts` runs it **on the referenced boundary** — she holds the
handler, so she asserts on a returned envelope:

```ts
const res = await runLambdaEndpoint.onReferenced({ event: { slug: 'bad' }, handler });
expect(asLambdaEndpointErrorEnvelope(res).error.class).toEqual('ConstraintError');
```

`getServiceBySlug.acceptance.test.ts` runs the **same endpoint, same bad input**, on the
**serialized boundary** — and she writes the same assertion, because why would it differ.

it fails. `res` is never assigned. the call **threw**.

she checks whether she broke the handler. she has not: the referenced suite is still green. **the
same endpoint, the same event, two boundaries, two opposite outcomes** — and both are correct.

then it lands. **on the serialized boundary she is not the host — she is a caller.** she addressed
the endpoint by slug, over a wire. a caller does not receive a lambda's internal envelope; a caller
receives a hydrated error, because that is what the wire delivers to every other caller in
production. `getParsedResponse.ts:52-108` does that conversion, and it is not a convenience for a
test — it is the real caller path.

> **the boundary you cross decides which side of the contract you stand on.**

on the referenced boundary she asks *"what did my handler do?"* — and gets the envelope it
returned. on the serialized boundary she asks *"what would my caller see?"* — and gets the throw
they would see. neither is more true. they answer different questions, and the **name of the
subdomain is which question she asked**.

⚠️ and the incumbent already knew this. `invokeLambdaForTestingLocally.ts:99` converts the returned
envelope into a thrown `LambdaInvocationError` — **on the local locus**, where no network exists at
all. its own comment at `:78` says why: *"make the response look like what aws-lambda would
return"*. so the conversion never followed the network; it followed **how the endpoint was
addressed**.

## the bdd

```
given a genLambdaEndpoint handler that rejects a bad slug with a ConstraintError

when [t0] it is run on the referenced boundary with a bad event
  then the call RESOLVES to an error envelope
  and the envelope's error.class is 'ConstraintError'    ← contemp, the default

when [t1] the SAME handler is run on the serialized boundary with the SAME event
  then the call REJECTS with a thrown ConstraintError
  and the thrown error carries the same message the envelope carried

when [t2] the boundary is serialized and at: 'local'
  then it REJECTS — identically to at: 'cloud'
  and the locus does not change the stance

when [t3] a malfunction is run on the serialized boundary
  then it REJECTS — as it does on the referenced boundary
  and only the constraint family differs between the two boundaries
```

`[t2]` is the load-bearer: it pins that the stance follows the **boundary**, never the locus. a
util that threw only over the real network would pass `[t0]`, `[t1]`, and `[t3]` and still be
wrong — and it would be wrong in the direction that makes a local acceptance run disagree with a
cloud one about the same handler.

`[t3]` guards the other over-correction: not every outcome flips. only the constraint family does,
because only the constraint family returns in the first place
(`genConstraintErrorMiddleware.ts:72` vs `genInternalServiceErrorMiddleware.ts:62`).

## the boundaries this walk crosses

1. **the run boundary** — referenced vs serialized (D5)
2. **the error stance** — returned envelope vs thrown error
3. **the locus sub-axis** — `.local` vs `.cloud`, proven inert for the contract
4. **the outcome family** — constraint flips, malfunction does not

**density 4.** it is the densest cell of the serialized half, and it is the one experience that
makes the two subdomains legible as two rather than as one with a flag.

## why this is a critipath

**every acceptance suite that asserts a rejection meets it.** the serialized surface is 24 repos /
519 sites, and a rejection assertion is among the most common acts such a suite performs. an author
who carries a referenced-boundary habit into an acceptance test writes an assertion that reads fine
and never runs.

🔴 **this passage claimed the failure was *"silent in the worst direction"* — a `TypeError` on an
unassigned `res` — until self-review r6 of the execution stage. it contradicted this demo's own
narrative, eight lines up.**

the two cannot both be true:

| line | what it says |
|---|---|
| :21, the narrative | *"it fails. `res` is never assigned. the call **threw**."* |
| this passage, as written | the **assertion** throws a `TypeError` |

⇒ if the `await` rejects, the `expect` line **never executes**. there is no `TypeError`, because
control left the function one statement earlier.

### what actually happens, traced

nia's acceptance test fails **at the `await`**, with the endpoint's own hydrated `ConstraintError`
(`getParsedResponse.ts:52-108`) — message intact, metadata intact. that is a **loud, named** failure,
not a silent one.

⇒ **so this demo overstated its own danger, and the correction makes the design look better rather
than worse.** the real edge is narrower and still real: nia sees a thrown `ConstraintError` where
she expected a returned value, and her first instinct is *"my handler broke"* rather than *"my
boundary changed"*. the cost is a wrong first hypothesis, never an inscrutable stack.

⚠️ **the dialect generic does NOT catch this one, and that boundary is owed a statement.** the
generic types the *envelope shape* per dialect, which makes
`asLambdaEndpointErrorEnvelope(res).error.class` type-safe on the referenced boundary. it cannot
type away the fact that `onSerialized` **throws rather than returns** — a `Promise<T>` that rejects
is well-typed. so the stance flip stays a runtime lesson, and the two subdomain names are the only
place the author is warned before they hit it.

⚠️ **and this passage's referenced-boundary sample was itself un-compilable** — it read
`res.error.class` bare, which the union rejects. corrected to the narrow above, same round, same
cause as the contract-screen defect.

⇒ the mitigation is the **name**. `onReferenced` and `onSerialized` are two words, so the author
who writes the second one has already been told they changed stance. a `locally: true` boolean —
the incumbent's shape — hides that behind a locus word, which is precisely the misread this demo
exists to prevent.
