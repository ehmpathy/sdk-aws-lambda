# case=1 — an endpoint-native migrant deletes the dependency

> cell #1 · happy · **critipath** · actor: migrant.endpoint-native **+ native** · density 1
> **the wish's literal done-when** — the entry leaves `package.json` and the suite is green.
> ⚠️ **rewritten 2026-09-08.** this demo used to stop short: kai swapped his handler tests and
> could **not** delete the entry, because the acceptance tests held a peer import. the wisher put
> all three export families in scope (wish **A2**), so the narrative now reaches its end.

## .the narrative

kai is three days into the `declapract` upgrade on `svc-home-services`. its four public handlers
already went `createStandardHandler` → `genLambdaEndpoint`
(`getAllLeadCaptureForms.ts:24`, `getLeadCaptureFormByService.ts:29`, `getServiceBySlug.ts:29`,
`getServiceByUuid.ts:29`); that part landed last week. what nags him is `package.json`: the legacy
test package `@0.5.1` is still sat there in `devDependencies`, a survivor of a family the upgrade
was supposed to retire. he pulls it and watches **six** files light up red — **four**
`*.integration.test.ts` on the in-process import, and **two**
`blackbox/lambdas/*.acceptance.test.ts` on the over-the-wire one.

two imports, two boundaries. and `sdk-aws-lambda` now answers both.

his handler tests move first:

```ts
- import { invokeHandlerForTesting } from 'simple-lambda-testing-methods';
+ import { runLambdaEndpoint } from 'sdk-aws-lambda';

- const result = await invokeHandlerForTesting({ event, handler });
+ const result = await runLambdaEndpoint.onReferenced({ event, handler });
```

his acceptance tests follow, and they change more — they carried a locus boolean, and the
successor names the boundary instead:

```ts
- await invokeLambdaForTesting({ service, function: fn, stage: 'prep', event });
+ await runLambdaEndpoint.onSerialized({ which: { service, function: fn }, event, at: 'cloud' });
```

then his error assertions. **these do not survive**, and he was told they would not:

```ts
- expect(result.errorType).toEqual('BadRequestError');       // ancient, the old default
+ expect(asLambdaEndpointErrorEnvelope(result).error.class)
+   .toEqual('ConstraintError');                             // contemp, the new one
```

⚠️ **that rewrite is the deliberate cost of the contemp default (F3).** the compiler names every
site — the return is a `TOutput | Envelope` union, so **every** bare error-field read is an error,
whichever dialect he picks — and it is a mechanical pass, not a hunt. it buys him the modern error
contract on day one rather than a deprecation later.

🔴 **this sample read `result.error.class` bare, and this paragraph credited F9 for the compile
error, until self-review r6's second pass.** both were wrong in the same direction: the **union**
rejects the field first, and the **dialect** only decides which field is legal *after* the narrow.
⇒ the two-gate order gap 17 corrected in the spec was still taught backwards here.

he greps for the third family and finds not one call — his endpoints are all `forAskEndpoint`, where
the event **is** the payload, so he never had an envelope to construct. ⚠️ **measured, not assumed**:
`rhx git.repo.get lines --in ahbode/svc-home-services --words 'createExample'` → **0 matches**.

green. then he opens `package.json`, deletes the entry, and the suite stays green.

**the aha**: the old package's whole surface had a home in the sdk he already depends on. two
imports migrated, one boundary each; the third family he never used, and `asLambdaEvent` waits in
the same package for the day a service of his takes an sqs or api-gateway trigger.
**one dependency, not two.**

⚠️ **the third clause was *"waits in the same package"* with no grep behind it until i018**, which
let the aha claim the *whole* surface had a home while the narrative showed two families of three. a
reader could not tell whether kai's factory imports were migrated, absent, or overlooked. ⇒ **an
absence must be measured to be claimed** — otherwise a demo's strongest line rests on the one fact
it never checked.

⚠️ **what this demo does NOT claim**: that it was free. kai rewrote his error assertions. the
wisher withdrew *"every handler test still passes"* precisely so this demo could be honest about
that — the migration is a **guided rewrite**, and the guide is the type checker.

## .the bdd sketch

```
given [case1] a repo whose handlers all use genLambdaEndpoint,
      and whose handler tests import the legacy util

  when [t0] the author replaces the in-process import with runLambdaEndpoint.onReferenced
    then the call site's input shape is unchanged — { event, handler }
    then the returned value is the handler's validated output — not a wrapper around it

  when [t1] the author replaces the over-the-wire import with runLambdaEndpoint.onSerialized
    then { service, function, stage, locally } maps onto { which, at }
    then no capability of the incumbent is lost in the map

  when [t2] the author's ancient-dialect error assertions are compiled against the new default
    then each one FAILS TO COMPILE — the dialect is in the return type
    then the failure names the site, so the rewrite is mechanical

  when [t3] the author greps the WHOLE repo for 'simple-lambda'
    then there is not one match — including a type-only import

  when [t4] the author removes the legacy package from package.json
    then no module-not-found error is raised anywhere in the suite
    then the full suite is green
```

## 🔴 the sketch was rewritten at 2026-09-08, twice over

**first at r5**, when `[t1]`–`[t3]` were narrowed: the originals claimed the package could be
removed after the handler-test swap alone, and this case's own exemplar repo falsified that —
`svc-home-services` imports the legacy package from **two** places, and the acceptance import
survived.

**then again when the wisher put all three families in scope (wish A2).** the narrowed version is
now too narrow: `[t4]` can assert the removal outright, because `onSerialized` covers the second
import.

⚠️ **`[t2]` is new, and it is the clause that keeps this demo honest.** it asserts a **compile
failure** — the contemp default (F3) breaks ancient-dialect assertions on purpose. a demo that
omitted it would let a reader infer the swap is free, which is the same overstatement the r5
narrowing was written to remove, pointed the other way.

⚠️ **and the directory name varies** — `blackbox/lambdas/` here, `acceptance/lambdas/` in
`svc-work`. any check for this must key on the **import**, never on a folder path.

**what the sketch tests that the narrative does not**: `[t3]`. the narrative ends when the tests go
green, which *feels* like done. but green tests with a leftover import would still fall short — the
goal is for the import to be **gone**, and a stray type-only import **anywhere in the repo** would
keep it alive while every test still passed. `[t3]` is the assertion the felt story misses.

⚠️ **that clause read *"in a twelfth file"* until i009 — a residual of the abandoned first draft.**
kai's repo (`svc-home-services`) holds **six** test files: four handler `*.integration.test.ts` and
two `blackbox/lambdas/*.acceptance.test.ts`. there is no twelfth. the count came from the discarded
`svc-notifications` scene, and it is the same class of leftover as the *"ninth test file"* corrected
at i004. ⇒ **the fix is to drop the count, not to correct it** — `[t2]` is a repo-wide grep
assertion, so a number was never what it needed.

## .why it is a critipath

**it is the wish's done-when, walked end to end.** if the three families do not together cover the
incumbent's surface, the legacy package survives the wave in every repo — which is the exact
outcome the wish exists to end. there is no workable fallback.

⚠️ **its critipath argument CHANGED on 2026-09-08, and the change is worth a note.** it used to
rest on *"if the swap is not one-line-equivalent, the wish fails at its own bar"* — an argument
about **migration cost**. the wisher withdrew that bar, so the demo's weight moved from *"the swap
is cheap"* to *"the coverage is complete"*. ⇒ **a demo can keep its cell and its critipath grade
while its reason changes entirely.** the reason is what a reader acts on, so it is the part that
must stay current.

## .the boundary it exercises

**the import seam** — the handoff where the incumbent's call shapes must line up with the
successors'. this is the only boundary in the demo, hence density 1. its low density is not low
importance; it is a narrow, load-bearing joint.

## .the scope this case does NOT cover

kai is the **endpoint-native** migrant: his handlers are already `genLambdaEndpoint`. measured
adoption says he is **1 repo of 20**. the other 19 hold `createStandardHandler` handlers and
**314 of the 318** legacy call sites — a different actor with a different boundary, demoed
separately as [case=7](1.vision.experience.case=7.the-legacy-handler-migrant-crosses-families.md).
