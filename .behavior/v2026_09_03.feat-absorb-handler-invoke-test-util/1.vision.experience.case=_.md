## .the collapse, stated first

**three** axes collapse across parts of the grid, and each collapse is itself a discovery — **but
they collapse over different scopes, and the scope is the part that kept getting mis-stated**:

| axis | collapses over | declared at |
|---|---|---|
| **D1** (actor) | mechanics, everywhere — never care | r2 |
| **D4** (fidelity) | `malfunction`, `introspect.granted`, `introspect.denied` | i002 |
| **D3** (frame) | `malfunction`, `introspect.granted` — **not** `introspect.denied` | i005, scope corrected at i009 |

- **D1 (actor)** does not change the *mechanics* of any cell — each migrant, the native, and the
  maintainer invoke the same function and get the same value back. it changes only which cells they
  *care* about. so the grid below is presented as **D2-state × D3 × D4 — 14 rows covering the 20
  cells each actor faces** (rows 1–8 carry D4 explicitly; rows 9–14 mark it `n/a` and cover two
  cells apiece). with the actor named per row as the one who owns that encounter, **all 80 are
  accounted for**, and the collapse is declared rather than silent — with **two regions barred by
  nature**, named just below.

  🔴 **one sub-column is barred by nature: `migrant.legacy-handler` × `wrapped` — found at peer
  review, and it is a real forbidden region the first walk missed.** the wrapped frame is a
  `genLambdaEndpoint` concept end to end: `trail` → `isContempCaller` → the contemp error dialect,
  produced by `genTrailMiddleware` and consumed by `genConstraintErrorMiddleware`. **the legacy
  family has no such switch** — `rhx git.repo.get lines --in ehmpathy/simple-lambda-handlers --words
  'isContempCaller'` returns **0 matches**, while it appears in **7 files** of this sdk.

  ⇒ so a `{ event, trail }` wrapper handed to a `createStandardHandler` handler is not a *frame*, it
  is a malformed **event** — its own zod schema rejects the extra `trail` key. the cell is
  **inapplicable rather than untested**, which is why cell #18 scopes itself `any × flat`.

  **this is a genuine D1 × D3 dependency**, and the *"each row is walked for all 4 actors"* claim
  overstated it. corrected: the rows are walked for all 4 actors **except the 10 wrapped-frame cells
  under `migrant.legacy-handler`, which are n/a-by-nature**. the region is barred by the handler
  family's own contract, so no experience hides there — but the bar is declared rather than implied.

  🔴 **and a SECOND region is barred, declared at i009: `migrant.legacy-handler` × `introspect`.**
  the legacy family has no introspection at all — `rhx git.repo.get lines --in
  ehmpathy/simple-lambda-handlers --words 'introspect'` returns **0 matches**. so neither
  `introspect.granted` nor `introspect.denied` exists for nia; an `{ introspect: 'schema' }` payload
  handed to her handler is simply an event her zod schema rejects. **a D1 × D2 dependency**, the same
  shape as the D1 × D3 one above and found by the same question: *does this actor's family even have
  the machinery this axis value names?*

  🔴 **the collapse is on MECHANICS; care is NOT collapsed — clarified at peer review.** under
  `define.experience`, care is a native coordinate of an experience, so the 80 cells genuinely
  *differ* in care across actors even where their mechanics coincide. **the `care` column below
  records the OWNER's care** — the actor for whom that cell is sharpest — never a care shared by all
  four. nia meets row 7 constantly; maya never does; the row lists nia's.
  ⇒ so the collapse is a legitimate presentation of 80 cells as 14 grid rows **plus an owner
  projection**, rather than a claim that actor is inert. read the `care` column as *"sharpest for
  whom, and how much"*.

  ⚠️ **the collapse holds for `migrant.legacy-handler` too — and the reason was sharpened mid-r2.**
  the util applies **no** error predicate: it strips, awaits, and relays whatever the handler's own
  middleware decided. so the actor's handler family cannot change the util's behavior, which is
  what makes the grid rows genuinely **subsumed** rather than assumed to be.

  🔴 **and the weaker reason i first wrote was wrong.** i claimed the two families *"split on the
  same predicate"*. they do not — `getIsConstraintError` (`:11-34`) is a strict **superset** of the
  legacy `decideIsBadRequestError`: both catch `BadRequestError`, but only the endpoint one catches
  **`ConstraintError`**, which the legacy handler *throws*. the families genuinely diverge there.
  the collapse survives because it never depended on their agreement — only on the util's silence.
  cell **#18** carries the residual claim that matters to the actor (her assertions survive on the
  `BadRequestError` path her handlers actually speak).
- **D4 (fidelity)** is inert for `malfunction` and `introspect` — a thrown error and a schema dump
  do not vary by whether the input carried a `Date`. those cells are marked accordingly.
- **D3 (frame)** is inert for `malfunction` and **`introspect.granted` only** — never for
  `introspect.denied`. `isContempCaller` is read solely by `genConstraintErrorMiddleware`
  (`:44-45`), and introspection runs *after* the trail middleware has absorbed the frame
  (`genTrailMiddleware.ts:45`; order 2 → 4). rows **#10** and **#12** say as much
  (*"identical to #9"*, *"as #11"*), **and row #14 says the opposite for the denied half**
  (*"as #13, contemp-shaped"*) — because that path throws a `ConstraintError`
  (`genIntrospectionMiddleware.ts:50`) which the dialect switch then shapes. the count agrees with
  all three rows.

  ⚠️ **this bullet read *"inert for those same two outcomes"* until i010** — the pre-i009 wording,
  left alive a few lines from its own correction at the top of this file. and its evidence list cited
  #10 and #12 while it omitted #14: **the same partial-footnote read the i009 lesson names**, still
  in the artifact that names it. ⇒ that is why the durable form is *"enumerate every footnote and
  mark each supports / refutes"* rather than *"read the footnotes"*.

## .the forbidden cell — an invariant AND a demoed critipath

> ⚠️ **re-graded at self-review r1.** i first filed this as "forbidden — an invariant" with no
> demo, as if an invariant were a thing you declare rather than a path a maintainer lives through.
> by `freq × cost` it is a **sharp critipath**, so the absent demo was a blocker. now demoed as

>
> the mis-grade was in the **frequency** term: i read it as the shoe-tie-at-75mph case (∞ cost,
> zero frequency → not critical). but frequency here is **high** — the repo already holds two
> violators, and F6's promotion requires a split of a file that exports both a portable and a
> jest-bound symbol. the obvious implementation commits the violation.

**#15 — the shipped util must not import jest.**

`jest` is devDependency-only (`package.json:80-115`). a consumer installs `sdk-aws-lambda` without
it. so any shipped module that imports a jest global fails at require-time in the consumer's
process.

the actor *can* attempt this — it is a one-line import away, and two in-repo assets already do it:

- `createTestContext.ts:27` — `createMockLog` calls `jest.fn()`
- `createInProcessLambdaHarness.ts:112` — types on `jest.Mock`

⇒ **the invariant**: the util, and each module it transitively imports, is jest-free. the pure half
of `createTestContext` is portable; `createMockLog` is not and must not travel with it. this is a
nurture-forbidden path — attemptable, and the behavior must reject it (a build-time or lint-time
guard, not a runtime one).
