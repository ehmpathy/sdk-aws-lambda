# 1.vision.yield — sdk-aws-lambda owns the way you TEST a genLambdaEndpoint handler

## .the contract, in one screen

**one operation, two subdomains — split on the RUN BOUNDARY**, the axis the wisher declared on
2026-09-08 and briefed at `define.lambda-endpoint-run-boundary`:

```ts
import { runLambdaEndpoint } from 'sdk-aws-lambda';

// ── onReferenced — you hold the handler; shapes cross by reference ──
// success — the handler's validated output, json-stripped.
// the return is a UNION, so a field read needs a narrow HERE TOO — the success
// arm is not privileged. `asLambdaEndpointOutput` is the success-side narrow,
// and it needs no dialect declared (Exclude leaves the output type inferred).
const out = await runLambdaEndpoint.onReferenced({ event: { uuid }, handler });
expect(asLambdaEndpointOutput(out).found).toEqual(true);

// constraint rejection — an envelope, RETURNED (the lambda succeeded).
// the narrow is named PER DIALECT, and the two are not peers in their certainty:
// contemp reads the CODEC-VERSIONED tag, so it is exact (F22).
const res = await runLambdaEndpoint.onReferenced({ event: { uuid: 'bad' }, handler });
expect(asLambdaEndpointErrorEnvelopeContemp(res).error.class).toEqual('ConstraintError');

// the ancient dialect is opt-in — declared on the call, and again on the narrow.
// this one reads the flat SHAPE, because the ancient wire carries no tag to read.
const old = await runLambdaEndpoint.onReferenced({
  event: { uuid: 'bad' }, handler, struct: { payload: 'ancient' },
});
expect(asLambdaEndpointErrorEnvelopeAncient(old).errorType).toEqual('BadRequestError');

// malfunction — THROWN, untouched, on either dialect
await expect(
  runLambdaEndpoint.onReferenced({ event, handler: brokenHandler }),
).rejects.toThrow(MalfunctionError);

// ── onSerialized — you hold the slug; shapes cross as json ──
// a constraint error THROWS here — you are a caller, not the host
await expect(
  runLambdaEndpoint.onSerialized({
    which: { service: 'svc-home-services', function: 'getServiceBySlug' },
    event: { slug: 'bad' },
    at: 'cloud',      // or 'local' — look the handler up in serverless.yml, simulate the wire
  }),
).rejects.toThrow(ConstraintError);   // both dialects hydrate to this (getParsedResponse.ts:59,92)
```

⚠️ **the two error lines read `res.error.class` and `old.errorType`, with no narrow, until
self-review r6 of the execution stage.** a type-gate probe of this very screen returned:

```
error TS2339: Property 'error' does not exist on type
              'LambdaEndpointRunOutput<{ uuid: string; }, "contemp">'.
error TS2339: Property 'errorType' does not exist on type
              'LambdaEndpointRunOutput<{ uuid: string; }, "ancient">'.
```

⇒ **F9 makes the envelope shape KNOWN; it does not make it READABLE.** the return is a union
because a caller fault is a legitimate answer, and typescript refuses a field that is not on every
arm. the vision promised direct access and the implementation cannot supply it — so the util grew
one operation the vision never named, and F9's own bounds table had already flagged the risk as
*"the success-vs-error narrow"*.

🔴 **the deviation is the vision's, not the junior's** — the shipped api is the correct one, and
this screen was the spec that was wrong. it is corrected in place rather than defended, because a
contract screen is the first artifact a migrant reads.

## 🔴 the envelope STAMPS ITS CODEC — ruled by the wisher, 2026-09-13 (**F22**)

> *"we should always say the codec (encode, decode) version ; i.e., `sdk-aws-lambda@vxyz` … version
> must be included at the least. contemp has version; ancient does not."*

```ts
_serde: 'LambdaEndpointError::contemp@0.4.0'   // was: 'LambdaEndpointError::contemp'
```

⇒ **this answers the F19/F20 council**, and it does so with a move neither row had priced. both rows
asked *may a classification rest on a declaration or a shape, where an authoritative signal exists or
could?* — and every branch on the board took the absent signal as a given. **the verdict makes the
signal exist.**

| the dialect | what the narrow reads | certainty |
|---|---|---|
| **contemp** | the codec-versioned tag | ✅ **exact.** we write every contemp envelope, so no tag means we did not write this |
| **ancient** | the flat `{ errorMessage, errorType }` pair | 🔴 a heuristic — and inherently so; the ancient wire has no tag to stamp |

🔴 **and it closes a live failhide.** the old guard read the ancient shape even under a contemp
declaration (`isLambdaEndpointErrorEnvelope.ts:69`), so a contemp caller who met an ancient value was
narrowed to a type the value lacks and read `.error.message` as **`undefined`, with no throw**. under
*"no tag → not a contemp envelope"* the guard returns false and the assert throws a `ConstraintError`.

⇒ so the rule is **better on the mismatch**, not merely simpler.

⚠️ **two bounds the blueprint must honor, and the first is a wire break if it is missed:**

1. **the detector matches the PREFIX; the version is data.** a tag compared by equality stops to
   recognize an envelope from any other release — and `LAMBDA_ENDPOINT_ERROR_SERDE_CONTEMP`'s own
   docblock already warns that such a disagreement *"does not fail loudly; the detector simply stops
   to recognize the envelope, and a caller fault reads as a success payload."*
2. **`sdk-environment`'s `commit` is the SERVICE's, not the CODEC's.** the directive offers it as
   *"even better"*, and it answers a different question — `getEnvironment()` resolves against the
   process that executes, so it stamps `svc-x@a1b2c3d` rather than `sdk-aws-lambda@0.4.0`. it is a
   complement (debug provenance), never a substitute for the version a decoder branches on.
   ✅ verified: `sdk-environment@0.1.5` is already a direct dependency **and is latest**, so no
   upgrade is owed.

⚠️ **and the first correction of this screen fixed only the ERROR half, which is a second deviation
of the same kind.** the narrow was added to the two rejection lines and the success line above them
was left bare, because the defect had been framed as *"error fields need a narrow"* rather than as
*"the union refuses a read."* probed one pass later:

```
error TS2339: Property 'scheduledAt' does not exist on type
              'LambdaEndpointRunOutput<{ scheduledAt: string; }, "contemp">'.
  Property 'scheduledAt' does not exist on type 'LambdaEndpointErrorResponseBodyContemp'.
```

⇒ **the success arm is not privileged, and it is the MAJORITY case** — most assertions read the
handler's own output. so the shipped api was short a narrow entirely, and `asLambdaEndpointOutput`
was added in that round.

🔴 **it went unseen for a structural reason worth a note: every test in this repo asserts with a
whole-object `toEqual({ … })`, which takes `unknown`.** so no field read is exercised anywhere, and
**601 green tests could not have caught it, by construction.** a real consumer reaches for
`res.field` on the first try. ⇒ **a suite can be exhaustive on behavior and blind to ergonomics**,
and only a sample run through the type gate closes that gap.

and the third family — the **event source**, briefed at `define.lambda-event-source`:

```ts
import { asLambdaEvent } from 'sdk-aws-lambda';

const event = asLambdaEvent.fromSqs({ messages: [JSON.stringify(task)] });
const event = asLambdaEvent.fromApiGateway({ body, httpMethod: 'POST' });
//            asLambdaEvent.from$Source(…)   ← the template
```

`as` because it is a **cast**, never a construction — a payload cast into an envelope shape, so
the transformer prefix applies (`rule.require.get-set-gen-verbs`). `from` because it names
**provenance**: the event arrives *from* sqs. ⚠️ `for` would invert the arrow, and `$Slug` is
taken — a slug is the endpoint's serialized key, so `from$Slug` would read as *"from the endpoint
slug"*.

🔴 **the boundary determines the error stance — that is the whole reason for the split.** address
the endpoint by **slug** and you are a *caller*, so a constraint error throws. hold the **handler**
and you are the *host*, so it returns. `at` is a sub-option of `onSerialized` only, and its two
values do **not** change that contract (`invokeLambdaForTestingLocally.ts:99` converts the envelope
to a throw on the **local** locus).

⚠️ **`referenced × cloud` is barred by nature — a function reference cannot cross a process — and
the bar is unrepresentable rather than policed.** `onReferenced` takes no `at` parameter, so the
impossible cell cannot be written (`rule.prefer.prevent-over-correct`, rung 1).

⚠️ **the `{ event, handler }` single-object shape is not a preference — it is measured.** the
legacy util takes exactly that shape, verified across 20 repos (see groundwork). a two-positional
signature would break the one-line swap that is this wish's done-when, and would also violate
`rule.require.input-context-pattern`. the faithful shape and the rule-compliant shape are the same
shape.

three properties of `onReferenced`, and they are the whole design:

1. **pass-through** — return what the handler returns; throw what the handler throws
2. **wire-faithful, in BOTH directions** — the event is JSON-stripped before it enters the handler,
   **and the output is JSON-stripped before it reaches the author**. the strip is a **fidelity
   guard**, never the boundary itself — it keeps a referenced-boundary test from a pass the
   serialized boundary would fail
3. **jest-free** — no module in the shipped path imports a test runner

## 🔴 the wish's contract omits half the strip — found at self-review r3

the wish states the strip requirement in one direction only:

> *"invoke a `genLambdaEndpoint` handler in-process with a plain `event`, **JSON-stripped the way
> the wire strips it** — the legacy util does `JSON.parse(JSON.stringify(event))`"*

**the legacy util strips the output too**, and the source now reads directly
(`ehmpathy/simple-lambda-testing-methods`, `src/invokeHandlerForTesting/invokeHandlerForTesting.ts`):

```ts
// :8   — inbound
const stripInvocationEvent  = (event: any)  => JSON.parse(JSON.stringify(event));
// :15-16 — outbound, which the wish never mentions
const stripInvocationOutput = (output: any) =>
  output === undefined ? undefined : JSON.parse(JSON.stringify(output));
// :36 applied to the callback result · :40 applied to the promise result
```

**why the omission would have broken the wish's own done-when.** aws serializes the *response* as
JSON too, so the round trip is lossy in both directions. a handler that returns a `Date`:

| | legacy util | an input-only-strip util |
|---|---|---|
| what the test receives | `'2026-09-03T14:00:00.000Z'` (string) | a live `Date` instance |
| `expect(res.createdAt).toEqual('2026-09-03T…')` | ✅ passes | ❌ **fails** |

so an input-only strip fails *"every handler test still passes"* for any test that asserts on a
wire-hostile output — and it re-opens the fidelity hole the strip exists to close, just pointed the
other way: a test could assert on an output shape the wire could never deliver.

⇒ **the contract is now two-directional.** this is the wish's own principle applied consistently;
the wish stated one half of it. see **Q9**.

## 🔴 .the wish's contract is half right — and the correct half wins

the wish states, in red:

> **`genLambdaEndpoint` does NOT throw on a domain error in-process.**

**this holds for the constraint family only.** verified in the code and in the repo's own committed
suite:

| error family | in-process | citation |
|---|---|---|
| `ConstraintError` / `BadRequestError` | **returns an envelope** | `genConstraintErrorMiddleware.ts:72` · test `…forAskEndpoint.test.ts:61-81` |
| each other error | **throws** | `genInternalServiceErrorMiddleware.ts:62` · test `…forAskEndpoint.test.ts:103-121` |

the two middlewares split on the same predicate and do opposite things with their halves.

**the vision follows the wish's *reason*, not its *sentence*.** the wish forbids a re-throw so that
"the two paths [do not] disagree about the same handler". a never-throw util would create that very
disagreement in the other direction — it would report as a value what the real handler raises. so
the util is a **pass-through**, which is what "stay faithful to what the handler actually returns"
means once the premise is corrected. it also keeps the util clear of `rule.forbid.failhide`: a
never-throw needs a `catch` that swallows a server fault.

⇒ **the wish's contract section needs an amendment.** see open question **Q1**. full reasoning:
[F1](.fulcrums/inventory.of=fulcrums.case=F1-faithful-passthrough-not-never-throw.md).

### before

`package.json` still carries the legacy test package, because its tests import from it and no
production file does. a retired family stays alive — in every repo the wave touches.

**the blast radius is measured, not guessed**: `rhx git.repo.get lines --repos 'ahbode/*' --words

every argument the vision builds on this number gets *stronger* with a larger population, so the
floor suffices — but it is a floor, and it is stated as one.

### the aha

it lands twice, and the second one is the real one:

1. **the shallow aha** — the swap is a find-and-replace, not a rewrite ([case=1](1.vision.experience.case=1.migrant-swaps-the-import.md)).
2. **the deep aha** — the in-process path and the wire path *genuinely disagree* about the same
   handler, and both are right ([case=2](1.vision.experience.case=2.constraint-error-returns-an-envelope.md)).
   a constraint error is a **returned envelope** to the handler and a **thrown `ConstraintError`**
   to the caller, because a caller's bad request is not a lambda failure
   (`invariant.badrequesterror-not-lambda-error`). the util is a handler-side instrument, so it
   shows the handler's truth. once that clicks, the whole error model clicks with it.

## .mental model

> **"it is `askLambdaEndpoint`, minus the network."**

that one line carries the whole model — and, usefully, it also carries the model's one lie, which
is the thing worth teaching.

| they say | we say | note |
|---|---|---|
| "call my handler directly" | in-process invoke | |
| "the fake lambda context" | `Partial<Context>` override | |
| "the error blob" | the error **envelope** | ancient or contemp dialect |
| "it acts like a real invoke" | wire-faithful **payload**, not wire-faithful **errors** | the lie ⚠️ |

**the lie is load-bearing.** "minus the network" implies *only* the network is subtracted — but the
network is also where envelope→throw conversion happens (`getParsedResponse.ts:52-108`). so the
in-process path is `askLambdaEndpoint` minus the network **and minus the error hydration**. every
confusion in [case=2](1.vision.experience.case=2.constraint-error-returns-an-envelope.md) and
[case=5](1.vision.experience.case=5.the-frame-flips-the-envelope.md) traces to that gap. the docs
should state it rather than let each repo rediscover it.

the better analogy, if a longer one is allowed: **a wind tunnel, not a test flight.** the air is
real and the physics are real; the airframe is bolted down. you learn true things about the wing.
you do not learn what the landing gear does.

### pros

- **the two-package seam closes.** one import for define + exercise.
- **the implementation is tiny and cannot drift.** strip → context → await → return. it makes no
  claim about `genLambdaEndpoint`'s error taxonomy, so it cannot fall out of sync with it.
- **it is a promotion, not an invention.** the shape already exists at
  `invokeHandlerForTest.ts:9-18`; the work is relocation + the strip + the reader.
- **it removes a cast the sdk itself pays.** three `as unknown as { errorMessage: string }` casts in
  one test file (`…forAskEndpoint.test.ts:83-87`, `:299-303`, `:333-337`).

### cons

- **it publishes a test util from the production barrel** (F4). jest-free, but a purist wants a
  subpath — which costs an `exports` map and a package-wide resolution change.

  🔴 **this line read "tree-shakeable and jest-free" until i004 r011, and the first word was
  false.** the build emits **CJS** (`tsconfig.json:19`), the package declares no `sideEffects`
  field, and a `require()` graph is opaque to esbuild/webpack DCE. ⇒ **no consumer tree-shakes this
  util out**, so the barrel choice costs every one of them `yaml`'s 670 KB rather than only those
  who use it.

  ⚠️ **the word was asserted, never measured, and it sat in the CONS section — the one place a
  reader looks to price the choice.** so the drive advertised a mitigation it did not have, in the
  paragraph whose whole job is to state the cost honestly. ⇒ **a con that understates itself is
  worse than an absent con**, because it reads as a cost already weighed. see F4.
- **it makes the ancient/contemp split a public concern.** today a handler author can ignore the
  dialect; the util puts it in their assertions.
- **it does not close the loop by itself.** the `declapract` fixer that rewrites the imports lives
  in another repo and is explicitly out of scope. until it ships, adoption is manual.

### edge cases, and how the design keeps the author in a pit of success

| edge | the guard |
|---|---|
| author expects a throw for a constraint error | the return type admits the envelope union → compile error, not a silent pass |
| author switches dialect and their error assertions break | the dialect is a **generic** (F9) → a cross-dialect field access does not compile |
| author crosses to `onSerialized` and expects a returned envelope | ⚠️ **the type does NOT catch this** — a rejected `Promise<T>` is well-typed. the two subdomain names are the only cue; [case=8](1.vision.experience.case=8.the-boundary-flips-the-stance.md) demos it |
| author passes a `Date` | stripped first; zod names the field |
| author's `event` object mutated by the strip | the strip copies; `[t3]` of case=4 guards it |
| a contributor adds a `catch` later | `[t3]` of case=3 asserts the absent `catch` structurally |
| the shipped util imports jest | forbidden-cell invariant; a build/lint guard, since a runtime failure would land in the consumer |

## .what is awkward

four, in descending order of discomfort. i am papering over none of them.

### 1. the frame silently rewrites the error dialect

the sharpest thing in this wish, and it has no mention in the wish text. an author who adds a trail
for **trail coverage** finds their **error assertions** rewritten
([case=5](1.vision.experience.case=5.the-frame-flips-the-envelope.md)). the coupling is real,
deliberate, and load-bearing — `invariant.ancient-vs-contemp-callers` exists so ancient callers keep
receipt of `BadRequestError`.

but it fights the author's mental model hard. they think they said "also record a trail"; they
actually said "i am a different kind of caller."

**the dialect generic (F9) makes the surprise LOUD — it does not make it go away.** priya's stale
`res.errorType` becomes a compile error rather than a silent `undefined`, which is rung 1 rather
than rung 4. what no type can do is make the coupling *feel* right: she still asked for a trail and
got an error-shape change.

⚠️ **and F9 leaves a live implementation question behind it — one knob too many.** the frame is
driven by the author's `trail:` input; the dialect is declared by `struct.payload`. **two knobs, one
fact**, so they can be set to disagree — `{ trail, struct: { payload: 'ancient' } }` asks for a
contemp frame and an ancient type. either the util derives `struct` from the frame (one knob, and
the generic loses its explicitness) or it refuses the mismatch at the type level. **the blueprint
must pick; the vision does not.**

⇒ **it is design debt in `genLambdaEndpoint`, not in this util** — the util merely exposes it — and
it is the fourth follow-up below. worth a separate look after this wish lands.

### 2. the JSON-strip is a silent mutation of the author's input

case=4 argues, correctly, that the strip is safer than its absence. that argument is sound and
still leaves a residue: the strip **silently** drops data. priya noticed because her schema was
strict. an author with `z.any()` or a passthrough field gets a quiet difference between the object
they wrote and the one the handler saw, with no signal at all.

the latent question the decomposition surfaced — **who owns the strip?** — reads as open, and at r5
it was triaged: **it is [answered], and what remains is discomfort rather than a fork.**

- **the util owns the strip — the wish directs it**, not a best-guess of mine: *"invoke a handler

### 4. the two families' error envelopes differ, and the handler migration will bill for it

**found at i007, by a field-by-field read the drive had never done.** the ancient envelopes are not
the same shape:

| field | legacy `createStandardHandler` | `genLambdaEndpoint` ancient |
|---|---|---|
| `errorMessage`, `errorType` | ✅ | ✅ |
| `stackTrace` | ✅ always | ❌ **absent** |
| `causeTrace?` | ✅ when `cause` is an `Error` | ❌ absent |
| `details?` | ❌ absent | ✅ when the error carries `metadata` |

citations: `badRequestErrorMiddleware.ts:93-103` · `getErrorResponseBody.ts:50-63`.

⚠️ **this does NOT touch this wish's swap** — the util relays, so a legacy handler returns its legacy
envelope before and after. it bills later: **any test that asserts `stackTrace` or `causeTrace`
breaks on the day its handler moves to `genLambdaEndpoint`.** that is a cost of the *handler*
migration (→ **Q10**), previously unpriced because the vision had asserted the envelopes matched
rather than compared them.

⇒ it is filed as awkward rather than as a defect because **the fix is not obviously to add the
fields** — `stackTrace` over a wire boundary is arguably the legacy design's mistake, and the
endpoint's `details` is a genuine improvement. the wisher should decide whether the endpoint adopts
the legacy fields for compat or the migration accepts the break.

### and a smaller one — the sdk will not eat its own dogfood at first

because they need jest. so the sdk keeps a private test-asset folder *and* ships a public test util,
and a contributor must know which belongs where. the line is principled (jest-free ships;
jest-bound stays) but it is a line someone will cross by accident. worth a lint guard rather than a
comment.
