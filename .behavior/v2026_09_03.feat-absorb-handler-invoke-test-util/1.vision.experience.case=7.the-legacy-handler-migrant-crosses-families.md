# case=7 — a legacy-handler migrant swaps the util with no handler migration

> cell #18 · happy · **critipath** · actor: migrant.legacy-handler · density 2
> ⚠️ **added at self-review r2.** **F7** (the util is handler-agnostic) was adopted at r1 and
> reframed the whole value story — but the experience decomposition was never rewalked against it.
> this actor is **19 of 20 repos** and **314 of 318 call sites**, and it had no cell, no verdict,
> and no demo. an absent critipath is a blocker.

## .why it was missed the first time

the dimensions were written **before** F7 and bound `migrant` to a repo whose handlers are already
`genLambdaEndpoint`. F7 removed that precondition and nobody rewalked the product, so the axis kept
a value the design had dropped. the care grade is not close:

| term | value | evidence |
|------|-------|----------|
| **frequency** | **the highest on the drive** | `genLambdaEndpoint` = 1 repo / 4 handlers. the legacy util = 20 repos / 318 sites. so **19 repos and 314 sites** are this actor, not case=1's |
| **cost** | **the wish's done-when, unreachable** | if the swap is not contract-identical, 19 repos cannot drop the legacy **handler-test import** until they finish a handler migration that has barely started |

`highest × high` → **critipath**. and it is the actor that decides whether this wish ships value to
20 repos or to 1.

## .the narrative

nia maintains `svc-notifications`. she has **10** handler integration test files, all on the legacy
util, and **12** handler files still on `createStandardHandler` — 24 call sites. the
`genLambdaEndpoint` migration is not on her quarter's roadmap.

she reads the release note for the new util and assumes it is not for her yet: the sdk is named for
the endpoint, the util is named for the endpoint, and her handlers are not endpoints. she is about
to close the tab.

then she reads one line: **the util takes a handler, not an endpoint.** it strips the event, builds
a context, awaits the function, returns what it returns. it never inspects what produced the
handler.

so she tries the swap on one file:

```ts
- import { invokeHandlerForTesting } from 'simple-lambda-testing-methods';
+ import { asLambdaEndpointErrorEnvelope, runLambdaEndpoint } from 'sdk-aws-lambda';

- const { errorMessage } = await invokeHandlerForTesting({ event, handler });
+ const res = await runLambdaEndpoint.onReferenced({
+   event,
+   handler,
+   struct: { payload: 'ancient' },   // ← her handler reads a FLAT payload
+ });
+ const { errorMessage } = asLambdaEndpointErrorEnvelope<'ancient'>(res);
```

her `createStandardHandler` handler, untouched. her assertion, **unchanged**:

```ts
expect(errorMessage).toContain('phone');
```

green. all ten files, green — and she touched not one handler. every handler test in the repo is off
the legacy import, with `createStandardHandler` still on every endpoint.

⚠️ **the assertion is unchanged; the line that FEEDS it is not.** the destructure moves onto a
narrow, because the return is a `TOutput | Envelope` union and typescript refuses a field that is
not on every arm. that is three edits per site, not one — see below.

**this is the most-met experience in the catalog** — 19 repos, 314 sites — and the narrative

🔴 **the second miss is the more instructive one, because it lives inside the REPAIR of the first.**
the r6 correction added the `struct` line, re-read the narrative, and left the line directly beneath

```ts
const { errorMessage } = await runLambdaEndpoint.onReferenced({ … });
//    ^^^^^^^^^^^^^^ — destructured off a UNION. probed: TS2339
```

⇒ probe output, verbatim:

```
error TS2339: Property 'errorMessage' does not exist on type

```

⚠️ **`struct: { payload: 'ancient' }` does not make the field readable.** it selects *which*
envelope the union's second arm holds; the union itself still refuses a field the first arm lacks.
that is the same **two-gate** order the spec had backwards at gap 17 — and I re-derived the wrong
half of it while I fixed the other.

### what actually happens, measured

`struct.payload` is one knob with **two** effects, and this demo reasoned about only the second:

| dialect | nia's handler RECEIVES | nia's handler ANSWERS |
|---|---|---|
| `contemp` (the default she would have got) | `{ event, trail }` | — |
| `ancient` (what she must declare) | the event, untouched | — |

`asFramedPayload.ts:51-55` wraps the event under the contemp default, and the legacy family never
unwraps it — a word search for `trail` across `ehmpathy/simple-lambda-handlers` returns **one**
match, and it is a biome config key. **zero trail code in the whole package.**

⇒ so nia's handler would read `event.customerId` off a `{ event, trail }` wrapper and find it
absent. clamped at `runLambdaEndpoint.onReferenced.test.ts` `[case7][t1]`:

```ts
expect(seen[0]).toEqual({ event: { uuid: UUID_GOOD }, trail: {} });  // what she receives
expect(result).toEqual({ uuid: null });                              // what her handler returns
```

### 🔴 how it survived — a failhide in a TEST TITLE

the clamp for this demo existed and was green. its `when` read **"[t0] the author swaps only the
import"**, and its body passed `struct: { payload: 'ancient' }` — a second change.

⇒ **the title asserted the demo's claim; the body quietly did what the claim denies.** a green
assertion, a false sentence, and no gate reads a sentence. the block is renamed to
*"the author declares the ancient dialect"*, and `[t1]` now clamps the true one-line swap.

### what SURVIVES, and it is the whole demo

**the aha is untouched.** nia still adopts today, with no handler migration, on all ten files. the
correction costs her **two added lines per call site**, not a migration — and a codemod writes both.

⚠️ **and the wisher already priced this.** wish **A1** withdrew *"every handler test still passes"* —
*"they don't need a one-line swap, that's not a concern."* so the three-line swap is **within the
amended scope**; what was out of scope was a demo that claimed otherwise. ⇒ the defect here was
never the api's ergonomics. it was that the catalog advertised a cheaper migration than the one the
wisher had already approved.

⇒ **F7 is unaffected**: the util still holds no opinion about what produced the handler. what this
correction shows is that F7's promise needs **one declaration** to be collected, and the demo
advertised it as free.

⚠️ **and the fix is a docs fix, never a code fix.** a default of `'ancient'` would serve nia and
betray `rule.require.contemp-contracts-default` plus F3's verdict. the honest move is to say the
second line out loud, everywhere nia reads.

🔴 **and nia is the one actor whose error assertions DO survive the contemp default** — for a
reason that must be stated precisely, because it looks like luck and is not. the contemp default
(**F3**) governs the envelope **our** endpoint emits. nia's handlers are `createStandardHandler`;
they emit the **legacy** family's envelope, which the util relays untouched. `struct.payload` does
not reach it. so her `errorMessage` destructure still holds — not because the two families agree
(they do not; see below), but because **the util holds no opinion about either.**

⇒ the same property that makes the util handler-agnostic (**F7**) also makes F3 inert for her.

**the aha**: the two migrations she assumed were sequenced are not. she thought "move off the legacy
handler-test util" was the *last* step of a handler migration she had not started. it is a
*standalone* step she can take today. the sdk's name suggested a bond its behavior does not have.

## .why the assertions survive — two claims, and only one of them carries the case

> ⚠️ **corrected within r2.** the first draft of this section claimed both families *"split on the
> same predicate — `decideIsBadRequestError`"*. **that is false**, and the correction puts F7 on
> firmer ground rather than shakier.

### the load it actually bears: the util applies NO predicate

the util is a **pass-through**. it strips, builds a context, awaits, returns — it never inspects the
error, never classifies it, never decides return-vs-throw. **whatever the handler's own middleware
chain decided, the util relays untouched.**

⇒ so the util cannot disagree with *either* family, because it holds no opinion to disagree with.
**that** is why F7 holds, and it holds no matter what the two predicates do. it is a property of the
util's own shape, which the util's own tests can pin (`[t4]`).

### the second claim — nia's assertions survive — rests on the util, NOT on a cross-family match

⚠️ **this section argued the wrong premise until i007, and the correct argument is stronger.** it
read: *"that needs the two families to emit the same envelope, and they do on the path her handlers
walk."*

**they do not.** read field by field, the two ancient envelopes genuinely differ:

| field | legacy `createStandardHandler` | `genLambdaEndpoint`, flat frame |
|---|---|---|
| `errorMessage` | ✅ | ✅ |
| `errorType` | ✅ `'BadRequestError'` | ✅ `'BadRequestError'` |
| `stackTrace` | ✅ **always** | ❌ **absent** |
| `causeMessage?` | ✅ when `cause` is an `Error` | ✅ when `cause` is an `Error` |
| `causeTrace?` | ✅ when `cause` is an `Error` | ❌ absent |
| `details?` | ❌ absent | ✅ when the error carries `metadata` |
| citation | `badRequestErrorMiddleware.ts:93-103` | `getErrorResponseBody.ts:50-63` (`getErrorResponseBodyAncient`) |

and on the throw path they agree: legacy `:114` (`return handler.error` → rethrow),
endpoint `genInternalServiceErrorMiddleware.ts:62`.

🔴 **so the cross-family envelope claim was false — and case=7 never needed it.** nia keeps her
`createStandardHandler` handler. **her** envelope is produced by `badRequestErrorMiddleware`, before
the swap and after it. the util relays; it constructs no envelope of its own. so what her assertions
need is not *"the two families match"* but *"the util does not alter what her handler returned"* —
which is F7 itself, already established above.

⇒ **the corrected argument is strictly stronger**: it depends only on the util's pass-through
property, which the util's own tests pin (`[t4]`), rather than on a cross-family coincidence that
turns out to be false. **a premise that was never load-bearing appeared to carry weight; removed,
the case rests on less and proves the same.**

⚠️ **and the table is now a migration hazard worth its own note.** the `stackTrace` row says that
when nia *later* migrates her handlers to `genLambdaEndpoint`, any assertion on `stackTrace` or
`causeTrace` **will** break — the endpoint emits neither. that is a real cost of the handler
migration, invisible before this read, and it belongs to the wisher's Q10 scope rather than to this
util's swap.

### 🔴 the predicates are NOT the same function, and not even equivalent

read side by side, `getIsConstraintError` (this repo, `:11-34`) is a strict **superset** of the
legacy `decideIsBadRequestError` (`badRequestErrorMiddleware.ts:9-32`):

| classified caller-fault? | legacy | genLambdaEndpoint |
|---|---|---|
| `BadRequestError` — instance, name, or prototype chain | ✅ | ✅ |
| **`ConstraintError`** | ❌ — falls through and **throws** | ✅ — **returns** an envelope (`:18,22,47`) |

so the families **diverge on `ConstraintError`**: the same error is a thrown server-fault under a
legacy handler and a returned caller-fault envelope under an endpoint.

**this does not touch case=7**, and the reason is precise: nia keeps her `createStandardHandler`
handler. its classification is whatever it always was; only the *test util* changed, and the util
relays. the divergence is a **handler-migration** concern, not a **util-swap** one — and when she
does migrate later, it surfaces as
[case=2](1.vision.experience.case=2.constraint-error-returns-an-envelope.md), already demoed.

⇒ the honest statement: **F7 is sound because the util is opinion-free.** the envelope table shows
her assertions survive on the `BadRequestError` path, which is the legacy vocabulary her handlers
already speak. the two facts are independent, and the first is the one the case rests on.

## .how the edge fails safe

the hazard here is **not** a broken swap — it is that nia never attempts one, because the name told
her it was not hers. so the fail-safe is about discoverability, not rejection:

- **fast** — the type accepts any `(event, context) => Promise<T>`. a handler the util cannot take
  fails at compile time in her editor, before she has invested a file.
- **loud** — if the two families ever diverge, her unchanged assertion goes red on the first file,
  not silently green on a changed shape. the flat envelope's keys are the assertion surface, so a
  shape change cannot pass unnoticed.
- **teaches the fix** — the readme states the family-agnosticism outright, with a
  `createStandardHandler` example beside the `genLambdaEndpoint` one. a util adoptable by 20 repos
  that documents only the 1-repo case has thrown away its own reach.
- **prevents rather than corrects** (`rule.prefer.prevent-over-correct`) — the highest rung is the
  **name**. `runLambdaEndpoint.onReferenced` reads endpoint-bound and actively deters this actor. that is
  a real cost of **F2**, and r2 raises it as **Q8**: the word may steer 19 repos away from a util
  that serves them.

## .the bdd sketch

```
given [case7] a repo whose handlers use createStandardHandler,
      and whose handler tests import the legacy util,
      and which has NOT moved to genLambdaEndpoint

  when [t0] the author swaps the import, declares struct: { payload: 'ancient' },
            AND narrows the result before the destructure,
            and leaves handler and assertions untouched
    then the test passes unchanged
    then no handler file is modified
    then the per-site cost is THREE edits — import, struct, narrow

  when [t0b] the author swaps ONLY the import, and omits the struct
    then the contemp default frames her event as { event, trail }
    then her handler reads its own fields off the wrapper and finds them absent
    then ⇒ the struct line is REQUIRED, never a refinement
      — corrected at self-review r6; [t0] read "swaps only the import" and its
        clamp quietly passed the struct, so the title was false and green

  when [t1] the handler rejects a caller-fault input
    then the util returns the ancient envelope her own handler built
      — { errorMessage, errorType: 'BadRequestError', stackTrace, causeMessage?, causeTrace? }
    then it is byte-identical to what the LEGACY UTIL returned FOR THIS SAME HANDLER
      — the comparison is before-swap vs after-swap, NOT legacy-family vs endpoint-family
      — those two families differ (see the field table above); this handler is in neither's crossfire
    then a destructure off the RESULT does not compile — the union refuses it
      — probed: TS2339, "Property 'errorMessage' does not exist on
        LambdaEndpointRunOutput<{ delivered: boolean }, 'ancient'>"
      — this line read "so a destructure ... still binds" until r6's SECOND pass,
        which is one hour after r6 corrected the struct line directly above it
    then a destructure off the NARROW binds, and the assertion is unchanged
      — const { errorMessage } = asLambdaEndpointErrorEnvelope<'ancient'>(res)

  when [t2] the handler raises a non-caller-fault error
    then the util THROWS it
    then the legacy util threw it too — the two agree

  when [t3] the legacy HANDLER-TEST import is removed everywhere
    then the full suite is green
    then not one handler moved to genLambdaEndpoint
    then the package.json entry is deletable once she ALSO swaps her acceptance
         tests to onSerialized and her fixtures to asLambdaEvent
         — both successors ship in THIS wish (A2), so it is one afternoon, not a second wish
    then each of the three swaps is independent of the other two
         — the point of this case: none of them needs a handler migration

  when [t4] the util's parameter type is inspected
    then it names a plain handler function
    then it does NOT name a genLambdaEndpoint-produced type
```

**what the sketch tests that the narrative does not**: `[t2]` and `[t4]`.

the narrative shows only nia's happy path — a constraint rejection that returns. `[t2]` pins the
**other** half of the contract, and it is the half that would break silently: if the new util
swallowed a malfunction that the legacy util threw, nia's suite would go **greener**, not redder,
and she would ship a handler whose failures no longer fail a test. a false green is the one outcome
worse than a red.

`[t4]` is the structural guard on F7 itself. a future contributor can narrow the parameter type to
a `genLambdaEndpoint` return type in a refactor, keep every extant test green (the sdk's own tests
all use endpoints), and silently lock 19 repos out. `[t4]` asserts the looseness on purpose, so the
agnosticism is a tested property rather than an accident of the current signature.

## .why it is a critipath

`freq × cost`, worked above: the highest-frequency actor in the population, and the one whose
failure makes the wish's done-when unreachable for 95% of the repos it was written for.

no workable fallback: the alternative for these 19 repos is "finish the handler migration first",
which is a far larger project that has been open long enough to reach 1 repo. to gate the
dependency cleanup behind it is to defer the wish indefinitely.

## .the boundaries it exercises

1. **the import seam** — the call shape must line up (shared with case=1)
2. **the relay seam** — the util must return a handler family it was not designed against, without
   an opinion about the envelope it carries. verified in both sources: the legacy handler builds the
   envelope (`badRequestErrorMiddleware.ts:93-103`), and the util constructs none of its own

⚠️ **item 2 read *"the cross-family contract seam — two … factories that must agree on the flat
in-process envelope"* until i008.** that is the premise the i007 repair removed, restated in a
summary list — **the same corrected fact, alive one section away from its own correction.** the
factories do NOT agree (they differ on `stackTrace`, `causeTrace`, `details`), and the case never
needed them to. the boundary is the **relay**, not an agreement.

density 2 — unchanged by the repair, since the relay is a boundary just as the supposed agreement
was. what changed is which property is under test.
