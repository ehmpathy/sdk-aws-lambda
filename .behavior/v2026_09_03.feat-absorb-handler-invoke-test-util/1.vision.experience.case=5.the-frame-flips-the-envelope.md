## .the narrative — 🔴 **as the vision imagined it, and NOT as it was built.** see the correction above

priya is back, on the same endpoint, now to test the rejection path. this endpoint still serves a
legacy consumer, so she wants the assertion to pin the shape **that** caller receives — she opts
into the ancient dialect explicitly, and it passes and type-checks:

```ts
const res = await runLambdaEndpoint.onReferenced({
  event: { reminderUuid: 'not-a-uuid', sendAt: '2026-09-03T14:00:00.000Z' },
  handler,
  struct: { payload: 'ancient' },        // ← deliberate: assert what the legacy caller sees
});
expect(res).toMatchObject({ errorType: 'BadRequestError' });   // ✅
```

then a reviewer asks her to cover trail propagation too — the exid should thread through to the
handler's logs. so she adds a trail to the same call, changes no other line, and reruns:

```ts
const res = await runLambdaEndpoint.onReferenced({
  event: { reminderUuid: 'not-a-uuid', sendAt: '2026-09-03T14:00:00.000Z' },
  handler,
  struct: { payload: 'ancient' },        // ← unchanged. the type still says ancient
  trail: { exid: 'exid:test-1' },        // ← the only line she added
});
expect(res).toMatchObject({ errorType: 'BadRequestError' });   // ❌ now fails
```

**same handler. same invalid input. same assertion. same declared dialect. red.**

she dumps the value:

```jsonc
// before — flat frame, ancient dialect
{ "errorMessage": "validation failed: reminderUuid must be a uuid",
  "errorType":    "BadRequestError" }

// after — wrapped frame, contemp dialect
{ "error": { "_serde":  "LambdaEndpointError::contemp",
             "class":   "ConstraintError",
             "message": "validation failed: reminderUuid must be a uuid" } }
```

the field moved, and the value changed with it. `errorType: 'BadRequestError'` became
`error.class: 'ConstraintError'` — **while the return type still said `errorType`.**

⚠️ **this narrative ran the other direction until i016.** it opened on a plain `{ event, handler }`
call that "passed" as ancient — true before the wisher flipped F3 on 2026-09-08, and false after:
the default is now **contemp**, so a plain call was never the ancient end of the walk. the flip
priya meets is toward contemp *from an explicitly declared ancient*, which is both correct under
the settled contract and a sharper demo — it exposes the knob conflict below, which the old
direction could not reach.

**the aha, and it is the disorienting kind**: she did not change the error. she changed *who she
said she was*. the trail wrapper is the sdk's signal for a contemporary caller
(`invariant.ancient-vs-contemp-callers`), and the handler answers ancient and contemp callers in
deliberately different dialects:

```ts
// genConstraintErrorMiddleware.ts:44-52
const isContempCaller = context.isContempCaller ?? false;
const body = isContempCaller
  ? getErrorResponseBodyContemp({ error, errorClass: 'ConstraintError' })   // wrapped frame
  : getErrorResponseBodyAncient({ error, errorType: 'BadRequestError' });   // flat frame
```

this is not a defect. it is the backwards-compat guarantee at work exactly as designed — an ancient
caller *must* keep receipt of `BadRequestError` or its error handlers break. but priya met it as an
invisible coupling: **an addition she made for an unrelated reason (trail coverage) silently
rewrote her error assertions.**

## .how the edge fails safe

this is the hardest fail-safe on the drive, because the edge cannot be removed — the dual dialect
is a load-bearing invariant. so the design makes it **impossible to meet by accident**:

- 🔴 **the dialect is in the TYPE, so the compiler catches it — not a runtime reader.** the util
  carries the payload dialect as a generic (**F9**), so the return type names which envelope this
  call yields:

  ```ts
  runLambdaEndpoint.onReferenced({ event, handler })
    // → TOutput | { error: { _serde, class, message, … } }     contemp, the default
  runLambdaEndpoint.onReferenced({ event, handler, struct: { payload: 'ancient' } })
    // → TOutput | { errorMessage, errorType, causeMessage?, details? }
  ```

  ⇒ priya's `res.errorType` on a contemp call is a **compile error**, not a silent `undefined` that
  fails an opaque `toMatchObject`. `rule.prefer.prevent-over-correct` rung **1**, where a reader
  was rung 4.

  ⚠️ **this replaced a runtime reader (`asLambdaErrorForTest`) when the wisher ruled on
  2026-09-08.** the reader normalized both dialects into one shape at runtime — which
  re-discovers, per call, a fact the caller stated on input. F5 is **superseded by F9**, not
  renamed: the dialect is deterministic from the payload frame (`genTrailMiddleware` sets
  `isContempCaller`), so it belongs in the type system.
- **and contemp is now the default (F3, flipped 2026-09-08)**, so the ancient end of the walk is
  reachable only by an explicit `struct: { payload: 'ancient' }` — a keystroke, in her diff. an
  author who never writes it never meets this case at all, which shrinks the blast radius to the
  repos that genuinely serve a legacy consumer.

- 🔴 **and the case exposes F9's one open bound: two knobs, one fact.** the **frame** is driven by
  `trail:`; the **dialect** is declared by `struct.payload`. they can be set to disagree, and
  priya's second call is exactly that state — a contemp frame under an ancient type. the blueprint
  must pick one of two closures:

  | closure | cost |
  |---|---|
  | derive `struct` from the frame | one knob, and the generic loses the explicitness that made F9 worth having |
  | refuse the mismatch at the type level | keeps both knobs, and `trail:` must then narrow `struct.payload` to `'contemp'` |

  ⇒ **either closure makes priya's second call a compile error rather than a red assertion**, which
  is the whole point. what the vision must not do is leave the pair unconstrained and call it typed
  — that ships a type whose promise the runtime can break, which is `rule.forbid.failhide` wearing
  a generic.
- **the trail input is explicit, never inferred.** the frame flips only when the author writes
  `trail:` — there is no heuristic, no auto-wrap, no "if the event looks like X". the author's
  keystroke is the whole trigger, which keeps the cause discoverable in the diff.

  ⚠️ **and the detection is stricter than it looks — an implementation constraint, not a detail.**
  `getIsWrappedPayload.ts:32-41` accepts a payload as wrapped only if it has **exactly two keys**,
  named `event` and `trail`, with `trail` a non-array object whose `exid` (if present) is a string.
  so the util must emit precisely `{ event, trail }` and no third key. add one — a stray `context`,
  a debug field — and detection silently fails: the handler treats the call as *ancient*, and the
  author gets the flat envelope while they believe they asked for contemp. that is a silent
  wrong-shape, the worst failure mode available here, so the util's construction of the wrapper is
  a spot that owes a direct test rather than trust.
- **the readme states the coupling in one line**, next to the trail example, rather than left to be
  rediscovered per-repo: *a trail marks you a contemporary caller; contemporary callers get the
  contemp error shape.*

what is **not** claimed: that priya will be unsurprised the first time. she will be surprised. the
fail-safe is that the surprise is loud (a **compile error**, not a silent pass), fast (at
type-check, not at the assertion and not in prod), and has a named fix (the field the other dialect
uses).

## .the bdd sketch

```
given [case5] one handler, one invalid input, held constant across the whole case

  when [t0] the util is called with NO struct argument — the default
    then the payload sent is WRAPPED, because contemp is the default (F3)
    then the settled value carries error.class: 'ConstraintError'
    then it has no top-level errorType

  when [t1] the util is called with struct: { payload: 'ancient' } and NO trail
    then the payload sent is FLAT
    then the settled value carries errorType: 'BadRequestError' at the top level
    then it has no `error` key

  when [t1b] the util is called with struct: { payload: 'ancient' } AND a trail
    then EITHER the call does not compile — the trail narrows the dialect to contemp
    then OR the util derives the dialect from the frame and the type says contemp
    ⇒ what it must NOT do is settle to a contemp envelope under an ancient return type
      (the two-knobs bound; see .how the edge fails safe)

  when [t2] each call's return TYPE is inspected
    then the contemp call's type admits `error.class` and NOT top-level `errorType`
    then the ancient call's type admits `errorType` and NOT `error`
    then a cross-dialect field access does not compile

  when [t3] the wrapped call's handler logs are inspected
    then the exid the author supplied is present in the trail
    then this is the reason the author added the wrapper at all

  when [t4] an ancient-declared call is made and the author writes `res.error.class`
    then the compiler rejects it — the union surfaces the absent key at build time

  when [t5] the util builds a wrapped payload
    then the emitted object has EXACTLY the keys event and trail — no third key
    then getIsWrappedPayload accepts it
```

**what the sketch tests that the narrative does not**: `[t1b]`, `[t2]` and `[t4]`.

🔴 **`[t1b]` is the clause that carries this case's real contract, and it is stated as a
disjunction on purpose.** the vision does not pick between the two closures — that is the
blueprint's call — but it does forbid the third outcome, which is the one the current design admits:
a contemp envelope settled under an ancient return type. a sketch that named only one closure would
smuggle a blueprint decision into a vision.

the narrative ends at priya's disorientation — it shows the divergence but never establishes that
the two shapes are *the same fact*. `[t2]` is the load-bearing assertion of this whole case: it
pins that the message is invariant across frames and that only the class name differs. without it,
a reader could conclude the two frames produce different *errors*, which would make the util look
non-deterministic.

`[t4]` catches a hole the felt story cannot reach at all: the story only shows a runtime failure.
if the type is loose, priya's mistake surfaces as a mysterious red assertion; if the type is a
proper union, it surfaces as a compile error that names the missing key. that is the difference
between an edge that cuts and an edge that guides.

## .why it is a critipath

it is the intersection of the two most-used features in a migrated handler suite: error assertions
and trail propagation. every repo that tests both will land on this cell. if it is undemonstrated,
each repo rediscovers it as a mystery failure, and the likely "fix" they reach for is to delete the
trail from the test — which quietly drops their trail coverage to make an error assertion pass.
that is a real regression bought with a false green.

there is no fallback: the author cannot get contemporary-caller trail semantics and ancient-caller
error shapes at once, because they are the same switch.

## .the boundaries it exercises

1. **the frame seam** — flat vs wrapped payload crossed into the handler
2. **the ancient/contemp branch** — the caller-identity switch at `genConstraintErrorMiddleware.ts:44`
3. **the constraint rejection** — the invalid input the handler refuses
4. **the two-shape divergence** — one fact, two serializations, and the reader that reunifies them
