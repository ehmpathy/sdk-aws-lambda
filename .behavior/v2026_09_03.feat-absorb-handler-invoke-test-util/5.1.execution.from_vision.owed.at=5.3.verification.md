## 🔴 .how row 2 was closed, and why it needed no credentials at all

> *"track ledger row 2 explicitly"* — i015 r010 `enroll-impl-behavior-intent`

it was tracked, and the track is what found it. the row asked for *the credential-free reject that
NAMES THE FIX* — a developer with an expired sso session should meet a fast, legible error rather
than a 90s hang. **the assertion had no subject**: `LambdaCredentialsAbsentError` was raised by
`getAllLambdaContracts` alone, so the invoke path had no such error to assert on.

so the repair was product code first, clamp second:

| step | what |
|---|---|
| **lift** | `throwIfCredentialsError` moved from `getAllLambdaContracts` to `lambdaEndpointWire/error/`, its common ancestor with `onSerialized` (`rule.prefer.most-common-denominator`: *"lift immediately when reused"*) |
| **wire** | `onSerialized`'s **cloud** branch catches, and maps a creds fault to a hinted `LambdaCredentialsAbsentError` |
| **hint** | the hint takes the caller's `access`, so a `prod` boundary is told to unlock `prod` — it read `--env prep` hardcoded, and a snapshot caught the lift |
| **clamp** | 10 unit tests (`throwIfCredentialsError.test.ts`) + `[case12]` of `onSerialized.integration.test.ts`, which asserts the full 3-layer cause chain |

🔴 **and it needs no credentials, because what is under test is how a credentials FAILURE is READ**,
never the credential chain itself. the sdk already injects `context.aws.lambda.sdk`, so a stub that
rejects with a `CredentialsProviderError` is the whole fixture. ⇒ **the "uncredentialed process"
the ledger demanded for six rounds was never the settler; a dependency injection was.**

🔴 **the boundary this was deliberately NOT wired into.** `askLambdaEndpoint` is a **runtime**
caller, and it is left alone on purpose:

| boundary | who meets an absent credential | what it means |
|---|---|---|
| `getAllLambdaContracts`, `onSerialized({ at: 'cloud' })` | a **developer**, at their terminal | an expired sso session — one command away |
| `askLambdaEndpoint` | a **deployed lambda**, in prod | a broken execution role — a server fault |

`LambdaCredentialsAbsentError extends ConstraintError`, and
`invariant.badrequesterror-not-lambda-error` fixes what that means: caller fault, no retry, **no
alarm**. ⇒ to map it on the runtime path would convert a broken execution role into a silent caller
fault and **suppress the prod alarm that names it**. the reason is recorded in the operation's own
docblock, so the next reader need not re-derive it from a gap.
