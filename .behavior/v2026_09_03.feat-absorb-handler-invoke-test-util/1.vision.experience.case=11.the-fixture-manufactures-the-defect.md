# case=11 — the fixture manufactures the defect it was meant to report

> cell **E1** · sharp · **critipath** · actor: migrant + native · density 3
> D6 = `apiGateway` · the event-source axis, declared at i015

## the narrative

**omar** maintains `svc-gateway`. he has a `forApiGateway` handler with a zod schema on its body,
and he writes the obvious test:

```ts
const event = asLambdaEvent.fromApiGateway({
  body: JSON.stringify({ crewMemberUuid }),
  httpMethod: 'POST',
});
const result = await runLambdaEndpoint.onReferenced({ event, handler });
expect(JSON.parse(result.body)).toMatchObject({ added: true });
```

it fails twice, and neither failure names its cause.

**the first failure is a 500 his handler never chose.** `forApiGateway` reshapes the v1 event before
any schema runs, and while it does so it reads `requestContext.requestId`. the incumbent factory
hardcodes every aws-specific field to one sentinel:

```ts
// eventMetadataWhichShouldNotBeNeeded.ts:10
export const EVENT_METADATA_WHICH_SHOULD_NOT_BE_NEEDED = undefined as any;
```

so `requestContext` is `undefined`, the deref throws a `TypeError`, and
`genInternalServiceErrorMiddleware.ts:39-58` answers a **500** — because on an api-gateway endpoint
a malfunction returns rather than throws. omar's schema never ran. every assertion past the status
check is unreachable, and the error he sees blames his handler for a fault the fixture introduced.

**the second failure hides behind the first.** middy picks a response serializer by a match against
the request's `Accept` header (`/^application\/json$/`). the fixture sends no headers, so no
serializer matches, and the body is handed back as an **object** where api gateway requires a
string. `JSON.parse(result.body)` then fails on `[object Object]`.

### the aha, and it is the uncomfortable kind

> **the fixture is LESS faithful than the wire, in the direction that breaks the handler.**

api gateway sends a `requestContext` on **every** real request, and an `Accept` header on nearly
all of them. a fixture that withholds both is not a minimal event — it is an event aws would never
send. so the test does not report a defect; it **manufactures** one.

and the omission was deliberate. the sentinel carries a documented argument
(`eventMetadataWhichShouldNotBeNeeded.ts:5-8`):

> *"because it would couple the contract of a lambda too closely with aws-specific +
> event-trigger-specific + lambda-api-specific metadata … contract should be based on request
> **data**, not environment specific **metadata**"*

**that position is coherent, and it predates `forApiGateway`.** the correction is narrow: the
argument is a claim about what a **handler** should read. it is not a claim about what a **fixture**
should send. a fixture that withholds what aws sends does not *enforce* the position — it hides the
handlers that violate it behind a `TypeError`.

⇒ so the successor supplies the metadata, and a handler that reads it gets caught by review rather
than by an undefined deref.

## the fork evidence — three consumers, and one names the upstream bug

this is not a hypothetical hazard. it has already been paid for, locally, three times:

| repo | the fork | why |
|---|---|---|
| `ahbode/svc-gateway` | `blackbox/createExampleApiGatewayEvent.ts` | supplies `requestContext` + `Accept`; its own doc-note calls itself *"the local half of the repair"* and names the upstream half — `ehmpathy/sdk-aws-lambda#18` |
| `ahbode/svc-funnel-comms` | `src/__test_utils__/createExampleSQSEvent.ts` | a local copy |
| `ahbode/svc-quotes` | `src/__test_utils__/createExampleSQSEvent.ts` | a local copy |

> **a fixture three consumers fork is a fixture whose contract is wrong**, not a fixture they
> misused.

⇒ the successor must **fix** the contract. to re-publish the incumbent shape under a new name
would import a known-defective fixture into the sdk that also owns the handler it breaks — and
`ehmpathy/sdk-aws-lambda#18` is open against this repo today.

## the bdd sketch

```
given [case11] a genLambdaEndpoint.forApiGateway handler with a zod schema on its body

  when [t0] the event is built by asLambdaEvent.fromApiGateway with only { body, httpMethod }
    then the event carries a requestContext — the factory supplies it, unasked
    then the event carries Accept: application/json — so middy's serializer matches
    then the handler's schema RUNS; the response is not a 500

  when [t1] the handler succeeds
    then result.body is a STRING, never an object
    then JSON.parse(result.body) yields the handler's output

  when [t2] the same handler is given a body that fails its schema
    then the response is { statusCode: 400 }, never a throw
    then the stance differs from forAskEndpoint — this is D6 rewriting D2's value set

  when [t3] the author overrides a metadata field the test is actually about
    then the override wins; the defaults fill only what was not named

  when [t4] a malfunction is raised inside the handler
    then the response is { statusCode: 500 } — it RETURNS
    then this differs from forAskEndpoint, which throws
```

**what the sketch tests that the narrative does not**: `[t2]`, `[t3]`, `[t4]`.

⚠️ **`[t2]` and `[t4]` are the clauses that prove D6 is not orthogonal to D2.** the same two outcome
families that the referenced/serialized walk covers — constraint and malfunction — take *different
shapes* here, because the source selected a different endpoint kind. a decomposition that treated
the event source as a parameter of D2 could not have stated them.

### 🔴 what `[t2]`/`[t4]` are NOT — the scope bound this demo carries

**the `forApiGateway` handler here is the vehicle, never the deliverable.** `dimensions.md` declares
the endpoint-kind axis out of scope for what this wish **builds**, and these two clauses assert that
kind's outcome semantics — which reads as a contradiction until the two senses of *scope* are split:

| this demo's `forApiGateway` handler is… | verdict |
|---|---|
| the vehicle that exercises the **in-scope** event factory | ✅ its subject |
| the **evidence** that endpoint kind rewrites D2's value set | ✅ why D6 sits outside the product |
| a commitment to ship `onReferenced` support for that kind | 🔴 **no** — that is Q6, a follow-on |

⇒ **out of scope to BUILD, in scope to WALK.** the walk is what makes D6's non-orthogonality
checkable rather than asserted, and it costs no shipped surface. flagged at i018, when a reviewer
cross-checked this demo against the scope note and found the two apparently at odds.

`[t3]` guards the over-correction: wire-faithful defaults must not become an immovable fixture. a
test whose subject **is** the metadata needs to set it.

## the boundaries it exercises

1. **the envelope's aws metadata** — present by default, overridable
2. **the serializer's `Accept` contract** — the header that decides whether `body` is a string
3. **the endpoint kind's outcome stance** — 400 and 500 **returned**, where the ask endpoint throws

density 3.

## why it is a critipath

**187 sites across 3 repos** construct an api-gateway event today
(`rhx git.repo.get lines --repos 'ahbode/*' --words 'createExampleAPIGatewayEvent'`), and
`svc-gateway` alone spreads them over 76 files. the family as a whole reaches **8 repos / 254
sites**.

no fallback exists that is not the fork itself — and the fork is the failure mode, not the
workaround: it is a maintenance burden each consumer carries alone, drifts from aws independently,
and hides the upstream defect from the repo that could fix it.

⇒ and the cost is asymmetric in the worst direction. a fixture that *omitted* a field the handler
never reads would cost naught. this one omits a field the framework reads **before** the handler,
so the failure lands where the author has the least context: a 500 with no schema error, in a test
they just wrote, about a handler that is correct.

## the pair

`ehmpathy/sdk-aws-lambda#13` — prebuilt zod schemas for aws event sources. **the same axis, the
other direction**: #13 validates an event source's shape; this factory constructs it. one source
list, two halves, and they must agree — a factory that emits an envelope its own sibling schema
rejects is the drift both tasks exist to close.
