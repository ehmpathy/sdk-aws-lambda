# case=2 — a constraint error arrives as a returned envelope, never a throw

> cell #5 · sharp · **critipath** · actor: **both migrants** · density 3
> ⚠️ the legacy call shape was corrected at r2 — see the note at the foot.

## .the narrative

the last of kai's four handler test files is the one that checks a rejection. the handler's zod
schema demands `serviceUuid: z.string().uuid()`, and the test feeds it `'not-a-uuid'` to prove
the endpoint refuses.

under the legacy util the assertion read:

```ts
const result = await invokeHandlerForTesting({
  event: { serviceUuid: 'not-a-uuid' },
  handler,
});
expect(result).toMatchObject({ errorType: 'BadRequestError' });
```

he pauses on it, because it looks wrong. every instinct built from `askLambdaEndpoint` says a bad
request **throws** — that is what the wire path does, and he has written `await expect(...).rejects`
against it a dozen times. so he half-expects the swap to force him to rewrite this one as a throw
assertion.

**it does not throw. it still returns.** what changes is only the envelope's *shape*, because the
default dialect is now contemp (**F3**):

```ts
const result = await runLambdaEndpoint.onReferenced({
  event: { serviceUuid: 'not-a-uuid' },
  handler,
});
- expect(result).toMatchObject({ errorType: 'BadRequestError' });   // ancient — will not compile
+ expect(asLambdaEndpointErrorEnvelope(result).error.class)
+   .toEqual('ConstraintError');                                    // contemp — the new default
```

🔴 **this sample read `result.error.class`, with no narrow, until self-review r6's second pass** —
and this very file states forty lines below that the form does not compile. ⇒ **the file
contradicted itself**, because r6 corrected the *prose* and left the *code* it was written about.

⚠️ **two changes are at play here, and this demo is about exactly one of them.** the *shape* change
comes from the contemp default, and it is a mechanical rewrite the compiler names (**F9**). what
does **not** change — and what this case exists to teach — is the **stance**: it returns. a reader
who conflates the two will credit the dialect flip for the surprise. the stance was always the
surprise.

⇒ if kai wants the old shape verbatim he can ask for it — `struct: { payload: 'ancient' }` — and
`asLambdaEndpointErrorEnvelope<'ancient'>(result).errorType` reads it. the stance is identical
either way.

⚠️ **this read *"and his `errorType` assertion compiles again"* until r6's second pass, and that
was false.** `struct` selects **which** envelope the union's second arm holds; it does not collapse
the union. a bare `result.errorType` is rejected on either dialect — the narrow is owed regardless,
and only its **type argument** varies.

and the ancient shape is not hypothetical: live consumer tests destructure that exact key today.
`ahbode/svc-funnel-comms/…/executeTaskAskJobOwnerToPickQuote.integration.test.ts:56,72,88` reads
`const { errorMessage } = await invokeHandlerForTesting({ … })`.

**the aha, and it is the uncomfortable kind**: the in-process path and the wire path genuinely
disagree about the same handler and the same input — and *both are right*. in-process, the
constraint middleware sets `request.response` to an envelope and the lambda **succeeds**
(`genConstraintErrorMiddleware.ts:72`); a caller's bad request is not a lambda failure
(`invariant.badrequesterror-not-lambda-error`). over the wire, `askLambdaEndpoint` reads that
envelope back and *converts* it to a thrown `ConstraintError`
(`getParsedResponse.ts:84-98`). the throw is the **caller's** side of the contract, not the
handler's.

kai's instinct was calibrated on the caller. the util is a handler-side instrument, and it shows
him the handler's truth.

## .how the edge fails safe

this is a sharp critipath, so the obligation is to show no one gets cut:

- **the shape is discoverable, not folklore.** the util's return type must not be a bare `TOutput`
  — a handler typed to return `{ delivered: boolean }` can also return an envelope, and a type that
  hides that teaches the author to trust a field that may be absent. the return type names the
  union, so the compiler surfaces the envelope before the test does.
- **the assertion needs no cast at all.** the sdk's own tests resort to one today
  (`…forAskEndpoint.test.ts:83-87` — `(result as unknown as { errorMessage: string })`) because the
  return type hides the envelope. the dialect **generic** (**F9**) puts the envelope shape *in* the
  type, and `asLambdaEndpointErrorEnvelope` reads it out — so `rule.forbid.as-cast` is satisfied by
  construction.

  🔴 **this read *"so `res.error.class` resolves directly"* until self-review r6, and that was
  false.** the two claims are not the same, and the gap between them is the whole design:

  | | what F9 gives | what it does NOT give |
  |---|---|---|
  | the envelope shape | **known** — per dialect, in the type | — |
  | a field read on the result | — | **readable** — the return is a `TOutput \| Envelope` union, and typescript refuses a field that is not on every arm |

  ⇒ so the cast is removed by the **narrow**, never by the generic alone. the generic decides
  *which* envelope you get once you have narrowed; it cannot decide *whether* you have one. a
  vision that promised direct access under-specified the util by exactly one operation — which is
  the bound F9's own table names as *"the success-vs-error narrow"*.
- **the divergence is documented at the point of confusion**, in the util's `.what` header and the
  readme: *this is the handler's answer; `askLambdaEndpoint` converts it to a throw.*

the edge cannot be designed away — it is `genLambdaEndpoint`'s real behavior, and to hide it would
be the failhide F1 rejects. so it is made **loud and legible** instead.

## .the bdd sketch

```
given [case2] a genLambdaEndpoint handler whose input schema requires a uuid

  when [t0] the util is called on the REFERENCED boundary at the DEFAULT dialect,
            with an event that carries an invalid uuid
    then the call RESOLVES — it does not reject
    then the resolved value is a contemp envelope: { error: { class: 'ConstraintError', message } }
    then the message names the field that failed, not merely 'validation failed'

  when [t1] the same call is made with struct: { payload: 'ancient' }
    then the call STILL RESOLVES — the dialect does not change the stance
    then the resolved value is an ancient envelope: { errorMessage, errorType: 'BadRequestError' }

  when [t2] the same handler and input are asked over the wire via askLambdaEndpoint
    then that call REJECTS with a ConstraintError
    then the ConstraintError message equals the envelope's message, unprefixed
    then this holds for BOTH dialects (getParsedResponse.ts:59 contemp, :92 ancient)

  when [t3] the author reads the util's return type
    then the type admits the envelope — it is not narrowed to the handler's TOutput alone
    then the type names WHICH dialect, per the struct.payload argument
```

**what the sketch tests that the narrative does not**: `[t1]`, `[t2]`, `[t3]`.

⚠️ **`[t1]` is new, and it is the clause that isolates this case's claim.** the contemp default
changed the envelope *shape* at the same time this case teaches the *stance*. `[t1]` holds the
stance constant while it flips the dialect — so it proves the two are independent, and a reader
cannot credit the dialect for the surprise.

`[t2]` asserts the in-process and wire paths are one fact in two shapes rather than two different
facts — the seam the wish warns about (*"the two paths disagree about the same handler and a test
proves the wrong one"*). its last clause pins that the thrown class is `ConstraintError` on
**either** dialect, which is a genuine asymmetry: the ancient *envelope* says `BadRequestError`,
and the ancient *throw* says `ConstraintError`. `[t3]` catches the type-level hole the felt story
cannot see.

## .why it is a critipath

constraint rejection is the single most-tested handler behavior in a migrated repo — every endpoint
with a schema has one. if the util converted it to a throw (or the author assumed it did), every
such test would need a rewrite and the wish's done-when fails. no fallback exists.

## .the boundaries it exercises

1. **the constraint rejection** — the invalid input the handler must refuse
2. **the return-not-throw seam** — the in-process/wire divergence about one handler
3. **the ancient envelope shape** — the flat frame's error format

density 3.

## ⚠️ .the r2 correction — the third surviving copy of one defect

the "before" snippet showed the legacy call as **two positional args**,
`invokeHandlerForTesting(handler, { … })`. that is the invented signature self-review **r1** caught
and corrected (its issue 4) — the measured legacy shape is a single named-arg object,
`invokeHandlerForTesting({ event, handler })`, verified across 20 repos.

r1 fixed the yield and four demos. **this copy survived**, and it did local damage: the case's whole
beat is *"the test passes untouched"*, yet its own before/after showed the argument shape change
from positional to object. the demo contradicted its own claim, and contradicted case=1's
one-line-swap promise.

this is the **third** instance of one pattern in this drive — a corrected fact with a surviving copy
elsewhere (r2 issue 1: the wrong repo; r2 issue 6: the predicate inside a repair; this one). the
pattern is now recorded as the standing next-time check: **grep the corrected fact across every
artifact, never only the one under review.**

**and the actor line was widened**: this envelope is what the *legacy* handler emits too
(`badRequestErrorMiddleware.ts:93-103`), so both migrants own this cell, not just the
endpoint-native one.
