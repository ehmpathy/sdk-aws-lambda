# case=4 — a wire-hostile event is stripped, so the test cannot pass on an impossible input

> cell #2 · sharp · **critipath** · actor: native · density 2

## .the narrative

priya writes a new endpoint, `scheduleReminder`, and its handler test. the schema takes
`sendAt: z.string().datetime()`. she builds the event the way she builds every object in this
codebase:

```ts
const result = await runLambdaEndpoint.onReferenced({
  event: { reminderUuid: 'abc-123', sendAt: new Date('2026-09-03T14:00:00Z') },
  handler,
});
```

a `Date`, because that is what her domain code passes around — `rule.require.iso-time` aside, the
legacy corner of this service still uses them.

she expects green. she gets a rejection: the envelope says `sendAt` must be a string.

her first reaction is irritation — the handler clearly *can* take a date, look at it. then it
lands: **it cannot.** aws serializes the invoke payload as JSON. by the time a real caller's event
reaches this handler in prep, `sendAt` is the string `'2026-09-03T14:00:00.000Z'` — a `Date`
instance cannot survive the wire. zod would reject it in production exactly as it just did here.

**the aha, and it is the valuable kind**: the util refused to let her write a test that could
never pass in production. had it handed her `Date` straight through, `z.string().datetime()` would
have failed anyway — but on a *different* input than the one prod sees, and the day someone
loosened the schema to `z.union([z.string(), z.date()])` to "fix" it, the test would go green while
prod stayed broken.

she changes one call — `.toISOString()` — and moves on. the whole encounter cost her ninety seconds
and bought a class of defect she will never meet.

### and the same lesson, pointed the other way

her handler returns `{ scheduledAt: new Date(...) }`, so her next assertion is the mirror image:

```ts
const res = await runLambdaEndpoint.onReferenced({ event, handler });
expect(asLambdaEndpointOutput(res).scheduledAt)
  .toEqual('2026-09-03T14:00:00.000Z');   // a STRING
```

🔴 **this sample read `res.scheduledAt` bare until self-review r6, and the narrow it now uses did
not exist.** the union refuses a field read on **either** arm — the success arm as much as the error
one — and the vision had promised only the error narrow:

> *"a field read needs a narrow, and `asLambdaEndpointErrorEnvelope` is it"*

that sentence is unqualified, and the narrow it names serves one arm. ⇒ **the majority case — a read
on the handler's own output — had no supported form at all**, and this demo advertised the form that
does not compile. `asLambdaEndpointOutput` was added in the same round.

⚠️ **and the repair exposed a deeper one: the narrowed type says `Date` where the value is a
`string`.** `TOutput` is the type the *handler* declares, and the strip this very demo teaches is
absent from it — so `out.scheduledAt.toISOString()` compiles and throws. clamped at
`advertisedExamples.test.ts [case8][t2]`, deferred as **F13** with a dream, because the repair is a
mapped type that ripples into both boundaries.

she wrote `toEqual(new Date(...))` first, out of symmetry with the handler's own return type, and it
failed. **the strip runs on the way out too.**

and the second time it lands faster than the first, because the reason is identical: aws serializes
the *response* as JSON as well, so a real caller receives the string. a util that handed back a live
`Date` would let her assert on a value the wire could never deliver — **the same hole as the inbound
case, pointed outward.**

⚠️ **this half is the drive's least-obvious discovery and the wish omits it entirely** — its
contract names only the inbound strip. the legacy util does both (`:15-16`, applied at `:36` and
`:40`), so an input-only strip would break every extant assertion on a wire-hostile output and miss
the wish's own *"every handler test still passes"* bar. see the yield's **Q9**.

⇒ one rule, two directions: **whatever cannot cross the wire does not reach the other side, in
either direction.** priya learns it once and it covers both.

## .how the edge fails safe

- **the strip is faithful, not clever.** `JSON.parse(JSON.stringify(event))` is precisely what the
  wire does: `Date` → ISO string, `undefined` keys vanish, class instances flatten to plain
  objects, `Map`/`Set` become `{}`. the util reproduces the wire's losses rather than the
  invention of its own.
- **the author's object is not mutated.** the strip produces a new value; priya's `event` literal
  is untouched, so a later assertion against it is not silently altered under her.
- **the failure teaches the fix** — because the failure is zod's, on the stripped input, and zod
  names the field and the expected type. the util does not need to explain the strip; the rejection
  already points at the exact key.
- **it fails at the boundary, not deep** — the strip is the first act the util takes, before the
  handler is ever entered, so no partial side effect precedes the rejection.

⚠️ **one place the strip does NOT fail safe — found at self-review r2, graded a nitpick.**
`runLambdaEndpoint.onReferenced({ event: undefined, handler })` has no `event` to strip, and the
util must say so rather than let the absence travel.

graded by `freq × cost`, deliberately, because r1's blocker was a mis-read frequency term:

| term | value | evidence |
|---|---|---|
| frequency | **zero, measured** | `event: undefined` → **0 matches** across `ahbode/*`; a call that omits `event` → **0 matches**. the no-event convention in this corpus is `event: {}` (`svc-home-services/getAllLeadCaptureForms.integration.test.ts:39`), which strips cleanly |
| cost | low-moderate | one opaque error at authorship time; loud, immediate, and not shippable |

`zero × moderate` → **not a critipath**. this is the genuine
`shoetie-on-carbumper-at-75mph` shape: a real edge that nobody walks. it owes a **guard**, not a
demo, and the frequency term was **measured rather than assumed**, which is the correction r1's
mis-grade demanded.

### 🔴 the guard was owed, and this record's account of WHY went stale — closed at peer review r009

this clause read, until r009:

> *"`JSON.parse(undefined)` coerces its argument to the string `"undefined"` and raises
> `SyntaxError`. so the call **dies on the util's first line** with an opaque parser error."*

**that is no longer what happens**, and the drift is the part worth a note. `asWireStripped.ts:27`
since added an early return for `undefined` — correct on its own terms, and it removed an
**accidental guard**. the value now flows *through*, is framed as `{ event: undefined, trail: {} }`,
and reaches the handler.

⇒ **a fix moved the error further from its cause**, and a record that names the old symptom cannot
notice.

⚠️ **and the cost term above under-prices it, on the measurement.** *"loud, immediate, and not
shippable"* describes the `SyntaxError` that no longer occurs. probed with the guard disabled, the
outcome depends on how the handler reads its argument:

| the handler | measured, guard off |
|---|---|
| a `genLambdaEndpoint` endpoint | survives — the trail middleware unwraps, zod names the fault |
| a plain handler that DESTRUCTURES — `({ slug }) => …` | `TypeError: Cannot read properties of undefined`, inside THEIR file |
| a plain handler that READS a field — `(e) => e.slug` | 🔴 **no error at all** — a success-shaped answer, green |

the last row is `rule.forbid.failhide`, not a message defect — so the cost is **not** bounded by
authorship time, and a `zero × moderate` grade rested on a symptom that had changed.

🔴 **`zero` still holds, so the CELL's verdict is unchanged** — it remains a non-critipath, and the
guard was owed either way. what changed is that the record's stated reason had rotted while its
conclusion stayed right, which is the harder defect to catch: a claim nobody re-reads because its
verdict still looks correct.

**the guard now exists on BOTH boundaries** — `runLambdaEndpoint.onReferenced.ts` and
`runLambdaEndpoint.onSerialized.ts`. it **rejects** rather than defaults, and the corpus settles
which: `event: {}` is already the measured convention for *no input*, so `undefined` means *I made
a mistake* — to default the second to the first would run the handler on a lie.

⚠️ the serialized guard is **not** redundant with the referenced one, and that too was measured: the
cloud locus never reaches the twin (`JSON.stringify` drops an `undefined` key), and the local locus
reaches it and then washes its throw through `asWireFunctionErrorPayload`, which returned
`metadata.hint === ""`. clamped at `[case4][t4]` (referenced, 3 assertions) and `[case8][t6]`
(serialized, both loci).

## .the sharp part that stays sharp

there is no fully comfortable answer here, and the demo should not pretend otherwise. the strip is
a **silent transformation of the author's input**. a `Map` becomes `{}` with no signal; an
`undefined` key disappears. priya got a loud zod rejection because her schema was strict — an
author with a looser schema (`z.any()`, or an unvalidated passthrough field) would get a *silent*
difference between what she wrote and what the handler saw.

that residue is real and is recorded in the yield's awkwardness section. the demo's claim is
narrower and defensible: **the strip's silent loss is strictly less dangerous than its absence**,
because absence lets a test pass on an input production cannot deliver, while presence at worst
matches production's own loss.

## .the bdd sketch

```
given [case4] a handler whose schema requires sendAt as an ISO datetime string

  when [t0] the util is called with an event whose sendAt is a live Date instance
    then the handler observes a STRING, not a Date
    then the string equals what JSON.stringify would have produced

  when [t1] the event carries a key set to undefined
    then the handler observes that key as ABSENT, not as undefined
    then this matches what the wire delivers

  when [t2] the event carries a domain-objects class instance
    then the handler observes a plain object
    then the instance's methods are gone — as they are over the wire

  when [t3] the caller's own event object is inspected after the call
    then it is unchanged — the strip produced a copy

  when [t4] the event is undefined
    then the util REFUSES it, with a named ConstraintError
    then the message names the argument and the fix — `event: {}`
    then the handler is never reached at all
    then an EMPTY event `{}` is still allowed — it is the corpus convention

  when [t5] the HANDLER returns a value that holds a Date
    then the author receives an ISO string, not a live Date
    then this matches what the legacy util returned (stripInvocationOutput)
    then so an extant assertion on that field still binds

  when [t6] the handler returns undefined
    then the util yields undefined
    then it does NOT raise a SyntaxError — the outbound strip guards it, as the legacy one does

  when [t7] the event holds a value JSON.stringify itself refuses
            — a circular reference, or a bigint
    then the util still fails — correct, since aws would refuse the payload too
    then but the error names the strip and its wire-fidelity reason,
         rather than a bare "Converting circular structure to JSON" that reaches the author
```

⚠️ **`[t4]` was rewritten at peer review r009**, and the rewrite narrowed it. it had offered the
implementer a choice — *"either treats the event as `{}` or names the argument and the fix"* — and
the corpus had already settled that choice: `event: {}` is the measured convention for *no input*,
so to default `undefined` to `{}` would collapse two distinct author intents into one and run the
handler on a lie. the clause now states the taken branch rather than the fork, and adds the
`{}`-is-still-allowed clamp that the taken branch makes necessary.

⇒ **a bdd clause that offers a fork is a clause a reader cannot check.** it went unimplemented for
nine review rounds partly because either branch would have satisfied it, and neither existed.

⚠️ **`[t5]`–`[t6]` were added at self-review r3**, when the legacy source was finally read directly.
the strip is **two-directional** — `invokeHandlerForTesting.ts:8` inbound, `:15-16` outbound, applied
at `:36` (callback) and `:40` (promise). the wish's contract names only the inbound half. an
input-only strip would hand the author a live `Date` where the legacy util handed an ISO string, and
break every extant assertion on a wire-hostile output — a direct failure of *"every handler test
still passes"*. see **Q9**.

⇒ note `:16`'s guard, `output === undefined ? undefined : …`. the legacy authors hit the exact
`JSON.parse(undefined)` throw this case flags at `[t4]` and guarded it **on the output path**. that
is precedent, not invention: the same guard is owed on the input path.

⚠️ **`[t7]` was added at self-review r4** — it covers the assumption every prior `[t]` shared:
*that the strip succeeds*. `JSON.stringify` throws on a circular reference and on a `bigint`, so
`stripInvocationEvent` inherits both throws. **the failure is correct** — aws serializes the payload
too and would refuse the same value, so a throw is the faithful outcome. **the message is not.**
a bare `TypeError` mentions neither the strip nor why it exists, so an author reads it as a defect
in the util rather than a wire-fidelity guard doing its job.

- **grade**: `freq × cost` = **low × medium** ⇒ an **alterpath**. the population offers no live
  trigger — `IsoPriceShape` (the `bigint` carrier) appears only in a brief, never in an event
  (`--words 'IsoPriceShape'` → 3 matches, all documentation).
- **the repair is a wrap, not a redesign** — `MalfunctionError.wrap` around the strip, with a
  message that names the wire-fidelity reason and the offending argument
  (`rule.require.errors-name-the-fix`, `rule.prefer.helpful-error-wrap`). the same wrap serves
  `[t4]`, so it is one guard for two cases rather than two.

**what the sketch tests that the narrative does not**: `[t1]` and `[t3]`. the narrative is about a
`Date`, the one loss priya *noticed* because her schema was strict. `[t1]` covers the loss no one
notices — a dropped `undefined` key — which is the silent half of the same behavior. `[t3]` guards
a property the story never raises: that the strip does not mutate the caller's object, an easy
implementation slip and a nasty one, since a later assertion on `event` would then quietly assert
against post-strip state.

## .why it is a critipath

this is the sole behavior the wish flags as easy to skip: "a util that skips this lets a test pass
on an object the wire could never deliver". a test that passes on an impossible input is worse than
absent — it is false confidence in the exact place (payload shape) where lambda defects concentrate.
no fallback exists, because the author cannot detect the problem from a green suite.

## .the boundaries it exercises

1. **the serde seam** — the JSON round-trip that the wire imposes and the util must reproduce
2. **the zod-validation boundary** — where the stripped value meets the schema
