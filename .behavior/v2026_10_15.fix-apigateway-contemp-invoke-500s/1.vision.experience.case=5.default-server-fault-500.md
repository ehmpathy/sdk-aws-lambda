# case 5 — a server fault carries the caller's exid

## narrative

kai's handler throws on a dead dependency. the wire gets the redacted 500 — no internal detail —
but its `correlationId` now equals the exid her suite passed in `trail`, carried in the
`x-trail-exid` header. she greps cloudwatch for that id and lands on the `handler.error` line with
the real message. on 0.7.1 a contemp call never reached trail, so no caller exid could arrive.

her teammate hand-rolls an api gateway object in one old test, not via `fromApiGateway`. the sdk
cannot know it is http, so it sends the `{ event, trail }` wrapper, and `forApiGateway` refuses it:
a 500, as on 0.7.1. this time the `handler.error` log line says why — a wrapper reached an http
endpoint — and names the fix: build the event via `asLambdaEvent.fromApiGateway`, or send
`x-trail-exid`.

## bdd

```
given('[case5] a handler that throws a MalfunctionError')
  when('[t0] onReferenced runs it with a fromApiGateway event, no struct, and trail { exid: "exid:kai-1" }')
    then('safe: status is 500 and errorMessage is "internal server error" — no internal detail')
    then('loud: handler.error is logged with the real message and the endpoint name')
    then('teaches the next move: body.correlationId is "exid:kai-1", the key to that log line')

given('[case5] a forApiGateway endpoint and an event not built by fromApiGateway')
  when('[t1] onReferenced runs it with no struct — the sdk sends the { event, trail } wrapper')
    then('safe: status is 500 and the body is redacted, as on 0.7.1')
    then('teaches the fix: handler.error names the wrapper and the two remedies — fromApiGateway, or x-trail-exid')
```
