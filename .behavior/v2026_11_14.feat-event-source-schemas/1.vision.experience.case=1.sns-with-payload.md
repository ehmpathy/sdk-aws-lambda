# case=1 — author wires an sns handler with a typed message

care: critipath · feel: happy · inventory: c1, c15

## .narrative

kai owns `svc-notifications`. ses publishes delivery notices to an sns topic; a lambda consumes them.
today the schema reads `z.custom<SNSEvent>(isSnsEvent)`, where `isSnsEvent` checks only for a
`Records` array, and the handler opens with `JSON.parse(Records[0]!.Sns.Message)` into an `any`
(`ahbode/svc-notifications`, `consumeSESEmailEventFromSNS.ts:33,51-58`).

kai swaps one line. the handler now reads `payload.Records[0].Sns.Message.notificationType` with
autocomplete, and the `JSON.parse` line is gone. the exported `handler` accepts an `SNSEvent` as aws
sends it — no cast at the call site.

```ts
import { asLambdaEventSchema, genLambdaEndpoint } from 'sdk-aws-lambda';

const schemaOfSesNotice = z.object({
  notificationType: z.enum(['Bounce', 'Complaint', 'Delivery']),
  mail: z.object({ messageId: z.string(), destination: z.array(z.string()) }),
});

export const handler = genLambdaEndpoint.forAsk({
  schema: {
    input: asLambdaEventSchema.fromSns({ payload: schemaOfSesNotice }),
    output: z.void(),
  },
  invoke: async ({ payload }, { log }) => {
    const notice = payload.Records[0]!.Sns.Message; // typed: { notificationType, mail }
    await setEmailDeliveryStatus({ notice }, { log });
  },
});
```
