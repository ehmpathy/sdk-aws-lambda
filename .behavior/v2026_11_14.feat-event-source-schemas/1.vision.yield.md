# 1.vision — event-source schemas

## .the contract, in one screen

```ts
import { asLambdaEventSchema, genLambdaEndpoint } from 'sdk-aws-lambda';

asLambdaEventSchema.fromSns()                           // ZodType<SNSEvent, SNSEvent>
asLambdaEventSchema.fromSns({ payload: schemaOfX })     // ZodType<SnsEventDecoded<X>, SNSEvent>
asLambdaEventSchema.fromKinesis()                       // ZodType<KinesisStreamEvent, KinesisStreamEvent>
asLambdaEventSchema.fromKinesis({ payload: schemaOfX }) // ZodType<KinesisStreamEventDecoded<X>, KinesisStreamEvent>

// a text message, not json — the same opt-out forSqs ships (F7); fromSns takes the same key
asLambdaEventSchema.fromKinesis({ payload: z.string(), deserialize: { payload: false } })
```

- **the family** mirrors `asLambdaEvent.from$Source`: that one constructs an envelope, this one
  validates it. two directions over one source vocabulary; the schema side ships a subset (sns,
  kinesis), each absence on a stated axis in `define.lambda-event-source`'s pair table (sqs is
  served by `forSqs`, F1). precedent for the
  `as…Schema({ payload })` shape: `asApiGatewayResponseSchema`
- **the wire face** (zod input) is the aws-lambda type, so `genLambdaEndpoint.forAsk` returns a
  handler that accepts `SNSEvent` with no cast
- **the handler face** (zod output) is the same envelope, with `Sns.Message` / `kinesis.data`
  replaced by the decoded, validated `payload`. with no `payload`, it is exactly the aws-lambda type
- **the decoded types are exported** (`SnsEventDecoded`, `KinesisStreamEventDecoded`), since a
  consumer's `handle` must name what `invoke` hands it
- **sqs is absent** on purpose: `genLambdaEndpoint.forSqs` already validates each record's body and
  answers per message (F1)

## .the outcome world

### before

```ts
// ahbode/svc-notifications, consumeSESEmailEventFromSNS.ts (origin/main)
const isSnsEvent = (value: unknown): boolean =>
  typeof value === 'object' && value !== null && 'Records' in value && Array.isArray(value.Records);
const schema = { input: z.custom<SNSEvent>(isSnsEvent), output: … }; // "it has Records"
…
const sesEvent: SESEvent = JSON.parse(Records[0]!.Sns.Message); // an any, typed by assertion
```

its kinesis peer (`consumeShortUrlCloudfrontLogFromKinesis.ts`) has the same guard, and a hand-rolled
`Buffer.from(data, 'base64')`. the schema says naught; the handler parses by hand; a misrouted event
fails deep in business logic.

### after

```ts
schema: { input: asLambdaEventSchema.fromSns({ payload: schemaOfSesNotice }), output: z.void() },
invoke: async ({ payload }) => {
  const notice = payload.Records[0]!.Sns.Message; // typed SesNotice, already validated
```

### the aha

one argument validates the aws envelope **and** the message inside it, and the `JSON.parse` line
disappears — the handler reads a typed field where it used to read `any`.

## .mental model

- to a friend: *"it's the zod schema for an sns (or kinesis) event, and you can hand it the schema
  of your message too."*
- analogy: a customs check that inspects the crate (envelope) and opens the box inside (message) in
  one pass.
- their words vs ours: they say *message*, *data*, *body*; we say `payload` for all three
  (`domain.terms/payload.md`, F6). they say *sns event*; we say the same — `fromSns`.

## .evaluation

### goals

| wish clause | met? |
|---|---|
| prebuilt schemas for sns, sqs, kinesis | sns + kinesis yes; sqs served by `forSqs` (F1, ask) |
| validate the envelope | yes, known keys validated, unknown kept (F4, F10) |
| optional inner-message schema | yes, `{ payload }`, decoded in place (F3, F7) |
| `as*` name | yes, `asLambdaEventSchema.from$Source` (F2) |
| shapes match aws-lambda types, no cast | yes on the wire face; declared return type (F8) |
| tests against real aws sample events | yes, case=7: docs samples as the floor, captured demo-account deliveries as the target |

### pros

- the rubber-stamp is retired with a one-line swap
- no new family, no new middleware: it rides `forAsk`'s codec types as-is
- introspection publishes the honest wire face (`io: 'input'` renders `Message: string`)
- pairs with the extant factories, so drift between them goes red

### cons

- an sns or kinesis handler rides the **ask** family. so `payload` means the whole envelope there,
  and the handler reads `payload.Records[0].Sns.Message` — "payload" inside "payload"
- kinesis + `payload` is all-or-none per batch (F5)
- a refusal is loud only because `forAsk` logs a warn line when an event-source schema refuses
  (F9, ruled: these schemas only) — new work in a shared family. every other `forAsk` caller keeps
  its debug-only log

### edges and the pit of success

| edge | contract |
|---|---|
| message not json | a refusal with a custom issue at the field, never a `JSON.parse` throw |
| kinesis `data` not valid base64 | node's base64 decode is lenient and never throws, so it is not caught as such; the garbage then fails the json step (default) or meets the text schema (row below) |
| aws adds a field | kept, never stripped or refused |
| docs sample vs types disagree on the cert-url key (`…URL` vs `…Url`) | contested key optional (F10) |
| sqs event misrouted to an sns handler | refused at `Records.0.Sns` |
| `payload` schema from another zod copy or major | a compile-time type error, as `forAsk` already gives; the doc names the one-zod precondition and its `pnpm.overrides.zod` cure (F11) |
| kinesis binary `data` (KPL aggregate, cloudwatch-logs gzip), sns s3-pointer messages | refused under a json `payload`; the doc names envelope-only for them |
| binary `data` under `deserialize: { payload: false }` | ⚠️ the utf8 decode cannot fail, so bytes arrive as a mangled string. a bare `z.string()` accepts it; the doc says to constrain the text's form |
| handler throws a server fault | invoke fails; sns: lambda's async queue retries twice; kinesis: the shard halts and the batch retries |

### assumptions

- consumers run the zod version this sdk ships (`zod@4.4.3`), one copy in the tree (q7)
- `@types/aws-lambda` is already a de-facto peer for consumers — the forSqs handlers return
  `MiddyfiedHandler<SQSEvent>` today

### out of scope

- sns→sqs fan-out (an sns envelope inside an sqs body): a `forSqs` payload concern; flagged, not built
- kinesis tumbling-window fields in the declared type (c23)
- the declapract fixer that wires these (c27): another repo, re-seeded after release
- a trail lift from sns `MessageAttributes` (`domain.terms/trail.md`: unbuilt)

## .groundwork

### external research

- sns sample event: `https://docs.aws.amazon.com/lambda/latest/dg/with-sns.html` § sample sns event
  shape. key constraints: sns invokes async; one published message per invoke
  (`sns-lambda-as-subscriber.html`, q5). ⚠️ the sample's cert-url key ends in `URL`, which conflicts
  with `@types/aws-lambda` (F10)
- async retry: `https://docs.aws.amazon.com/lambda/latest/dg/invocation-async-error-handling.html` —
  on a function error, lambda's async queue runs it two more times, then discards it (or sends it to
  a dlq / on-failure destination). a success is never retried. so under `forAsk` a schema refusal
  (an answered `ConstraintError`, `getValidationError.ts:137`) is not retried, and a server fault is
  retried twice
- kinesis sample event: `https://docs.aws.amazon.com/lambda/latest/dg/with-kinesis.html` § example
  event. key constraints: batches per shard; `data` base64; an error return halts the shard, a
  success advances it
- type shapes: `node_modules/@types/aws-lambda/trigger/sns.d.ts`, `kinesis-stream.d.ts` (v8.10.161)
- zod 4 probe (temp unit test, deleted): `looseObject` + `string().transform().pipe()` decodes json
  in place, keeps unknown keys, and refuses non-json with an issue at the exact path. the probe's
  tsc run showed a `looseObject`'s inferred input type does not accept `SNSEvent` (no index
  signature) → F8

## .what is awkward

- **the ask family carries aws-delivered events.** `forAsk` reads a `{ event, trail }` wrapper, and
  `invariant.ancient-vs-contemp-callers` forbids that read at an aws-delivered family. aws never
  sends one to sns or kinesis, so it is inert, but this feature makes `forAsk` the paved path for
  them. a `forSns` / `forKinesis` family is the honest home; this wish ships the schema half only
- **`payload.Records[0].Sns.Message`** reads oddly — the term "payload" means the envelope here,
  the message inside it is the real payload. a family would lift it to `payload` directly
- **kinesis all-or-none** (F5) is the uncomfortable tradeoff: a stricter schema can skip good data
- **one cast in the sdk** (F8) to save every consumer one — the right trade, still a cast
