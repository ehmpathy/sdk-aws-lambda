# case=9 — a kinesis stream of text lines, not json

care: critipath (the one evidenced kinesis consumer) · feel: happy, with a sharp turn (c8 at t1) · inventory: c28, c8, c14 (kinesis half)

## .narrative

kai's `consumeShortUrlCloudfrontLogFromKinesis` reads cloudfront real-time logs from kinesis. each
record's `data` is base64 of a tab-separated text line, not json. today the handler opens with
`Buffer.from(Records[0].kinesis.data, 'base64').toString('utf-8')` and an envelope check of "it has
a `Records` array" (`ahbode/svc-notifications`, that file, lines 34-37 and 56-63).

kai declares the message a string and turns off the json step. the schema decodes base64 and hands
over the log line. the `Buffer` call is gone, and a non-kinesis event is refused at the envelope.

```ts
schema: {
  input: asLambdaEventSchema.fromKinesis({
    payload: z.string().min(1),
    deserialize: { payload: false },
  }),
  output: schemaOfConsumed,
},
invoke: async ({ payload }) =>
  consumeShortUrlCloudfrontRealTimeLogEvent({
    encodedShortUrlCloudfrontRealTimeLogEvent: payload.Records[0]!.kinesis.data, // the log line
  }),
```

if kai forgets `deserialize: { payload: false }`, every record fails the json step, with an issue at
`Records.0.kinesis.data` that names the fix: set `deserialize.payload: false` for a text stream. the
same rule `forSqs` documents.
