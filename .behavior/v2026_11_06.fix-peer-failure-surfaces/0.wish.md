# wish: a peer failure surfaces, at cause (ehmpathy/sdk-aws-lambda#77)

## .outcome

1. a lambda endpoint that fails logs that failure at warn (a constraint) or error (all else), never at debug beside a success. on-call sees it in the logs, though the invocation itself still reads a success.
2. a peer lambda ConstraintError or BadRequestError no longer surfaces in the consumer as the consumer own ConstraintError. it surfaces as a distinct class (or a MalfunctionError), so an api-gateway consumer answers its caller with a 5xx for a request it composed, never a 400 the caller cannot fix. a pass-through to the old behavior is opt-in.

## .why

these two behaviors hid 24 prod failures in svc-gateway (2026-10-08T21Z to 2026-10-11T22:24Z): cloudwatch Errors read 0, no error line existed, and the svc-notifications#236 outage looked like a caller fault. svc-gateway holds a stopgap catch at its svc-notifications boundary, marked to delete once this lands.

## .done

each behavior clamped by a test that fails without the fix. a pr against main, ci green, ready for review.
