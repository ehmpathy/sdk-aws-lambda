# case=4 — a test author still sees `ConstraintError`

feel: happy · care: critipath · boundaries: test → `runLambdaEndpoint.onSerialized` → hydration

## .narrative

a test author in svc-notifications writes an integration test: send a payload with no template id, expect a refusal. she calls `runLambdaEndpoint.onSerialized({ …, at: 'local' })` and asserts `rejects.toThrow(ConstraintError)`.

no peer stands between her and the handler. she composed the event, so the refusal is hers to fix. the hydration she meets passes `ConstraintError` as the refusal class, so her test reads exactly as it did before this wish. the same holds for `at: 'cloud'`.

## .bdd sketch

```
given('a handler that refuses an event with a ConstraintError')
  when('[t0] runLambdaEndpoint.onSerialized runs it at local')
    then('rejects with ConstraintError')
    then('not a LambdaEndpointRefusedError')
  when('[t1] runLambdaEndpoint.onSerialized runs it at cloud')
    then('rejects with ConstraintError')
  when('[t2] the same handler is asked via askLambdaEndpoint')
    then('rejects with LambdaEndpointRefusedError — the caller view differs by road')
```
