# 1.vision.experience.dimensions

two behaviors, two products. each cell carries one verdict: **demoed** (a `case=N` + `[tn]`) · **itemized** (a row in `case=_`) · **forbidden** (the behavior rejects it; an invariant) · **impossible** (cannot occur by nature).

## .B1 — what a host logs on its own outcome

| # | axis | values |
|---|---|---|
| A | host outcome | success · own caller fault · server fault · killed (timeout, out of memory, init failure) |
| B | family | `forAsk` · `forApiGateway` · `forSqs.perRecord` · `forSqs.perBatch` |
| H | `context.log` at the failure | present (trail ran) · absent (a throw before trail) |

### A × B × H (32 cells)

| A | H | forAsk | forApiGateway | forSqs.perRecord | forSqs.perBatch |
|---|---|---|---|---|---|
| success | present | demoed `case=2` [t0] — debug | demoed `case=2` [t0] | demoed `case=2` [t0] | demoed `case=2` [t0] |
| success | absent | impossible — a success passes trail's `before` | impossible | impossible | impossible |
| own caller fault | present | demoed `case=2` [t1][t2] — warn | demoed `case=2` [t1][t2] | demoed `case=2` [t1] — `perRecord` catches the fault inside its logic, so the chain sees a success: `handler.output` stays at debug, and the one warn line is the extant `sqs.record.refused` (`local.sqsQueue [case6]`, `[case9][t1]`) | demoed `case=2` [t1] — warn, then forwarded; batch redrives (`local.sqsQueue [case10][t1]`) |
| own caller fault | absent | impossible — no `forAsk` `before` throws ahead of trail | demoed `case=2` [t4] — warn via console | impossible — no sqs `before` throws ahead of trail | impossible |
| server fault | present | demoed `case=2` [t3] — error, beside `handler.error` | demoed `case=2` [t3] | demoed `case=2` [t3] | demoed `case=2` [t3] |
| server fault | absent | impossible (as above) | itemized `case=_` row 9 — error via console | impossible | impossible |
| killed | present | impossible — the runtime ends the process, so no `onError` hook runs; aws itself fails the invocation, so the lambda `Errors` metric and its own log line carry it | impossible | impossible | impossible |
| killed | absent | impossible (as above) | impossible | impossible | impossible |

the `absent` row is reachable only where a `before` hook ahead of trail can throw. that is `forApiGateway`'s normalization (`genApiGatewayRequestEventNormalizationMiddleware.ts:35`, a `ConstraintError`; `.test.ts:150`, a `MalfunctionError`). trail's own throw sits on an unreachable `never` branch (`genTrailMiddleware.ts:55-61`). `forAsk`'s one pre-trail hook, `genAskEventOnwireCaptureMiddleware` (`forAsk.ts:210`), holds no `throw` (grepsafe `throw` on that file → 0; globsafe lists the file, so the scope is real). the sqs chain puts trail first among `before` hooks (`genSqsEndpointMiddlewares.ts:84-86`; the internal-service entry declares only `onError`). an implicit throw (a bad property read) in the capture hook would land in the `absent` row; the console fallback covers it all the same.

the `killed` row bounds this wish: it covers every failure a middleware can observe. a killed invocation is aws's to report, and it already does — the invocation fails, so it never reads as the silent success the wish removes.

## .B2 — what a consumer throws on a peer's outcome

| # | axis | values |
|---|---|---|
| C | peer outcome | success · refusal (caller fault) · server fault · no answer (throttle, absent function, network) |
| D | road | `askLambdaEndpoint.viaInvoke` · `askLambdaEndpoint.viaApiGateway` · `runLambdaEndpoint.onSerialized` |
| E | answer shape | contemp envelope · ancient / flat shape · none (no response reached the caller) |
| F | consumer opt | default · `refusal: { as: 'ConstraintError' }` |

a generated sdk (`genServiceSdk`) calls `viaInvoke` and passes its `options.refusal` through, so both `F` values are reachable from it; itemized `case=_` row 20.

`F` has two more cells off its grid. an opt outside the two values is refused at the ask, before any invoke is sent (`case=_` row 22). two asks with opposite opts at once, on one dedupe cache, each keep their own class, since the cache key carries the opt (`case=_` row 23).

`E` and `F` are not orthogonal to `C` and `D`: an answer has a shape and no answer has none, and the opt exists only on the two ask roads. so the latent axis — **"did the peer answer?"** — is closed on both sides: `C = no answer` pairs only with `E = none`, and every other outcome pairs only with a real shape. each cell where `E` or `F` cannot apply is verdicted `impossible`, never dropped. a peer that exceeds its duration is an answer, not a silence: aws returns a type-less ancient envelope with a `functionError`, so it sits on `server fault × ancient`.

## .the downstream consequence — the consumer family a refusal lands in

the class (B2) decides what the consumer's own family does with it (B1):

| consumer family | refusal, default | refusal, pass-through | verdict |
|---|---|---|---|
| forApiGateway | 500 + correlationId, error lines | 400, warn line | demoed `case=1` [t0] / `case=3` |
| forAsk | invoke fails, `Errors` +1 | caller-fault body, warn line | itemized row 8 |
| forSqs.perRecord | redrives, then dead-letters | acknowledged, `sqs.record.refused` | itemized row 7; tested `local.sqsQueue [case9]` |
| forSqs.perBatch | batch redrives | batch redrives (any perBatch throw forwards) | itemized row 7 |

## .actor — a column, not an axis

the actor is not orthogonal to the cells: each cell is met by whoever stands at its boundary (an on-call engineer at a log line, an http caller at a 500, a consumer author at a catch, a test author at `onSerialized`, or **system** — an sqs consumer with no human at the call, whose only witness is the log line and the dead-letter queue). so `case=_` names the actor per row, and no actor × cell product is walked.
