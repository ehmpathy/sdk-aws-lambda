# case=5 — a consumer upgrades past the class change

feel: sharp · care: critipath (every extant consumer meets it once) · boundaries: package bump → consumer catch → consumer tests

## .narrative

svc-gateway bumps `sdk-aws-lambda`. its stopgap at the svc-notifications boundary reads:

```ts
catch (error) {
  if (error instanceof ConstraintError) { log.error(…); throw new MalfunctionError(…); }
  throw error;
}
```

after the bump, a peer refusal no longer matches `instanceof ConstraintError`, so the stopgap's branch goes dead and the error rethrows as `LambdaEndpointRefusedError` — which the chain already turns into a 500 and an error line. the stopgap can now be deleted, as its own comment says.

a second consumer, svc-quotes, catches `ConstraintError` from `askLambdaEndpoint` to re-answer 400. after the bump its test that asserts a 400 goes red, loudly, in ci — never silently in prod. the failure message is the refusal's own: its first line names the peer and its reason, and the fix, `refusal: { as: 'ConstraintError' }`, follows the peer's own details, ahead of the metadata block. she adds the key; the test goes green.

the release notes name the change as a break. the package is at `0.7.3`, so under 0.x semver the break ships as `0.8.0`; a consumer pinned exactly (`rule.require.pinned-versions`) meets it only when it bumps the pin.

## .bdd sketch

```
given('a consumer that catches ConstraintError from askLambdaEndpoint')
  when('[t0] it upgrades, the peer refuses')
    then('the ConstraintError branch does not run')
    then('the thrown error is LambdaEndpointRefusedError, whose message names the opt-in')
  when('[t1] it adds refusal: { as: "ConstraintError" }')
    then('the ConstraintError branch runs, as before the upgrade')
```
