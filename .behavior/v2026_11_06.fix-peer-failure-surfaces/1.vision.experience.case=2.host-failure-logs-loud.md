# case=2 — a host's failure logs loud

feel: sharp · care: critipath · boundaries: handler → middleware chain → log outlet → on-call filter

## .narrative

an on-call engineer filters cloudwatch to `level >= warn` for svc-gateway.

today, a caller fault leaves a `handler.output` line at debug, beside each success. it never shows in that filter. a server fault shows only via `handler.error`.

with the wish, the io logger reads the error class on the error path:
- a caller fault (`getIsConstraintError` true — it reads both `ConstraintError` and `BadRequestError`, by `instanceof` and by `.name`, `getIsConstraintError.ts:23-28`) → `handler.output` at **warn**, with `errorMessage` + `stackTrace`
- any other fault → `handler.output` at **error**, with the same fields

a success still logs `handler.output` at debug. the invocation outcome does not change: a caller fault still succeeds; a server fault fails or answers 500 as before.

## .bdd sketch

```
given('a lambda endpoint, any family')
  when('[t0] the handler succeeds')
    then('handler.output logs at debug')
  when('[t1] the handler throws ConstraintError')
    then('handler.output logs at warn, with errorMessage + stackTrace')
    then('no handler.output at debug')
  when('[t2] the handler throws BadRequestError')
    then('handler.output logs at warn')
  when('[t3] the handler throws a plain Error')
    then('handler.output logs at error')
    then('handler.error logs at error (extant)')
  when('[t4] an api-gateway event fails normalization, before trail sets context.log')
    then('handler.output logs at warn via console, not skipped')

given('a forSqs.perRecord endpoint')
  when('[t5] the handler throws ConstraintError')
    then('the message is acknowledged, so the chain sees a success')
    then('handler.output stays at debug; the one warn line is sqs.record.refused (extant)')
```

`perRecord` catches a caller fault inside its own logic (`genLambdaEndpoint.forSqs.perRecord.ts`), so `[t1]` holds for every family save that one. its warn line is the extant `sqs.record.refused`; the wish is met there by that line.

## .the pre-trail edge

a failure can occur before `genTrailMiddleware` puts `log` on the context: `forApiGateway`'s normalization throws a `ConstraintError` for an event that is neither v1 nor v2 (`genApiGatewayRequestEventNormalizationMiddleware.ts:35`). today the io logger's `if (log)` skips that failure entirely. with the wish it falls back to `console`, so no failure the chain observes is silent. a killed invocation (timeout, out of memory) never reaches `onError`; aws fails it and reports it itself (dimensions, B1 `killed`).
