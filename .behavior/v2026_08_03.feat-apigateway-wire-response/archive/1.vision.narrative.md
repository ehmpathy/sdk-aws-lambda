# 1.vision — an api-gateway handler owns its own wire response

> illustrate the world implied by the wish: a lambda behind `sdk-aws-lambda` can
> return its **exact wire response** — any status, any headers, any body (or none) —
> and the sdk passes it through.

**the shape of the answer: widen the one contract. do not add a second one.**

`forApiGateway`'s output type becomes `PickAny<{ status, headers, body }>`. no peer
export, no mode flag, no second middleware chain. this is a **break** in the return
type, which the wisher has confirmed is acceptable — the library is new and has no
installed base to protect.

**the root cause, named:** the sdk had **the wrong type at its output point**. `invoke` returned a
*body*, so the wire encode had to invent everything else — and it invented
`{ statusCode: 200, body: JSON.stringify(x) }` (`forApiGateway.ts:168-171`). a body cannot carry a
status, so 204, 308, and xml were inexpressible by construction:

```
inputBefore  →  inputAfter  →  [ invoke ]  →  output  →  [ wire encode ]
  the wire        yours           yours         yours       the sdk's, fixed
```

so the wish's fix is to **widen the type at that one point** — `TBody` becomes
`ApiGatewayResponse<TBody>`, and the encode's inventions become defaults the handler drives. the
wisher then directed a second, larger piece of work on the same insight: **name these points, at
the common ancestor**, and bind them structurally so the conflation cannot recur (F12–F26). that
lift serves no acceptance line and is the bigger half of the diff — flagged plainly for a
reviewer's scope judgment.

---

## the outcome world

### day-in-the-life

a mechanic on `svc-notifications` wires up a twilio voice webhook.

**today** they cannot use the sdk for this at all. `forApiGateway` hardcodes
`{ statusCode: 200, body: JSON.stringify(x) }` (verified:
`genLambdaEndpoint.forApiGateway.ts:168-171`), so they hand-roll `forApiGatewayPlain`
— ~20 lines of try/catch that re-derives the sdk's own error seam from memory
(`0.wish.md:53-73`) — and lose trail propagation, io logging, v1/v2 normalization,
and introspection in the trade. the next repo with a webhook writes the same file.

**after this wish** they write the handler:

```ts
export const handler = forApiGateway({
  schema: {
    input: z.any(),                                    // form blob in
    output: asApiGatewayResponseSchema({ body: z.undefined() }),  // a response, no body
  },
  translate: { payload: { input: false } },  // disarmed: the untouched wire event reaches invoke
  invoke: async ({ event }, { log }) => {
    await recordInboundCall({ form: event.body }, { log });
    return { status: 204 };
  },
});
```

note that with `input: false` the translate is disarmed, so `inputAfter` **is** `inputBefore` —
the untouched v1-or-v2 event — and the form string sits at `event.body`. with the default
translator instead, `event` would be whatever that translator yields.

### before / after

| dimension                | before (hand-rolled adapter) | after (widened `forApiGateway`) |
| ------------------------ | ---------------------------- | ------------------------------- |
| 204 / 308 / xml           | only by leaving the sdk       | first-class                     |
| error contract            | re-typed per repo, drifts     | the sdk's own seam, one definition |
| trail (`exid`)            | lost                          | kept                            |
| io logging                | lost                          | kept, metadata-only by default (F10) |
| introspection             | lost                          | kept — always, since schema is required |
| v1/v2 normalization       | dropped deliberately          | opt-out-able — `input: false`   |
| payload transform (both ways) | hardcoded in the adapter  | `translate.payload` — declared, overridable (F12) |
| lines a consumer writes   | ~20 + its tests               | 0                               |
| **sdk exports involved**  | n/a                           | **one** — `forApiGateway`       |

✅ **the normalization row stopped being a tradeoff (F25).** an earlier draft flagged it as a
cost: the wish records that `svc-notifications` dropped security headers, cors, **and** v1/v2
normalization deliberately (`0.wish.md:98-101`), and a `UnifiedApiGatewayEvent` handed to `invoke`
would have been a different event contract than the hand-roll's raw `APIGatewayProxyEvent` — so
retirement of the adapter would have been a rewrite per call site rather than a swap.

the tri-state removes the cost. `translate: { payload: { input: false } }` hands `invoke` the
**untouched** v1-or-v2 event, which is exactly what the hand-roll received. so a consumer who
wants the normalization gets it by default, and one who does not opts out **by value, at the call
site** — no power lost either way, and no shape imposed.

### the "aha"

> "the sdk stopped deciding what my response looks like, and kept deciding what my
> **errors** look like. those were always two different jobs."

response shape is the handler's business; error conversion is the platform's.
`forApiGateway` bundled both. this unbundles the first without unbundling the second
— and without a second export.

### the wish's own open question, answered

> *"does the passthrough own the SUCCESS path only, or the error path too? … a wrong
> split is awkward to undo once consumers declare against it."* — `0.wish.md:103-104`

**the success path only; the platform keeps errors — as a fallback, never a ceiling.**
a handler that wants to own an error response catches and returns one:

```ts
invoke: async ({ event }) => {
  try { return { body: await renderTwiml(event) }; }
  catch { return { status: 422, headers: { 'Content-Type': 'text/xml' }, body: errorTwiml }; }
}
```

so neither choice is exclusive, which defuses the reversibility worry entirely: full
error ownership is available today with no sdk change, and the platform contract is
what you get when you do not catch.

## user experience

### the contract

```ts
import type { PickAny } from 'type-fns';

/**
 * .what = the http response a handler puts on the wire
 * .why = api gateway proxy integration maps these fields; PickAny demands at least one
 */
export type ApiGatewayResponse<TBody> = PickAny<{
  status: number;                    // defaults to 200
  headers: Record<string, string>;
  body: TBody;
}>;
```

`PickAny` (verified: `ehmpathy/type-fns:src/types/PickAny.ts` — "requires specifying
at least one, or more, key") gives exactly the right guarantee:

| return | valid? | wire |
|---|---|---|
| `{ body: x }` | ✅ | 200 + json |
| `{ status: 204 }` | ✅ | 204, empty body |
| `{ status: 308, headers: { Location } }` | ✅ | 308 redirect |
| `{ headers: { 'Content-Type': 'text/xml' }, body: xml }` | ✅ | 200 + xml verbatim |
| `{}` | ⛔ **compile error** | — |

that last row is the guardrail. an empty return is meaningless, and left unchecked it
would reach middy's `normalizeHttpResponse`, which does `statusCode ??= 500`
(verified in the installed `@middy/util@4.7.0` source) — a silent 500. `PickAny`
closes that at compile time, so **no field needs to be required** to stay safe.

### the factory

```ts
export const forApiGateway = <TInput, TBody>(
  config: {
    schema: {
      input: ZodSchema<TInput>;                       // describes inputAfter
      output: ZodSchema<ApiGatewayResponse<TBody>>;   // describes outputBefore
    };
    invoke: (
      input: { event: TInput; payload: ApiGatewayEventPayload },
      context: ContextLogTrail,
    ) => Promise<ApiGatewayResponse<TBody>>;
    translate?: Translate<{
      inputBefore: ApiGatewayEventPayload;            // the wire in, v1 or v2, untouched
      inputAfter: TInput;                        // exactly what invoke gets
      outputBefore: ApiGatewayResponse<TBody>;   // exactly what invoke returns
      outputAfter: APIGatewayProxyResult;        // the wire out, body already a string
    }>;
    cors?: CorsConfig;
  },
  context?: ContextAwsLambdaServer,
): middy.MiddyfiedHandler<APIGatewayProxyEvent, APIGatewayProxyResult, Error, Context>;

/** .what = the wire payload an api-gateway trigger delivers, either version */
export type ApiGatewayEventPayload = APIGatewayProxyEvent | APIGatewayProxyEventV2;
```

### the schema rule — `input` describes `inputAfter`, `output` describes `outputBefore`

**each schema names a point in the bag, never a field inside one.** this is the rule the
wisher set (F25), and it is what makes the two namespaces cohere rather than merely coexist:

```ts
schema: {
  input: ZodSchema<TShapes['inputAfter']>;
  output: ZodSchema<TShapes['outputBefore']>;
}
```

a draft had `schema.output: ZodSchema<TBody>` — the **body**, which is a field one level
inside `outputBefore`. that gap is what let the two namespaces drift: `schema` spoke about a
sub-field while `translate` spoke about whole shapes, so a reader could not line them up, and
this vision itself wrote `inputBefore` as two different types in two sections (F25).

**and each schema guards the point of consequence.**

| schema | guards | whose mistake it catches |
|---|---|---|
| `input` | `inputAfter` — what the handler receives | a caller who sent the wrong shape |
| `output` | `outputBefore` — what the handler returns | a handler that built the wrong response |

both name **the handler's own boundary** — what it receives, and what it returns. that is where a
mistake is still recoverable: a bad inbound shape is refused before the handler runs, and a bad
response is refused before the encode turns it into bytes.

⚠️ **note this diverges from the wisher's literal instruction** — *"schema.output should describe
the outputAfter"* — and only because what `outputAfter` binds to changed under it (F26). when that
instruction was given, `outputAfter` held `ApiGatewayResponse<TBody>`, i.e. the whole response the
handler authors; the instruction's substance was **"the envelope, never just the body,"** and
`outputBefore` is that envelope now. once `outputAfter` correctly became the post-encode wire shape,
a schema there would report `{ statusCode, body: string }` — an envelope whose contents are spent,
which teaches codegen none of the domain contract. **the instruction's intent is kept; only the
member name it points at moved.** flagged rather than silently re-aimed.

**`schema` stays required, and the opt-out is `z.any()`.** an earlier draft made it
optional "to spare webhook authors ceremony". that was a code-path hazard: absence
would have branched validation *and* introspection, and a consumer who forgot the
field would be indistinguishable from one who chose to skip it. required-with-a-
visible-opt-out collapses both branches and makes the choice reviewable
(`rule.require.explicit-optout`).

it also makes introspection **always** available: an endpoint with `z.any()` honestly
reports `any`, which is more useful than a report of no schema at all.

**the ceremony cost, and the helper that pays it.** `ZodSchema<ApiGatewayResponse<TBody>>`
is more to write than `ZodSchema<TBody>` was, and it lands on every call site
(`rule.prefer.defaults-match-common-case` cuts against it). so the family ships the builder:

```ts
/**
 * .what = wraps a body schema into the response-envelope schema
 * .why = keeps the common case a one-liner, and keeps the body type reachable
 *        for introspection + codegen
 *
 * .note = `body` is NAMED because the envelope has three fields (status, headers,
 *         body) and the argument must say which one it supplies. a bare positional
 *         would read as "a response schema" when it is a schema for one field of one
 */
export const asApiGatewayResponseSchema = <TBody>(input: {
  body: ZodSchema<TBody>;
}): ZodSchema<ApiGatewayResponse<TBody>> => ...;
```

⬆️ **[wisher: should this take `{ body }`?]** yes — and the repo's own grain makes it a rule,
not a taste. `rule.require.named-args` + `rule.require.input-context-pattern` mandate a
destructured `input` object, and **14 of the 16 `as*` transformers in `src/` already take one**
(`asLambdaEndpointSchema({ payload, endpoint })`, `asMechanismFnSource({ service, function,
schema, dobjRefs })`, `asDomainObjectPragma({ node })`, …). the two positional exceptions —
`asContractRecord(contracts)`, `asCacheWithoutSet(cache)` — each take **the whole subject** they
cast, which is the one case a positional reads honestly.

this is not that case. the argument is not the response; it is **one field of** the response,
and a positional cannot say which. the named form also keeps the door open: if `headers` ever
earns a schema, it is an additive key rather than a second positional
(`rule.require.illegal-states-unrepresentable` — the ceiling on a positional list is where
this kind of drift begins).

```ts
schema: {
  input: MyRequestSchema,
  output: asApiGatewayResponseSchema({ body: MyBodySchema }),   // 200 + json, the common case
}

schema: {
  input: z.any(),                                              // form blob in
  output: asApiGatewayResponseSchema({ body: z.undefined() }),  // no body out
}
```

that second call is now legible without a comment — **"a response whose body is undefined"** —
which is exactly what a positional `asApiGatewayResponseSchema(z.undefined())` failed to say.

introspection reads the body schema back out of the envelope, so a generated sdk still learns
the domain type rather than `{ statusCode, body }`.

### `translate` — the generic namespace, lifted to the common ancestor (F12)

**scope note: this is a wisher-directed extension.** the wish's `.acceptance` has no line
about config namespaces; the wisher directed *"solve it generically, at the most common
ancestor"* after this vision proposed to seed it separately. recorded so a reader sees the
bound grew by instruction, not by drift.

#### the dimension already exists — four times, named none of them

every endpoint family already translates the payload in **both** directions before and after
`invoke`. none calls it that, and only one exposes any of it:

| family | direction | the extant translate | exposed? |
|---|---|---|---|
| `forApiGateway` | in | `genApiGatewayEventNormalizationMiddleware` — v1/v2 unify + body parse | a sliver (`deserialize.body`) |
| `forApiGateway` | out | `{ statusCode: 200, body: JSON.stringify(x) }` (`forApiGateway.ts:168-171`) | not at all |
| `genLambdaEndpoint` | in | `genTrailMiddleware` → `getUnwrappedEventWithExid` — strip the `{ event, trail }` wrapper | not at all |
| `genLambdaEndpoint` | out | `getValidatedOutput` passthrough — return IS the payload | n/a |

so this is not a new capability. it is **one dimension, expressed four times, named none of
them** — `rule.require.widen-before-parallel` applied to a config namespace rather than to an
export.

the second row is the wish's own root defect: an outbound translate so thoroughly unnamed that
it was hardcoded to one shape. this is the strongest evidence for the lift — the bug we are
here to fix *is* an unnamed translate.

the same holds for the io-log projection: `logTranslate` is declared **inline and
identically in both families** (`genLambdaEndpoint.forAskEndpoint.ts:58, 90` and
`genLambdaEndpoint.forApiGateway.ts:69, 132`), which is duplication of the shared
`IoLogTranslate` contract at two leaves when it belongs at their ancestor
(`rule.prefer.most-common-denominator`).

#### the ancestor is a directory that already exists

the repo's grain is already right — shared middleware sits at
`genLambdaEndpoint/middleware/` and family-specific middleware nests below in
`genLambdaEndpoint.forApiGateway/middleware/`. only the **config contract** was left
un-lifted. so the placement question answers itself: the shared types go beside the shared
middleware.

#### the noun is `payload`, not `event` — verified, not chosen

an earlier draft named the load-bearing member `translate.event` and argued the
`.{input,output}` split was impossible because "`event` already means inbound". that was an
artifact of the **wrong noun**, and a grep settles it: `payload` is *already bidirectional*
in this repo, while `event` is inbound-only.

| site | direction |
|---|---|
| `sdkLambdaInvoke.ts:10` — `payload: Uint8Array \| undefined` | **response** |
| `sdkLambdaInvoke.ts:39` — `payload: result.Payload` | **response** |
| `asLambdaEndpointSchema.ts:6` — "cast a lambda response payload" | **response** |
| `LambdaIntrospectionNotSupportedError.ts:7` — "the invoke returned no payload" | **response** |
| `WrappedPayload<TInput>` / `FlatPayload<TInput>` | inbound |

so `payload` is the extant ubiqlang term for *the wire-side representation, in either
direction*, and `event` is what it becomes after translate — exactly what `invoke({ event })`
receives. the translate therefore reads honestly as **payload → event** inbound, and
**response → payload** outbound.

this also retires a latent wart: `translate.event` was ambiguous about which end it named
(the value translated, or the value produced), and it collided with `invoke`'s `rawEvent` — a
field which the F25 pass then renamed to `payload`, since `rawEvent` was **not** raw. so the noun
lands consistently: `invoke({ event, payload })` where `payload` is `inputBefore` and `event` is
`inputAfter`.

```ts
// genLambdaEndpoint/ — the common ancestor of both families

/**
 * .what = projections applied to io before it reaches cloudwatch
 * .why = keeps secrets and PII out of logs; cosmetic, never load-bearing
 */
export interface TranslateLog {
  input?: (payload: unknown) => unknown;
  output?: (response: unknown) => unknown;
}

/**
 * .what = a function that re-renders one shape as another
 * .why = the agent noun for the act; `asPayloadTranslator` and
 *        `asApiGatewayEvent` already speak this word
 */
export type Translator<TFrom, TInto> = (from: TFrom) => TInto;

/**
 * .what = the four shapes an endpoint's data takes, named at the translator boundaries
 * .why = these four are the fundamental types of any lambda endpoint, and the
 *        pairs most often conflated (see the beware table). a named bag is a
 *        STRUCTURAL BIND to the terms — a constraint against future deviation
 *
 * .note = a SHAPE is not the same thing as a TRANSLATE SLOT. all four shapes exist
 *         on every endpoint; `Translate` offers a slot for each boundary a consumer
 *         may drive. do not delete a shape because its translate has a fixed
 *         default — that erases the vocabulary the bind exists to hold
 */
export interface LambdaEndpointShapes {
  inputBefore: unknown;   // before the input translator  — as it arrives
  inputAfter: unknown;    // after  the input translator  — as `invoke({ event })` gets it
  outputBefore: unknown;  // before the output translator — as `invoke` returns it
  outputAfter: unknown;   // after  the output translator — as it lands on the wire
}

/**
 * .what = the translate namespace: what changes en route, and what logs see
 * .why = one bound generic; every payload member tri-state
 *
 * .note = each payload member is TRI-STATE — three states, three senses:
 *
 *   absent   -> the family's default translator runs
 *   false    -> DISARMED; no translate, the shape passes through untouched
 *   function -> yours, in place of the default
 *
 *         on `output`, DISARMED means the handler returns the wire shape itself,
 *         so `outputAfter` IS `outputBefore` and the encode does not run
 *
 *         the off-state is `false`, never `null`. absent and off carry OPPOSITE
 *         senses here (default-on vs translate-off), so they must not be the two
 *         most confusable values in the language (rule.forbid.opposite-senses-
 *         on-undefined-and-null). `false` also matches the extant grain: this
 *         repo reads `null` as an absent value and `false` as a switch that is
 *         off — and this concept already shipped as `deserialize: { body: false }`
 */
export interface Translate<TShapes extends LambdaEndpointShapes> {
  payload?: {
    input?: Translator<TShapes['inputBefore'], TShapes['inputAfter']> | false;
    output?: Translator<TShapes['outputBefore'], TShapes['outputAfter']> | false;
  };
  log?: TranslateLog;
}
```

#### `outputAfter` is the envelope with opaque contents — which is why the pair is real (F26)

⬆️ **[wisher: "why am i still seeing this outdated forbidden shape?" then "it should exist, no?"]**
the shape a draft shipped was

```ts
outputBefore: ApiGatewayResponse<TBody>;  // exactly what invoke returns
outputAfter: ApiGatewayResponse<TBody>;   // identity by default
```

**the same type, twice, in every family.** that is a real defect — a `Translator<T, T>` with an
identity default constrains no one, so the bind proved a tautology
(`rule.avoid.constraints-the-state-already-proves`) at the exact site F16 built it to prevent a
conflation.

⚠️ **and this vision then drew the wrong conclusion from it: it deleted `outputAfter`.** the wisher
caught that too — *"even if we have to say `outputAfter: unknown`, it still exists"*. right, and the
error underneath was a **category confusion**:

| the question | the answer |
|---|---|
| does the endpoint HAVE a post-encode wire shape? | **yes, always** — so `LambdaEndpointShapes` must name it |
| may a CONSUMER supply the translate into it? | a separate question, with its own answer |

a shape and a translate slot are not the same thing, so the count of one never bounds the other.
to delete a **shape** because its **translate** looked redundant erased the vocabulary for *the
very value this wish is about* — what lands on the wire — and re-created draft 4's defect
(the points unnamed) on the output side.

**the fix was the binding, never the member.** `outputAfter` is not another
`ApiGatewayResponse<TBody>`; it is the **envelope after the encode**, whose contents are opaque by
then — the body is a `string`, whatever `TBody` was:

```ts
outputBefore: ApiGatewayResponse<TBody>;  // body: TBody   — the domain type is live
outputAfter: APIGatewayProxyResult;       // body: string  — an envelope, contents spent
```

the two differ, so the slot constrains something real, and the encode becomes what it always was:
**the default output translator**, exactly parallel to `asApiGatewayEvent` inbound.
that is the symmetry the namespace was reaching for, and it now holds without a fudge:

| slot | default | `false` means |
|---|---|---|
| `payload.input` | `asApiGatewayEvent({ deserialize: { body: true } })` | the untouched wire event reaches `invoke` |
| `payload.output` | `asApiGatewayResponsePayload` — `status ?? 200`, `body ?? ''`, body→string | `invoke` returns the wire result itself, verbatim |

that `false` on the output side is worth the whole restoration: it is **total wire control**, the
wish's own theme, stated in the config rather than argued around. and note it is what the
hand-rolled `forApiGatewayPlain` adapter effectively did (`0.wish.md:53-73`) — a consumer who wants
that adapter's exact behavior now declares it.

so the earlier claim that the encode is "adapter-fixed" was itself the arbitrary move. **no fact
made the inbound translate overridable and the outbound one not** — that asymmetry was an artifact
of binding `outputAfter` to the wrong type and then reasoning from the redundancy it produced.

⚠️ **the wisher's fallback matters even where a family cannot say more.** *"or we can say
`outputAfter: Envelope<any>` — e.g. the api gateway envelope, but the contents any."* that is the
escape hatch that keeps the bag honest: where a family genuinely cannot name the post-encode
contents, it binds the envelope with opaque contents, or `unknown` outright. **a shape is never
deleted for lack of a precise type** — an imprecise binding still holds the term, and a held term
is what the bind is for.

#### the names are positions at the translator boundary, not claims about the value

an earlier draft used `payloadInput` / `payloadOutput`, which forced a claim about *what the value
is* — and every such claim ran into trouble: `Serialized` is false (the runtime already parsed the
envelope), `Payload` is true but only by AWS's own convention, and `Raw` names a quality rather
than a value.

`before` / `after` name the **position relative to the translator**, so no claim is needed. it is
also the repo's own documented pattern — `rule.require.order.noun_adj` gives **`userbefore`,
`userafter`** as its canonical examples, so `inputBefore` / `inputAfter` is `[noun][adj]` exactly
as prescribed, and the four sort direction-grouped:

```
inputAfter, inputBefore, outputAfter, outputBefore
```

the map to the extant vocabulary is exact:

| shape | is | extant name | schema |
|---|---|---|---|
| `inputBefore` | the wire in, as it lands | — (was unnamed) | — |
| `inputAfter` | what `invoke({ event })` gets | `TInput` | **`schema.input`** |
| `outputBefore` | what `invoke` returns | `TOutput` | **`schema.output`** |
| `outputAfter` | the wire out, contents spent | — (was unnamed) | — |

note what that table shows: **the two absent names are the wire-side pair.** the sdk had vocabulary
for the handler's contract on both sides and none for either wire shape — which is why the inbound
translate was hardcoded (only a sliver, `deserialize.body`, was ever exposed) and the outbound one
was hardcoded outright.

and note the two schemas sit on the **handler's** side of both translators, never the wire's. that
is the point-of-consequence rule, and it is also what keeps codegen fed: the wire shapes carry a
`string` body, so a schema on either would report an envelope with spent contents.

one wrinkle, recorded rather than hidden: `before`/`after` alternates which side is "outer".
`inputAfter` and `outputBefore` are the two **handler-side** shapes; `inputBefore` and `outputAfter`
are the two **wire-side** shapes. a reader who carries "after = later in the pipeline" reads all
four right; one who carries "after = outer" gets the input side backwards.

⚠️ **the wrinkle has teeth, and it bit this vision.** the F25 defect was exactly this: a draft
wrote `inputBefore: UnifiedApiGatewayEvent` (the **post**-translate shape) in one section and the
raw event in another. **the tell for a reviewer: check each shape against the pipeline diagram,
never against a peer's position.**

#### the tri-state, formalized

each `payload` member is tri-state, and the `.note` on `Translate` makes the three states a
**declared contract** rather than a convention:

| state | sense | who translates |
|---|---|---|
| **absent** (`undefined`) | the family's default translator runs | the sdk |
| **`false`** | **disarmed** — no translate; the shape passes through untouched | no one |
| **a function** | yours, in place of the default | the consumer |

the absent/off split is the part that carries the weight: absence and `false` carry **opposite**
senses here (default-on vs translate-off), so a reader must not be left to infer which is which.
this is the deliberate exception to `rule.forbid.undefined-inputs` — that rule forbids
`undefined` where it smuggles a third state, and here the third state **is** the contract,
declared and documented.

⚠️ **the tri-state is documented, not aliased.** a draft extracted
`TranslateMember<TFrom, TInto> = Translator<TFrom, TInto> | false` and justified the alias as
what "formalizes the tri-state". the wisher asked *"why is it called TranslateMember?"* and then
cut it: *"no TranslateMember; just Translator is good."* two defects behind that question:

- **the name names its own container.** a grep finds `member` in this repo exactly 6 times, all
  as a local variable inside codegen that emits TypeScript object literals
  (`getTypescriptFromJsonSchema.ts:97`, `asResourceClassSource.ts:98,117`) — so its only extant
  sense is "a property in generated source", which is syntax jargon, not a domain term.
  `TranslateMember` therefore reads as "a property of `Translate`" and says not one word about
  what the value is. same class as `TranslatePipeline` (F19), at the same one-level-up position
  the `ungrounded-type-params` reviewer test names.
- **a type alias cannot formalize a tri-state.** the enumerated `.note` does that, and it belongs
  on `Translate` where a reader meets it. the alias was credited with a job it cannot perform.

the union inlines at 2 usages, below the rule-of-three (`rule.prefer.wet-over-dry`), and the
`| false` is now visible **at the site a consumer writes it** rather than behind an alias they
must go open. the tell that settles it: no good name existed — `TranslatorOrOff`,
`DisarmableTranslator`, `TranslateOption` are each either mechanism-jargon or break
`rule.require.order.noun_adj`. **when no name fits, there is usually no concept there.**

#### the off-state is `false`, never `null` — and the reason generalizes

⚠️ **an earlier draft used `null` for the off-state, and the wisher caught it: *"translate:
payload: input: null? vs translate: payload: input: false"*.** `false` is correct, on two
independent counts.

**1. `undefined` and `null` must not carry opposite senses.** they are the two most confusable
values in the language, and this contract assigns them *inverse* behavior — absent means the
translator **runs**, off means it **does not**. a reader who misremembers which is which gets
the exact inverse, and every idiom that flattens the pair (`??`, `?.`, truthiness) hides the
error. `false` is maximally distinct from `undefined`, so `undefined | false` cannot be misread
the way `undefined | null` can. **the general lesson is enbriefed** as
`rule.forbid.opposite-senses-on-undefined-and-null`.

**2. the repo already draws this line, and this concept already sits on the `false` side.**

| pattern | how this repo reads it |
|---|---|
| `exid: string \| null`, `body: string \| null`, `rawBody: string \| null` | **an absent value** |
| `isBase64Encoded: false`, `isContempCaller: false`, `success: false` | **a switch that is off** |

our sense is *"the translate is off"* — a switch, not an absence. and the precedent is exact:
`deserialize: { body: false }` (`forApiGateway.test.ts:264`) is **this very concept, in this
very position**, already expressed as `false`. the field moves to the translator factory (F21),
but the vocabulary should not move with it.

`rule.forbid.nullable-without-reason` cuts the same way — it demands a clear *domain* reason
for a nullable, and "off" is a boolean concept, not an absence concept.

this **removes `TAlias` entirely**, and with it the closed alias set, the de-alias step, and the
`never` default. one generic remains.

it also retires a footgun this vision measured empirically: `never` means **opposite things by
position** — it closes a union, but a `never` in a *parameter* slot is contravariant and accepts
every function, so `inputBefore: never` would have silently **opened** the slot rather than closed
it (probe: `.temp/probe.variance.ts`, case 2 compiled clean). with no alias union, no `never`
appears in the shape at all.

#### the default is a real function — the family ships a translator factory

what was an alias becomes an exported factory, so the default is a value a consumer can name,
inspect, and re-configure rather than a flag the sdk interprets:

```ts
/**
 * .what = the api-gateway payload translator: v1/v2 unify + base64 decode, then body extract
 * .why = the family's default; exported so a consumer can re-configure it instead of
 *        re-implement it
 *
 * .note = it composes BOTH extant input steps, so its output is what invoke gets
 *         (inputAfter), not the intermediate UnifiedApiGatewayEvent. that intermediate
 *         is a step INSIDE this function, never a point in LambdaEndpointShapes (F25)
 */
export const asApiGatewayEvent = <TInput>(input: {
  deserialize: { body: boolean };
}): Translator<ApiGatewayEventPayload, TInput> => ...;
```

note the option keeps the **extant vocabulary verbatim** — `deserialize: { body: boolean }`, the
wisher's call. the term does not disappear; it **moves to the grain where it is accurate**. it was
never a property of the endpoint, it was a property of this translator, and the factory is where
it belongs (`rule.prefer.most-common-denominator`).

⚠️ **the return type is `TInput`, not `UnifiedApiGatewayEvent` — and that is the F25 fix.** an
earlier draft returned the intermediate, which forced `inputAfter` to be the envelope and left
`TInput` buried one level inside it, reachable only through the extant `event.body as TInput` cast
(`forApiGateway.ts:158`, an `as`-cast against `rule.forbid.as-cast`). once the translator composes
**both** steps, its output is exactly what `invoke` receives, the cast has no work left, and the
two families bind `inputAfter` identically.

a consumer who wants the intermediate as their handler shape still has it — bind
`TInput = UnifiedApiGatewayEvent` and pass `{ deserialize: { body: false } }`.

so all three cases are expressible, and the middle one needs no hand-composition:

```ts
// default (absent) — equivalent to:
input: asApiGatewayEvent({ deserialize: { body: true } })

// unify, no body parse — exactly today's `deserialize: { body: false }`
input: asApiGatewayEvent({ deserialize: { body: false } })

// disarmed — the untouched APIGatewayProxyEvent reaches invoke
input: false
```

#### `deserialize` is removed from the endpoint config

the field goes away as *endpoint* config — the wisher's call: *"rip out
`deserialize: { body: false }` altogether."* it survives as the translator factory's option, so
**no capability is lost and no trade is owed**:

| case | today | after |
|---|---|---|
| parse the body | `deserialize: { body: true }` (default) | absent (default) |
| unify, no parse | `deserialize: { body: false }` | `asApiGatewayEvent({ deserialize: { body: false } })` |
| no translate at all | **inexpressible** | `input: false` |

the factory form is longer at the call site than the boolean was, which is the honest cost — but
it buys a third state the extant config could not express, and it puts the option on the thing it
actually configures. `[case6]` (`forApiGateway.test.ts:251-277`) is rewritten against the factory
form, so the behavior stays under test.

#### the off-state needs no equality constraint — it defines one

a draft of this section called it a hole that the compiler cannot verify `inputAfter` equals
`inputBefore` when the member is off, and proposed a conditional type to close it. the wisher cut
that: **if it is off, there is no need to confirm it.**

right, and on two counts:

1. **`false` makes them identical by definition.** no translate runs, so the shape that reaches
   `invoke` *is* the shape that landed. there is no pair to reconcile — a constraint would restate
   what the state already denotes.
2. **a mismatched `schema.input` fails loud anyway.** validation is always-on (F8 — `schema` is
   required, `z.any()` to opt out), so a consumer who disarms while declaring the parsed shape gets
   a zod error that names the field. that is `rule.require.failfast` at the layer that owns it, not
   a silent defect.

so the conditional type would have bought a compile-time check for a case the runtime already
catches loudly, at real ceremony — `rule.prefer.prevent-over-correct` puts a type at the top of the
ladder, but only where the error is otherwise **silent**. this one is not.

the general lesson, worth a reviewer's attention on any tri-state: **do not add a type-level
constraint for an invariant a state makes true by construction.** the state is the proof.

#### every name here traces — including the ones an earlier draft invented

a draft of this section named the bag `TranslatePipeline` and typed the functions inline. two
defects, both caught by the wisher:

- **`Pipeline` is an invented mechanism-word.** it appears nowhere in this repo, which is the
  exact defect `rule.forbid.ungrounded-type-params` names — committed in the same document that
  states the rule, one level up from where it was applied.
- **the function had no name at all**, though `asPayloadTranslator` and
  `asApiGatewayEvent` were already in this vision's own text. **`Translator` was
  the extant domain noun the whole time**, and the type failed to use it.

| name | traces to |
|---|---|
| `Translator<TFrom, TInto>` | the agent noun already in use here; `from`/`into` follow the repo's `--from` / `--into` skill convention |
| `LambdaEndpointShapes` | `LambdaEndpoint` (the repo's core domain entity — `define.lambda-endpoint-ubiqlang`) + `shape` (`rule.require.shapefit`) |
| `inputBefore` / `inputAfter` | `input` (extant) + `before`/`after` — the literal examples in `rule.require.order.noun_adj` |
| `outputBefore` / `outputAfter` | `output` (extant) + the same pair |
| *(no alias for the tri-state)* | a draft added `TranslateMember`; deleted (F24) — `member` traces only to codegen jargon, and a `.note` on `Translate` carries what the alias claimed to |

note that `Translator<TFrom, TInto>` is a **two-parameter generic utility**, which the rule's own
caveat permits without a domain term per slot — it is `Ref<T>`-grade plumbing, not a
domain-specific contract.

the alias set is **gone entirely** (see the tri-state section): the default is now an exported
factory, so there is no second type parameter and no closed union to maintain.

#### the four points — a structural bind to the terms

`inputBefore`, `inputAfter`, `outputBefore`, `outputAfter` are the **fundamental types of any lambda
endpoint**. the `extends LambdaEndpointShapes` clause makes them a **structural bind**: a family
cannot express a translate without a value for all four, so the compiler — not a review — is what
holds the vocabulary. that is the durable constraint against future deviation, and it is worth more
than the ceremony it costs.

every design defect on this stone was a **conflation of one adjacent pair**, which is the case for
the bind:

| conflation | what it produced |
|---|---|
| `inputBefore` ≡ `inputAfter` | the `event`-vs-`payload` error — the wire shape was assumed to *be* the handler shape, which produced a false claim that the type could not be symmetric |
| `outputBefore` ≡ `outputAfter` | **the wish's own root defect** — `{ statusCode: 200, body: JSON.stringify(x) }` assumes the handler's return *is* the wire payload, so a body was the only thing a handler could author |
| `inputAfter` ≡ a step inside the default translator | the F25 incoherence — `UnifiedApiGatewayEvent` promoted from an internal step to a named point, so three shapes had to fit two names |

⚠️ **and the bind caught a fourth conflation — its own (F26).** a draft named `outputBefore` and
`outputAfter` and then **bound both to `ApiGatewayResponse<TBody>`**, so the bag re-committed row 2
at the very site built to refuse it. this vision's first correction made it worse: it deleted
`outputAfter` rather than fix the type, which traded a tautology for an **absent term**.

two lessons, and the second is the one a reviewer should carry:

- **a bind can hold a wrong model as firmly as a right one** — so
  `rule.require.retest-the-model-on-every-family` asks that the model be re-tested *before* it is
  bound, not after.
- **when a bound pair collapses to one type, suspect the binding before the member.** the member
  usually names a value the domain genuinely has; the type usually names it wrong. delete a term
  only once you have tried `unknown` there and found the term itself empty.

and note the bind is empirically verified, not asserted: the probe confirmed that an omitted member
fails the `extends` clause (TS2344 — `.temp/probe.variance.ts`, case 4).

#### why a named bag, and not a positional list

three earlier drafts grew a positional parameter list, and one over-corrected and removed the
parameterization entirely:

| draft | shape | defect |
|---|---|---|
| 1 | `<TRaw, TInput, TSpec>` | 2 of 3 invented; `TRaw` names a quality, not a value |
| 2 | `<TRaw, TInput, TOut, TWire, TSpec>` | 4 of 5 invented; `TOut` a synonym of extant `TOutput` |
| 3 | `<TPayloadInput, TInput, TOutput, TPayloadOutput, TDeclared>` | all traced, but 5 positional slots a reader must count, and `TDeclared`'s ground was weak |
| 4 | `<TPayload>`, families inline their own types | ✅ no invented names — but it left **the four points unnamed**, buried in anonymous object literals, so no bind survived |
| 5 | `<TPipeline extends TranslatePipeline>` | bound and non-positional — but `Pipeline` was itself invented, and the translator function stayed anonymous |
| 6 | `<TShapes extends LambdaEndpointShapes, TAlias = never>` | every name extant — but the member names still claimed *what the value is* (`payload*`), and `TAlias` carried a closed union the tri-state made unnecessary |
| 7 | four members, `outputAfter` bound to `ApiGatewayResponse<TBody>` | positions, not claims — but the output pair bound **one type in every family**, a tautology (F26) |
| 8 | three members, `outputAfter` **deleted** | over-corrected: a shape deleted for its slot's redundancy, so the wire-out term became unnameable (F26) |
| **9** | **four members, `outputAfter` bound to `APIGatewayProxyResult`** | ✅ the pair differs, so every slot constrains something real and no term is absent |

draft 4's collapse rested on a rule that was **over-applied**: *"a generic whose every bind is a
constant is not a generic."* that test asks whether a **caller** varies the type — but
`Translate` lives at the **ancestor**, and its consumers are the two **families**. across
families the payload types genuinely do vary. so parameterization was never the defect;
**positional** parameterization was.

draft 4's real cost was worse than a long list: it made the four most important types in the design
anonymous, so a reader had to re-derive each from its position in an inline literal, and the
vocabulary rested on discipline rather than on the compiler. **draft 8 repeated that cost on one
member** — proof the failure mode recurs whenever a term is dropped for a local convenience.

#### each family binds the points by name

```ts
// ── forApiGateway
translate?: Translate<{
  inputBefore: ApiGatewayEventPayload;           // the wire in, v1 or v2, untouched
  inputAfter: TInput;                       // what invoke gets, what schema.input validates
  outputBefore: ApiGatewayResponse<TBody>;  // what invoke returns, what schema.output validates
  outputAfter: APIGatewayProxyResult;       // the wire out, body already a string
}>;

// ── genLambdaEndpoint
translate?: Translate<{
  inputBefore: LambdaHandlerInput<TInput>;  // wrapped or flat
  inputAfter: TInput;                       // what invoke gets
  outputBefore: TOutput;                    // what invoke returns
  outputAfter: TOutput;                     // the return IS the payload — no encode to run
}>;
```

`TInput` and `TOutput` remain **extant and unmoved** (`forApiGateway.ts:122`,
`genLambdaEndpoint.forAskEndpoint.ts:83`, plus both `schema` fields) — the only two type-parameter
names this repo ever had.

**both families now read identically at every slot's sense**, which is what the bind was for.
`inputAfter` **is** `TInput` in both; `outputBefore` **is** the handler's return in both;
`schema.input` describes `inputAfter` and `schema.output` describes `outputBefore` in both.

and note the one place the families genuinely **diverge**, which is the bind earning its keep:

| family | `outputBefore` → `outputAfter` | why |
|---|---|---|
| `forApiGateway` | `ApiGatewayResponse<TBody>` → `APIGatewayProxyResult` | an http envelope must be encoded; the body becomes a string |
| `genLambdaEndpoint` | `TOutput` → `TOutput` | a lambda invoke response **is** the payload; no encode exists to run |

so ask-endpoint's output pair is identical **because its domain says so**, not because the model
fudged it — and its `payload.output` default is a true identity. api gateway's pair differs, so its
default is a real encode. one namespace, two honest bindings: exactly the variation
`rule.forbid.ungrounded-type-params` says a parameter must have to earn its slot.

#### the three corrections that got the bindings here (F25)

a draft of this section wrote api gateway's bindings **two different ways in two sections**, and
the wisher caught it: *"is the vision coherent? seems weird."* it was not. the contradiction:

| where | it claimed `inputBefore` was |
|---|---|
| the family-binding section | the RAW v1/v2 event |
| the pipeline section | `UnifiedApiGatewayEvent` |

both survived because each section reasoned locally. that is the tell, and the contradiction was
a **symptom** — three defects sat beneath it.

**1. the model was derived from one family and never re-tested against the other.**
api gateway's input side runs **two** transforms — unify+decode, then body-extract
(`forApiGateway.ts:158`) — while ask-endpoint runs one. so three shapes had to fit two names, and
each section picked a different pair.

the resolution: **a step the sdk owns is never a point in the model.** the bag names only the
boundaries a *consumer* can hook. the `UnifiedApiGatewayEvent` is a step **inside**
`asApiGatewayEvent`, so the default absorbs both steps and returns `TInput`. it
remains a real type and a useful one — it simply is not a point, any more than middy's serializer
is.

⚠️ **and this rule has a limit F26 had to find the hard way.** "a step the sdk owns is never a
point" is about **which translates a consumer may drive** — it says not one word about which
*shapes* exist. F26's first pass over-read it, concluded the wire encode's output shape was
therefore no point, and deleted `outputAfter`. the encode is in fact a **default** a consumer may
replace, so it was never sdk-owned in the sense this rule means.

**2. `schema` described a sub-field, so the two namespaces could not be lined up.**
`schema.output: ZodSchema<TBody>` names the body inside the output point. the wisher's rule —
`schema.input` describes `inputAfter`, `schema.output` describes the output point — closes the gap
on both sides, and is what makes the drift detectable next time: **every schema names a point, so a
reader can check the pair against the bag in one glance.**

**3. the extant `.body as TInput` cast was the conflation, in code.** `forApiGateway.ts:158` reads
`event.body as TInput` — an `as`-cast (`rule.forbid.as-cast`) that *asserts* the relation the
translator should *derive*. once the default translator returns `TInput`, the cast has no work left
and goes away. the defect and its fix both sat in the one line the model could not name.

#### what the corrected shape costs `invoke`

`rawEvent: UnifiedApiGatewayEvent` becomes `payload: ApiGatewayEventPayload` — the untouched v1-or-v2
event, since that is now the named point (`inputBefore`) rather than a translator's internal step.
**this is a second break to `invoke`'s signature**, on top of the return-type break the wisher
already licensed.

three notes on the trade:

- the rename is honest: `rawEvent` was **not** raw — it was normalized. `payload` is the extant
  bidirectional term (F13) and `inputBefore` is the point it names.
- no power is lost. a consumer who wants the normalized shape binds
  `TInput = UnifiedApiGatewayEvent` and supplies
  `asApiGatewayEvent({ deserialize: { body: false } })` — the factory is exported
  precisely so the default is re-configurable rather than re-implementable.
- ⚠️ **it widens the break past what the wish asked for.** the acceptance asks for wire-response
  control; `invoke`'s *input* signature is not that. a reviewer may reasonably scope this to the
  `translate` deliverable (already flagged as out-of-acceptance) or defer it, and accept that
  `inputAfter` stays envelope-shaped until then.

#### `payload.output` has evidenced consumers — the wisher named two

⬆️ **[wisher: "the output translator sanitizes any sensitive info; or flags for profanity"]** — that
retires this vision's repeated claim that the slot served no one. both examples are **load-bearing**
response work: they change what the http client receives, so neither can live in `translate.log`
(cosmetic, cloudwatch-only) and neither belongs in the handler, since the point of a redaction pass
is that **every** response gets it, whatever branch produced it.

| consumer | what it supplies | why not elsewhere |
|---|---|---|
| the wire encode | `status ?? 200`, `body ?? ''`, body→string | the family's default — the sdk's own translate, now nameable |
| a redaction pass | strips PII / secrets from any response before it leaves | in the handler it must be repeated per return; in `log` it would sanitize only cloudwatch |
| a profanity flag | screens generated body content | same — one gate, applied to every response |
| total wire control | `false` — `invoke` returns the `APIGatewayProxyResult` itself | this is what `forApiGatewayPlain` hand-rolled (`0.wish.md:53-73`) |

and the redaction case shows the slot **composes** rather than replaces, exactly like the input
side. a consumer who redacts still wants the encode, so they wrap the exported default:

```ts
translate: {
  payload: {
    output: (response) => asApiGatewayResponsePayload({ response: asRedactedResponse(response) }),
  },
}
```

that is why the default is an **exported factory** and not an inlined step: a consumer extends it
without re-implementing `status ?? 200` and the body→string encode.

⚠️ **this reverses three earlier claims in this vision — the reversals are the record worth
keeping.** F13 called the wire map "the outbound load-bearing cell" but gave it no slot; F25 bound
it as an identity and called it symmetry-only; F26's first pass deleted it as unused. all three
shared one root error: **the slot was judged by whether the SDK needed it, never by what a consumer
would want to do there.** the wisher's two examples took seconds to produce, which is the measure of
how weak the "no evidenced consumer" claim was.

**a reviewer's test, corrected:** a slot earns its place if a **consumer** can name a transform they
would put in it. do not test the slot against the sdk's own defaults — the sdk's default is only
ever the *first* occupant.

#### one honest cost

the indexed accesses (`TShapes['inputBefore']`) make the *declaration* slightly noisier than
positional parameters would, and typescript's error messages on a mismatch are a little worse.
the trade is deliberate: a declaration is read once, a bind site many times, and the bind sites
are where the conflations happen.

#### the grid — four cells, each with a real default

the axes are **direction** × **blast radius**, and every cell holds a member with a default a
consumer may replace:

| | load-bearing (the handler or the wire sees it) | cosmetic (only cloudwatch sees it) |
|---|---|---|
| **inbound** | `translate.payload.input` — default: `asApiGatewayEvent` | `translate.log.input` — default: metadata-only (F10) |
| **outbound** | `translate.payload.output` — default: `asApiGatewayResponsePayload` (the wire encode) | `translate.log.output` — default: metadata-only (F10) |

⚠️ **this vision filled that outbound load-bearing cell four different ways before it landed.** an
early draft called it empty; F13 called it the `ApiGatewayResponse → APIGatewayProxyResult` map; a
draft bound it as an **identity** on `ApiGatewayResponse<TBody>`; F26's first pass then **deleted**
it. the sequence is the useful record, because each error had a distinct cause:

| draft | the cell held | why it was wrong |
|---|---|---|
| 1 | empty | the encode demonstrably runs on every response |
| 2 (F13) | the encode, unnamed as a member | right value, no slot — so it could not be driven |
| 3 (F25) | `Translator<Response, Response>`, identity | **the wrong type**; an identity default looks like a member while it constrains no one |
| 4 (F26 first pass) | deleted outright | a **shape** deleted for a **slot**'s redundancy — a category error |
| **5** | `Translator<ApiGatewayResponse<TBody>, APIGatewayProxyResult>`, default = the encode | the pair differs, so the slot is real and the default is honest |

draft 3 is the one a reviewer should study: **an identity default is how a miscategorized step
disguises itself as a working member.** the tell is that both ends bind one type. draft 4 shows the
matching over-correction — the tell there is that a *named value the domain plainly has* stops being
nameable.

**and the restored cell settles a question the deleted one had to argue.** with `payload.output`
present and always applied, `invoke` remains the sole **author** of the response while the encode is
a **stage** over it — composition, not the fork `rule.forbid.parallel-codepaths` guards against.
there is one path; `false` merely shortens it.

the serializer's `Content-Type` behavior stays where it is: a branch on **observed data**
(the handler set a content-type, or did not), which that rule explicitly permits.

#### the boundary — what belongs under `translate`, and what does not

`deserialize` sits under `translate` because it **is** a translate: string ⇄ object is a
re-render of one value, so `translate` is the genus and `deserialize` a species. the parts do
not vary independently (a deserialize is always a translate), which is why this narrows rather
than mashes (`rule.forbid.names-that-mash-dimensions`).

but that raises the real hazard: if a deserialize is a translate, nearly every middleware
touches data in flight, and `translate` becomes a dump for the whole chain. so the namespace
owes a boundary test.

**a translate re-renders the same subject, derived from that subject.**

lossiness does **not** disqualify. an eli5 is a translation; so is a summary, so is a
redaction. no translation between natural languages preserves every nuance — reduced fidelity
for a different audience is what translation *does*. so `translate.log` is honest rather than
loose: it re-renders the payload for a reader who must not see secrets.

what disqualifies is **fabrication** (information that was never in the subject) or
**substitution** (a different subject altogether):

| operation | same subject, derived from it? | verdict |
|---|---|---|
| deserialize body | yes — string ⇄ object | **translate** |
| v1/v2 unify | yes — same fields, one shape | **translate** |
| trail unwrap (`{ event, trail }` → event) | yes — a split, no loss | **translate** |
| `ApiGatewayResponse` → `APIGatewayProxyResult` (the wire encode) | yes | **translate** → `payload.output` |
| redaction of a response body | yes — lossy, still the same subject | **translate** → `payload.output` |
| metadata-only log projection | yes — lossy, still the same subject | **translate** → `log` |
| schema validation | no — asserts about it, re-renders no value | **not** |
| cors / security headers | no — **fabricates** info absent from the subject | **not** |
| error → response | no — **substitutes** a different subject | **not** |
| introspection short-circuit | no — **substitutes** the schema for the response | **not** |

so `cors` and `schema` stay **peers** of `translate`, never members — which is the shape
already proposed, now with a reason rather than an intuition. a reviewer can apply this test to
any future config member instead of a fresh debate about the namespace.

⚠️ **and note this table predicted F26, four drafts before the design caught up.** row 4 has said
"the wire encode is a translate" since this section was first written — while the grid section
simultaneously called it "adapter-fixed, never a member," and a later pass deleted its output shape
outright. **the design contradicted its own boundary test and no self-review noticed**, because each
section was read on its own terms.

that is the sharpest available argument for `rule.require.review-attempts-deletion`: a verification
review reads each claim against its neighbors, so a document that states a test in one place and
breaks it in another passes every local check. **the tell a reviewer can actually use: apply the
document's own stated test to the document's own conclusions.**

#### one grammar — a translator, always

a draft of this section defended a **mixed** grammar: a boolean alias (`deserialize: false`) beside
a function. it argued the alias was shorthand for a translator we own, which was true but did not
justify the second grammar — the alias needed a de-alias step, a closed union to maintain, and a
type parameter (`TAlias`) to carry.

the tri-state removes all three, because the shorthand becomes **the function itself**:

```ts
// what was an alias
{ deserialize: { body: false } }

// is now simply the factory that alias named
asApiGatewayEvent({ deserialize: { body: false } })
```

so every state of a `payload` member is either a `Translator` or `false`. one grammar, no
translation between grammars, and the option keeps its extant name at the grain where it is
accurate.

#### the tri-state collapses once, at construction

no code path may fork on which state the caller supplied
(`rule.forbid.parallel-codepaths` — a fork on handed config):

```ts
// decide ONCE per direction; the chain sees exactly one function each
const translateIn =
  config.translate?.payload?.input === false
    ? identity                                                    // disarmed
    : (config.translate?.payload?.input ??
       asApiGatewayEvent({ deserialize: { body: true } }));  // default

const translateOut =
  config.translate?.payload?.output === false
    ? identity                                        // disarmed: invoke returns the wire shape
    : (config.translate?.payload?.output ??
       asApiGatewayResponsePayload);            // default: the wire encode
```

three states in, one function out, on each side — so no middleware ever branches on the caller's
choice. note this is the **one** place the off-state and `undefined` must be told apart, which is
why the `.note` on `Translate` declares the distinction rather than a reader's inference
(`rule.forbid.undefined-inputs` — the declared exception). the `=== false` guard is also why the
off-state must not be `null`: an `if (!supplied)` shorthand would collapse absent into off, and a
`?? default` would treat off as absent — both silent inversions the explicit comparison avoids.

⚠️ **and note `identity` is type-honest only in the disarmed case.** on the input side
`false` makes `inputAfter ≡ inputBefore` by construction (F22); on the output side it makes
`outputAfter ≡ outputBefore`, so the handler must return the wire shape itself. in **both** cases
the identity is well-typed exactly because the caller disarmed it — which is why no conditional
type is owed at either end.

#### every member is optional — and that is the rule, not an exception to it

`rule.require.explicit-optout` fires only when **absence disables a guarantee**. it offers
two legitimate remedies, and this namespace uses the second:

| remedy | where this design uses it |
|---|---|
| require the field + an explicit opt-out value | `schema` — `z.any()` opts out |
| **make the default the guarded one** | `translate` — absence is the safe path |

- `translate.log` absent → the metadata-only projection (F10). absence is the **guarded**
  state, so no guarantee is disabled by omission. the opt-**in** is what must be written:
  `translate: { log: { input: (e) => e } }` — an identity projection the author declares,
  visible at the call site and reviewable as a choice.
- `translate.payload.input` absent → the family's extant normalization, i.e. today's
  behavior unchanged.
- `translate.payload.output` absent → the family's extant wire encode, i.e. today's behavior
  unchanged. **absence is the safe path on both payload members**, because each default is the
  step the sdk already ran.

so `translate?`, `translate.payload?`, and `translate.log?` are all correctly optional. had
`log` kept its identity default, this rule would have demanded it be required — the F10
default is precisely what earns the option. the `payload` members differ in kind: absence asks
for the family's **extant** translate, so omission changes no guarantee at all.

⚠️ **the one place this rule bites is the opt-IN, not the opt-out (F26).** a consumer who supplies
`payload.output` **replaces** the encode, so a forgotten wrap of
`asApiGatewayResponsePayload` disables it silently. that inverts the safe default the moment
the field is present — a real `rule.require.safe-by-default` hazard, recorded at awkwardness #10
with a `{ before }` / `{ after }` compose affordance as the candidate fix.

#### `inputAfter` is free — a consumer may hand `invoke` any shape at all

the bind makes an important capability explicit that the extant config hides: `inputAfter` is
**not** constrained to "the payload minus a wrapper". it is whatever the translator returns, and
`schema.input` declares it. so a consumer can hand `invoke` a domain object:

```ts
genLambdaEndpoint({
  schema: { input: SurfLessonSchema, output: z.undefined() },   // input = SurfLesson
  translate: { payload: { input: (payload) => asSurfLesson(payload.Records[0].body) } },
  invoke: async ({ event }) => { /* event: SurfLesson */ },
});
```

`inputAfter` here bears no resemblance to `inputBefore` — which is exactly the point to name both.

⚠️ **but that example does not type-check against the extant signature, and the reason is a
find worth the record.** `genLambdaEndpoint<TInput, TOutput>` declares its handler as
`MiddyfiedHandler<LambdaHandlerInput<TInput>, ...>`
(`genLambdaEndpoint.forAskEndpoint.ts:93-98`), and `LambdaHandlerInput<TInput>` is
`FlatPayload<TInput> | WrappedPayload<TInput>` — i.e. **`TInput` wrapped**. so `inputBefore` is
today *derived from* `input`, which forbids the very freedom claimed above: an sqs record is not
`SurfLesson & { trail? }`.

so the two are **structurally conflated in the extant signature** — the exact defect the bind
exists to expose, caught by the bind itself on its first application. the fix is one added
parameter with a default, so no extant caller changes:

```ts
export const genLambdaEndpoint = <
  TInput,
  TOutput,
  TPayload = LambdaHandlerInput<TInput>,   // default preserves today's behavior
>(...): middy.MiddyfiedHandler<TPayload, TOutput, Error, Context> => ...
```

with the default, `inputBefore: LambdaHandlerInput<TInput>` stays correct for every extant
consumer, and a consumer who supplies a translator names its own `TPayload`. the same holds for
`forApiGateway`, whose payload is fixed by the trigger and so needs no parameter.

**this is a genuinely new find, not a wisher instruction** — it enlarges the F12 diff by one type
parameter on one factory. flagged rather than absorbed in silence; a reviewer may reasonably
scope it to a later round and accept that `input` stays wrapper-derived until then.

#### the trail unwrap is an invariant, never replaceable

⚠️ **a translator composes AFTER the trail unwrap; it does not replace it.** an earlier draft's
example implied a consumer could supply a translator in place of the extant unwrap. that is a
footgun, because `getUnwrappedEventWithExid` returns **three** values, not one
(`getUnwrappedEventWithExid.ts:13-17`):

| it yields | what depends on it |
|---|---|
| `unwrappedEvent` | what `invoke` receives |
| `exidFromPayload` | trail correlation across invocations (`genTrailMiddleware.ts:30`) |
| `isContempCaller` | the ancient-vs-contemp error contract (`invariant.ancient-vs-contemp-callers`) |

a custom translator that replaced the unwrap would silently kill trail correlation **and** flip
every error body to the wrong format — a failure with no signal at the call site, against
`rule.require.safe-by-default`.

so **one sdk-owned step stands outside the namespace**, and all four points sit after it:

```
  wire → [ trail read: exid + isContempCaller ]   ← invariant, always runs, reads only
           │                                        sdk-owned, never a member
      inputBefore ── [translate.payload.input] ──> inputAfter
       the wire in       yours; default = the         what invoke gets
                         family's translator          │
                                         [schema.input validates] ← describes inputAfter
                                                      │
                                                  invoke({ event })
                                                      │
      outputBefore ─ [translate.payload.output] ─> outputAfter
       what invoke      yours; default = the wire      the wire out,
       returns          encode (status ?? 200,         body already a string
        │               body ?? '', body→string)               │
   [schema.output validates] ← describes outputBefore                → wire
```

note where each schema sits: **both guard the handler's own boundary**, and neither guards
`outputAfter`. that is deliberate — by `outputAfter` the body is a `string`, so a schema there
would report `{ statusCode, body: string }` to codegen and teach it none of the domain contract.

⚠️ **this diagram is where the F25 incoherence lived.** an earlier draft ended this section with
*"for `forApiGateway` the same holds of v1/v2 normalization: it runs first, which is why that
family's `inputBefore` is `UnifiedApiGatewayEvent` rather than a raw `APIGatewayProxyEvent`"* —
which contradicted the family-binding section outright, and was **wrong** for a reason worth the
record: the trail step and the v1/v2 unify are **not the same kind of step.**

| step | reads or re-renders? | outside the namespace? |
|---|---|---|
| trail read (`exid`, `isContempCaller`) | **reads** — the payload passes through untouched | ✅ yes — it re-renders no value, so it is no translate (see the boundary test) |
| v1/v2 unify + base64 + body parse | **re-renders** — a different shape comes out | ⛔ no — it is exactly a translate, so it belongs **inside** the default translator |
| wire encode (status default, body→string) | **re-renders** | ⛔ no — it is a translate too, and it is the **default** for `payload.output` (F26) |

so the unify does not "run first, before `inputBefore`" — it **is** the first half of what
`asApiGatewayEvent` does, and `inputBefore` is the untouched wire event it starts
from. the earlier draft had promoted a translator's own internal step to a model point.

note the table's third row is what F26 corrected: the wire encode reads as *sdk-owned* only because
the sdk shipped it. **it re-renders a value, so it is a translate, so it owes a slot** — and once it
has one, `outputBefore → outputAfter` is a pair a consumer can drive rather than a step they must
work around. exactly **one** step on this table sits outside the namespace, and it is the trail read,
because it re-renders no value at all.

#### one coupling worth a note

`schema.input` describes `inputAfter`, which is by definition the **post-translate** shape. a
consumer who supplies a custom `translate.payload.input` therefore owes a `schema.input` that
matches that translator's output, not the wire. that is coherent, and it means the introspection
report describes the handler's contract rather than the raw trigger's — the right choice for a
generated sdk, and worth a line in the readme so no consumer expects the wire shape.

**the way out owes no such debt**, and the reason is worth stating because it looks asymmetric:
`schema.input` sits **after** its translator, so a custom translator moves what it must describe;
`schema.output` sits **before** its translator, so a custom translator moves no part of what it
describes. `schema.output` always describes exactly what `invoke` returns.

that is the point-of-consequence rule paying out twice: each schema guards the handler's own
boundary, and only the inbound one can be moved by a consumer's choice. so a custom
`payload.output` never desyncs the contract — it only changes the bytes **after** the contract was
already verified, which is where a redaction or an encode belongs.

#### what the rename costs

`logTranslate` → `translate.log`, and `deserialize` is **removed** from endpoint config (it lives
on the translator factory instead). both are breaks, which the wisher has licensed. the
`IoLogTranslate` export becomes `TranslateLog`, and `asApiGatewayEvent` joins the
public surface. the ask-endpoint family gains `translate` where it had `logTranslate`, so its
extant tests move too — a wider diff than the wire-response work alone, and the deliberate price
of the lift.

#### the name is a motive, not a mechanism

an earlier draft filed `translate` under awkwardness as "a mechanism-name where the repo's
grain prefers a motive". the wisher corrected it: **the motive IS to translate.**

that is right, and the earlier read confused two levels. `howto.domain-discovery` asks that a
name state *why the thing exists*. why does this config exist? so a consumer can translate
between the wire's representation and the handler's. the translation is not the implementation
of some further purpose — it *is* the purpose. a mechanism-name here would be `mapFn`,
`transformHooks`, or `middlewareOverrides`: words that describe the machinery rather than the
intent.

"redaction" and "parse" are the motives of *particular instances*, not of the namespace. the
namespace's own motive is the act itself, and the members carry the instance motive — `log`
says which side, `payload` says which representation.

### `schema.output` describes `outputBefore`, and it always runs

one path, no conditional validation. the schema describes the **whole** response — the point
`outputBefore` names — and the body schema goes inside it via the envelope builder:

| endpoint | `schema.output` |
|---|---|
| always returns json | `asApiGatewayResponseSchema({ body: z.object({...}) })` |
| always 204 | `asApiGatewayResponseSchema({ body: z.undefined() })` |
| sometimes either | `asApiGatewayResponseSchema({ body: z.object({...}).optional() })` |
| opts out entirely | `z.any()` |

**a note on which of the four points this describes.** `schema.output` validates `outputBefore` —
the whole `ApiGatewayResponse<TBody>`, not the `body` inside it. that is the wisher's rule (F25),
and it fixes a real gap: a draft had `schema.output: ZodSchema<TBody>`, which named a field one
level **inside** a point, so a reader could not line `schema` up against the bag — and this vision
consequently wrote `inputBefore` as two different types in two sections.

**and it validates `outputBefore` rather than `outputAfter` on purpose (F26).** by `outputAfter` the
encode has run, so the body is a `string` — a schema there would report an envelope with spent
contents and teach codegen none of the domain type. so the schema sits where the domain type is
still live, which is also where a handler's mistake is still recoverable.

the envelope-level schema also buys a guarantee the body-level one could not: it proves the
response is **total** before it leaves. `{}` is already a compile error via `PickAny`
(`rule.require.illegal-states-unrepresentable`), and this closes the runtime half of the same
class — so a silent 500 cannot arrive from a path the compiler could not see.

per the wisher (F17), the `z.undefined()` requirement is a **pro**: the contract states its own
truth about whether a body exists, so a reader, a reviewer, and the introspection report all
learn it from the declaration rather than from the handler body. the builder keeps that legible —
`asApiGatewayResponseSchema({ body: z.undefined() })` reads as "a response whose body is undefined"
at a glance.

### serialization: the extant serializer becomes the mechanism, not the obstacle

`httpResponseSerializer` skips when `Content-Type` is already set (verified in the
installed source). so the two cases fall out of one chain:

- **handler omits `Content-Type`** → serializer JSON-stringifies `body`, stamps
  `application/json`. the convenient default, unchanged for json consumers.
- **handler sets `Content-Type`** → serializer returns early, body reaches the wire
  byte-identical. this is how xml works.

no chain fork. the escape hatch and the paved road are the same code path.

### timeline (bdd)

```
given  a twilio number pointed at an api-gateway route backed by forApiGateway
when   twilio POSTs a form-encoded voice webhook
then   the handler runs with a fresh trail exid and the raw body string

given  the handler throws a TypeError deep in a dao
```

## mental model

> "you hand the sdk a response instead of a value. omit `status` and it is a 200;
> omit `body` and there is no body; set a `Content-Type` and your bytes are yours."

**analogy** — a print shop that accepts either a manuscript (it lays out the
letterhead) or camera-ready art (it prints what you gave it). same shop, same
mailroom, one intake desk.

| they say | we say |
|---|---|
| "raw / passthrough response" | `ApiGatewayResponse` |
| "no schema" | `z.any()` — an explicit opt-out |
| "no body" | `body` omitted |
| "the raw event" / "the parsed event" | `inputBefore` / `inputAfter` — two of the four points |
| "what my handler returns" | `outputBefore` |
| "what goes on the wire" | `outputAfter` |
| "the response schema" | `asApiGatewayResponseSchema({ body })` — describes `outputBefore` |
| "sanitize / redact every response" | `translate.payload.output`, wrapped over the default (F26) |
| "i want to emit the raw wire result myself" | `translate.payload.output: false` |

there is deliberately **no new noun** for a response mode. an earlier draft proposed a
peer export named `forApiGatewayWire`, which mashed two orthogonal dimensions —
trigger (api gateway) and response mode (wire) — into one token, as if
"ApiGatewayWire" were a platform. it is not
(`rule.forbid.names-that-mash-dimensions`).

### the four points are the model worth carrying

> "a payload passes four points; the two in the middle are yours, and you may drive the
> translate into either edge."

```
        inputBefore → inputAfter → [ invoke ] → outputBefore → outputAfter
          the wire in    yours        yours         yours       the wire out
              └ translate ┘                            └ translate ┘
                         ↑                             ↑
                    schema.input                  schema.output
```

the extant sdk conflated the last two — it assumed `outputBefore` (what a handler returns) **was**
`outputAfter` (what api gateway receives), which is exactly why a 204 or an xml body could not be
said. every other confusion on this stone was a conflation of one adjacent pair too, so the
four-point model is the mental model that prevents the next one.

three properties make the diagram load-bearing rather than decorative:

- **the two schemas name points**, never a field inside one, so a reader can check the whole design
  against this one picture (F25)
- **both schemas sit on the handler's side** of their translator, because that is where the domain
  type is live and where a mistake is still recoverable
- **each edge translate has a real default** a consumer may replace or disarm — the inbound
  normalization, the outbound encode

⚠️ the model failed **twice** on this stone, and both failures were at an edge: once when
`schema` pointed at a sub-field and a translator's internal step got promoted to a point (F25), and
once when `outputAfter` was first bound to the wrong type and then deleted outright (F26). **the
edges are where a reader stops paying attention** — which is exactly why they are the two the sdk
had never named.

## evaluation

| acceptance line | met by |
|---|---|
| arbitrary status / headers / body, empty incl. | `PickAny<{ status, headers, body }>` returned unmodified |
| 204 / 308 / xml each proven expressible | three wire-byte tests |
| `BadRequestError` → 400 w/ errorMessage/errorType/causeMessage | reuse `genConstraintErrorMiddleware({ apiGateway: true })` — already emits exactly this (verified: `getErrorResponseBody.ts:50-63`) |
| that 400 leaves the invocation a SUCCESS | middy `onError` sets `request.response`, never rethrows (verified: `genConstraintErrorMiddleware.ts:55-68`) |
| other errors log loudly, 500, no leak | reuse `genInternalServiceErrorMiddleware` — **deliberate divergence from the literal "no body", wisher-approved, see F2** |
| the fixed-shape path still serves | ⚠️ **retracted by the wisher** — this is now a break; see below |
| coverage proves the wire bytes | proxy-integration harness + real `fetch` — **partially**; see F4 for the limit, now filed as `declastruct-aws#90` |

⚠️ **the `translate` namespace serves no row of this table.** F12–F26 — the config lift, the four
named points, the tri-state, the schema rule, the `invoke` input rename, the output-translate
slot — answer **no** acceptance line. the wish asks for wire-response control; a config namespace
is not that. it is in scope by wisher instruction, and it is the largest part of the diff.
a reviewer who weighs scope should treat the response work and the `translate` lift as two
deliverables that happen to share a branch, and may reasonably ask for them to share a branch no
longer (`feedback: one deliverable, one pr` — the habit this vision cited before the wisher
overrode it).

one caveat on that split, though: **`translate.payload.output` is the one part of the lift that
touches the acceptance's own subject.** `false` there is total wire control, which is precisely what
the hand-rolled adapter did — so a reviewer who defers the whole lift should check that the
response work alone still covers the adapter's case (it does, via `ApiGatewayResponse`; the slot
makes it declarative rather than possible).

### the retracted acceptance line

the wish says *"the extant fixed-shape path still serves consumers who want it. this
ADDS a way to own the response; it does not remove the convenient default."* the
wisher has **retracted** this: the library is new, so a breaking return-type change
costs no installed base, and one contract beats two.

what survives of the intent: the *convenient default* is preserved — `{ body: x }`
still yields 200 + json with no extra ceremony. what changes is that a handler returns
`{ body: x }` instead of `x`. this warrants a major version bump.

### pros

- **one contract, one chain, one export.** no drift between peers is possible,
  because there is no peer. this deletes the shared-chain-builder refactor, the
  peer-vs-flag fork, and the middy-vs-plain fork from the design entirely.
- **the guardrails survive.** trail, io logging, normalization, introspection all
  kept — the hand-roll lost every one.
- **the footgun closes at compile time.** `{}` is unrepresentable, so no field must
  be required to keep the response safe.
- **`z.undefined()` and `z.any()` make the contract state its own truth.** ⬆️
  **[wisher: this is a pro, not a con]** — an earlier draft filed the ceremony as a
  cost. it is the opposite. `output: z.undefined()` says "this endpoint returns no
  body" **in the contract**, so a reader, a reviewer, and the introspection report all
  learn it from the declaration instead of from the handler body. `z.any()` says
  "validation was declined here" as a visible, reviewable choice rather than an absent
  field nobody can tell apart from an oversight (`rule.require.explicit-optout`). the
  keystrokes buy a contract that cannot lie about whether a body exists.
- **the four points become structurally bound.** `LambdaEndpointShapes` means a family cannot
  express a translate without a value for `inputBefore`, `inputAfter`, `outputBefore`, and
  `outputAfter` — so the **compiler** holds the vocabulary that the extant code conflated,
  rather than a reviewer's vigilance (F16). it earned its keep three times: the bind caught the
  `inputBefore`-derived-from-`inputAfter` conflation in the extant ask-endpoint signature (F18),
  the F25 pass caught the `event.body as TInput` cast that had hidden the same conflation in
  the api-gateway family, and F26 caught a pair the bind itself had bound to one type — a defect
  that would have been invisible without four named slots to compare.
- **both wire shapes are now nameable, and one of them never was.** `outputAfter` is the value
  this whole wish is about, and the extant sdk had no term for it — which is why it could be
  hardcoded for so long without anyone able to say what had been hardcoded. a term you cannot
  say is a term you cannot review (F26).
- **`schema` and `translate` now line up, point for point.** each schema names a member of the
  bag, so a reader checks two namespaces against one diagram instead of holding a level-gap in
  their head (F25). that alignment is also the drift detector: the incoherence this pass fixed
  was invisible precisely because `schema` pointed one level below the bag.

### cons

- **a break for extant callers, in three places** — `return x` → `return { body: x }`;
  `schema.output` now describes the response rather than the body; `invoke`'s `rawEvent` becomes
  `payload` with a different type. each is mechanical, and the third serves no acceptance line.
- **two config renames, plus one for the ask-endpoint family** — `logTranslate` → `translate.log`
  and `deserialize` removed from endpoint config. this is the F12 lift, and it serves no
  acceptance line.
- **a builder is now owed on the schema side.** `asApiGatewayResponseSchema` exists to keep the
  call site a one-liner once `schema.output` describes the envelope. it is a real addition to the
  public surface, bought by the F25 rule.
- **the diff spans two deliverables.** wire-response control (the wish) and the `translate` lift
  (wisher-directed). each is coherent alone; together they make one branch harder to review and
  one revert harder to scope.
- **the design took four wisher corrections to cohere** (F20, F21, F23, F25) after the shape was
  settled. the last one was a self-contradiction a self-review had read past four times, which is
  a cost worth recording against the review process, not only against the design.

### edgecases → pit of success

| edgecase | how the contract keeps you safe |
|---|---|
| handler returns `{}` | compile error — `PickAny` demands at least one key |
| handler omits `status` | 200, explicitly defaulted by the sdk before any middleware sees it, so `normalizeHttpResponse`'s `??= 500` never applies |
| handler sets `Content-Type: text/xml` | serializer returns early; xml reaches the wire byte-identical. under the old chain it was measurably json-quoted **and** re-stamped `application/json` (probe 1) → twilio 11200 |
| handler omits `body` on a 204 | sdk emits `body: ''` — `APIGatewayProxyResult.body` is a **required string** (verified: `@types/aws-lambda/.../api-gateway-proxy.d.ts:154-166`) |
| body present, `Content-Type` absent | serializer stamps `application/json` — a real default, not a gap |
| a twilio body carries caller PII (`From`/`To`) | **guarded by default** — `translate.log` defaults to a metadata-only projection (method, path, status, body byte-length); body content never reaches cloudwatch unless a consumer opts in (F10) |
| handler returns a non-object | fail loud via `isApiGatewayResponse.assure(...)` (`withAssure`, per `rule.require.assure-via-type-checks`) |
| two `Set-Cookie` headers / binary body | see F7 — deferred, since `PickAny` makes each an additive key later |
| `{ introspect: 'schema' }` to a form-encoded webhook | never triggers: with `input: false` (or `deserialize: { body: false }` on the factory) the body stays a string, and `isIntrospectionPayload` requires an object (verified: `genIntrospectionMiddleware.isIntrospectionPayload.ts:6`) |
| a secret in an error message | 500 never echoes `error.message` (verified: `genInternalServiceErrorMiddleware.ts:46-54`) |
| a consumer supplies a `translate.payload.input` that drops the trail wrapper | cannot happen — the trail unwrap runs **first** and is not replaceable, so `exid` and `isContempCaller` survive any custom translator (F12) |
| a consumer disarms (`input: false`) but declares a parsed `schema.input` | fails loud at validation — zod names the field. `false` makes `inputAfter` ≡ `inputBefore` by construction, so no type constraint is owed (F22) |
| a reader confuses "absent" with "off" | the two states differ maximally in form — `undefined` vs `false`, never `undefined` vs `null` (F23) |
| a family omits one of the four shapes | compile error — `extends LambdaEndpointShapes` requires a value for every member (F16, verified by probe: TS2344) |
| a consumer supplies `payload.output` and forgets to wrap the default encode | ⚠️ **not guarded** — an unencoded response reaches the wire. the type cannot catch it, since a hand-written `Translator<Response, ProxyResult>` is well-typed either way. flagged at awkwardness #10; a compose affordance is the candidate fix (F26) |
| a consumer needs to redact every response, not each return | `translate.payload.output` — one gate over all branches, whatever the handler returned (F26) |

## groundwork

### external research

> **method note.** `WebFetch` is credential-gated in this session
> (`🔐 XAI_API_KEY locked`), so the doc claims below were verified via `WebSearch`
> summaries quoting those pages. the one external fact that drives a design decision
> is cross-checked against a source on disk.

- **api gateway proxy response format** — [AWS docs](https://docs.aws.amazon.com/apigateway/latest/developerguide/set-up-lambda-proxy-integrations.html):
  output is `{ isBase64Encoded, statusCode, headers, multiValueHeaders, body }`;
  headers may be omitted; a 204 uses `body: ""`. cross-checked on disk:
  `APIGatewayProxyResult.body` is **required `string`** while
  `APIGatewayProxyStructuredResultV2.body` is optional
  (`@types/aws-lambda/trigger/api-gateway-proxy.d.ts:154-166, 320-330`) — which also
  proves the two versions' **output** shapes are not interchangeable, even though
  this repo normalizes their **inputs**.
- **twilio** — [webhooks overview](https://www.twilio.com/docs/usage/webhooks/webhooks-overview),
  [error 11200](https://www.twilio.com/docs/api/errors/11200): inbound sms/voice
  expects TwiML xml; an empty 200/204 is acceptable when no reply is needed; **a
  Content-Type that does not match the body raises 11200**.
- **308 + `Location`** — standard http (RFC 7538). no repo-specific constraint.
- **declastruct api-gateway support** — verified **absent** by exhaustive content
  search: `apigateway` (case-insensitive) returns **zero matches** across all of
  `node_modules/declastruct-aws/dist`. the search was calibrated first — the same
  grep for `DeclaredAwsLambda` returns 5 files — so the zero is trustworthy. drives F4.
- **`PickAny`** — verified in `ehmpathy/type-fns:src/types/PickAny.ts`, exported from
  its index. **not currently a dependency here** (zero `type-fns` imports in `src/`,
  absent from `package.json`) → F11.

### empirical probe — what the extant chain actually emits

reading middleware is not proof of what it emits, so the extant `forApiGateway` was
**run** (one throwaway probe, since deleted):

1. **the double-encode is real.** a handler returning
   `'<Response><Say>aloha</Say></Response>'` emits
   `body: "\"<Response>…\""` with `Content-Type: application/json` — the exact pairing
   twilio rejects with 11200. this is the measured basis for the serializer decision,
   not an inference.
2. **`normalizeHttpResponse` defaults an absent status to 500.** → why `{}` must be
   unrepresentable and why the sdk defaults `status ?? 200` itself.
3. **the chain already emits a body-less response** when a handler returns
   `undefined`: `{ statusCode: 200, headers: {...} }`, no `body` key. body-less output
   is not new plumbing; only the ability to *choose* status and headers is.
4. **error responses carry no security headers** — the 500 emitted only
   `Content-Type`, because `httpSecurityHeaders` registers `after`, never `onError`.
   pre-existing inconsistency, surfaced below.

**findings that drove F12–F25** (each verified, none inherited)

- **`IoLogTranslate` is declared inline in both families** (`forAskEndpoint.ts:58,90`;

  `unwrappedEvent`, `exidFromPayload`, `isContempCaller`. two guarantees ride on it, so it must
  precede any consumer translator rather than be replaceable by one.
- **`LambdaHandlerInput<TInput>` derives the payload from the input**
  (`forAskEndpoint.ts:35-37, 93-98`) — the extant conflation F18 fixes.
- **api gateway's input side runs TWO transforms, ask-endpoint's runs one.** unify+base64+parse
  (`genApiGatewayEventNormalizationMiddleware.ts:41-50, 68-119`), then `event.body as TInput`

- **`event.body as TInput` is an `as`-cast in prod code** (`forApiGateway.ts:158`) — the extant

- **the extant internal `ApiGatewayResponse` is the total shape** (`genConstraintErrorMiddleware.ts:11-15`,

## what is awkward?

1. **`asApiGatewayResponseSchema({ body: z.undefined() })` for a 204-only endpoint** is a
   mouthful, though the wisher classes the choice beneath it as a pro (F17): the contract
   states its own truth about whether a body exists. the alternative — validate only when a
   body is present — is the branch we deliberately removed. the builder is the ceremony the
   schema-names-a-point rule (F25) costs, and it lands on every call site. the named `{ body }`
   argument adds keystrokes over a positional one and buys the legibility back: the call now
   reads as "a response whose body is undefined" with no comment needed.
2. **"verbatim" is aspirational once any middleware runs.** cors may add headers, and
   the introspection middleware can short-circuit with its own response. the promise
   holds where it is claimed: *once the handler returns, its response is verbatim*.
3. **the breaking change lands on a suite, not just consumers.** all 10 extant test
   cases change shape, which is exactly the signal that the contract moved.
4. **two `ApiGatewayResponse` types will briefly coexist, and they differ in kind** — the
   extant internal one (`genConstraintErrorMiddleware.ts:11-15`) is the **total** shape
   `{ statusCode; body; headers? }`; the new public one is the `PickAny` **partial**. so this
   is a semantic collision, not only a name clash: the total one is what the adapter's wire
   encode produces, the partial one is what a handler authors. a rename is owed; deferred to
   the blueprint, with the F25 vocabulary (`outputBefore` vs the encoded wire shape) as the
   guide for which name each should take.
5. **a new dependency for one type.** `type-fns` for `PickAny` (F11).
6. **the `translate` lift widens the diff past the wish's own acceptance (F12).** it
   touches `genLambdaEndpoint` — a family whose response shape this wish never mentions
   — and breaks two public config fields plus one exported type. it is wisher-directed
   and the evidence for it is strong, but a reader who checks the diff against
   `0.wish.md` will find work no acceptance line asks for. the scope note in the
   `translate` section is what keeps that honest.
7. **the factory call is longer than the boolean was.**
   `asApiGatewayEvent({ deserialize: { body: false } })` replaces
   `deserialize: { body: false }` at the call site, and it lands on the *most common*
   override (`rule.prefer.defaults-match-common-case` cuts against it). it buys a third
   state (`false`) the extant config could not express, and puts the option on the thing it
   configures — but a reviewer may judge the trade the other way.
8. **the indexed accesses are a type-level move a reader must decode.**
   `TShapes['inputBefore']` inside the declaration is noisier than a positional
   parameter, and typescript's mismatch errors are a little worse. accepted so the four
   terms are structurally bound rather than by convention — but it wants comments at the
   declaration, not only in this yield.
9. **`genLambdaEndpoint` binds `outputBefore` and `outputAfter` to the same type** — honestly,
   since a lambda invoke response **is** the payload, so that family's output translate is a
   true identity. api gateway's pair differs (F26). the redundancy is therefore domain-true in
   one family rather than a model fudge in both, but a reviewer should still check that the
   ask-endpoint identity is documented at its bind site, else it reads as the F26 defect.
10. **`translate.payload.output` composes with a default a consumer must know to call.** a
    redaction pass wants the wire encode too, so it wraps
    `asApiGatewayResponsePayload` by hand — and a consumer who forgets to wrap it
    silently ships an unencoded response. that is a real footgun (`rule.require.safe-by-default`)
    which the input side shares. a blueprint may want a `{ before }` / `{ after }` compose
    affordance so the default is never accidentally displaced. **this is now the item a
    reviewer should study first**, in place of the prune this list previously recommended.
11. **the `invoke` input break serves no acceptance line (F25).**
    `rawEvent: UnifiedApiGatewayEvent` → `payload: ApiGatewayEventPayload` follows from the
    corrected model, not from the wish. it is the right shape and it kills an `as`-cast, but
    a reviewer may reasonably defer it and accept an envelope-shaped `inputAfter` in the
    interim. flagged rather than folded in quietly.
12. **this vision reversed itself four times on one slot, and the log of that is item-worthy
    in its own right.** `translate.payload.output` went: empty → the wire map with no slot
    (F13) → an identity that constrained no one (F25) → deleted (F26 first pass) → the encode
    as a real default (F26). every draft judged the slot **against the sdk's own needs**; the
    wisher settled it in one line by asking what a **consumer** would put there. the reversals
    are kept visible rather than edited away, because **the pattern is the useful part** — and
    the pattern is that a config slot must be tested from the caller's side, never the
    library's.

## open questions & assumptions

### answered

- **[answered]** error path ownership → platform, as a fallback; a handler can catch
  and return its own response. this was the wish's flagged question.
- **[answered]** does one response type serve v1 and v2? **no** — input events are
  normalized, output shapes are not (`multiValueHeaders` is v1, `cookies` is v2).
  the vision had assumed output symmetry because the input side has it.
- **[answered]** a body with no `Content-Type`? now a real default (json via the
  serializer), so the earlier "loud debug log" mitigation is unnecessary — the gap it
  guarded is closed by the retained serializer.
- **[answered]** runtime validation of the returned shape → `isApiGatewayResponse`
  via `withAssure` (`rule.require.assure-via-type-checks`).
- **[answered]** does `getValidatedOutput` still apply? **yes** — it validates `body`
  against `output`, which now always exists.
- **[answered]** security headers on 3xx/empty responses? moot — the probe showed the
  middleware never runs on the error path, and F3 leaves success behavior as today.
- **[answered, F10]** body logs default → metadata-only.

a rule applied without its counterweight over-fires, and this stone has the measurements: the
first pair's left side alone approved `payloadInput`; the second's produced a conditional type
that proved a tautology; the third's produced `null` as an off-state. **three of the four late
defects were an unbounded rule, not an absent one** — which is what a rule pack's own failure mode
looks like, and it argues that a promoted rule should carry its counterweight or not go at all.

⚠️ **and F26 is the fourth measurement, on the pair whose counterweight was already in the pack.**
`prefer.wet-over-dry` fired correctly on `translate.payload.output` — a slot with no evidenced
consumer — and this vision **deleted a domain term** to satisfy it. the term was not the speculation;
the *binding* was. so even a correctly-fired counterweight needs its own bound: **do not delete a
name to satisfy a rule about scope.** the wisher supplied both the catch (*"it still exists"*) and
the missing evidence (*"the output translator sanitizes any sensitive info"*) in two lines. that
sequence — a rule fires, a term dies, the evidence surfaces a moment later — is the one every
promotion of `wet-over-dry` should carry as its caution.

note the fourth pair's counterweight is **already in the extant pack** — proof that this pattern is
not an artifact of these seven rules. every one of the four left-side rules is a "do more of X"
mandate, and each needs a bound; the pack already knew that for `wet-over-dry` and did not yet know
it for the other three.

⚖️ **each pair is now cross-linked bidirectionally in the briefs.** a one-way link was the real
hazard: a reader who lands on the left-side rule never learns the bound exists, which is exactly how
three of these defects happened. the `⚖️` marker at the head of each `.see also` names the
counterweight and states what the left side alone approves.

the promotion column is a proposal, not a claim of placement. each rule cites the repo case
that produced it, so a promotion must generalize the case first.

## for the next driver — the guard's review level is off by one, about half the time

recorded at the wisher's request; it cost real time on this stone.

when a self-review guard refuses `--as promised` with *"the pond barely rippled"*, the
usual cause is **not** a thin review — it is that the artifact sits at the wrong `rN`
level, and **the level the guard prints is not always the level it checks**. measured
across all four self-reviews of this stone:

| slug | printed | accepted |
|---|---|---|
| `has-grounded-in-reality` | r1 | **r0** |
| `has-questioned-requirements` | r2 | r2 |
| `has-questioned-assumptions` | r3 | r3 |
| `has-questioned-questions` | r4 | **r3** |

right about half the time; when wrong, **one too high**. the reliable move: write at
the printed level, and if refused, place the same artifact at `printed − 1` as well,
then promise again. leave the duplicates (the scaffold gitignores them).

two traps:
- **do not read the scold as the diagnosis.** the refusal text is generic; it says the
  review was shallow when the complaint is a filename. (still worth asking whether it
  *was* shallow — on this stone the fourth genuinely was, and the push-back produced
  four real findings — but fix the level first, then judge depth on merit.)
- **do not read compiled `dist`** under `node_modules/.pnpm` to work this out. the
  printed path, the status-bar `rN/M`, and `git check-ignore` settle it far faster.
