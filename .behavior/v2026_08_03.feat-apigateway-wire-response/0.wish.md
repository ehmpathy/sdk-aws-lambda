# wish: an api-gateway handler owns its own wire response

## .what

a handler behind `sdk-aws-lambda` can return its **exact wire response** — any `statusCode`,
any `headers`, any body (or none at all) — and the sdk passes it through verbatim.

today `forApiGateway` fixes `{ statusCode: 200, body: JSON.stringify(x) }`, so a 204 with no
body, a 308 with a `Location` header, and an xml or text body cannot be expressed at all.

## .why

**the fixed 200+json contract cannot carry the shapes real webhooks require.**

- **twilio** voice/sms webhooks answer with 204 (no body) and with twiml **xml** bodies
- **cloudfront** / short-url redirects answer with **308** and a `Location` header

neither is expressible, so the cost lands on every consumer instead — and it has already
landed once. `svc-notifications` hand-rolled a `forApiGatewayPlain` adapter for exactly this:
to pass `statusCode` / `headers` / `body` through, and to preserve the error-conversion
contract its prior middy stack had given it.

that adapter is not special to that repo. **every repo whose api-gateway lambdas need a
non-200 or non-json response re-writes the same file.** a shipped affordance retires the
duplication and keeps one consistent error contract instead of N hand-rolled ones.

## .acceptance

- a handler can return an arbitrary `statusCode`, arbitrary `headers`, and an arbitrary body —
  **an empty body included** — and the wire response matches what the handler returned
- the three real shapes are each proven expressible: **204 with no body**, **308 with a
  `Location` header**, and an **xml body**
- the error-conversion contract holds:
  - `BadRequestError` yields a **400** whose body carries `errorMessage`, `errorType`, and
    `causeMessage` when a cause is present
  - that 400 leaves the lambda invocation a **SUCCESS** — a client fault must not emit a
    cloudwatch error nor signal a retry
  - any other error logs loudly and yields a **500 with no body** — no internal detail and no
    secret ever reaches the wire
- the extant fixed-shape path still serves consumers who want it. this ADDS a way to own the
  response; it does not remove the convenient default
- coverage proves the wire bytes, not just the return value — an assertion that the handler
  returned `{ statusCode: 204 }` does not prove api gateway sees a 204 with no body

## .ground — verified, NOT instruction

the adapter this would retire, from `svc-notifications` branch
`beav/feat-declapract-upgrade`, `src/contract/handlers/utils/forApiGatewayPlain.ts`:

```ts
export const forApiGatewayPlain =
  (logic: (event: APIGatewayProxyEvent) => Promise<PlainApiGatewayResponse>) =>
  async (event): Promise<APIGatewayProxyResult> => {
    try {
      const response = await logic(event);
      return { statusCode: response.statusCode, headers: response.headers, body: response.body ?? '' };
    } catch (error) {
      if (!(error instanceof Error)) throw error;
      if (error instanceof BadRequestError)
        return {
          statusCode: 400,
          body: JSON.stringify({
            errorMessage: error.message,
            errorType: 'BadRequestError',
            ...(error.cause instanceof Error ? { causeMessage: error.cause.message } : {}),
          }),
        };
      log.error('handler.error', { errorMessage: error.message, stackTrace: error.stack });
      return { statusCode: 500, body: '' };
    }
  };
```

read it as EVIDENCE of the shape a consumer needed, not as a design to copy. it was written
under deadline, from outside this repo, by someone who could not see this repo's extant grain.

## .open questions worth a decision (yours to settle)

- the prior middy stack ALSO added owasp security headers, cors, and v1/v2 event normalization.
  `svc-notifications` dropped all three **deliberately** — its webhooks configure no cors, and
  neither twilio nor cloudfront depends on those headers for the wire contract. so: opt-in
  affordance, separate round, or out of scope? the acceptance does not ask for them.
- does the passthrough own the SUCCESS path only, or the error path too? the two could split,
  and a wrong split is awkward to undo once consumers declare against it.
