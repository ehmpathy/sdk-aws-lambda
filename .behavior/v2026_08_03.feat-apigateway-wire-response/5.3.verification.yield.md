## ⚠️ a green review that could not have gone red — the sixth instance, found by l3

**two independent l3 reviewers (r009 and r011) converged on the same catch**, and neither was
prompted toward it:

> the l1 reviewers `ergo-contract-snapshots` (r002), `ergo-acceptance-journey-coverage` (r004),
> and `mech-test-intent` (r007) each ran with `paths: **/*.snap` intersected with the diff —
> visible in each report's own stdout header. so **not one of them ever opened a `.test.ts` file**.

a rubric about *journey shape* or *test intent* cannot be scored from fixture output: whether a
case runs in-process or over a socket, whether it is single-step or multi-step, whether an
assertion was loosened — none of that appears in a `.snap`. so those `0 blockers / 0 nitpicks`
verdicts are evidence the **fixtures** are sane, and **no evidence at all** about the dimension
each was named for.

that is exactly how r009's first nitpick (`local.payloadCompat`'s "user journey" block asserts the
return value, never wire bytes) survived four review rounds unflagged — and r011 reached the same
conclusion from the other side, by a direct read of all 10 test diffs, which it found sound.

**this is the SIXTH instance on this branch of one defect class:** a signal credited with a
dimension it could not have failed on.

| # | the signal | why it could not go red |
|---|---|---|
| 1 (F30) | aws's `.d.ts` said `body: string` | a vendor type states what they ACCEPT, never what we emit |
| 2 (F31) | "cors and security-headers both read `request.event`" | sourced to a shared role, never to a grep of the dist |
| 3 (r3) | `grepsafe --glob 'blackbox/**'` → 0 | a basename filter matches no path-shaped glob; a real absence prints the same zero |
| 4 (r8) | 11 green header snapshots | every one an ALLOWLIST, so an unlisted header was structurally invisible |
| 5 (F32) | 5 reviewers found one dead `onError` | convergence proves a defect was VISIBLE, never that it was SINGULAR |
| **6** | **3 green l1 verdicts on journey/intent** | **scoped `**/*.snap`, so they never read a test file** |

**the fix applied:** a `⚠️ .note on GRAIN` now heads that `describe` block. it states that the
block asserts the return value, why that is the right grain for an sdk-author's contract check,
and points at `local.wireResponse.acceptance.test.ts` for the wire proof — so a reader cannot
over-credit it.

**the fix NOT applied, and why:** the reviewer scopes itself; a driver cannot re-scope a peer
rubric from inside the run. that is a route-level repair, flagged here for the route owner.
