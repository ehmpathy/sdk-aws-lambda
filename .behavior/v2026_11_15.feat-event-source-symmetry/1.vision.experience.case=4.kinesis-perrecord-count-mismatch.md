# case=4 — kinesis.perRecord · a batch of other than one — sharp × criti

## .narrative

the deployer leaves `batchSize` at the kinesis default of 100. the first invoke carries 100 records. a silent `records[0]` would serve one and, on success, advance past 99. instead the sdk fails loud, before any record is served, and names both fixes. kinesis retries; the deployer reads the error and sets `batchSize: 1`.

## .timeline

```
given forKinesis.perRecord
when an event of 3 records arrives
then invoke is not called
  and the invoke throws a MalfunctionError 'forKinesis.perRecord received a batch of other than one record'
    with { count: 3, fix: 'set the event source `batchSize` to 1, or reach for `genLambdaEndpoint.forKinesis.perBatch`', ids }
  and kinesis retries, so no record is skipped
```

## .the fail-safe

a deployer fault, so `MalfunctionError`; never acknowledged, so no record is lost.

the cost differs from sqs: a kinesis shard retries the failed batch until `maximumRetryAttempts` or record expiry, and no later record on that shard moves meanwhile. the loud signal is the `MalfunctionError` on every attempt, logged with the fix; an iterator-age alarm, where the deployer set one, fires too. the doc names the stall, so a deployer who sees it knows to read the error.
