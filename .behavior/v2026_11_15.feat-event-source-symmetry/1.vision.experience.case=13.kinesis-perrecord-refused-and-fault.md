# case=13 — kinesis.perRecord · a refused record, then a server fault — sharp × criti

## .narrative

an audit stream runs at `batchSize: 1`. a producer writes a record that is not json. the sdk refuses it before the handler runs, logs `kinesis.record.refused` with the `sequenceNumber` and `eventID`, and returns success: kinesis advances past it. the bad bytes would refuse the same way forever, so to retry them would stall the shard for naught.

later the audit store times out and the handler throws a `MalfunctionError`. that is not the caller's fault, so the sdk logs it at error and lets it escape; kinesis retries the record until it lands or the retry limit is hit.

## .timeline

```
given forKinesis.perRecord({ schema: { input: z.object({ payload: schemaOfAudit }) }, invoke })
when one record arrives with data = base64('not json')
  then invoke is not called
  and one warn `kinesis.record.refused` { id: sequenceNumber, eventID, issues } — the not-json issue names the `deserialize: { payload: false }` fix
  and the invoke succeeds, so kinesis advances past the record
when one valid record arrives and invoke throws ConstraintError('unknown tenant')
  then the same warn, and the invoke succeeds
when one valid record arrives and invoke throws MalfunctionError('audit store down')
  then the error is logged at error by the internal-service-error middleware
  and the throw escapes, so kinesis retries the record
```

## .the fail-safe

the class is the verdict, as at `forSqs.perRecord`: a caller fault is acknowledged with a warn (never a silent drop, never a shard stall), and any other fault redrives (never a swallow).
