# case=6 — sns · refused (schema, or a caller fault the handler throws) — sharp × criti

## .narrative

a publisher sends `{"nope":1}`. the sdk refuses it before lena's code runs, logs `sns.record.refused` at warn with the `MessageId` and the zod issues, and returns success — so lambda does not retry a message that would refuse the same way three times. later lena's own handler throws a `ConstraintError` for an unknown tenant; same fate, same warn.

## .timeline

```
given forSns with payload z.object({ id: z.string() })
when Message = '{"nope":1}'
then invoke is not called
  and one warn `sns.record.refused` { id: MessageId, error }
  and the invoke succeeds (no async retry, no dead-letter entry)
given an invoke that throws ConstraintError('unknown tenant')
when a valid message arrives
then the same warn, and the invoke succeeds
```

## .the fail-safe

a caller fault is logged, never silent — the warn is the discard's trace (`invariant.constraint-errors-never-redrive-sqs`, the same law for sns).
