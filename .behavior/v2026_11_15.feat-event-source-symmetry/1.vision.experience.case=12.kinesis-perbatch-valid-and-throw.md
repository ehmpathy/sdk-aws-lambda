# case=12 — kinesis.perBatch · all valid, then a throw — happy × criti, then sharp × criti

## .narrative

on a quiet hour kai's consumer gets 3 clean clicks, writes them, names all three, and the sdk answers an empty failure list: kinesis checkpoints past the batch.

an hour later the warehouse is down. kai's `invoke` throws a `MalfunctionError` before it names any success. the sdk logs the fault at error and lets the throw escape, so the whole batch fails and kinesis retries it from the first record. no record is skipped.

## .timeline

```
given forKinesis.perBatch({ schema: { input: z.object({ payload: schemaOfClick }) }, invoke })
when 3 valid records arrive and invoke returns { successes: records }
  then invoke received records = the 3 decoded records, in delivery order
  and the answer is { batchItemFailures: [] }
  and kinesis checkpoints past the batch
when 3 valid records arrive and invoke throws MalfunctionError('warehouse down')
  then the error is logged at error by the internal-service-error middleware
  and the throw escapes, so no answer is returned
  and kinesis retries the whole batch (records already written are redelivered; the write must be idempotent)
```

## .the fail-safe

a throw with no named success redrives every record, never acknowledges one — the same contract `forSqs.perBatch` keeps (`genSqsEndpointMiddlewares.ts`, `perBatch [case7]`).
