# case=15 — any record source · a schema callback throws — sharp × criti

## .narrative

an author's payload schema carries a `.refine()` that looks up a tenant in a cache. one day the cache client is unset, and the callback throws a raw `Error` instead of a zod issue. the record is fine; our schema is broken.

the sdk must not read that as the sender's fault. a refusal is acknowledged, and an acknowledged record is gone. so the sdk sorts by class: a zod refusal is a caller fault, and any other throw from the schema is a fault of ours.

at `perBatch` it logs that record at error, as `kinesis.record.invalid` (or `sqs.` at `forSqs.perBatch`), with the error and its stack, and names that record alone in `batchItemFailures`, so it redrives while its peers are still served. at `perRecord` the throw escapes, so the source retries the record, and the escaped throw is its trace. either way the valid record waits for the fix rather than vanish.

## .timeline

```
given forKinesis.perBatch({ schema: { input: z.object({ payload: z.object({ tenant: z.string() }).refine(() => { throw new Error('cache unset') }) }) }, invoke })
when a batch of two records arrives
  then invoke is called with records: []
  and two error lines `kinesis.record.invalid` { id: sequenceNumber, class: 'Error', errorMessage: 'cache unset' }, each with a stack
  and the answer names both records in batchItemFailures, so kinesis redrives them
given a batch where one record trips the callback and one is valid
  then invoke receives the valid record alone
  and the answer names only the record whose schema threw
```

## .the fail-safe

a schema fault never reads as a refusal, so a valid record is never acknowledged away by a defect of ours (`invariant.constraint-errors-never-redrive-sqs` names the other half: a true refusal never redrives).

## .tests

`record/setRecordsValidated` `[case1]` (one record of each disposition) · `record/logRecordInvalid` `[case1]`–`[case3]` (the error line per source)
