# case=11 — migrate `forAsk` + `fromSns` → `forSns` — happy × alter (chosen)

## .narrative

an extant sns handler is `forAsk({ schema: { input: fromSns({ payload }), output: z.void() }, invoke: ({ payload }) => handle(payload.Records[0]!.Sns.Message) })`. it still runs after the upgrade — no member is removed. the author moves to `forSns`; the handler reads `payload` directly, gains `headers`, and drops `output: z.void()`.

## .timeline

```
given the extant forAsk + fromSns handler
when the package upgrades
then it compiles and runs unchanged (fromSns and forAsk are untouched)
when the author rewrites to forSns({ schema: { input: z.object({ payload }) }, invoke: ({ payload }) => handle(payload) })
then handle receives the same decoded message
```
