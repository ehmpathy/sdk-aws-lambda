# case=7 — sns · server fault — sharp × criti

## .narrative

lena's database blips. her handler throws. the sdk logs the fault loud and lets the throw escape, so lambda's async retry (and, past it, any on-failure destination the deployer set) keeps the message.

## .timeline

```
given forSns whose invoke throws MalfunctionError('db down')
when a valid message arrives
then the error is logged at error by the internal-service-error middleware
  and the throw escapes the handler, so lambda retries the async invoke
```

## .the fail-safe

any fault that is not the caller's escapes (`rule.forbid.failhide`); only a caller fault is acknowledged.
