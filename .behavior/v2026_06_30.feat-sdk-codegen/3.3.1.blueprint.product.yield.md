# 3.3.1 product blueprint — sdk codegen

## summary

build a new CLI + orchestrator that generates a per-service sdk from live lambda
contract introspection. the command:

```sh
npx sdk-aws-lambda gen --for svc-jobs --into src/access/svcs/ --env prep
```

(`--env` is required — introspection is prep-gated, and `env.access` is required
context with no default per `rule.require.env-access-in-context`.)

calls the extant `getAllLambdaContracts` spine (untouched), then emits three
files per service — `<svc>.ts` (barrel), `<svc>.mechanisms.ts` (typed
`(event, context)` fns), `<svc>.resources.ts` (prefixed dobj classes with
metadata, no validation schema).

**shape:** one orchestrator (`genServiceSdk`) composes pure transformers (name
transform, pragma read, type emit, file assembly) + one atomic communicator
(`setGeneratedFilesBatch`).
purely additive — zero [REPLACE] of extant code (per prod research). the type
half uses `json-schema-to-typescript`; the metadata half reads the
`x-domain-object` pragma from `domain-objects@0.32.0` `.contract` (per external
research F1–F4).

## domain decomposition (grains)

### orchestrator (composition, narrative)

- **`genServiceSdk`** — `(input:{ which:{service}, into:string }, context:
  ContextAwsLambdaCaller) => Promise<{ files: GeneratedFile[] }>`
  narrative: discover contracts → derive symbols → collect dobjs → assemble 3
  files → write. no decode-friction; each line a named op. **note (blocker 1):**
  `context.env.access` is required (per `rule.require.env-access-in-context`); the
  cli routes the `--env` flag into `context.env.access` before calling this.

### transformers (pure, unit-tested)

- **`asServiceSymbols`** — `{ service:'svc-jobs' } → { object:'svcJobs',
  prefix:'SvcJobs' }`. the name→symbol rule. **consistency note:** the extant
  `asLambdaEndpoint` slug parser treats service as exactly `svc-{noun}` (2 parts;
  `asLambdaEndpoint.ts:44`). `asServiceSymbols` MUST match that model — it
  validates the `svc-` prefix the same way and treats the service as `svc-{noun}`.
  so `svc-jobs` → `svcJobs`/`SvcJobs`; a hyphenated noun (if ever used) follows
  the same 2-segment assumption as the rest of the repo, not a divergent
  multi-hyphen rule. (reuses the repo's name model rather than a new one.)
- **`getAllDomainObjectsFromContracts`** — walks every endpoint's `{input,output}`
  json-schema, extracts each `x-domain-object` pragma, de-dupes by dobj name →
  `DomainObjectContract[]` (name, primary, unique, alias, nested, shape).
- **`asDomainObjectPragma`** — reads one `x-domain-object` keyword off a
  json-schema node → typed pragma (or null if absent).
- **`asResourceClassSource`** — `DomainObjectContract → string` (a prefixed
  `DomainEntity`/`DomainLiteral` class w/ primary/unique/alias/nested; **no**
  schema). **base-class rule (blocker 3):** picks `extends DomainEntity<T>` vs
  `extends DomainLiteral<T>` from the contract's **`kind`** field (see
  DomainObjectContract below). **class-name rule (nitpick 4):** emitted name =
  `prefix + dobj.name` (the TS class name carried in the pragma), **not**
  `alias.singular`. **nested-prefix rule (nitpick 1):** each type name in `nested`
  is prefixed via the same formula as top-level dobj names (`address: Address` →
  `address: SvcJobsAddress`).
- **`asMechanismFnSource`** — `(endpoint fn name, input/output TS types) →
  string` (a typed `(event, context)` wrapper around `askLambdaEndpoint`; `event`
  is the repo's ubiqlang lambda-payload input, satisfies input-context structure).
- **`getTypescriptFromJsonSchema`** — wraps `json-schema-to-typescript.compile`;
  maps the `x-domain-object`-tagged nodes to the prefixed resource name via
  `tsType` (per external research: `tsType` handles non-standard extensions).
  **grain note (nitpick 3):** `compile` is async but is used on a **self-contained
  schema (no external `$ref` URL fetch)** — so it stays a pure transformer,
  unit-tested; execution MUST NOT pass options that introduce i/o (that would flip
  the grain to communicator).
- **`asMechanismsFileSource`** / **`asResourcesFileSource`** /
  **`asBarrelFileSource`** — assemble final file text (+ the "generated — do not
  edit" banner, a shared module-level const in the `file/` dir).
  **import-emit rule (blocker 4):** each carries an explicit import block —
  hard-coded package names (`domain-objects`, `sdk-aws-lambda` — required peer
  deps in the consumer env) + deterministic relative specifiers from the file
  naming (`./svcJobs.resources`, `./svcJobs.mechanisms`). specifically:
  - `asResourcesFileSource` emits `import { DomainEntity, DomainLiteral } from 'domain-objects'`
  - `asMechanismsFileSource` emits `import { askLambdaEndpoint, type ContextAwsLambdaCaller } from 'sdk-aws-lambda'` + `import type { <dobjs> } from './svcJobs.resources'`
  - `asBarrelFileSource` emits `export { svcJobs } from './svcJobs.mechanisms'` + `export * from './svcJobs.resources'`
  - **composition (nitpick 2):** `asResourcesFileSource` receives, per dobj, a
    `{ dobj: DomainObjectContract; typeText: string }` pair (typeText from
    `getTypescriptFromJsonSchema`, class from `asResourceClassSource`), emits
    `interface` + `class` block per dobj.
  **format (nitpick 5):** each file-source biome-formats its output **in-process**
  (via `@biomejs/biome` api — added to deps) so snapshots are deterministic across
  node/biome versions.

### communicator (i/o boundary, integration-tested)

- **`setGeneratedFilesBatch`** — `({ files: GeneratedFile[] }) => Promise<void>` —
  the single impure leaf, atomic (blocker 2): writes all files to temp names, then
  renames each into place as the last step; on ANY write error, removes the temp
  files and throws `MalfunctionError`. so three files land all-or-none even under a
  mid-write fs failure. creates parent dir if absent (uc.1). the orchestrator calls
  it **once** with all files assembled in memory — the temp-write/rename/cleanup
  logic stays out of the orchestrator (no inline decode-friction).

### domain.objects (new)

- **`GeneratedFile`** — `{ path:string; content:string }` (DomainLiteral).
- **`DomainObjectContract`** — the parsed pragma: `{ name; kind:'entity'|'literal';
  primary; unique; alias; nested; shape:JSONSchema }` (DomainLiteral). the
  **`kind`** field (blocker 3) carries whether the upstream dobj was a
  `DomainEntity` or `DomainLiteral`; `asResourceClassSource` reads it to pick the
  base class. **[KHUE→execution]:** confirm the `x-domain-object` pragma from
  `domain-objects@0.32.0` carries `kind` (it is stamped by `DomainObject.contract`,
  which knows the subclass); if absent from the pragma, fall back to the inference
  rule "`primary` non-empty → entity, else literal" and pin it against a real
  introspected sample.
- **`LambdaDomainObjectNotCapturableError`** — `extends ConstraintError` (uc.9).

## error → exit-code map (cli contract)

per `rule.require.exit-code-semantics` (0 ok / 1 malfunction / 2 constraint):

| condition | error (source) | exit | uc |
|-----------|----------------|------|----|
| success | — | 0 | 1,2 |
| absent/invalid `--for`/`--into`/`--env` | `ConstraintError` (from asGenArgs) | 2 | — |
| `--env` ≠ prep (access ≠ prep) | `LambdaIntrospectionBlockedError` [←] | 2 | 6 |
| absent creds | (aws creds error, wrapped) | 2 | 7 |
| service not found | `LambdaServiceNotFoundError` [←] | 2 | 5 |
| endpoint unsupported | `LambdaIntrospectionNotSupportedError` [←] | 2 | 8 |
| dobj uncapturable | `LambdaDomainObjectNotCapturableError` [+] | 2 | 9 |
| unexpected | `MalfunctionError` | 1 | — |

**all-or-none invariant:** `genServiceSdk` assembles all file *content in memory*
first; only after every transform succeeds does it call `setGeneratedFilesBatch`
**once** with all files. so any error → **no files written** (satisfies the "no
partial sdk" invariant across uc.5/6/8/9). gate order (args→access→creds→service→
endpoint→dobj) is enforced by compose order (args validated in the cli before the
spine is even called).

**mid-write atomicity (blocker 2, resolved):** the assemble-then-write shape
guards all *logic/discovery* errors (uc.5/6/8/9) — those throw before any write.
but a raw sequential write of 3 files could still leave a partial set if the fs
fails on file 2 of 3 (disk full, permission). to hold "no partial sdk" even under
fs failure, the atomicity lives in the **`setGeneratedFilesBatch` communicator**
(not the orchestrator): it writes all files to temp names, then renames each into
place last; on any write error it removes the temp files and throws
`MalfunctionError` (exit 1). the orchestrator calls it **once** with all files —
so the on-disk result is all-or-none for both logic AND fs failures, and the
staging logic stays out of the narrative orchestrator.

  total contract snapshots = 3 positive + 5 negative = 8, exhaustive.

- **drift (uc.3)**: add a field to a harness handler → snapshot diff shows only

### journey acceptance test (mandatory — one end-to-end narrative)

`blackbox/local.codegen.journey.acceptance.test.ts` — a single multi-timestep
journey through the mechanic's real workflow (vision day-in-life), snapshotted at
each checkpoint:

```
given [case1] a mechanic adopts svc-jobs into svc-gateway
  when [t0] before gen — target dir absent
    then access/svcs/ does not exist            (precondition)
  when [t1] gen --for svc-jobs --into access/svcs/ --env prep
    then exit 0; 3 files created; dir auto-created
    then svcJobs.ts / .mechanisms.ts / .resources.ts each match snapshot
    then SvcJobsJob carries primary/unique/alias/nested, no schema  (uc.2 snapshot)
  when [t2] re-gen, upstream unchanged
    then output byte-identical to [t1]           (uc.3 idempotency snapshot)
  when [t3] upstream adds a Job field, re-gen
    then snapshot diff shows only the new field   (uc.3 drift snapshot)
  when [t4] a blocked scenario — same gen with --env prod
    then exit 2; stderr "introspection only in prep"  (uc.6 error snapshot)
    then no files changed on disk                (recovery: [t1] output intact)
  when [t5] a schema-less dobj is introduced upstream, re-gen
    then exit 2; stderr names the uncapturable dobj  (uc.9 error snapshot)
    then no partial write                        (all-or-none held)
  when [t6] journey complete — revert upstream, final gen
    then final state matches the [t1] snapshot   (final-state verification)
```

this exercises the realistic flow (adopt → sync → drift → blocked → recover →
final) across 7 timesteps, snapshots each checkpoint, covers error+recovery
states inline, and verifies the final state. it is the whole-feature proof that
complements the isolated acceptance cases above.

## maintenance & readability notes

- **narrative orchestrator:** `genServiceSdk` reads top-to-bottom as prose — each
  line a named op, no inline decode (per `rule.forbid.inline-decode-friction`).
- **one op per file, get/set/gen + as\* verbs:** every leaf is a single-purpose
  file whose name equals its export (`rule.require.sync-filename-opname`).
- **input/context pattern:** every op is `(input, context?)`; `env.access` stays
  ambient in context (`rule.require.env-access-in-context`).
- **wet-over-dry:** the three `as*FileSource` transformers stay separate (not a
  premature generic "asFile") — they differ enough and there are exactly 3.
- **directional deps:** `contract/cli` → `domain.operations` → `domain.objects`;
