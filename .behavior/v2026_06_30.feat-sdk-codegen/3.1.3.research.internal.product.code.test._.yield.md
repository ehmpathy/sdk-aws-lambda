## T1 — the in-process lambda harness  [REUSE — the keystone test asset]

**cite 2** — `src/__test_assets__/createInProcessLambdaHarness.ts:112`
> "export const createInProcessLambdaHarness = (
>   handlers: HarnessHandlers,
> ): { mockSdkLambda: jest.Mock; mockSend: jest.Mock; } => {"

**cite 3** — same file, `:104`
> ".why = enables e2e tests without AWS credentials or network"

**cite 4** — same file, `:141`
> "const handler = handlers[service ?? '']?.[fn ?? ''];
>  if (!handler) { // aws sdk throws ResourceNotFoundException for absent functions
>    throw genResourceNotFoundError({ functionName: fnName }); }"

relation: this is the single most valuable reuse. it runs **real
`genLambdaEndpoint` handlers** and fakes only the sdk `send`, so the codegen can
be tested end-to-end — introspect real handlers → emit files — **without a
deploy per case**. it already simulates `ResourceNotFoundException` (criteria
usecase.5). **[REUSE]** verbatim: register test handlers (some with
`.contract`-bearing dobjs, some without) and run `gen` against the harness.

>  blackbox/local.introspection.acceptance.test.ts / ...

> "src/domain.operations/askLambdaEndpoint/**/__snapshots__ ,
>  genLambdaEndpoint/**/__snapshots__ , getAllLambdaContracts/**/__snapshots__"

## gaps flagged for the blueprint (new test scaffolding)

- **[EXTEND-new] test dobjs with + without `static schema`** — the harness needs
  handlers whose zod schemas reference `SomeDobj.contract` (capturable) AND a case
  that references a schema-less dobj (uc.9 error). no such fixtures yet.
- **[EXTEND-new] filesystem-write assertion helper** — codegen writes files; tests
  must assert on emitted file contents. today all output is in-memory payloads.
  a small "gen into a temp dir, read back, snapshot" helper is new (integration
  grain, since it crosses the fs boundary per `rule.forbid.unit.remote-boundaries`).
- **[EXTEND-new] idempotency assertion** — run gen twice, assert byte-identical
  (uc.3). new, but trivially built on the snapshot + temp-dir helper above.
