## matrix.A — command outcome by precondition (usecases 1, 5, 6, 7, 8, 9)

the dominant behavior: given a set of preconditions, does gen emit files or fail
loud? the fail-loud invariant is **"clear error + no files written"** across all
error rows.

| ind: access | ind: creds | ind: service found | ind: all endpoints introspectable | ind: all dobjs capturable | dep: outcome | dep: files written | dep: error names culprit | uc |
|-------------|------------|--------------------|-----------------------------------|---------------------------|--------------|--------------------|--------------------------|----|
| prep | present | yes | yes | yes | success: 3 files | yes | n/a | 1,2 |
| prod | present | yes | yes | yes | error: introspection-blocked | no | n/a | 6 |
| test | present | yes | yes | yes | error: introspection-blocked | no | n/a | 6 |
| prep | absent | yes | yes | yes | error: creds (+ unlock hint) | no | n/a | 7 |

| prep | present | yes | yes | no | error: dobj-uncapturable | no | **yes (dobj)** | 9 |

**precedence note (flagged):** the rows imply an evaluation order — access-gate
→ creds → service-found → endpoint-support → dobj-capture. rows below the first
failing gate are marked `—` (not reached). the blackbox says each fails loud;
the *order* is a blueprint concern, not a blackbox one, but worth a confirm that
access is checked before any network call (vision says yes: gated up front).

**gap check:** the happy row requires all five preconditions true; each error row
flips exactly one to false. no combination of preconditions lacks a specified
outcome. ✓ symmetric.

## dimension summary & decomposition signal

| matrix | ind dims | rows | verdict |
|--------|----------|------|---------|
| A (command outcome) | 5 | 7 | **watch** — 5 ind dims trips the 4+ decomposition signal |
| B (output shape) | 1 | 3 | clean |
| C (capture fidelity) | 1 | 3 | clean |
| D (idempotency/drift) | 2 | 3 | clean |
| E (override) | 2 | 3 | clean |

**decomposition callout (matrix.A):** 5 independent preconditions *looks* like an
explosion, but it is **not** a true 2^5 combinatorial space — the dimensions are
**sequential gates**, not orthogonal. exactly one can be the "first false," so
the meaningful rows are linear (n gates → n+1 rows), not exponential. so the
usecase boundary is sound; no decomposition needed. the matrix is presented as a
gate-precedence table, which is the honest shape of the behavior.

the remaining matrices (B–E) each have ≤2 ind dims and are individually clean —
evidence the usecases are already at the right behavioral grain.
