# 2.1 blackbox criteria — sdk codegen

> experience boundaries only. what the caller does + sees + receives. no
> mechanism or implementation detail. the system under test is the command
> `npx sdk-aws-lambda gen --for <service> --into <dir>/`.

---

# usecase.1 = generate a service sdk into the consumer repo

```
given a service is deployed to prep
and the caller has prep access
  when the caller runs `npx sdk-aws-lambda gen --for svc-jobs --into src/access/svcs/`
    then three files appear under src/access/svcs/:
         svcJobs.ts, svcJobs.mechanisms.ts, svcJobs.resources.ts
      sothat the caller has a typed sdk with no hand-transcription
    then the barrel svcJobs.ts re-exports the `svcJobs` object and all resources
      sothat one import path serves both the calls and the types
    then each generated file carries a "generated — do not edit; re-run to update" banner
      sothat readers re-run rather than hand-edit

  when the caller opens svcJobs.mechanisms.ts
    then it exports a `svcJobs` object with one async fn per discovered endpoint
    then each fn accepts (event, context) and returns the endpoint's typed output
      sothat calls are typed end-to-end

  when the target directory does not yet exist
    then gen creates it
      sothat first-run needs no manual setup
```

---

# usecase.2 = capture upstream domain objects, namespaced, metadata intact

```
given svc-jobs surfaces a `Job` domain object through its contract
  when the caller generates the svc-jobs sdk
    then svcJobs.resources.ts declares `SvcJobsJob` (originator-prefixed)
      sothat it cannot collide with the consumer's own `Job` or another service's `Job`
    then SvcJobsJob carries the same primary + unique + alias + nested metadata as upstream
      sothat identity, refs, and change-detection work on the captured dobj
    then SvcJobsJob carries no re-declared validation schema
      sothat consumers do not re-validate what the originator already checks

given the same domain object is referenced by many endpoints
  when the caller generates the sdk
    then that dobj is declared once in resources
      sothat resources are de-duplicated, not repeated per endpoint

given a domain object nests another dobj (e.g. Job nests an Address)
  when the caller generates the sdk
    then both the outer and the nested dobj are captured and prefixed
      sothat nested references reconstruct correctly
```

---

# usecase.3 = re-generate to detect upstream drift

```
given a prior generated sdk is committed
  when svc-jobs adds a field and the caller re-runs gen
    then the regenerated files change to include the new field
      sothat the diff surfaces the change in review
    then no runtime surprise occurs at call time
      sothat drift is caught at build, not in production

given the upstream contract is unchanged
  when the caller re-runs gen
    then the generated files are byte-identical to before
      sothat re-generation is idempotent and yields no spurious diff
```

---

# usecase.4 = own the unqualified namespace / override

```
given the consumer wants its own `Job` that translates the upstream one
  when the consumer declares its own `Job` and casts from `SvcJobsJob`
    then no name collision occurs
      sothat the consumer owns the unqualified namespace while it references the origin
```

---

# usecase.5 = service not found / no discoverable endpoints

```
given a service name with no endpoints deployed in prep (typo or undeployed)
  when the caller runs gen
    then the caller receives a clear "service not found / no endpoints" error
    then no files are written
      sothat a typo or undeployed service fails loud, not as a silent empty result
```

---

# usecase.6 = introspection blocked outside prep

```
given the caller's access is prod or test
  when the caller runs gen
    then the caller receives a clear "introspection only available in prep" error
    then no files are written
      sothat upstream schemas never leak outside prep
```

---

# usecase.7 = absent prep credentials

```
given the caller has not unlocked prep credentials
  when the caller runs gen
    then the caller receives a clear credentials error with a hint on how to unlock
    then no files are written
      sothat the failure is actionable, not a cryptic stack trace
```

---

# usecase.8 = an endpoint lacks introspection support (all-or-none)

```
given one endpoint in the service does not support introspection
  when the caller runs gen
    then the caller receives an error that names the unsupported endpoint
    then no partial sdk is written
      sothat a broken or half-complete sdk is never emitted
```

---

# usecase.9 = a contract-surfaced dobj cannot be captured

```
given an endpoint references a domain object that declares no schema to capture
  when the caller runs gen
    then the caller receives a clear error that names the dobj which cannot be captured
    then no partial sdk is written
      sothat the gap is visible and fixable at the source, not silently dropped
```

---

## exchange boundary summary (atomic input → output)

```
input:
  --for   <service>     a svc-$noun service name (required)
  --into  <dir>/        target directory for the generated files (required)
  ambient: caller's prep access + prep credentials

output (success):
  <dir>/<svc>.ts              barrel: re-exports mechanisms object + resources
  <dir>/<svc>.mechanisms.ts   `<svc>` object of typed (event, context) async fns
  <dir>/<svc>.resources.ts    prefixed dobj classes w/ primary/unique/alias/nested

errors (each: clear message, no files written):
  service not found / no endpoints         (usecase.5)
  introspection blocked (access ≠ prep)     (usecase.6)
  absent / expired prep credentials         (usecase.7)
  endpoint lacks introspection support      (usecase.8, names the endpoint)
  dobj cannot be captured                   (usecase.9, names the dobj)

boundary conditions:
  - target dir absent → created
  - re-run, upstream unchanged → byte-identical output (idempotent)
  - re-run, upstream changed → minimal diff that shows the change
  - a dobj referenced N times → declared once
```
