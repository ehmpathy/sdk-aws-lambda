## playtest: `sdk-aws-lambda gen` — codegen a per-service sdk from live introspection

### prerequisites

- node + this repo installed (`npm ci` already run).
- for the deterministic steps (1–5, 7–10): **no AWS creds needed** — they use an
  in-process lambda harness that runs the REAL handlers + fakes only the sdk
  transport (per `rule.forbid.acceptance.mocks`, documented inline in each test).
- for the real-fidelity "aha" step (6): **prep AWS creds** —
  `rhx keyrack unlock --owner ehmpath --env prep` (approve the browser SSO). this
  deploys a real lambda + runs the codegen over the wire.
- the CLI ships as a `bin`: `package.json` → `"sdk-aws-lambda":
  "dist/contract/cli/gen.js"`. `npm run build` produces it (verified: build green).

### sandbox

- steps 1–10 write only into the OS temp dir (`mkdtemp`), never the repo. the
  acceptance tests clean up their own temp dirs in `afterAll`.
- if you hand-run the real bin (optional, alongside step 6), target `@gitroot/.temp/`:
  `mkdir -p .temp && node dist/contract/cli/gen.js --for svc-jobs --into .temp/svcs --env prep`.
  never point `--into` at `src/` in a playtest.

### happy paths

1. **adopt — one command yields 3 typed files (barrel + mechanisms + resources).**
   - run:
     ```sh
     rhx git.repo.test --what acceptance --against local --env test --mode apply --scope 'path://blackbox/local.codegen.acceptance'
     ```
   - expected: `[case1]` passes. the `gen({ argv })` CLI happy path exits 0 and
     writes exactly `svcJobs.ts`, `svcJobs.mechanisms.ts`, `svcJobs.resources.ts`.
   - eyeball the emitted files (the reviewer-visible vibecheck):
     ```sh
     cat blackbox/__snapshots__/local.codegen.acceptance.test.ts.snap
     ```
     - barrel re-exports both: `export { svcJobs } from './svcJobs.mechanisms';`
       + `export * from './svcJobs.resources';`
     - mechanisms: `export const svcJobs = {` with `getJob:` + `getJobs:`, each a
       typed `askLambdaEndpoint<{event}, {result}>(...)` wrapper.
     - resources: `SvcJobsJob` (entity) + nested `SvcJobsAddress` (literal), banner
       `generated by \`sdk-aws-lambda gen\` — do not edit` on top.
   - cites: `blackbox/local.codegen.acceptance.test.ts` `[case1]`.

2. **the "aha" — the captured dobj IS the upstream dobj, metadata intact.**
   - in the same resources snapshot from step 1, confirm:
     - `export class SvcJobsJob extends DomainEntity<SvcJobsJob>` — a real
       DomainEntity, not a bare interface.
     - `public static primary = ['uuid'] as const;` — propagated identity.
     - `public static unique = ['title'] as const;` — propagated natural key.
     - `public static alias = { singular: 'job', plural: 'jobs' };` — propagated.
     - `public static nested = { address: SvcJobsAddress };` — nested dobj, prefixed.
     - **no `static schema`** — consumers do not re-validate (the originator does).
   - cites: `blackbox/local.codegen.acceptance.test.ts` `[case1]` (resources
     assertions: `toContain('SvcJobsJob')`, `toContain('static primary')`,
     `not.toContain('static schema')`).

3. **stay in sync — re-gen with an unchanged upstream is byte-identical (idempotent).**
   - run:
     ```sh
     rhx git.repo.test --what acceptance --against local --env test --mode apply --scope 'path://blackbox/local.codegen.journey'
     ```
   - expected: journey `[t2]` passes — `expect(after).toEqual(before)`. two codegen
     runs on the same contract produce identical bytes (no churn in a PR).
   - cites: `blackbox/local.codegen.journey.acceptance.test.ts` `[t2]`.

4. **drift — an upstream field addition surfaces as a minimal diff.**
   - expected (same journey run): `[t3]` passes — after the upstream adds a `note`
     field, the resources file `toContain('note')` and the `t3-drift-resources`
     snapshot shows the new field. drift is a reviewable diff, not a silent bug.
   - cites: `blackbox/local.codegen.journey.acceptance.test.ts` `[t3]`.

5. **recover — a full journey ends byte-identical to its start (roundtrip).**
   - expected (same journey run): `[t6]` passes — after adopt → sync → drift →
     blocked → uncapturable → revert, the final gen equals the `[t1]` output
     byte-for-byte (`expect(files).toEqual(t1Files)`).
   - cites: `blackbox/local.codegen.journey.acceptance.test.ts` `[t6]`.

6. **the deployed "aha" — real fidelity over the wire (needs prep creds).**
   - run (unlock first):
     ```sh
     rhx keyrack unlock --owner ehmpath --env prep
     rhx git.repo.test --what acceptance --against cloud --env prep --mode apply --scope 'path://blackbox/deployed.codegen'
     ```
   - expected: deploys a real `svc-surf-prep-getSurfboard` lambda, runs the codegen
     against it, and the generated `svcSurf.resources.ts` reconstructs
     `SvcSurfSeaturtleSurfboard` — `extends DomainEntity`, `primary = ['uuid']`,
     `unique = ['brand', 'length']`, a nested inline `length: { inches: number }`, an
     `alias`, and **no schema** — proof
     the `x-domain-object` pragma survives a real `z.toJSONSchema()` round-trip.
   - cites: `blackbox/deployed.codegen.acceptance.test.ts` `[case1]`.

### edgey paths

7. **blocked — `--env prod` fails loud and writes NO files (introspection gate).**
   - covered two ways:
     - CLI atomically: `local.codegen.acceptance` `[case2]` t5 → exit 2 +
       `LambdaIntrospectionBlockedError` + `re-run with --env prep` hint.
     - in-sequence: journey `[t4]` (SDK) + `[t7]` (CLI) → the prior on-disk state is
       intact after a blocked run (`expect(after).toEqual(before)`).
   - expected → pass if: a prod-access run exits 2, names the block, and leaves any
     prior generated files untouched. **✗ fail if** any file is written or the exit
     is 0.
   - cites: `local.codegen.acceptance.test.ts` `[case2]` t5;
     `local.codegen.journey.acceptance.test.ts` `[t4]` + `[t7]`.

8. **uncapturable dobj — fails loud, NAMES the culprit, no partial write.**
   - expected (journey `[t5]` + `local.codegen.acceptance` `[case3]` t2): an upstream
     dobj whose schema declares no properties throws
     `LambdaDomainObjectNotCapturableError`, the message names `Ghost`, and the target
     dir is empty (`expect(await readdir(dir)).toEqual([])`). all-or-none holds.
   - the fixture uses a REAL `DomainEntity` with `static schema = z.object({})` via
     `.contract`, so it exercises the production capture path, not a hand-stamped pragma.
   - cites: `local.codegen.journey.acceptance.test.ts` `[t5]`;
     `local.codegen.acceptance.test.ts` `[case3]` t2.

9. **endpoint lacks introspection support — fail loud, NAMES the endpoint.**
   - expected (`local.codegen.acceptance` `[case3]` t1): a service whose endpoint does
     not answer `{ introspect: 'schema' }` (a non-schema payload) throws
     `LambdaIntrospectionNotSupportedError`, and the message names the culprit endpoint
     slug `svc-jobs-prep-getLegacy`. all-or-none: exit 2, the target dir stays empty.
   - the same all-or-none-over-a-batch behavior is also proven at the spine in
     `local.introspection.acceptance` `[case12]` ("error names the offending function").
   - cites: `local.codegen.acceptance.test.ts` `[case3]` t1;
     `local.introspection.acceptance.test.ts` `[case12]`.

10. **service not found / absent creds — fail loud with an actionable hint.**
    - expected (`local.codegen.acceptance` `[case3]` t0 + t3): an unknown service →
      `LambdaServiceNotFoundError` ("check the --for service name and verify it is
      deployed to prep"); absent AWS creds → `LambdaCredentialsAbsentError` ("unlock
      prep creds … then re-run"). both exit 2, write no files.
    - cites: `local.codegen.acceptance.test.ts` `[case3]` t0 + t3.

11. **bad CLI args — every malformed invocation exits 2 with a usage hint.**
    - run:
      ```sh
      rhx git.repo.test --what integration --env test --mode apply --scope 'path://src/contract/cli/gen'
      ```
    - expected: `gen.integration` passes — absent/invalid `--for` (two DISTINCT
      messages: `--for is required` vs `invalid --for value 'jobs'`), `--env prod`
      blocked → all exit 2 with `sdk-aws-lambda gen --for svc-<noun> --into <dir>
      --env <test|prep|prod>` usage. also `local.codegen.acceptance` `[case2]` covers
      all 6 pre-AWS variants exhaustively.
    - cites: `src/contract/cli/gen.integration.test.ts`;
      `local.codegen.acceptance.test.ts` `[case2]`.

### pass/fail criteria

- ✓ **pass if:**
  - steps 1–5 + 7–11 pass with `rhx git.repo.test --what acceptance/integration` at
    0 failed, 0 skipped (self-run: acceptance **165 passed**, integration
    **32 passed**).
  - the generated snapshots read as clean, idiomatic TypeScript: a real
    `DomainEntity`/`DomainLiteral` per dobj with `primary`/`unique`/`alias`/`nested`
    and no `static schema`; a typed `svcJobs` mechanisms object; a 2-line barrel.
  - step 6 (deployed) reconstructs `SvcSurfSeaturtleSurfboard` from real prep AWS
    with its keys + alias intact.
- ✗ **fail if:**
  - any codegen error path exits 0, or writes a partial/broken file set.
  - a captured dobj loses its `primary`/`unique`/`alias`/`nested`, or re-emits a
    `static schema`.
  - a re-gen on an unchanged upstream produces a non-empty diff (idempotency broken).
  - the deployed test cannot reconstruct the dobj from the real wire round-trip.
