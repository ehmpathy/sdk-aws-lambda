# 4.1 roadmap — sdk codegen execution

> checklist-style, dependency-ordered phases to execute the product blueprint
> (`3.3.1.blueprint.product.yield.md`). each phase declares: what to build, which
> briefs to read first, the behavioral acceptance criteria, and how to verify.
>
> **grain reminder (all phases):** `(input, context?)`, get/set/gen + as* verbs,
> one op per file, inline i/o types, no barrel forwarders, fail-loud errors.
> run `rhx git.repo.test --what types|lint|unit|integration` after each phase.

## dependency graph (summary)

```
p0 foundations ──┬─► p1 name transform ──┐
                 └─► p2 dobj capture ─────┼─► p3 source emit ─► p4 file+write ─► p5 orchestrator ─► p6 cli ─► p7 local acceptance ─► p8 deployed acceptance ─► p9 release
                                          │
      (p1 + p2 are parallel after p0) ────┘
```

- **p8 (deployed)** is the only phase gated on a real prep deploy — by design, it's
  the last acceptance step. the `domain-objects@0.32.0` dependency (shipped) is
  already installed, so no external blocker remains.
- **p1 and p2** can run in parallel once p0 lands.
