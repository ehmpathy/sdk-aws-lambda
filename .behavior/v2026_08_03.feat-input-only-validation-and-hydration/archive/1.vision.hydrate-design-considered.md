> **what this is** — the built-out alternative that `X.contract()` superseded
> (`rule.always.yield-the-output-not-the-archaeology`). kept whole so the comparison is
> auditable rather than asserted, and so the fork is not re-litigated from scratch.
>
> **why it was rejected** — `.coerce()` wins on every axis measured, and repairs two defects this
> design could not: the `ZodSchema<any>` type erasure, and the shapeless hydration error. the
> verdict is `q.10`, in `../appendix/1.vision.groundwork-and-decisions.md`.
>
> ⚠️ **no line below is a proposal.** the live proposal is `../1.vision.yield.md`. the `hydrate`

>
> ✅ **every `output: z.void()` below is FINE after all** — and this note flipped twice, so the
> trail is worth the four lines. stone `5.1` measured that `z.void()` threw

> the better one. the full trail is in `../1.vision.yield.md` under *"the input-only case"*.

> ⇒ the `z.void()` lines below still must not be copied — but for the reason the `.what` above
> gives (the `hydrate` key was never built), never for the render.

## the outcome world

### day in the life

a mechanic migrates `configureProxyPhoneNumber` from `createStandardHandler`. they need
`handle` typed against `Agent`, and they have no output shape worth a claim.

**before** — the handler that motivated this wish (verbatim, `.wish.md` §.ground):

```ts
export const handler = genLambdaEndpoint(
  {
    schema: { input: schema, output: z.any() }, // <-- rubber-stamp, not a real contract
    invoke: async ({ event }) =>
      handle({
        ...event,
        assignment: event.assignment
          ? {
              ...event.assignment,
              agent: event.assignment.agent
                ? new Agent(event.assignment.agent) // <-- manual nested hydration
                : null,
            }
          : null,
      }),
  },
  { env: { access: envStatic.access } },
);
```

**after**:

```ts
export const handler = genLambdaEndpoint(
  {
    schema: { input: schema, output: z.void() }, // a claim, not a rubber-stamp — extant zod
    hydrate: { with: [Agent] },                  // identity only; position comes from the schema
    invoke: async ({ event }) => handle(event),
  },
  { env: { access: envStatic.access } },
);
```

**only one of those two lines is new.** `output: z.void()` needs no sdk change at all — it was
available the whole time ([q.9](#q9--the-wisher-challenged-the-none-premise-itself-does-none-survive-ruled-drop-none)), and it is a *positive claim* where `z.any()` was a shrug.
that swap is a doc-and-steer fix, not a feature.

`hydrate` is the deliverable. note what it does **not** say: where `Agent` sits. in the evidence
`assignment` is a **plain** wrapper (the original spreads it into an object literal,
`0.wish.md:57-67`) and only `agent` is a domain class — a position the sdk reads off the
schema's `x-domain-object` pragma rather than one the consumer restates
([g.13](#g13--stamp-_dobj-from-the-schema-pragma-then-deserialize--it-works-and-it-reaches-arrays)). so the declaration cannot drift out of sync with the schema's shape, and it
does not grow when the shape nests one level deeper.

the `invoke` collapses to a passthrough. the spread, the ternaries, the nested `new Agent`
— all gone.

> **on the two vocabularies in this yield.** `Agent` / `assignment` appear only where the record
> is **real**: the wish's verbatim `.ground` quote above, and the probe transcripts in
> [groundwork](#groundwork). those are cited evidence and are left exactly as they ran
> (`rule.require.trust-but-verify`). every **illustrative** example below uses the house surf
> domain — `Surfer`, `SurfLesson`, `WaveReport` — so a reader can tell an invention from a
> citation at a glance.

### the before/after contrast

| | before | after |
|---|---|---|
| domain instances in `handle` | hand-rebuilt per field, per level | `hydrate: { with: [Agent] }` |
| nested domain objects | hand-rolled, one `new X()` per level | the schema walk reaches plain wrappers **and** arrays ([g.13](#g13--stamp-_dobj-from-the-schema-pragma-then-deserialize--it-works-and-it-reaches-arrays)); below a dobj, `.nested` is free ([g.7](#g7-nested-hydration-already-ships-in-domain-objects033)) |
| a deeper input shape | one more `new X()` per level, per handler | the same one-line declaration |
| the alternative a tired author reaches for | `event as ...` (forbidden — `rhachet-roles-ehmpathy#537`) | the declaration is now the shorter path |
| "output is un-validated" | `z.any()` — a shrug | `z.void()` — a claim. **no sdk change; this row is a steer, not a feature** ([q.9](#q9--the-wisher-challenged-the-none-premise-itself-does-none-survive-ruled-drop-none)) |

### the "aha"

> **the schema already says where the domain objects are. every hand-rolled `new X()` restates
> what the sdk was already told.**

`X.contract` stamps an `x-domain-object` pragma that survives `z.toJSONSchema()`
([g.2](#g2--xcontract-stamps-identity-and-it-survives-ztojsonschema)) — that is how this repo's codegen already recognizes a dobj on the wire
(`getAllDomainObjectsFromContracts.ts:47`). the endpoint holds that same schema at runtime. so
every hand-written `new Agent(event.assignment.agent)` restates a fact the sdk could read.

what `domain-objects` genuinely cannot supply is a **constructor** from a name
([g.6](#g6-hydration-cannot-be-inferred--domain-objects-carries-no-nameclass-registry)) — so the consumer owes a class **list**, and no more. identity is theirs; position is
the schema's. that split is the whole design, and it is why `hydrate` stays one line as the
input shape grows.

**this reframes the deliverable.** it is not "add a hydration hook"; it is "keep the identity
the schema already carries" — which is why the mechanism composes with the codegen (`#10`)
rather than lives beside it.

## user experience

### who, and what goal

| user | goal | today's cost | this vision |
|---|---|---|---|
| handler author whose `handle` takes domain classes | give `handle` its true contract | hand-rebuilds the graph, or reaches for `event as ...` (forbidden — `rule.forbid.as-cast`, `rhachet-roles-ehmpathy#537`) | **solved** — `hydrate` |
| the same author, one refactor later | keep it correct as the input shape deepens | every new level is another `new X()` in every handler that takes it | **solved** — the declaration does not grow |
| handler author who migrates off `createStandardHandler` | preserve input-only behavior | writes a shrug, adds a comment that apologizes for it | **out of scope** — `z.void()` was available and unreached; a steer defect, not a capability gap ([q.9](#q9--the-wisher-challenged-the-none-premise-itself-does-none-survive-ruled-drop-none)) |
| downstream consumer who codegens an sdk | a typed caller | gets `Promise<unknown>` with no signal why | **reported, not built** ([g.1](#g1-output-zany-degrades-the-generated-sdk-to-promiseunknown)) |

### the contract inputs & outputs

**one key added; no other line moves.**

```ts
export type GenLambdaEndpointInput<TInput, TOutput> = {
  schema: {
    input: ZodSchema<TInput>;                // <-- unchanged
    output: ZodSchema<TOutput>;              // <-- unchanged (q.9 cut the widening)
  };
  hydrate?: { with: DomainObjectClass[] };   // <-- the whole change; optional, identity only
  invoke: EndpointOperation<TInput, TOutput>;
  logTranslate?: IoLogTranslate;
};
```

- `hydrate.with` — a **flat list** of the `DomainObject` classes that may appear in the input.
  identity only: the sdk reads each one's *position* from the schema's `x-domain-object` pragma
  ([g.13](#g13--stamp-_dobj-from-the-schema-pragma-then-deserialize--it-works-and-it-reaches-arrays)), so the declaration does not restate the shape and cannot drift from it.
- **`hydrate` is optional and additive.** an endpoint without it behaves exactly as today, so
  wish acceptance bullet 6 holds by construction rather than by care.

**the schema walk runs once, at handler construction — not per invocation.** `genLambdaEndpoint`
holds the zod schema when it builds the handler, so `z.toJSONSchema(schema.input, { io: 'input' })`
is computed there and reused. two consequences that shape the design:

- **cost is amortized**, so hydration adds no per-invocation serialization.
- **construction is the moment a mismatch is decidable** — a class in `with` that the schema
  never stamps can be refused *then*, before any caller sees a silent no-op
  ([f.2](#f2-what-shape-does-hydrate-take), `rule.prefer.prevent-over-correct`).

the `{ io: 'input' }` argument is load-bearing, not incidental: with zod's default (`'output'`)
the walk would crash on any input schema that carries a `.transform()` — a **shipped, tested**
feature of this repo ([g.9](#g9-transform-bearing-input-schemas-are-a-shipped-feature-and-they-are-already-broken)). [g.4](#g4-io-input-vs-io-output-is-codegen-neutral) proves that direction is codegen-neutral.

**the `TInput` side carries a caveat i cannot design away.** against `X.contract` the position
types as `any`, because `getContract` returns `ZodSchema<any>` ([g.14](#g14--xcontract-is-typed-zodschemaany-so-it-erases-the-position-it-stamps)). so the dobj positions
are already `any` before hydration is considered, and no shape of `hydrate` recovers a type the
schema erased. upstream `domain-objects`, not a mechanism choice — see [q.8](#q8--the-type-level-half-of-no-as-cast-rests-on-an-upstream-any-report-it-answered).

### what it looks like to leverage it

uc.1–4 isolate the four shapes a dobj can sit in; **uc.5 is the one to read if you read only
one** — it puts all four in a single endpoint and shows the declaration stay one line.

**uc.1 — a dobj at the top level**

```ts
genLambdaEndpoint({
  schema: { input: z.object({ surfer: Surfer.contract }), output: SurfLesson.contract },
  hydrate: { with: [Surfer] },
  invoke: async ({ event }) => genSurfLesson(event.surfer), // event.surfer instanceof Surfer
});
```

**uc.2 — a dobj under a PLAIN wrapper** — the shape the wish's evidence actually has, and the
one a top-level-only design would miss

```ts
genLambdaEndpoint({
  schema: {
    input: z.object({
      signup: z.object({                     // <-- a plain object, NOT a dobj
        surfer: Surfer.contract,             // <-- the dobj lives one level down
        note: z.string(),
      }).nullable(),
    }),
    output: z.void(),
  },
  hydrate: { with: [Surfer] },               // unchanged — the schema says where to look
  invoke: async ({ event }) => {
    event.signup?.surfer;                    // instanceof Surfer
    event.signup?.note;                      // still a plain string
  },
});
```

**uc.3 — a dobj inside an array** (unreachable by a hand-declared map; free here)

```ts
genLambdaEndpoint({
  schema: { input: z.object({ surfers: z.array(Surfer.contract) }), output: z.void() },
  hydrate: { with: [Surfer] },               // unchanged again, deeper shape
  invoke: async ({ event }) => event.surfers.every((s) => s instanceof Surfer), // true
});
```

**uc.4 — a dobj nested in another dobj** (`.nested` does the inner one for free)

```ts
// WaveReport declares `public static nested = { spot: SurfSpot }`
genLambdaEndpoint({
  schema: { input: z.object({ report: WaveReport.contract }), output: z.void() },
  hydrate: { with: [WaveReport] },           // SurfSpot is NOT listed — .nested covers it (g.7)
  invoke: async ({ event }) => event.report.spot, // instanceof SurfSpot
});
```

**uc.5 — the realistic case: several dobjs, at several depths, one list**

the four shapes above are isolated for clarity; a real endpoint mixes them. this is the example
that shows the design actually pays:

```ts
// WaveReport declares `public static nested = { spot: SurfSpot }`
genLambdaEndpoint({
  schema: {
    input: z.object({
      surfer: Surfer.contract,                   // depth 0 — a dobj at the top
      signup: z.object({                         // a PLAIN wrapper...
        spot: SurfSpot.contract,                 //   depth 1 — a dobj beneath it
        note: z.string(),
      }).nullable(),
      boards: z.array(Surfboard.contract),       // depth 1 — dobjs inside an array
      report: WaveReport.contract,               // depth 0 — carries .nested { spot: SurfSpot }
    }),
    output: SurfLesson.contract,
  },

  hydrate: { with: [Surfer, SurfSpot, Surfboard, WaveReport] },

  invoke: async ({ event }) =>
    genSurfLesson({
      surfer: event.surfer,          // instanceof Surfer   — schema walk
      spot: event.signup?.spot,      // instanceof SurfSpot — schema walk, through the wrapper
      boards: event.boards,          // Surfboard[]         — schema walk, every element
      swell: event.report.spot,      // instanceof SurfSpot — .nested, NOT the schema walk
    }),
});
```

**read the `with` list against the schema and note what it does NOT encode:** no depth, no key
path, no array-ness, no order. four names, flat, in any order. the schema supplies all the rest.

**note `SurfSpot` arrives by two different routes here, and that is not a contradiction.** the
one under `signup` is found by the schema walk, so its class must be in `with`. the one inside
`report` is rebuilt by `WaveReport`'s own `.nested` ([g.7](#g7-nested-hydration-already-ships-in-domain-objects033)) — it would arrive hydrated even
if `SurfSpot` were absent from the list. **`with` names what the SCHEMA must locate, not every
class that ends up instantiated.** the two mechanisms compose without either one knowing about
the other.

and the hand-rolled equivalent — what every handler writes today for this same shape:

```ts
invoke: async ({ event }) =>
  genSurfLesson({
    surfer: new Surfer(event.surfer),
    spot: event.signup?.spot ? new SurfSpot(event.signup.spot) : null,
    boards: event.boards.map((b) => new Surfboard(b)),
    swell: new WaveReport(event.report).spot,
  }),
```

four constructors, one `.map`, one ternary for the nullable — and every one of them has to be
revisited when the schema shape moves. **the `with` list does not move.** that is the whole
delta, and it is why the value grows with the shape rather than holds flat.

it also shows the failure mode the sdk removes: the hand-rolled version is **correct only by
vigilance**. drop the ternary and a `null` signup throws; forget the `.map` and `boards` stays
plain while its type says otherwise ([g.14](#g14--xcontract-is-typed-zodschemaany-so-it-erases-the-position-it-stamps) means the compiler will not catch that). the
declaration has no such failure mode because there is no per-position code to get wrong.

a `null` or absent value at any position is left untouched — matching how `domain-objects`
treats a nullable `.nested` prop, so `signup: null` stays `null` rather than throwing.

**uc.6 — no `hydrate` at all** (the extant path, untouched — wish acceptance bullet 6)

```ts
genLambdaEndpoint({
  schema: { input: inSchema, output: outSchema },
  invoke: async ({ event }) => compute(event),
});
```

### the timeline a caller goes through

```
handler construction (once)
  └─ schema walk       NEW  → z.toJSONSchema(schema.input, { io: 'input' }); locate every
                              x-domain-object pragma; refuse if `with` and schema disagree

payload arrives (per invocation)
  ├─ trail middleware       → unwraps { event, trail }, injects log
  ├─ introspection          → if { introspect: 'schema' }, short-circuit with the json-schema pair
  ├─ input validation       → schema.input.safeParse → ConstraintError on failure (caller fault)
  ├─ hydration         NEW  → stamp `_dobj` at the located positions, then deserialize;
  │                           each dobj's own `.nested` resolved by domain-objects
  │                           → see f.3 for the two fault attributions
  ├─ invoke                 → receives hydrated event, real domain contract
  └─ output validation      → unchanged
```

two placements matter, and both are deliberate:

- **the walk is at construction**, so a `with`/schema disagreement is a deploy-time failure
  rather than a per-invocation one.
- **hydration is after input validation**, so a malformed payload is rejected by the declared
  contract before any class constructor sees it — the constructor never has to double as a
  wire-format guard.

## mental model

### how a user describes it to a friend

> "the schema says what crosses the wire; `hydrate` says what it becomes once it's inside.
> you list which classes can show up — the schema already knows where."

### analogies

- **customs, then baggage claim.** validation is customs — it checks the declaration and
  turns away anything that doesn't match. hydration is baggage claim — the thing that
  cleared customs gets handed to you in the form you actually use it in. two counters, two
  jobs; you don't want customs handing you your suitcase.
- **a lineup roster, not a map of the break.** `with: [Surfer, SurfSpot, Surfboard]` says *who
  may paddle out*. the schema already holds *where each one sits in the lineup*. a map has to be
  redrawn every time the swell shifts; a roster does not.

### terms — theirs vs ours

| they say | we say | why ours |
|---|---|---|
| "cast it to the class" | **hydrate** | `rule.forbid.as-cast`; matches `domain-objects`' own `hydrateNestedDomainObjects` |
| "the plain object" | the **validated input** | it is validated; it is just not yet a domain instance |
| "the hydration map" | `with` — the **class list** | there is no map; a map implies position, and position is the schema's ([g.13](#g13--stamp-_dobj-from-the-schema-pragma-then-deserialize--it-works-and-it-reaches-arrays)) |
| "rubber-stamp" | (we keep it) | the wish's own word; names the smell exactly |

`hydrate` is **not a new term** — `domain-objects@0.33.0` already ships
`hydrateNestedDomainObjects` and documents "hydration honors that promise on `.build`".
we reuse the domain's word rather than coin one (`rule.require.ubiqlang`).

## evaluation

### against the wish's acceptance

| acceptance | verdict |
|---|---|
| input-only declared explicitly & greppably | **already satisfied — no sdk change.** `output: z.void()` is explicit, greppable, and a positive claim. ruled out of scope ([q.9](#q9--the-wisher-challenged-the-none-premise-itself-does-none-survive-ruled-drop-none)). |
| `z.any()` no longer the only way | **already satisfied — it never WAS the only way.** `z.void()` / `z.unknown()` are valid ZodSchemas today; the wish's "forced" premise does not hold ([q.9](#q9--the-wisher-challenged-the-none-premise-itself-does-none-survive-ruled-drop-none)). |
| input arrives as domain instances, no cast, no per-field rebuild | ✅ at runtime, via `hydrate`. **⚠️ partial at the type level** — `X.contract` erases the position to `any` ([g.14](#g14--xcontract-is-typed-zodschemaany-so-it-erases-the-position-it-stamps)), so the cast is removed but not replaced by a narrowed type. upstream, not closable here ([q.8](#q8--the-type-level-half-of-no-as-cast-rests-on-an-upstream-any-report-it-answered)). |
| hydration reaches nested | ✅ the schema walk reaches dobjs under plain wrappers (the evidence's shape) **and** inside arrays ([g.13](#g13--stamp-_dobj-from-the-schema-pragma-then-deserialize--it-works-and-it-reaches-arrays)); `.nested` covers each dobj's own graph below that ([g.7](#g7-nested-hydration-already-ships-in-domain-objects033)). a top-level-only map would fail this bullet. |
| failed construction fails loud, never half-built | ✅ **already true today** ([g.8](#g8-a-dobj-that-refuses-a-validated-input-surfaces-today-but-with-an-inconsistent-error-shape)) — this is a "do not regress", not a "build" |
| `{ input, output }` path unchanged | ✅ **by construction** — `hydrate` is a new optional key; the `schema` type is byte-identical to today's |

### pros

- **the pit of success** — the ergonomic path becomes the recommended path. today, per the
  wish, "the cast is what a tired author reaches for."
- **cheap** — the hard parts (nested hydration, pragma-stamped contracts, the recursive walk)
  all already ship in `domain-objects`; this sdk composes them rather than reimplements them.
- **it does not grow with the input shape** — one declaration covers plain wrappers, arrays,
  and any depth below a dobj. the hand-rolled alternative grows with every level.
- **codegen-neutral** — no change to emitted types for extant consumers ([g.4](#g4-io-input-vs-io-output-is-codegen-neutral)).
- **strictly additive** — an endpoint without `hydrate` takes no new code path at all.

### cons

- **two validation passes.** zod validates, then the dobj constructor validates again. see
  [q.2](#q2-hydration-double-validates-is-that-acceptable-answered) — answered, accepted, with a reason.
- **hydration binds to `X.contract`.** position is read off the pragma, so a hand-written
  `z.object` gets no hydration at all. that must be a loud construction-time refusal rather
  than a silent no-op ([f.2](#f2-what-shape-does-hydrate-take)) — otherwise it is the same failhide shape [g.11](#g11--raw-deserialize-on-a-plain-payload-is-a-silent-no-op) found.
- **the type-level guarantee is weaker than the runtime one.** `X.contract` is `ZodSchema<any>`
  ([g.14](#g14--xcontract-is-typed-zodschemaany-so-it-erases-the-position-it-stamps)), so `handle(event)` compiles whether or not hydration ran. the wish's actual
  complaint — the hand-rolled graph rebuild — is fully answered; the implied type-safety upside
  is not, and cannot be from inside this repo ([q.8](#q8--the-type-level-half-of-no-as-cast-rests-on-an-upstream-any-report-it-answered)).

### edge cases, and how the contract keeps a user in the pit of success

| edge case | how the contract holds |
|---|---|
| author declares `hydrate: { with: [Surfboard] }` where the schema stamps no `Surfboard` | **must refuse at handler construction** — the schema is known then, so the mismatch is decidable before any invocation (`rule.prefer.prevent-over-correct`). left silent, it is a no-op that reads as hydration (`rule.forbid.failhide`, cf. [g.11](#g11--raw-deserialize-on-a-plain-payload-is-a-silent-no-op)). |
| schema stamps a dobj the author left out of `with` | `domain-objects` already throws `MalfunctionError` (exit 1, server fault) — correct attribution ([f.3](#f3-is-a-hydration-failure-a-caller-fault-or-a-server-fault)), but better raised at construction than per-invocation. |
| author uses a hand-written `z.object` rather than `X.contract` | same refusal as above. this is the design's real cost ([a.5](#assumptions-surfaced--and-questioned)) — the mitigation is that a consumer learns it at deploy, in one message that names `.contract` as the fix, rather than by a quiet no-op in prod. |
| the dobj's schema is stricter than the declared input schema | hydration throws, and **already reaches the caller today** as `BadRequestError` ([g.8](#g8-a-dobj-that-refuses-a-validated-input-surfaces-today-but-with-an-inconsistent-error-shape)) — so the bullet holds. the raw `HelpfulZodValidationError` dump could be normalized to the `{ issues }` shape, but that is **opportunistic, not required**. |
| the input schema carries a `.transform()` | the walk must use `{ io: 'input' }` or it crashes ([g.9](#g9-transform-bearing-input-schemas-are-a-shipped-feature-and-they-are-already-broken)). transforms are a shipped, tested feature of this repo, so this is a live path, not a hypothetical. |
| a consumer hydrates via `.transform()` instead | three independent failures: it breaks introspection at runtime ([g.3](#g3-transform-hydration-breaks-introspection-at-runtime)), its throw escapes `safeParse` and bypasses the middleware's only error branch ([g.10](#g10--safeparse-does-not-contain-a-throw-from-inside-a-transform)), **and** it would publish domain classes a cross-service caller cannot construct ([a.7](#assumptions-surfaced--and-questioned)). the third holds even if zod later lifts the first. |
| `hydrate` absent (every extant endpoint) | no walk, no stamp, no deserialize — the code path does not exist for them. |
