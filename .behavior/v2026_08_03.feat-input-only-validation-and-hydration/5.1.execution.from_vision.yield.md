## 3 — the input seam now has one root primitive

**new**: `src/domain.operations/genLambdaEndpoint/middleware/getValidatedInput.ts`

```ts
export const getValidatedInput = <TInput>(input: {
  schema: ZodSchema<TInput>;
  value: unknown;
}): TInput => {
  const result = input.schema.safeParse(input.value);
  if (!result.success) throw getValidationError({ error: result.error });
  return result.data;
};
```

both families route through it:

| site | before | after |
|---|---|---|
| `genZodEventValidationMiddleware` (ask) | `safeParse(request.event)` + throw + assign | `getValidatedInput({ schema, value: request.event })` |
| `genZodBodyValidationMiddleware` (apigateway) | `safeParse(event.body)` + throw + assign | `getValidatedInput({ schema, value: event.body })` |

**behavior-identical.** what moved is the validation; what stayed is each family's **slot choice** —

## 7 — the ambient-credential hole

**found while retrying the blocked suite, and it is a `rule.forbid.failhide` at the credential
layer.**

a test run with no `AWS_PROFILE` and no static keys **silently acquires the box's ec2 instance
role** and runs against whatever account that role belongs to. measured on this host: the wrong
account resolved, the suite ran, and no output said so.

### the mechanism, from the vendor's own source

`@aws-sdk/credential-provider-node/dist-cjs/index.js`:

```js
defaultProvider = memoizeChain([
  fromEnv, fromSSO, fromIni, fromProcess, fromTokenFile,
  async () => (await remoteProvider(init))(),   // <-- the last link before the throw
  async () => { throw new CredentialsProviderError("Could not load credentials..."); },
]);

const remoteProvider = async (init) => { /* ... */ return fromInstanceMetadata(init); };
```

⇒ when every prior link declines, the chain **does not fail** — it reaches IMDS and succeeds with an
identity nobody selected. **no env var is involved**, which is why no check of `AWS_PROFILE` or
`AWS_ACCESS_KEY_ID` can detect it.

### the two levers, one line each, at three sites

| site | change |
|---|---|
| `jest.integration.env.ts` | `process.env.AWS_EC2_METADATA_DISABLED = 'true'` · `mode: 'lenient'` → `'strict'` |
| `jest.acceptance.env.ts` | same, plus the discriminant fix below |
| `provision/aws.infra/account=demo/resources.ts` | same · the highest stakes, since it CREATES resources |

**the sweep found three sites, not the two I first cited** — the provision wish sources its own
credentials and was invisible to a grep of `jest.*.env.ts` (`rule.require.sweep-the-defect-class`:
grep the SUBJECT, `keyrack.source`, never the shape of the instance you already fixed).

### the acceptance discriminant tested the wrong thing

```ts
// before
const hasAwsCredentials = !!(process.env.AWS_ACCESS_KEY_ID || process.env.AWS_PROFILE);
keyrack.source({ mode: hasAwsCredentials ? 'lenient' : 'strict', ... });
```

⚠️ **a credential from ANY account disarmed the check** — precisely the state that makes the check
matter, so the guard was weakest exactly when it was most needed. the question it means to ask is
*"is this ci?"*, so it now asks that:

```ts
keyrack.source({ mode: process.env.CI ? 'lenient' : 'strict', ... });
```

**ci is unaffected by either lever**: github oidc resolves at `fromEnv` / `fromTokenFile`, both
ABOVE `remoteProvider` in the chain, and ci stays `lenient` because it has no keyrack grant to make.

### the bound this does NOT close

`AWS_EC2_METADATA_DISABLED` disables **IMDS**, never "ambient" in general. from the same source, the
container check runs **first** and returns early, so on ecs/fargate
`AWS_CONTAINER_CREDENTIALS_RELATIVE_URI` still resolves and bypasses the flag.

⇒ **the complete repair is an account assertion** — call `sts:GetCallerIdentity` after the source and
compare `Account` against the expected id. that catches a wrong account from ANY source, including a
keyrack pointed at the wrong org. named here rather than built, since it is larger than this bound.

### the positive control

the levers do not break a healthy run: **integration 7/7 green with IMDS disabled and strict mode
on**, and the full acceptance suite green beside it.

**`ehmpathy/declapract-typescript-ehmpathy#611`** — every repo that runs aws-touching tests on a box
