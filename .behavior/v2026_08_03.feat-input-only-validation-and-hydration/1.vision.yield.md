## what this does

**a handler declares a domain object in its schema. the handler receives an instance; the
generated client receives the wire shape; the publish that hands it over stops crashing.**

```ts
genLambdaEndpoint({
  schema: { input: z.object({ surfer: Surfer.contract() }), output: z.null() },
  invoke: async ({ event }) => genSurfLesson(event.surfer),   // event.surfer instanceof Surfer
});
```

three consequences, and each is observable:

| layer | what it gets | today |
|---|---|---|
| `invoke` | a real `Surfer` — nested + arrays included | a plain object, rebuilt by hand or cast |
| a peer service's generated sdk | `{ surfer: { uuid, name } }`, pragma-tagged | — |
| `{ introspect: 'schema' }` | serializes | 💥 takes down `getAllLambdaContracts` service-wide |

**the `genLambdaEndpoint` contract gains no key.** the capability rides inside the schema value, so
a handler that names no domain object behaves exactly as today.

## the three changes

| # | change | why |
|---|---|---|
| 1 | `getJsonSchemaFromZod` passes `{ io: 'input' }` | publish the wire face instead of a throw — `#17` |
| 2 | bump `domain-objects` `0.33.0` → `0.34.0`, conform 16 call sites | `X.contract()` exists, and coerces |
| 3 | extract `getValidatedInput` to shared `middleware/` | one input-validation primitive, both families |

## the one behavior change a consumer can observe

**a `.default()` field publishes as optional instead of required.**

```
io=output   required: ["name","limit"]   →   { name: string; limit: number; }
io=input    required: ["name"]           →   { name: string; limit?: number; }
```

today the published contract lies: it tells a cross-service caller it MUST send a field that has a
default. `case6` of `local.introspection.acceptance.test.ts` carries
`limit: z.number().int().min(1).max(100).default(10)`, and the resnap drops `"limit"` from
`required`.

⚠️ **this is a real behavior change for any consumer whose schema defaults** — named here rather
than met in a diff.

## why it is urgent

`X.contract()` **always** coerces on `0.34.0`, and a coerce is a `.transform()`. zod's
`toJSONSchema` defaults to `io: 'output'`, where a transform has no rendition:

```
{ introspect: 'schema' }
  → genIntrospectionMiddleware.ts:58        getJsonSchemaFromZod(opts.schema.input)
  → …getJsonSchemaFromZod.ts                z.toJSONSchema(schema)     ← defaults io:'output'
  → zod/v4/core/json-schema-processors.cjs:271
  → Error: Transforms cannot be represented in JSON Schema
```

a bare `Error`, not a `HelpfulError`. **so on `0.34.0` every domain-object position in every schema
crashes the whole service's introspection until this lands.**

the same crash is already reachable today via a hand-written `.transform()` — a shipped, tested
feature (`forAskEndpoint.test.ts` `case6`). the two features were each tested in isolation and
never crossed, so the defect was invisible to the suite.

## the shapes a domain object can sit in

⚠️ **there is no `.coerce()` member.** the shipped surface is `X.contract()`, and the call always
coerces — verified against `0.34.0`'s `ContractOf`, which exposes `ref()` and no other member.

uc.1–4 isolate each shape; **uc.5 is the one to read if you read only one.**

**uc.1 — at the top level**

```ts
schema: { input: z.object({ surfer: Surfer.contract() }), output: z.null() }
// event.surfer instanceof Surfer
```

**uc.2 — under a PLAIN wrapper** — the shape the wish's evidence has, and the one a top-level-only
design would miss

```ts
schema: {
  input: z.object({
    signup: z.object({                     // <-- a plain object, NOT a dobj
      surfer: Surfer.contract(),           // <-- the dobj lives one level down
      note: z.string(),
    }).nullable(),
  }),
  output: z.null(),
}
// event.signup?.surfer instanceof Surfer · event.signup?.note still a plain string
```

**uc.3 — inside an array**

```ts
schema: { input: z.object({ surfers: z.array(Surfer.contract()) }), output: z.null() }
// every element instanceof Surfer
```

**uc.4 — nested in another dobj** — `.nested` covers the inner one for free

```ts
// WaveReport declares `public static nested = { spot: SurfSpot }`
schema: { input: z.object({ report: WaveReport.contract() }), output: z.null() }
// event.report.spot instanceof SurfSpot — via .nested
```

**uc.5 — several dobjs, at several depths**

```ts
genLambdaEndpoint({
  schema: {
    input: z.object({
      surfer: Surfer.contract(),                    // depth 0
      signup: z.object({                            // a PLAIN wrapper...
        spot: SurfSpot.contract(),                  //   depth 1 beneath it
        note: z.string(),
      }).nullable(),
      boards: z.array(Surfboard.contract()),        // depth 1, inside an array
      report: WaveReport.contract(),                // depth 0, carries .nested
    }),
    output: z.null(),                               // a claim, not a rubber-stamp
  },
  invoke: async ({ event }) =>
    genSurfLesson({
      surfer: event.surfer,        // instanceof Surfer   — its own contract
      spot: event.signup?.spot,    // instanceof SurfSpot — its own contract, through the wrapper
      boards: event.boards,        // Surfboard[]         — every element
      swell: event.report.spot,    // instanceof SurfSpot — .nested, NOT a contract of its own
    }),
});
```

**`SurfSpot` arrives by two routes, and that is not a contradiction.** the one under `signup`
declares its own contract; the one inside `report` is rebuilt by `WaveReport`'s `.nested`. the two
mechanisms compose without either aware of the other.

**what a handler writes today, for the same result:**

```ts
invoke: async ({ event }) =>
  genSurfLesson({
    surfer: new Surfer(event.surfer),
    spot: event.signup?.spot ? new SurfSpot(event.signup.spot) : null,
    boards: event.boards.map((b) => new Surfboard(b)),
    swell: new WaveReport(event.report).spot,
  }),
```

four constructors, one `.map`, one ternary — **each revisited when the schema shape moves.** the
declaration form does not move.

### at the OUTPUT border — what the bump made mandatory

```ts
schema: { input: z.object({ uuid: z.string() }), output: z.object({ trophy: SurfTrophy.contract() }) },
invoke: async ({ event }) => ({
  trophy: new SurfTrophy({ uuid: event.uuid, … }),   // <-- an INSTANCE, not a prop bag
}),
```

⇒ `X.contract()` binds `TOutput` to the instance type, so a prop-bag return is now a **compile
error**. the old `ZodSchema<any>` getter accepted it silently.

### the input-only case, which needed no feature at all

```ts
schema: { input: MyInput.contract(), output: z.void() },   // <-- always worked
```

⇒ `z.void()`, `z.undefined()`, `z.null()` and `z.never()` each answer the wish's first complaint.
reach for `z.unknown()` only where a value does come back and its shape is genuinely open.

⚠️ **this line was CORRECTED TWICE, and the second correction restored the first.** the trail, so
no later reader re-litigates it:

| when | the claim | verdict |
|---|---|---|
| vision | the idiom is `z.void()` | right, for the wrong reason — unmeasured |
| stone `5.1` | ⛔ **false** — `z.void()` / `z.undefined()` THROW on every io face (`Void cannot be represented in JSON Schema`), so the idiom is `z.null()` | right, and measured |
| after `5.3` | ✅ the throw is **repaired**, so `z.void()` is an idiom again — and the better one | measured, and clamped |

the repair: `getJsonSchemaFromZod` now passes `unrepresentable: 'any'` beside a
`setAbsentPositionsRendered` override, so an absent position publishes `{ "not": {} }` — "no json
value is valid here" — rather than a throw. the flag alone would render it `{}`, which is the
`z.any()` rubber-stamp the wish complained of, so the override is what makes it honest.

⇒ **and `z.void()` now outranks `z.null()` for a handler that returns no value.** `z.null()`
publishes `{"type":"null"}`, which claims a JSON `null` crosses the wire; for a `204` and for a
direct-invoke void return, none does. `{ "not": {} }` is the true statement. the measurement table
is in `5.1.execution.from_vision.yield.md`, and `[case11]` of
`genIntrospectionMiddleware.getJsonSchemaFromZod.test.ts` clamps every row of it.

### what a peer service generates

```ts
export const genSurfLesson = (input: {
  surfer: { uuid: string; name: string };    // the WIRE face, pragma-tagged
}): Promise<void> => { /* … */ };
```

**this is what makes `{ io: 'input' }` load-bearing.** `invoke` receives the instance; the report
publishes the wire shape; **the two differ by design.**

## `io` names the SIDE of a contract, never the BORDER of an endpoint

| the word | scope | values |
|---|---|---|
| **border** | the endpoint — which way a message travels | request / response |
| **side** | the contract — which face of the codec | wire (in) / instance (out) |

the wire face is what crosses at **both** borders, so one rule serves both. measured:
`JSON.stringify` is the real encoder on the response path, and it emits the wire face regardless of
what output validation returns.

⇒ this overturned my own first verdict ([awkward](#what-is-awkward)). upstream reached it
independently and now **clamps it in their own acceptance suite**, against the same trap:
*"`{ io: 'output' }` on the OUTPUT border reads natural and is wrong."*

## mental model

- **to a friend** — *"the schema parses the wire and hands you the object"*
- **the analogy** — a customs form. the wire face is what you declare at the border; the instance is
  what you carry once through
- **terms**

| they say | we say | why ours |
|---|---|---|
| hydrate / cast | **coerce** | the act `.contract()` performs, and upstream's own word |
| the plain object | the **wire shape** | it names the side, which is the distinction that matters |
| deserialize | *(two senses — unsettled)* | `JSON.parse` here, dobj-revival upstream |

⚠️ the `deserialize` collision is **live and shipped**, and spans two repos — see
[what we owe out](#what-we-owe-out).

## acceptance

- zero bare `z.toJSONSchema(schema)` calls remain
  - exactly one call site exists in `src`, and that function **is** the guard the upstream handoff
    asks for ⇒ the face is folded into the function rather than passed per caller
- a schema that carries a `.transform()` serializes on `{ introspect: 'schema' }` rather than throws
- **the crossed clamp uses a real `X.contract()` position, not only `case6`'s hand-written
  transform** — red before the repair, green after
- a two-border endpoint with real `X.contract()` / `.ref()` positions emits on both borders, pragma
  intact
- **a `.default()` field publishes as optional**, and the clamp says so
- `forApiGateway` shares `genIntrospectionMiddleware`, so one site reaches both families — verified

> **cut from this list: *"an output schema that cannot be encoded is refused."*** it was written
> when i expected the coerce to ship as a `z.codec`. it did not — upstream declined the codec
> deliberately (they import zod as `import type`) and **clamp that `z.encode` is unavailable**.
> their convention is `.parse` at both borders, safe because decode converges. that bullet would
> have refused the headline usecase.

## evaluation

- **pros** — no new surface, so no new way to hold it wrong · the type recovers, an axis no design
  of mine reached · one primitive serves both families · the published contract stops its lie
- **cons** — the bump breaks any consumer on `.contract` (ruled `minor`, usage is nil) · the diff is
  one argument plus a dep bump; the headline feature is upstream
- **edge cases**
  - `deserialize: { body: false }` × a dobj schema → the coerce meets a string; the error should
    read *"expected object, received string"*
  - an unbound dobj in a ref position → already guarded by `assertAllDomainObjectRefsBind`
  - a **tree-shaped** dobj (`Comment.replies: Comment[]`) → a `static schema` that calls its own
    `.contract()` throws, per js class-field order. upstream names `z.lazy(() => X.contract())` as
    the escape, and clamps it

## what is awkward?

**1. the wisher had to put the same question twice, and it killed a capability each time.** both
died to *"is this already possible?"* — the cheapest question available, and the one i skipped in
favor of *"how would i build it?"*.

**2. four claims in this yield were verified against a source i controlled, not against the artifact
itself — and every one fell.** the root: **verification reaches only the claim you aim it at**, so a
probe against my own model confirms the model rather than the world.

| the claim | the source i aimed at | what the artifact said |
|---|---|---|
| the `io` verdict is half-right | a probe of an unstated premise | `JSON.stringify` is the encoder — the verdict held in full |
| `io:'input'` is codegen-neutral | two fixtures i wrote, transform-free and default-free | `case6`'s shipped `.default(10)` differs across the faces |
| an un-encodable output must be refused | the handoff's guess that the coerce ships as a `z.codec` | it shipped one-way; the bullet would refuse the headline usecase |
| `.contract().coerce()` is the surface | the wish i was handed | no such member — the `.d.ts` exposes `.contract()` alone |

⇒ **when you measure a property of a dependency, reach for the dependency** — its `.d.ts`, its
shipped fixtures, its actual encoder — never for the model of it you already hold. the tell, present
each time: the source agreed with me on first read, and none had to meet a hard case.

**3. this yield led with its own journey rather than with what it does.** its `.tldr` opened on *"the
wish named two capabilities, and neither one needs a new surface"* — a verdict on my process, where
a reader needs the change. rewritten to declare the behavior first; the process moved below.

**4. it was 2,925 lines before condensation, from a 6.2k-char wish** — past the point where reviewers
overflow and render no verdict. the archaeology now lives in `appendix/` and `archive/`, by path.
