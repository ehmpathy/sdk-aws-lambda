# case=6 — after step 2, a `Map` / `Set` in the payload becomes read-only

critipath · sharp · actor = handler author · inventory row 3 · fulcrum F4

## narrative

a dedupe endpoint's schema ends in `.transform((ids) => new Set(ids))`, so its handler receives
`payload.seen: Set<string>`. two lines in its `invoke` touch it:

```ts
const seen = payload.seen;
seen.add(currentId);                 // a mutator
await markSeen({ seen }, context);   // a sink typed `{ seen: Set<string> }`
```

on 0.7.0 and after step 1, both compile: the local object arm maps `Set`'s keys and keeps its
methods, so `.add` is still there and the frozen value is still assignable to `Set`. at run time
`.add` succeeds too — `Object.freeze` does not seal a `Set`'s entries — so the sdk's own rule
(*no value handed to `invoke` is writable*) was never held for this shape.

after step 2 (type-fns `FrozenDeep`), `payload.seen` is `ReadonlySet<string>`. both lines stop to
compile: `.add` does not exist on a `ReadonlySet`, and a `ReadonlySet` is not assignable to `Set`.
and the runtime holds it too: the walk is type-fns' `asFrozenDeep` (F3), so a cast past the type
meets `a frozen Set refuses .add()`, and the sdk reports it as a server fault.

the edge fails safe:

- **fast** — at compile time, at the upgrade, not at run time.
- **loud** — `tsc` names it: `Property 'add' does not exist on type 'ReadonlySet<string>'`.
- **teaches the fix** — `ReadonlySet` says the value is not the handler's to change. the route is a
  copy — `const seen = new Set(payload.seen)` — or a sink typed `ReadonlySet<string>`.

so the break is real but has a one-line route out, and it moves the type toward the guarantee the
freeze promises. it rides a patch release only if the wisher accepts that (F4).

## timeline

```
given('[case6] a payload schema whose `.transform()` yields `seen: Set<string>`')
  when('[t0] after step 1, the handler calls `payload.seen.add(…)`')
    then('tsc accepts it')                                     # unchanged from 0.7.0
  when('[t1] after step 2, the handler calls `payload.seen.add(…)`')
    then('tsc refuses it — `add` does not exist on `ReadonlySet`')
  when('[t2] after step 2, the handler forwards `payload.seen` to a `Set<string>` sink')
    then('tsc refuses it')
  when('[t3] after step 2, the handler copies — `new Set(payload.seen)` — and mutates the copy')
    then('tsc accepts it — the route the error points at')
```
