# 1.vision — FrozenDeep keeps branded primitives, sourced from type-fns

## the outcome world

**before (0.7.0).** a handler whose payload holds an `IsoTimeStamp` cannot forward it:

```ts
invoke: async ({ payload }) => ({ payload: await getThreadsByParticipant(payload, context) })
//                                                                      ^ tsc: frozen `lastMessageAt` is not `string`
```

`IsoTimeStamp` is `string & OfGlossary<…>`. the tag half is an object type, so the intersection
`extends object`, and `FrozenDeep` maps it to a readonly bag of `String.prototype` methods plus
`_dglo`. the runtime freeze returns early on `typeof value !== 'object'` and never touches the
string — only the type lies. svc-chat carries `patches/sdk-aws-lambda@0.7.0.patch` to compile.

**after (0.7.1).** the same line compiles. `FrozenDeep<IsoTimeStamp>` is `IsoTimeStamp`, so the
type now mirrors the runtime's `typeof` check. writes into a frozen object are still refused at
every depth. svc-chat drops its patch. and the sdk no longer owns a deep-readonly type at all — it
re-exports type-fns' `FrozenDeep`, so a consumer's `import type { FrozenDeep } from 'sdk-aws-lambda'`
is unchanged.

**the aha.** a primitive has no interior to freeze. the type should say exactly that — and once it
does, every glossary-branded value (iso-time, iso-price, any `OfGlossary`) just flows through.

## the contract

step 1 — `setEventFrozen.ts`, one arm ahead of the rest:

```ts
export type FrozenDeep<T> =
  T extends string | number | boolean | bigint | symbol | null | undefined
    ? T
    : /* function · array · object arms, unchanged */
```

step 2 — the local declaration goes; the source moves; the public surface does not:

```ts
// setEventFrozen.ts + every variant
import type { FrozenDeep } from 'type-fns';
// src/index.ts
export type { FrozenDeep } from 'type-fns';
```

`type-fns` bumps `1.21.4 → 1.21.5` (prod dep; the release that exports `FrozenDeep`).

the brief `rule.require.frozen-invoke-inputs.md:101` names `setEventFrozen.ts` as the home of "its
`FrozenDeep` type"; step 2 re-points that line at type-fns. no other doc names the type's home
(`grepsafe` over `readme.md` → 0; over `.agent/repo=.this` → 17 lines, only `:101` names a file).

## mental model

- *to a friend:* "the sdk's deep-readonly type treated a branded string like an object. now strings
  stay strings, and the type lives in type-fns."
- *analogy:* shrink-wrap. you wrap the box and every box inside it; you do not try to shrink-wrap a
  sticker on the box.
- *their words vs ours:* they say "the timestamp isn't assignable"; we say "a branded primitive took
  the object arm".

## evaluation

- **goals:** both met — branded primitives survive (step 1); the sdk declares no `FrozenDeep`
  (step 2).
- **pros:** one line fixes every family at once (all four type their slots through one `FrozenDeep`);
  type and runtime agree; the general type has one owner.
- **cons:** a dep bump rides a patch release. and type-fns' `FrozenDeep` is stricter than the local
  one in one reachable spot: a `.transform()` can put a `Map` / `Set` in a payload, and type-fns maps
  it to `ReadonlyMap` / `ReadonlySet`, so a handler's `.set` / `.add` — or a hand-off to a `Map` /
  `Set` sink — stops to compile (`case=_` row 3, `case=6`, fulcrum F4). that refuses a write the
  sdk's own rule already forbids, with a one-line route out (copy it); dobj methods and `Date`s are
  unchanged (rows 11, 12).
- **edgecases held:** a brand nested, in an array, or nullable takes the same arm (rows 1, 2 —
  case=1 `[t1]`–`[t3]`); a plain primitive stays green (row 8); a write is still refused at depth
  two, with a read as the positive control (case=2, row 4 — recorded as a forbidden invariant).

## groundwork

### external research

- **type-fns `FrozenDeep`** — exists and is released. `gh release list --repo ehmpathy/type-fns` →
  `v1.21.5 Latest 2026-10-01`. at tag `v1.21.5`, `src/index.ts:19` exports `./types/FrozenDeep`;
  `src/types/FrozenDeep.ts:36-53` opens with the primitive arm
  (`string | number | boolean | bigint | symbol | null | undefined ? T`). its arrays take the
  homomorphic object arm (readonly array / readonly tuple, `:13-14`).
- **iso-time** — latest `1.11.7` (`npm view iso-time version`); in this repo only transitively
  (`pnpm why iso-time`), so a test cannot import it without a direct devDep.

### internal research

- **the defect:** `src/domain.operations/genLambdaEndpoint/setEventFrozen.ts:17-23` — no primitive
  arm; `:42` — runtime returns early on non-objects.
- **the defect, reproduced here:** a throwaway probe (`string & { _dglo: 'iso-time.IsoTimeStamp' }`,
  the exact shape `AsOfGlossary` emits — `domain-glossaries/src/AsOfGlossary.ts:46`) under
  `rhx git.repo.test --what types` → `TS2322` at all three positions: top-level, nested one level, and
  array item (`readonly { readonly toString…; readonly _dglo… }[]`). no other type error in the repo.
  probe removed after.
- **consumers of the type** (`grepsafe FrozenDeep --path src`, 46 lines): `InvokeInputSuperset.ts:1`,
  `forAsk.ts:15`, `forApiGateway.ts:21`, `forSqs.perRecord.ts:9`, `forSqs.perBatch.ts:9` import it
  from `../setEventFrozen`; `src/index.ts:165` re-exports it. all must move to `type-fns`.
- **the clamp's home:** `setEventFrozen.test.ts` — `[case7]` already holds the type-level clamp in
  the `@ts-expect-error` form; the new case sits beside it.
- **deps:** `type-fns` `1.21.4` (prod, `package.json:76`); release-please cuts a patch from a
  `fix(...)` commit (`.github/workflows/release.yml` → `please-release`).

## what is awkward?

- the step-1 arm lives locally for one commit only, then moves to type-fns. it exists so the clamp's
  bite is proven against a line this repo owns.
- after step 2, the sdk's clamp guards a type it does not declare. it still earns its place: a local
  `FrozenDeep` re-introduced without the arm, or a future type-fns that drops it, goes red here. a
  reader may still wonder why it is not in type-fns alone.
- a dependency bump inside a patch release. it adds an export and changes no runtime, so a patch is
  honest — yet it is the one part of 0.7.1 a consumer did not ask for.
