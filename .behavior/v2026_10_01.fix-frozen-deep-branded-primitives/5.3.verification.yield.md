### why the contract proof is type-level, not a snapshot

the fix is a **type**: `FrozenDeep`. its caller-facing effect is which handler code compiles. the
runtime swap to `asFrozenDeep` (F3) changes only what a write or a mutator does — the shape of every
value a handler reads is unchanged, so no `.snap` moved. each type claim is clamped where it lives —
at `tsc` — and each runtime claim by a `toThrow` or a classified outcome:

- a positive arm compiles a sink call (red under the 0.7.0 type: `TS2345`)
- a negative arm holds the refused line under `@ts-expect-error` (red when the refusal lapses:
  `TS2578`), with a read beside it as the positive control

the acceptance layer (`test:acceptance`, `blackbox/`) runs every handler through `src/index`, so it
re-proves that the frozen hand-off still serves real invokes. no `blackbox/` file names `FrozenDeep`
or `setEventFrozen` (`grepsafe 'FrozenDeep|setEventFrozen' --path blackbox` → 0; the same form returns 145 lines for
`genLambdaEndpoint`, so the tool reads that scope).
