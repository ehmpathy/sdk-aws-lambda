# case=5 — a patched consumer upgrades and drops its patch

critipath · happy · actor = consumer repo maintainer (ahbode/svc-chat) · the densest walk

## narrative

svc-chat adopted 0.7.0 and hit the defect, so it carries `patches/sdk-aws-lambda@0.7.0.patch` —
the step-1 line, applied by pnpm at install. that patch is debt: it pins the sdk to one exact
version, and every upgrade must re-cut it.

0.7.1 lands. the maintainer bumps the pin, deletes the patch file and its `patchedDependencies`
entry, and reinstalls. `tsc` is green with no patch: the upstream type now does what the patch did.
the handler line — the one case=1 shows,
`invoke: async ({ payload }) => ({ payload: await getThreadsByParticipant(payload, context) })` — is
unchanged throughout — the fix crossed the sdk release, the package manager, and the handler
without a touch to the handler.

## boundaries crossed

sdk release (0.7.1) → pnpm install (patch removed) → consumer `tsc` → handler forward of a branded
value. four boundaries, one walk, no code change in the consumer's domain.

## timeline

```
given('[case5] svc-chat on sdk-aws-lambda@0.7.0 with the step-1 patch applied')
  when('[t0] the sdk pin moves to 0.7.1 and the patch + its entry are removed')
    then('pnpm install succeeds')
    then('tsc is green, with `getThreadsByParticipant.ts` unchanged')
```

the sharp twin — the pin moves and the stale `@0.7.0` patch entry is left behind — is pnpm's to
surface, not this sdk's. it is itemized (`case=_` row 15), not demoed here.
