# case=2 — a write into the frozen payload is still refused

critipath · sharp · actor = handler author · inventory rows 4 and 21 (forbidden)

## the invariant

no value handed to `invoke` is writable, at any depth (`rule.require.frozen-invoke-inputs`). the
primitive arm must not weaken it: it answers only *"what is a primitive?"*, and sits ahead of an
object arm that is otherwise unchanged.

## narrative

the same author, in a hurry, tries to stamp a default before the forward:
`payload.page.lastMessageAt = asIsoTimeStamp(now())`. the compiler refuses it, exactly as on 0.7.0.
the edge fails safe on all three counts:

- **fast** — at compile time, before a frozen-write `TypeError` could turn the handler into a 500.
- **loud** — `tsc` names the field: `Cannot assign to 'lastMessageAt' because it is a read-only
  property` (TS2540). and should a cast slip past, the runtime freeze throws on the write.
- **teaches the fix** — the read-only field says *"this is not yours to change"*, which points at the
  one move that is: build a new value — `{ ...payload, page: { ...payload.page, lastMessageAt } }` —
  and forward that.

later, the same author tags the thread before the forward: `payload.tags.push('read')`. an array
is a container rather than a field, so it gets its own refusal, and the same three counts hold:
`tsc` names the gap — `Property 'push' does not exist on type 'readonly string[]'` (TS2339), and for
an index write `Index signature in type 'readonly string[]' only permits reading` (TS2542). a cast
past the type meets the runtime freeze, which throws. the fix is the same as before: build a new
array, `[...payload.tags, 'read']`, and forward that.

## timeline
