# case=4 — a server fault still redrives

**cell**: perRecord × handler × server, perBatch × handler × server · sharp × criti
**seat**: the on-call engineer, mid-outage

from that seat: the dead-letter queue alarm still fires when the database is down — and now it means only that, since producer faults no longer feed it. once the database is back, the engineer redrives the dead-letter queue and every message is served.

## narrative

the order database is down. the `consumeOrder` handler throws a `MalfunctionError('database unreachable')`.

before and after alike: the throw fails the invoke (perRecord), or redrives the whole batch (perBatch). sqs retries the message, and it dead-letters if the outage outlasts `maxReceiveCount`. the message was fine; the service was not, so a retry is the right answer. this case is the guard rail on the change: the catch allowlists caller faults only, so a fault of ours is never swallowed into a deleted message (`rule.forbid.failhide`).

## sketch

```ts
given('[case4] a forSqs endpoint whose handler throws a server fault', () => {
  when('[t0] perRecord: the handler throws MalfunctionError', () => {
    then('the invoke fails, so sqs redrives the message', ...);
    then('no sqs.record.refused is logged', ...);
  });
  when('[t1] perBatch: the handler throws MalfunctionError', () => {
    then('the invoke fails, so sqs redrives the batch', ...);
  });
});
```
