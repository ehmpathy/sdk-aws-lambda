# case=2 — a server fault stays a server fault, now named

sharp × critipath. B2 × C1 × D3.

## narrative

leilani calls `getQuote` from svc-checkout via `runLambdaEndpoint`. the forAsk handler behind it hits a dead upstream and throws `MalfunctionError`. she must be able to retry it, and the on-call engineer must see it.

before: locally her caller got `MalfunctionError`; on cloud, `Error`. both read as server faults, so retry worked — but cloudwatch showed `errorType: Error`, and the on-call engineer could not tell a malfunction from a bare throw.

after: the guard names the throw `MalfunctionError` before the internal middleware logs and rethrows it. both loci write `errorType: 'MalfunctionError'`. leilani's caller reads a server fault — never a caller fault — so her retry stays correct. the failure is loud: the invocation fails, cloudwatch records `MalfunctionError` by name, and the `handler.error` log names the endpoint.
