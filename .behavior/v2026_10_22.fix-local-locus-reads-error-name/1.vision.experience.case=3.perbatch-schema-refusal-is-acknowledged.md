# case=3 — a perBatch record the schema refuses is acknowledged

**cell**: perBatch × schema × caller · sharp × criti
**seat**: the operator of the consumer team, who reads the dead-letter queue depth

from that seat: before, one malformed message per bad producer release crept into the dead-letter queue, and each had to be read and discarded by hand. after, the queue depth stays at zero for producer faults, and a refused record is one warn line, found by its message id.

## narrative

a `forSqs.perBatch` endpoint receives ten messages. one lacks a required field.

before: the validator's refusal is logged as `sqs.record.invalid`, the record is held back from the handler, and its id lands in `batchItemFailures`. sqs redrives that one message until it dead-letters. the nine healthy messages are served and deleted.

after: the refusal is a caller fault, so it is logged as `sqs.record.refused` and its id is left out of `batchItemFailures`. sqs deletes it with the nine. the handler still sees only the nine, exactly as before — it is never handed a record it cannot read.
