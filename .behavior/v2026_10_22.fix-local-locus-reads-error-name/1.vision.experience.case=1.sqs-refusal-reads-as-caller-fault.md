# case=1 — an sqs refusal reads as a caller fault, on both loci

sharp × critipath. the svc-quotes defect.

## narrative

kai owns an sqs consumer built with `genLambdaEndpoint.forSqs.perRecord`. a message arrives with a malformed quote id; the handler throws `ConstraintError('quote id malformed')`. the family rethrows on purpose, so sqs redrives and dead-letters it.

before: kai's local acceptance test reads a `ConstraintError`. green. prep reads `LambdaEndpointError`, since the runtime wrote `errorType: 'Error'`. red, and kai cannot reproduce it locally.

after: the name guard sets `.name = 'ConstraintError'` as the throw escapes. the local locus reads `.name` exactly as the runtime does. both loci write `errorType: 'ConstraintError'`; the caller reads a caller fault on both. if a future error class ever lacked a name, the local run would go red first — fast and loud, at the pr gate, not in prep.

## bdd

```
given [case1] a forSqs.perRecord endpoint whose handler throws a helpful-errors ConstraintError
  when [t0] the endpoint handler runs
    then the escaped error carries .name = 'ConstraintError'
  when [t1] it runs on the local locus via runLambdaEndpoint
    then the caller rejects with a ConstraintError (caller fault)
  when [t2] the escaped error is serialized as the runtime does (errorType = error.name)
    then errorType = 'ConstraintError'
```
