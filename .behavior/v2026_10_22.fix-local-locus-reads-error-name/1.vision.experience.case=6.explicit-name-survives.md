# case=6 — an explicit `.name` survives the guard

sharp × critipath. B2 × C2 — fulcrum F2.

why critipath: a team that sets `name = 'ConstraintError'` on its subclass does so to be read as a caller fault. if the guard clobbered it with the class name, every such refusal would read as a server fault and the caller would retry it forever. cost is unbounded; frequency is every throw of that class.

## narrative

malia owns an sqs consumer. her team declares `class QuoteStaleError extends ConstraintError { name = 'ConstraintError' }`, so a stale quote reads as the sender's fault. the same consumer wraps an aws sdk call that throws a plain `Error` whose `.name` is `'CredentialsProviderError'`.

when a stale quote arrives, the guard sees `.name === 'ConstraintError'` — not the default `'Error'` — and leaves it. the runtime writes `ConstraintError`; malia's local acceptance run writes the same; her test caller reads a caller fault on both loci, exactly as her team intended. when the credentials fail, the guard leaves `CredentialsProviderError` alone too, so the on-call engineer sees aws's own name in cloudwatch. fail-safe: the guard only ever fills a blank; it never overwrites a choice.

## bdd

```
given [case6] a forSqs.perRecord endpoint whose handler throws a ConstraintError subclass with name = 'ConstraintError'
  when [t0] the endpoint handler runs
    then the escaped error's .name is 'ConstraintError', not 'QuoteStaleError'
  when [t1] it runs on the local locus via runLambdaEndpoint
    then the caller rejects with a caller fault
given [case6b] the handler throws an Error with .name = 'CredentialsProviderError'
  when [t0] the endpoint handler runs
    then the escaped error's .name is still 'CredentialsProviderError'
```
