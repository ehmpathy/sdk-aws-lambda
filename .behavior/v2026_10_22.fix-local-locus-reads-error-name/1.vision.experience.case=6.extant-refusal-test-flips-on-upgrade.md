# case=6 — an author's extant refusal test flips on the upgrade

**cell**: off-grid, lifecycle — upgrade · sharp × criti

## narrative

an endpoint author has a `forSqs.perRecord` test that asserts a refusal rejects: `expect(await getError(handler(event, ctx))).toBeInstanceOf(ConstraintError)`. it encoded the old contract — a refusal redrives.

after the bump, the same call succeeds: the refusal is acknowledged. the test goes red with "expected an error, none thrown". that red is the contract change, surfaced at the author's own gate rather than in production. the release note and the `sqs.record.refused` log tell the author what to assert instead: the call succeeds, and the warn names the message.

the fail-safe: the change is loud. no test that asserted a rejection stays green by accident, and no handler code changes — only the assertion.

## sketch

```ts
given('[case6] a perRecord test written against the redrive contract', () => {
  when('[t0] the suite runs on the upgraded sdk', () => {
    then('the rejection assertion fails loud — the call now succeeds', ...);
    then('the release note names the new assertion: the call succeeds, with sqs.record.refused logged', ...);
  });
});
```

## care

critipath: every consumer with a perRecord refusal test meets it on the bump — svc-quotes first. the sdk side owes a release note in the PR body and the commit; the consumer side owes one assertion swap.
