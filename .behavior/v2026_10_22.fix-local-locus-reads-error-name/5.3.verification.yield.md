### found in verification

- **a local-vs-cloud label divergence, fixed.** a re-read of the runtime's `_isError` (`aws/aws-lambda-nodejs-runtime-interface-client` `main`, `src/Errors.js`) shows it asks no `typeof` of the value. `isRuntimeErrorShape` required `typeof value === 'object'`, so a named function with a string `message` and `stack` read `'function'` locally and its `.name` on the cloud. the gate now accepts `object` or `function`. clamp: the `asErrorTypeOfErrorLike.test.ts` row "a named function that carries the trio" → `'quotaFault'`. fix reverted → 14 passed / 1 failed; restored → 15 / 0. a serde test comment that gave the wrong reason for the anonymous-function row is corrected
- **the `'handled'` message differed by locus, fixed.** the runtime's catch arm writes one fixed message ("callback called with Error argument, but there was a problem while …") and no trace. the local payload wrote `String(error)` (`"null"`, `"undefined"`) or, for a stackless native error, its own message. `asWireFunctionErrorPayload` now writes the runtime's text for every `'handled'` payload. clamp: `[case1][t1]` "the whole payload is the runtime's catch arm" plus the `[case3][t1]` snapshot rows. branch disabled → 20 passed / 2 failed; restored → 22 / 0
- **a thrown `null` / `undefined` read `'handled'` locally and `'string'` on the cloud, fixed.** found by `blackbox/deployed.faultLabel.acceptance.test.ts` on its first run against the real runtime: 3 failed, each on the `null` kind (cloud `errorType: 'string'`, `errorMessage: 'handled'`; local `'handled'` + the fixed text). cause: the runtime's `CallbackContext.fail` swaps a null or undefined rejection for the string `'handled'` before `toRapidResponse` runs. `asWireFunctionErrorPayload` now makes the same swap. rerun → 6 passed / 0 failed; serde unit → 96 / 0
- **the real-queue sqs proof is deferred to a dream, by the director's verdict (F12).** the suite met `sqs:createqueue` AccessDenied on the demo sso role. the vision scopes aws's redrive out (`1.vision.yield.md:66`), and the director ruled the p0 ships without an iam grant it does not need. the suite, its handler asset, and the blocker evidence are parked in `.dream/2026_10_22.demo-infra-sqs-endpoint-for-cloud-disposition.assets/`; `@aws-sdk/client-sqs` is removed. what the sdk hands sqs stays pinned by `blackbox/local.sqsQueue.acceptance.test.ts` (36 passed)
