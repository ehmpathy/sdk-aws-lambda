# wish: the local locus serializes a thrown error the way the aws runtime does

## .the defect

ehmpathy/sdk-aws-lambda#73. the aws node runtime serializes a thrown error as `errorType: error.name`. sdk-aws-lambda's local locus builds the payload from `error.constructor.name`. so a local run names a ConstraintError correctly while the cloud wire names it `Error`, and the pr gate stays green while prep is red (svc-quotes run 38852404042). root cause: helpful-errors#45, cured in the peer tree helpful-errors.beav.fix-error-name-from-class.

## .the outcome

- the local locus reads `error.name`, exactly as the runtime does, so a local run reproduces the cloud wire
- a handler built via `genLambdaEndpoint` that throws a helpful-errors ConstraintError reaches the client as a caller fault (`ConstraintError`), locally and on the cloud shape alike, once helpful-errors carries `.name`
- optional, best-guess and itemize: a guard in `genLambdaEndpoint` that sets `.name` from the class before a throw escapes, so an error class that lacks `.name` still reaches the wire named

## .done

1. a clamp: a thrown error whose `.name` differs from its constructor name serializes as `.name` on the local locus. red before, green after
2. a clamp: a ConstraintError thrown through `genLambdaEndpoint` is parsed by the client as a caller fault
3. if the clamps need the new helpful-errors before it releases, pin it via a pnpm link or `pnpm patch` in this tree, so this PR is not blocked on that release; say in the PR body that the pin swaps to the released version
